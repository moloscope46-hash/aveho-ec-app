La vue v_stats_activite_global calcule en une seule passe toutes les comparaisons mois courant vs précédent :

Performance : la vue agrège audit_log filtré par created_at en une seule passe avec des filter. Avec les index existants sur (structure_id, created_at), elle reste rapide même sur de gros volumes.

2. SQL — RPC drill-down

create or replace function get_heatmap_drill(
  p_structure_id uuid,
  p_jour_semaine int,    -- 0=dim, 1=lun, ..., 6=sam
  p_heure int,           -- 0-23
  p_limit int default 50
)
returns table (id, action, entite, entite_id, 
               user_email, user_id, details, 
               created_at, jour_label)
  • Stable + security invoker : respecte la RLS de audit_log (un user ne voit que ses lignes structure)
  • Filtre 90 jours : cohérent avec la heatmap qui affiche cette même fenêtre
  • Tri DESC : les plus récentes d'abord
  • jour_label formaté : "Mar 28/05 14:32" — directement affichable
  • grant authenticated : tout user connecté peut appeler (RLS protège)

3. Composant TrendBadge

Composant SVG inline réutilisable. Aperçu des 4 états :

Hausse (mode normal)
↗ +21% vs mois dernier
Baisse (mode normal)
↘ −18% vs mois dernier
Stable (< 2%)
≈ vs mois dernier
Pas de N-1
Nouveau vs mois dernier

API

<TrendBadge 
  current={125}        // valeur actuelle
  previous={100}       // valeur N-1
  inverse={false}      // true = baisse = bon (taux refus, erreurs)
  label="vs mois dernier"
  size="sm"            // "sm" ou "md"
/>

Logique

  • Calcul : pct = (current − previous) / previous × 100
  • Seuil neutre : |pct| < 2% → "≈" gris (évite le bruit visuel sur micro-variations)
  • previous = 0 et current > 0 → "Nouveau" vert (impossible de diviser par 0)
  • Mode inverse : pour taux de refus, erreurs, etc. — la baisse est positive
  • Si current ou previous est null → retourne null (pas affiché)

4. Heatmap cliquable

Le composant <Heatmap> de Charts.js accepte maintenant une prop onCellClick :

<Heatmap 
  data={heatmap}
  color="#185FA5"
  onCellClick={(cell) => {
    // cell = { jour_semaine: 1, heure: 14, nb_actions: 23, jour_label: "Mar" }
    openDrill(cell);
  }}
/>
  • Cellules avec nb_actions > 0 deviennent cliquables (cursor pointer)
  • Cellules vides restent passives
  • Tooltip natif enrichi : "Mar 14h : 23 actions — cliquer pour détail"
  • Hint visible sous la heatmap : "💡 Clique sur une cellule colorée pour voir le détail"

5. Modale drill-down

Au clic sur une cellule, une modale s'ouvre avec :

  • Titre : "Mar 14h — 23 actions"
  • Note : précise que les 50 dernières actions sont agrégées sur 90 jours pour ce créneau (tous les mardis confondus)
  • Tableau : Date complète · Action · Entité · Utilisateur
  • Couleurs par action : creer (vert), modifier (orange), supprimer (rouge), valider (teal), refuser (rouge), recevoir (violet), cloturer (bleu)
  • Icônes par entité : 8 entités mappées (intervention, achat, transfert, signalement, patient, materiel, maintenance, consentement)
  • Scroll interne : maxHeight 480px pour ne pas dépasser l'écran

États gérés :

  • loading : spinner pendant le fetch RPC
  • vide : "Aucune action sur ce créneau" (peut arriver si la heatmap a une cellule à 0 cliquée — théoriquement impossible mais robuste)
  • erreur : message d'erreur RPC avec icône warning
