3. A Migration & dette technique

3.1 Auto-rattachement admin aux établissements

Le piège #7 de la 0.15.6 documentait qu'un admin de structure n'était pas automatiquement admin d'établissement. Il fallait l'INSERT manuel dans membres_etablissements. C'est désormais automatique grâce à 2 triggers SQL :

  • trg_auto_rattach_admin sur membres_structure : déclenché sur INSERT et UPDATE de role/role_id. Si l'utilisateur devient admin, il est rattaché à tous les établissements de sa structure.
  • trg_rattach_admins_new_etab sur etablissements : déclenché sur INSERT. Si un nouvel établissement est créé, tous les admins existants de la structure y sont rattachés.

Le patch inclut aussi une requête de rattrapage qui répare les admins déjà existants qui n'auraient pas été rattachés.

3.2 Colonne interventions.due_date

La 0.15.5 avait retiré due_date du select calendrier parce que la colonne n'existait pas. Le patch SQL ajoute add column if not exists due_date date + un index conditionnel sur les non-null. Le code app/calendrier/page.js remet due_date dans le select des interventions.

Pour saisir l'échéance d'une DI, il faudra une 0.16.2 qui ajoute le champ dans la modale d'édition.

3.3 Schéma rôles legacy clarifié

La table membres_structure a deux colonnes pour le rôle :

  • role (text) — legacy 0.1, valeurs 'admin' / 'lecture' / 'membre'
  • role_id (uuid) — moderne, référence roles.id

Le patch SQL synchronise les deux dans les deux sens :

  • Si role_id est set mais role est null → on déduit role en regardant si le rôle référencé est "Administrateur" ou "Lecture seule"
  • Si role est set mais role_id est null → on rattache au rôle système correspondant dans la structure

À terme (0.17), la colonne role sera dépréciée au profit de role_id uniquement. Le code app gère déjà les deux via la tolérance useAuth.

3.4 Manifest PWA modernisé

Le warning Chrome "<meta apple-mobile-web-app-capable> is deprecated" est résolu en ajoutant le tag moderne <meta mobile-web-app-capable> dans app/layout.js. Le tag legacy reste présent via la metadata Next.js (appleWebApp.capable) pour la compatibilité iOS.

4. B Refactor — composants partagés

4.1 Composant <FilterBar>

Nouveau composant dans app/ui.js qui standardise la barre de filtres en pastilles avec compteurs. Pattern qui était dupliqué sur Achats, Utilisateurs, Invitations (et le sera bientôt sur DI/Statistiques).

Usage :

<FilterBar
  label="Voir :"
  value={filtreStatut}
  onChange={setFiltreStatut}
  options={[
    { v:"actifs", l:"Actifs", count:5 },
    { v:"archives", l:"Archivés", count:2 },
    { v:"tous", l:"Tous", count:7 },
  ]}
/>

Options supportées : v (valeur), l (label), count (compteur affiché entre parenthèses), icon (icône Tabler optionnelle). Plus paramètre color pour personnaliser la couleur active (par défaut teal).

La page Utilisateurs (membres + invitations) a été migrée vers FilterBar. Code passé de 30 lignes dupliquées à 8 lignes par usage.

5. C Nouvelles fonctions

5.1 Bouton "Commander un remplacement"

Sur la fiche matériel, un nouveau bouton (à côté d'Imprimer et Modifier) déclenche un parcours unifié vers /achats :

  1. Clic sur "Commander remplacement"
  2. Redirection vers /achats?nouvelle=oui&designation=Lit+Hill-Rom&motif=Remplacement+...&qte=1
  3. La page /achats détecte les query params et ouvre automatiquement la modale "Nouvelle demande d'achat" pré-remplie
  4. L'utilisateur ajuste le fournisseur, le prix, et soumet

Le motif est auto-renseigné avec le S/N du matériel (ex. "Remplacement Lit médicalisé Hill-Rom (S/N HR-2019-4421)"). Sept query params supportés : nouvelle, designation, motif, qte, prix, fournisseur, et l'URL est nettoyée après le pré-remplissage pour éviter de re-trigger au refresh.

6. Patch SQL 0.16.1

Le script aveho-PATCH-vers-0.16.1.sql (178 lignes) effectue dans l'ordre :

  1. Fonction auto_rattach_admin_etabs() + trigger sur membres_structure
  2. Fonction auto_rattach_admins_to_new_etab() + trigger sur etablissements
  3. Rattrapage des admins déjà existants qui n'étaient pas rattachés
  4. Colonne interventions.due_date + index conditionnel
  5. Synchronisation role ↔ role_id dans les deux sens
  6. Seed de 10 étiquettes par défaut pour les structures sans étiquettes

100% idempotent (create or replace, add column if not exists, drop trigger if exists, not exists dans les inserts). Rejouable sans risque. Inclut un bloc de requêtes de vérification en commentaire à la fin.

8. Procédure d'application

  1. SQL d'abord : dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.16.1.sql → Run. Tu dois voir Success sans erreur. Idempotent donc rejouable.
  2. Vérification SQL : décommenter et exécuter le bloc de requêtes en fin de fichier pour confirmer que les triggers sont créés, les étiquettes seedées, etc.
  3. Code ensuite : 
    cd C:\aveho-ec-app
# Décompresse aveho-ec-app.zip par-dessus (garde .env.local)
npm install
npm run dev
  4. Tests dans le navigateur (Ctrl+Shift+R d'abord) :
    • /etablissement/edition sur un nouveau user invité : il peut directement créer batiments / étages sans piège membres_etablissements
    • /calendrier : aucune erreur 400, les échéances apparaîtront quand on en saisira
    • /etiquettes : 10 étiquettes seedées visibles
    • /utilisateurs : les filtres s'affichent avec le pattern FilterBar (identique visuellement)
    • /materiel/<id> : tooltips sur S/N, Parc, Lot, Réf. — bouton "Commander remplacement" qui ouvre /achats avec la modale pré-remplie
  5. Mise en ligne Vercel : 
    cd C:\aveho-ec-app-01
robocopy C:\aveho-ec-app C:\aveho-ec-app-01 /E /PURGE /XD .git node_modules .next
git add . ; git commit -m "Aveho EC 0.16.1 - roadmap 0.16 finalisée" ; git push

10. Roadmap 0.17 suggérée

  1. Notifications push navigateur (VAPID) — chantier service worker. Permet d'alerter en temps réel pour les DI urgentes, les achats à valider.
  2. Intégration Teams / Slack — webhook outbound pour relayer les notifs critiques (DI urgentes, achats validés, alertes maintenance).
  3. Drag tactile mobile Kanban — refactor avec dnd-kit pour faire fonctionner le drag-and-drop sur téléphone (actuellement HTML5 DnD qui ne marche pas sur touch).
  4. Notes 0.12 → 0.14 enrichies — sections "Pièges connus" pour chacune, dans le style des notes 0.15.6 / 0.16.0 / 0.16.1.
  5. Saisie due_date dans la modale DI — petit ajout UI sur /interventions et /interventions/kanban.
  6. Dépréciation role text — supprimer toute référence à la colonne legacy une fois le code 100% sur role_id.
  7. Refactor profond — séparer logique métier de la présentation, extraire les hooks personnalisés (useAuth déjà OK, mais à étendre).
  8. Tests unitaires — au moins sur les helpers critiques (canDo, fmtDate, statutClass).
  9. Audit accessibilité (a11y) — passe sur les modales, les boutons, les contrastes.
  10. Affichage "En ligne il y a X" sur la liste membres (basé sur v_user_activity.derniere_activite).
