🐛 Les 2 problèmes corrigés

1. Mobile — popup coupée à droite

La popup hover faisait 460px de large + se positionnait au curseur. Sur écran 380px, elle débordait largement à droite et le contenu était inaccessible.

2. PC — flash apparaît/disparaît

Le tooltip était lié à la position de la souris avec onMouseMove, donc il bougeait en permanence. Avec un setTimeout de 250ms avant le fetch, on avait des cas où le tooltip s'affichait juste pour disparaître quand l'user bougeait la souris vers le titre suivant.

🎯 La nouvelle UX

Click pour ouvrir, plus de hover

Le hover est complètement supprimé. À la place :

  • Clic sur le titre d'une version → la modale s'ouvre, highlight basé sur le titre
  • Clic sur une évolution (ligne avec chip code en couleur) → la modale s'ouvre, highlight basé sur le texte de l'évolution cliquée
  • Curseur pointer + fond ambre clair au hover pour indiquer les zones cliquables

Modale plein écran (max 960×92vh)

  • Header gradient navy → couleur de la version
  • Compteur de matches "3/12" avec boutons ⬆ et ⬇
  • Bouton Télécharger HTML (teal)
  • Bouton X de fermeture
  • Bandeau jaune : "N passages surlignés pour « ajout de droit »" + liste des mots-clés extraits
  • Zone scrollable avec la note HTML complète (styles scopés à .cl-note-scope pour éviter la pollution CSS)

🔍 Le système de highlight

Extraction des mots-clés (côté client)

Quand on clique sur une évolution avec le texte "Page /utilisateurs : bouton 'Créer un utilisateur' avec modale enrichie", on extrait :

  1. Tokenisation : split sur espaces + ponctuation
  2. Filtre : longueur ≥ 4 caractères
  3. Filtre : pas dans la liste de stopwords français (le, la, les, dans, avec, pour, etc.)
  4. Bonus : versions (0.55.12), acronymes 3+ chars majuscules (RPC, FR, CERFA)

Résultat pour l'exemple ci-dessus : ["page", "utilisateurs", "bouton", "créer", "utilisateur", "modale", "enrichie"]

Injection des marks dans le HTML

On découpe le HTML en tokens (alternance tags / texte) avec une regex pour ne PAS matcher dans les attributs ni dans les balises <style> :

const tokenizer = /<[^>]+>|[^<]+/g;

Pour chaque segment de texte uniquement, on applique le pattern multi-keywords :

(?<![a-zà-ÿ0-9])(motcle1|motcle2|...)(?![a-zà-ÿ0-9])

Les lookarounds remplacent les \b qui marchent mal avec les accents. Chaque match devient un <mark class="cl-match" data-cl-idx="N">.

Navigation

Le state currentMatch est un entier. À chaque changement :

  1. On enlève la classe .active de tous les marks du conteneur
  2. On ajoute .active sur le mark [data-cl-idx="N"]
  3. On déclenche scrollIntoView({behavior:"smooth", block:"center"})

Le match courant a un style ambre vif (#EF9F27) + outline blanc + glow.

⌨ Raccourcis clavier dans la modale

  • Échap — ferme la modale
  • F3 ou n — match suivant
  • Shift+F3 ou p — match précédent
  • Clic en dehors de la modale — ferme

Les raccourcis n/p sont ignorés si le focus est dans un champ texte.
