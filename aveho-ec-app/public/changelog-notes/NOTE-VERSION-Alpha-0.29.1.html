Contexte

Au premier lancement de la 0.29.0 en local, 3 erreurs sont apparues dans la console navigateur sur la page /profil :

🐛 Bug #1 — Table audit_events inexistante (404)

Symptôme : GET /rest/v1/audit_events?... → 404

Cause : J'ai utilisé le nom audit_events dans la requête, mais la vraie table créée dans le schéma (depuis la 0.4) s'appelle audit_log. Erreur de mémoire en codant rapide.

Conséquence : Le panneau "Mes 15 dernières actions" ne se chargeait jamais.

🐛 Bug #2 — Colonne signalements.user_id inexistante (400)

Symptôme : GET /rest/v1/signalements?...&user_id=eq.xxx → 400 (column does not exist)

Cause : J'ai supposé qu'il y avait un user_id sur la table signalements, mais le schéma a été conçu volontairement anonyme — pas de user_id, seulement un champ signature text optionnel si l'auteur veut signer. Commentaire explicite dans le SQL :

-- NOTE : pas de user_id sur cette table. Volontaire pour l'anonymat.

Conséquence : KPI "Signalements" du dashboard /profil cassé.

🐛 Bug #3 — Service Worker servant 503 Offline sur /maintenance

Symptôme : maintenance:1 Failed to load resource: 503 (Offline)

Cause : Le SW PWA a mis en cache une réponse "Hors-ligne" pour /maintenance lors d'un test offline précédent (DevTools → Network → Offline). Le SW ressert cette réponse stockée même quand le réseau est revenu.

Type : Bug d'usage utilisateur, pas du code Aveho. La logique networkFirst du SW est correcte, mais le cache contient une réponse 503 figée.

Fix #3 — Documentation côté utilisateur

Procédure pour vider le cache du Service Worker :

  1. Ouvrir Chrome sur http://localhost:3000
  2. F12 → onglet Application
  3. Sidebar gauche → Service Workers
  4. Clic Unregister à côté de l'entrée Aveho
  5. Application → Storage → Clear site data
  6. Fermer et rouvrir l'onglet

Plus rapide : Ctrl + Shift + R (hard refresh ignore cache)
