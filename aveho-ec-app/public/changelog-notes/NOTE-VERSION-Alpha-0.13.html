3. Fiche patient 360° NOUVEAU

3.1 Accès

Sur la page Patients, le nom d'un patient devient cliquable et ouvre sa fiche détaillée à l'URL /patient/[id]. C'est le pendant symétrique de la fiche matériel livrée en 0.12.

3.2 Contenu de la fiche

  1. Entête — nom prénom, âge calculé depuis la date de naissance, chambre, service, établissement, numéro de dossier, étiquettes, état, médecin traitant
  2. 4 KPIs — matériels affectés, en location active, DI ouvertes, DI sur les 30 derniers jours
  3. Tableau Matériels affectés — toutes les lignes materiels.patient_id = patient_id, cliquables vers la fiche matériel /materiel/[id]
  4. Tableau DI — toutes les demandes d'intervention sur ce patient, ordonnées par date desc, cliquables
  5. Historique d'activité — derniers 20 événements rattachés au patient (depuis la table evenements)

3.3 Cas d'usage

  • Synthèse rapide pour un nouveau membre de l'équipe qui prend en charge un patient
  • Revue trimestrielle du dossier : combien de DI, combien de matériels, étiquettes appliquées
  • Sortie / décès / transfert : checklist des matériels à récupérer en un coup d'œil
  • Navigation fluide : patient ↔ matériels ↔ DI sans repasser par la liste à chaque fois

4. Statistiques signalements NOUVEAU

La page /statistiques gagne une nouvelle section Signalements anonymes qui s'affiche dès qu'il y a au moins un signalement dans les 6 derniers mois. Trois graphes :

  1. Répartition par type (DonutChart) — Problème / Idée / Question / Autre avec les couleurs déjà utilisées dans la page Signalements
  2. Répartition par statut (DonutChart) — Nouveau / En cours / Traité / Archivé pour suivre l'avancement
  3. Taux de réponse (jauge KPI) — pourcentage de signalements avec réponse écrite, code couleur : vert ≥ 60%, orange ≥ 30%, rouge sinon. Permet à la direction de mesurer sa réactivité à la remontée terrain.

Cas d'usage métier

  • Bilan trimestriel direction : "a-t-on des Problèmes récurrents ? Combien d'idées proposées ? Combien traitées ?"
  • Indicateur RH soft : un taux de réponse qui baisse peut signaler un désengagement de la direction
  • Animation du dispositif : voir si le volume de signalements augmente après une communication interne

5. Filtres combinés Matériels NOUVEAU

Le panneau Filtres avancés de la page Matériels gagne deux nouveaux filtres en plus des existants (Recherche, État, Tag) :

  • Dépôt — sélecteur des dépôts définis dans la collectivité, apparaît seulement s'il y a au moins un dépôt
  • Affecté à un patient — booléen Oui / Non, utilise un accessor qui regarde r.patient_id

Combinabilité

Tous les filtres sont cumulables. Exemples utiles :

  • "Matériels Critiques au dépôt Figeac" = Tag "Critique" + Dépôt "Figeac"
  • "Pompes en location chez un patient" = Recherche "pompe" + Affecté "Oui" + État "En location"
  • "Matériels À remplacer libres au dépôt général" = Tag "À remplacer" + Affecté "Non" + Dépôt "Général"

6. Mode auto jour/nuit NOUVEAU

6.1 Concept

Le mode foncé livré en 0.7 nécessitait un toggle manuel. La 0.13 ajoute un troisième mode dans Paramètres : Auto, qui bascule automatiquement entre clair et foncé.

6.2 Deux sous-options du mode Auto

Quand tu actives Auto, deux radio-boutons apparaissent dans un encart turquoise :

  1. Suivre le système (option par défaut) — utilise prefers-color-scheme du navigateur, donc s'aligne sur le réglage Windows/macOS. Si tu passes ton OS en mode nuit, Aveho suit immédiatement.
  2. Selon l'heure — bascule en mode foncé entre 19h et 7h, mode clair sinon. Vérification toutes les minutes (interval discret) pour passer à 19h pile sans recharger la page.

6.3 Hook enrichi

Le hook useTheme a été élargi pour gérer cette troisième valeur. L'API change peu :

const { theme, mode, autoMode, toggle, setMode, setAuto } = useTheme();
// theme = "light" | "dark" (la valeur effective appliquée)
// mode  = "light" | "dark" | "auto" (la préférence utilisateur)
// autoMode = "os" | "horaire" (sous-option si mode=auto)

Le badge "Mode foncé" visible dans Paramètres affiche désormais le statut effectif quand le mode est en auto, par exemple "Mode auto actif — actuellement : foncé".

7. Aperçu impression A4 NOUVEAU

7.1 Concept

Avant la 0.13, les exports PDF (Stats en 0.8, Maintenance en 0.12) ouvraient une nouvelle fenêtre et lançaient l'impression directement. Risque d'imprimer par accident un document mal cadré, et impossible de modifier les filtres après avoir vu le rendu.

7.2 Solution

Nouveau helper réutilisable lib/pdfPreview.js qui affiche une modale fullscreen avec :

  • En-tête turquoise "APERÇU AVANT IMPRESSION" + titre du document
  • iframe A4 (90% de la largeur, 80vh de hauteur) qui rend le HTML exactement comme à l'impression
  • Bouton Annuler qui ferme la modale
  • Bouton Imprimer qui lance window.print() sur l'iframe (sans recharger la page)
  • Sortie via touche Échap

7.3 Usage

import { openPdfPreview } from "../../lib/pdfPreview";

openPdfPreview({
  titre: "Planning Maintenance (12)",
  html: "<!DOCTYPE html>...",
  filename: "planning-maintenance"
});

Déjà appliqué à l'export PDF Maintenance en 0.13. Le pattern est facilement portable à l'export Stats (chantier 0.14 si tu veux).

10. Procédure de mise à jour depuis Alpha 0.12

Mise à jour simple : pas de SQL.

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  4. Tests rapides :
    • Sur Patients, clique le nom d'un patient : tu arrives sur sa fiche 360°
    • Sur Matériels, ouvre les Filtres avancés : tu vois maintenant les sélecteurs Dépôt et Affecté à un patient en plus des existants
    • Sur Paramètres → Apparence : tu vois 3 boutons au lieu de 2. Clique Auto : un encart turquoise apparaît avec les sous-options. Bascule entre OS et horaire pour voir l'effet.
    • Sur Maintenance, clique Export PDF planning : tu vois maintenant la modale d'aperçu au lieu d'une nouvelle fenêtre qui imprime. Appuie sur Échap pour fermer sans imprimer.
    • Sur Statistiques (si tu as des signalements dans les 6 derniers mois) : la section Signalements apparaît avec 3 graphes dont la jauge taux de réponse.
  5. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.13"
git push

📌 Pièges connus (rétro-doc depuis 0.17.0)

Cette section a été ajoutée après les sessions de migration 0.15.6 et 0.16.1.

⚠️ Piège : tables etiquettes + patient_etiquettes

La fonctionnalité étiquettes nécessite les 2 tables créées via 13_etiquettes.sql. Sans ça, la page /etiquettes et la modale Gérer (livrée 0.15) plantent silencieusement.

En 0.16.1, un seeder a été ajouté qui crée 10 étiquettes par défaut (RGPD, ALD, Dépendance, Fragile, Isolement, Soins palliatifs, Allergique, MCI, Douleur, Post-op) pour les structures qui n'en ont pas. Voir aveho-PATCH-vers-0.16.1.sql section 4.

⚠️ Piège : pdfPreview.js et document.write() deprecated

Le helper d'aperçu PDF utilise document.write() qui génère un warning Chrome. Cosmétique, pas bloquant — l'aperçu fonctionne. À refactoriser en 0.18 avec un blob URL et un iframe propre.
