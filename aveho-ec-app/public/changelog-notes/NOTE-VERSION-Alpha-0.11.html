1. Résumé exécutif

L'Alpha 0.11 muscle le module Maintenance livré en 0.10 avec trois automatismes métier majeurs : création automatique d'une DI quand une maintenance passe en retard, création de la maintenance suivante quand on en clôture une avec récurrence, et notifications J-7 avant échéance. En parallèle, ajout des tags matériel (similaires aux étiquettes patients de la 0.9) et fusion des maintenances dans la vue calendrier pour avoir tout sous les yeux.

Cette version introduit 2 nouvelles tables SQL (tags_materiel + materiel_tags) et 4 colonnes sur maintenances (recurrence_jours, parent_id, di_id, notif_j7_envoyee). Script unique 15_tags_materiel.sql à exécuter dans Supabase.

3. Création auto de DI quand maintenance en retard NOUVEAU

Au chargement de la page /maintenance, pour chaque maintenance dont la date_prevue est passée et qui n'est ni Faite ni Annulée, et qui n'a pas encore de DI liée (di_id IS NULL), Aveho crée automatiquement :

  1. Une nouvelle DI dans interventions avec :
    • Type = "Maintenance en retard"
    • Urgence = Normal
    • Statut = Nouvelle
    • Description = référence à la maintenance + intervenant prévu
    • Matériel lié à celui de la maintenance
  2. Le champ di_id sur la maintenance est mis à jour pour pointer vers la DI créée. Cela empêche les doublons : à la prochaine ouverture de la page, la DI ne sera pas recréée.
  3. Une trace audit est posée et une notification est envoyée via logEvent.

Cas d'usage

Tu reviens de vacances, tu ouvres la page Maintenance, tu vois :

  • 3 maintenances passées en "En retard" sont devenues automatiquement des DI Nouvelles
  • Tu les retrouves dans la page Interventions, prêtes à être traitées par l'équipe technique
  • Plus jamais de maintenance oubliée qui dort dans un fichier Excel

4. Maintenances récurrentes NOUVEAU

4.1 Champ Récurrence dans la modale

Quand tu crées ou modifies une maintenance, un nouveau sélecteur Récurrence propose 6 valeurs :

  • Pas de récurrence (par défaut)
  • Tous les mois (30 j)
  • Tous les 3 mois (90 j)
  • Tous les 6 mois (180 j)
  • Tous les ans (365 j)
  • Tous les 2 ans (730 j)

Un message vert apparaît dès qu'une valeur > 0 est choisie : "Quand cette maintenance sera marquée Faite, la suivante sera créée automatiquement à +N jour(s)."

4.2 Création de la suivante

Quand tu passes une maintenance récurrente à Faite, Aveho :

  1. Vérifie qu'aucune "suivante" n'existe déjà (champ parent_id) pour éviter les doublons même si tu cliques 2× sur "Faite"
  2. Calcule la prochaine date = date_realisee (ou date_prevue à défaut) + recurrence_jours
  3. Crée une nouvelle ligne maintenance avec mêmes type, intervenant, récurrence — parent_id pointe vers celle qu'on vient de clôturer
  4. Statut = Planifiée, notes = trace de l'origine
  5. Notification cloche : "Maintenance récurrente programmée — Révision annuelle sur Lit Bastide programmée le 28/05/2027"

4.3 Cas d'usage

Tu paramètres une révision annuelle sur 20 concentrateurs O2. Chaque année, quand un technicien clôture la révision sur un appareil, la suivante est automatiquement programmée à +1 an. Tu n'as plus à tenir une liste manuelle.

5. Notifications J-7 avant échéance NOUVEAU

Au chargement de la page Maintenance, pour chaque maintenance dont la date_prevue est dans la fenêtre [aujourd'hui ; aujourd'hui + 7 jours], et qui n'a pas encore eu sa notif J-7 (notif_j7_envoyee = false) :

  1. Une notification cloche est envoyée à tous les membres de la collectivité
  2. Titre : "Maintenance proche"
  3. Message : "Révision annuelle sur Lit médicalisé Bastide prévue le 5/06/2026"
  4. Le flag notif_j7_envoyee passe à true — la notif ne sera plus renvoyée même si la page est rechargée 50 fois

Limites assumées

Comme la détection se fait au chargement de la page, la notif est envoyée quand quelqu'un ouvre la page Maintenance, pas à minuit pile. Pour un déclenchement plus précis (cron quotidien Supabase), ce serait le chantier Edge Function dont on parle depuis quelques versions. Pour l'instant ça marche bien parce que quelqu'un ouvre la page tous les jours ou presque.

6. Tags matériel NOUVEAU

6.1 Modèle SQL

Architecture identique aux étiquettes patients (0.9) :

tags_materiel (id, structure_id, libelle, couleur, description)
materiel_tags (id, materiel_id, tag_id, structure_id, created_at)
              unique (materiel_id, tag_id)

Tables avec RLS scope collectivité.

6.2 Page de gestion /tags-materiel

Nouvelle page Administration, accessible uniquement aux Admins. CRUD complet des tags : libellé, palette de 9 couleurs Aveho, description, aperçu live. 5 tags démo pré-installés pour la collectivité de test :

  • Critique (rouge) — matériel essentiel à la prise en charge
  • Sous garantie (vert) — couverture constructeur en cours
  • À remplacer (orange) — fin de vie programmée
  • Hors service (gris) — inutilisable temporairement
  • À surveiller (violet) — comportement anormal détecté

6.3 Application aux matériels

Sur la page Matériels, dans la colonne Article :

  • Les tags appliqués s'affichent comme des pastilles colorées sous le libellé
  • Une icône à côté du libellé ouvre une modale toggle pour appliquer/retirer des tags
  • Persistance instantanée (pas de bouton Valider)

6.4 Filtre par tag

Dans le panneau Filtres avancés des Matériels, un nouveau sélecteur Tag apparaît si au moins un tag est défini. Permet par exemple de lister "tous les matériels Critiques" ou "tous ceux À remplacer".

7. Maintenances dans le calendrier NOUVEAU

La page Calendrier (livrée en 0.9, enrichie d'une vue semaine en 0.10) affiche maintenant aussi les maintenances en plus des DI, dans les deux vues.

Distinction visuelle

  • Les DI gardent leurs couleurs par statut (rouge Nouvelle, orange En cours, etc.)
  • Les maintenances sont toutes en turquoise sombre (#5a8f8f) avec une icône clé à molette
  • Clic sur une maintenance ouvre la page /maintenance, clic sur une DI ouvre /interventions

Toggle "Afficher les maintenances"

Une case à cocher en haut à droite du calendrier permet de masquer les maintenances si tu veux te concentrer sur les DI uniquement. Activée par défaut.

Légende enrichie

La légende du calendrier en bas inclut maintenant le pictogramme Maintenance pour identifier visuellement le type d'événement.

10. Procédure de mise à jour depuis Alpha 0.10

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans Supabase SQL Editor : exécute supabase/15_tags_materiel.sql.
    Sans ce script, les pages Tags matériel et certaines fonctionnalités Maintenance (récurrence, DI auto, notif J-7) échoueront.
  4. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  5. Tests rapides :
    • Va sur /tags-materiel : 5 tags démo
    • Sur Matériels, clique l'icône à côté d'un libellé : modale d'application
    • Sur Maintenances, crée une maintenance avec récurrence "Tous les mois" → passe-la à Faite → tu vois une "suivante" apparaître dans la liste
    • Si une maintenance démo est en retard, ouvre la page : tu vois apparaître une nouvelle DI "Maintenance en retard" dans /interventions
    • Sur /calendrier, regarde les pastilles turquoise qui représentent les maintenances. Décoche "Afficher les maintenances" pour ne voir que les DI
  6. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.11"
git push
