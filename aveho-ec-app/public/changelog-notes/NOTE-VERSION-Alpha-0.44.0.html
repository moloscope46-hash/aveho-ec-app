Chantiers livrés

J Activation groupée templates RGPD

  • Bouton "Activer en masse" apparaît à droite du titre "Historique des versions" dans /parametres-rgpd — visible uniquement si ≥ 2 brouillons
  • Modale multiselect avec liste des brouillons :
    • Affiche pour chaque template : version, nom optionnel, portée (Global ou nom de l'établissement), date de création
    • Boutons "Tout sélectionner" / "Tout désélectionner" si > 1 brouillon
    • Bouton final "Activer (N)" qui affiche le compteur en live
  • Logique d'activation : pour chaque template à activer, le système désactive automatiquement le template actif existant du même couple (structure, etablissement) avant d'activer le nouveau. Pas de risque de doublon actif.
  • Validation : exécute la même validateTemplate que l'activation simple — si des warnings critiques apparaissent sur un template, ils sont remontés dans le confirm() avant exécution
  • Cas d'usage : après avoir dupliqué un template v2.0 vers 5 établissements via la modale "Dupliquer vers..." (chantier K de la 0.43), tu peux maintenant les activer tous d'un coup au lieu de cliquer 5× sur Activer.

K Realtime sur DI, signalements, achats

  • Hook useRealtimeTable dans lib/useRealtimeTable.js — généralisation du pattern utilisé dans NotifBell en 0.43
  • API simple : 
    useRealtimeTable({
  table: "interventions",
  structureId: auth.structureId,
  event: "INSERT", // ou "UPDATE" ou "*"
  onInsert: (row) => { ... },
  onUpdate: (row, old) => { ... },
});
  • Filtre RLS côté Supabase : structure_id=eq.${structureId} → aucune fuite cross-structure
  • Pattern useRef pour garder les callbacks à jour sans recréer la subscription à chaque rerender
  • Helper showRealtimeToast : crée un toast in-app glissant en bas à droite (alternative au Notification API qui n'est dispo que si tab masqué)
    • Position fixe, z-index 9999, auto-disparition configurable
    • role="status" + aria-live="polite" pour les lecteurs d'écran
    • Bouton ✕ pour fermer manuellement
  • Intégration accueil : 3 subscriptions actives en parallèle
    • interventions : toast rouge vif (8s) si urgent, sinon orange (5s)
    • signalements : toast teal avec icône message
    • achats : toast orange avec icône shopping-bag

L Cron auto-génération récurrences maintenance

  • Extension de la Edge Function maintenance-daily-cron existante (créée en 0.12)
  • Logique ajoutée :
    1. Sélectionner toutes les maintenance_recurrences actives dont la prochaine_due est dans la fenêtre [aujourd'hui ; +7j]
    2. Pour chaque récurrence, vérifier qu'aucune maintenance planifiée n'existe déjà pour le couple (matériel, date_prevue, type) → évite les doublons si le cron tourne plusieurs fois
    3. Si pas de doublon → INSERT dans maintenances avec statut "Planifiée", notes auto = "Généré auto depuis récurrence"
    4. L'établissement de la maintenance est hérité du matériel
  • Réponse JSON enrichie : nouveau champ maintenancesGenerees à côté de notifsEnvoyees et disCreees
  • Idempotence : la fonction peut tourner plusieurs fois sans créer de doublons (vérif `select` avant `insert`)
  • Note : le pg_cron daily à 6h UTC créé en 0.12 prend en charge ces récurrences automatiquement sans config supplémentaire.

O Audit accessibilité (a11y)

  • Composant <Btn> amélioré :
    • Icônes décoratives marquées aria-hidden="true" (les lecteurs d'écran lisent le texte du bouton, pas le nom de l'icône)
    • Si bouton icon-only sans texte, aria-label="Action" par défaut + nouveau prop ariaLabel pour le surcharger
  • Nouveau composant <IconButton> :
    • Remplace les <i className="ti ..." onClick> qui étaient inaccessibles au clavier et invisibles pour les lecteurs d'écran
    • Vrai <button> avec aria-label obligatoire, focus visible, support disabled
    • API simple : <IconButton icon="ti-trash" ariaLabel="Supprimer X" onClick={...} />
  • Cas critiques patchés : suppression patient (/patients), suppression article panier (/panier). Audit complet à venir dans une prochaine version.
  • Composant <Modal> déjà très complet (depuis 0.18) : role="dialog", aria-modal="true", aria-labelledby, focus trap au Tab, ESC pour fermer, restauration du focus à la fermeture
  • Toasts realtime : role="status" + conteneur aria-live="polite" pour annonce non intrusive aux lecteurs d'écran

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.44.sql → Run. Le patch finit par notify pgrst, 'reload schema', donc pas besoin de le faire manuellement après.
  2. Vérifier les indexes : 
    -- 19 indexes créés
select indexname from pg_indexes 
where schemaname = 'public' 
  and indexname like 'idx_%' 
order by indexname;

-- Tester un plan d'exécution sur une query type
explain analyze 
select * from interventions 
where structure_id = 'aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa'
  and statut = 'Nouvelle'
order by created_at desc limit 50;
-- → tu dois voir "Index Scan using idx_interventions_struct_statut"
  3. Activer Realtime sur les 3 nouvelles tables (Supabase Dashboard → Database → Replication → activer pour) :
    • public.interventions
    • public.signalements
    • public.achats
    (la table notifications a déjà été activée en 0.43)
  4. Redéployer la Edge Function : 
    supabase functions deploy maintenance-daily-cron
  5. Décompresser le zip par-dessus C:\aveho-ec-app\.
  6. Nettoyer le cache + npm install + tests + dev : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test       # 736 passed
npm run dev
  7. Tester :
    • Dans 2 onglets, ouvrir /accueil dans l'un et /interventions dans l'autre. Créer une DI urgente dans le 2ᵉ → toast rouge "Nouvelle DI" doit apparaître en bas à droite de l'onglet 1 ✨
    • /parametres-rgpd : dupliquer un template vers plusieurs etabs (modale 0.43), puis cliquer "Activer en masse" → cocher tous → "Activer (N)"
    • Manuellement déclencher le cron pour tester : 
      curl -X POST https://<projet>.supabase.co/functions/v1/maintenance-daily-cron \
  -H "Authorization: Bearer <service_role_key>"
# → JSON avec maintenancesGenerees: N
    • Mesurer un gain de perf : créer 10 000 interventions de test, recharger /interventions → la liste doit se charger en < 200ms grâce aux indexes
    • A11y : sur /patients, naviguer au clavier (Tab) → tous les boutons d'action sont focusables avec outline visible · sur n'importe quel bouton de suppression, le lecteur d'écran annonce "Supprimer [nom du patient]"
