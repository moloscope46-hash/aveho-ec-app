1. Résumé exécutif

L'Alpha 0.16.0 est une itération UX & administration. Trois chantiers menés en parallèle après stabilisation de la 0.15.6.

  1. TopBar refondue avec un bloc utilisateur visible (avatar + nom) qui ouvre un sous-volet contenant les raccourcis : Mon profil, Mon établissement, Paramètres, Télécharger l'appli, Déconnexion. Comportement responsive : popover sur desktop, bottom-sheet sur mobile.
  2. Archivage des membres et invitations : nouveau filtre Actifs / Archivés / Tous, action archive/restore par ligne, et une modale "Infos utilisateur" qui affiche les statistiques d'activité (dernière connexion, actions 7j / 30j, total) et permet d'ajouter poste, téléphone, date d'arrivée, notes.
  3. Tooltips réutilisables (composant <Tooltip>) appliqués sur la fiche patient : les infos secondaires (date de naissance, numéro de dossier, médecin, date d'entrée) sont accessibles au survol/tap au lieu d'envahir la ligne.
1 patch SQL livré : aveho-PATCH-vers-0.16.sql — 39 lignes, idempotent. Ajoute la colonne archive, les colonnes d'infos utilisateur, et la vue v_user_activity.

3. TopBar refondue

3.1 Comportement desktop

Le bloc utilisateur remplace l'ancien bouton de déconnexion isolé. Affichage par défaut :

CM Cédric MIGNOT ⌄

Au clic, un sous-volet popover apparaît juste sous le bouton (ancré à droite) avec animation pop d'apparition. Contenu :

  • En-tête : grosse pastille colorée (initiales), nom complet, email, rôle avec icône bouclier
  • Mon profil → /profil
  • Mon établissement → /collectivite
  • Paramètres → /parametres
  • Télécharger l'appli (uniquement si installable, item en gradient bleu pour la mise en avant)
  • Déconnexion (rouge, en bas)

Couleur de la pastille déterministe à partir du user_id (palette de 8 couleurs). Cédric tombe sur le teal par défaut. Initiales calculées depuis nom_affiche, sinon depuis l'email.

3.2 Comportement mobile (≤ 760px)

Sur mobile, le nom complet serait débordant donc on n'affiche que la pastille seule (cercle de 40px). Au clic, un bottom-sheet remonte du bas de l'écran (animation slide-up). Le contenu est identique au desktop mais avec des items plus grands (44px de hauteur, lisibles au pouce).

3.3 Sélecteur établissement responsive

L'ancien etab-switch avec max-width: 200px débordait quand le nom de l'établissement était long. Nouveau comportement :

  • ≥ 760px : largeur normale (200px max)
  • < 760px : largeur réduite (140px) + sélecteur réduit (90px), le titre de la page actuelle est masqué pour libérer de l'espace
  • < 480px : le sélecteur d'établissement disparaît complètement, on peut le retrouver dans le menu (Mon établissement)

3.4 Détection installation PWA

Le composant InstallPWA.js historique (bouton flottant en bas de page) est démonté. Sa logique de détection est désormais embarquée dans UserMenu.js :

  • Android / Chrome desktop : intercepte l'événement beforeinstallprompt et stocke la promesse
  • iOS Safari : détecte le user-agent et affiche une instruction "Touchez Partager puis Sur l'écran d'accueil"
  • Déjà installé (display-mode standalone) : l'item Télécharger n'apparaît pas

4. Archivage & infos utilisateur

4.1 Filtre statut

Tout en haut de l'onglet Membres, trois pastilles cliquables avec compteurs :

  • Actifs (par défaut) — tous les membres avec archive = false
  • Archivés — affichage en opacité réduite (55%) pour distinguer visuellement
  • Tous — actifs + archivés mélangés

Distinction sémantique :

ÉtatSensVisible dans la liste ?Peut se connecter ?
ActifMembre normalOui (filtre Actifs)Oui
InactifSuspendu temporairementOui (filtre Actifs)Non
ArchivéHors équipe, conservé pour historiqueNon (sauf filtre dédié)Non (recommandé : passer aussi en Inactif)

4.2 Modale Infos utilisateur

Accessible par clic sur le nom ou sur l'icône ti-info-circle. Contenu :

En haut, encart stats d'activité (lecture seule, calculé en direct depuis audit_log) :

  • Dernière activité (date)
  • Actions totales (nombre)
  • Actions 7 derniers jours (en bleu)
  • Actions 30 derniers jours (en bleu)

En dessous, formulaire éditable (4 champs nouveaux + nom_affiche existant) :

  • Nom affiché (existant)
  • Poste / fonction (ex. "Infirmière coordinatrice")
  • Téléphone
  • Date d'arrivée
  • Notes internes (textarea)

Dans le tableau Membres, si un membre a un poste renseigné, il s'affiche en sous-titre sous son nom (12 px, gris).

5. Workflow invitations

L'onglet Invitations a été enrichi avec :

  • Filtre En cours / Archivées / Toutes avec compteurs (cohérent avec Membres)
  • Bouton Renvoyer (icône avion en papier) sur les invitations non acceptées et non archivées. Réinvoque la fonction Edge invite-user.
  • Bouton Archiver / Restaurer sur chaque ligne
  • Statut affiné : pastille verte pour "Acceptée", rouge pour "Expirée", orange pour "En attente" (par défaut)

Ainsi tu peux faire un suivi d'invitations sans les supprimer (traçabilité), tout en gardant un workspace propre via les archives.

6. Tooltips fiche patient

Nouveau composant <Tooltip content="..." side="top|bottom|left|right">. Comportement :

  • Desktop : ouverture au hover, fermeture au mouseleave
  • Mobile : ouverture au tap, fermeture au tap ailleurs ou avec Échap
  • Marqueur visuel : soulignement pointillé teal (border-bottom: 1px dotted) pour signaler "il y a plus à voir"
  • Bulle navy sur fond foncé avec flèche pointant vers la cible

7. Patch SQL 0.16.0

Le script aveho-PATCH-vers-0.16.sql ajoute en base :

  1. Colonne archive (boolean, default false) sur membres_structure et invitations
  2. Index sur (structure_id, archive) pour les filtres rapides
  3. 4 colonnes sur membres_structure : telephone, poste, notes, date_arrivee
  4. Vue v_user_activity : agrégat par user_id (nb_actions, derniere_activite, actions_7j, actions_30j). Suit les RLS de audit_log par construction.

100% idempotent (add column if not exists, create or replace view), rejouable sans risque. À exécuter avant d'appliquer le zip de code, sinon les nouvelles fonctionnalités plantent avec "column does not exist".

9. Procédure d'application

  1. SQL d'abord : dans Supabase → SQL Editor → coller le contenu de aveho-PATCH-vers-0.16.sql → Run. Tu dois voir Success sans erreur. C'est idempotent donc rejouable.
  2. Code ensuite : 
    cd C:\aveho-ec-app
# Sauvegarde le .env.local d'abord
# Décompresse aveho-ec-app.zip par-dessus (écrase, garde .env.local)
npm install
npm run dev
  3. Tests dans le navigateur (Ctrl+Shift+R d'abord pour purger le cache) :
    • TopBar : ton nom + avatar visible en haut à droite, clic ouvre le menu
    • Mode mobile (F12 → toggle device toolbar) : pastille seule, bottom sheet au clic
    • /utilisateurs : filtres en haut, clic sur un nom → modale avec stats d'activité
    • Fiche patient : survol des badges sous le nom → bulles d'info en navy
  4. Mise en ligne Vercel : 
    cd C:\aveho-ec-app-01
robocopy C:\aveho-ec-app C:\aveho-ec-app-01 /E /PURGE /XD .git node_modules .next
git add .
git commit -m "Aveho EC 0.16.0 - UserMenu + archivage + tooltips"
git push

11. Roadmap 0.16.1 suggérée

  1. Étendre les tooltips à la fiche matériel (S/N, lot, date achat, garantie) et aux listes (badges étiquettes / tags)
  2. Auto-rattachement admin aux établissements via trigger SQL ou helper côté useAuth
  3. Migration interventions.due_date et remise du select calendrier
  4. Modèles d'étiquettes par défaut : seeder de 8-10 étiquettes types (RGPD, ALD, dépendance, fragile, isolement, soins palliatifs, allergique, MCI, douleur, post-op)
  5. Affichage "En ligne il y a X" sur la liste membres (basé sur v_user_activity.derniere_activite)
  6. Filtre par poste / par rôle dans la liste membres
  7. Import en masse des utilisateurs depuis un CSV
  8. Recherche dans la liste membres (utile dès 20+ users)
