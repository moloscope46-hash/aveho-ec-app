Chantier 1 — Connexion à la base FINESS officielle

Architecture

Source de données : référentiel t_finess publié par Atlasanté sur data.gouv.fr. Mis à jour bi-mensuellement. Recense tous les établissements sanitaires, médico-sociaux et sociaux français — entités juridiques (EJ) et sites géographiques (ET).

Stack technique :

  • API tabulaire data.gouv.fr (officielle) — endpoint https://tabular-api.data.gouv.fr/api/resources/796dfff7-cf54-493a-a0a7-ba3c2024c6f3/data/
  • Proxy côté serveur Next.js (app/api/finess/route.js) qui :
    • Évite les soucis CORS éventuels
    • Cache les réponses 1h (revalidate: 3600 + Cache-Control: s-maxage=3600)
    • Filtre automatiquement les entrées OBSOLETE (seulement etat=ACTUEL)
    • Filtre par défaut sur les ET (sites géographiques) — paramètre type ajustable pour EJ
    • Uniformise le format de retour (mapping des 50+ champs vers ~15 utiles)
  • Composant frontend <FinessSearch /> avec autocomplete debouncé (350ms, min 3 caractères)

Affichage des résultats

Chaque résultat affiche en chips colorées :

  • 📋 Catégorie courte (chip bleu) — ex : "C.H.R.", "EHPAD", "Pharmacie d'Officine"
  • 🏛/🏢 Public / Privé (chip vert si public, ambre si privé)
  • 🏷 Domaine (chip violet) — Sanitaire, Médico-Social, etc.
  • 🛏 Capacité (chip rouge) — nombre de lits si renseigné
  • 📍 Icône GPS verte si géolocalisation disponible

Intégration dans /etablissement/fiche

Un nouvel encart vert "Import depuis la base FINESS officielle" est apparu en haut de la page. L'utilisateur tape :

  • Un nom : "EHPAD Les Mimosas", "CHU Bordeaux", "Hopital Cochin"
  • Une ville : "Lyon", "Marseille" (l'API cherche dans la raison sociale qui contient souvent la ville)
  • Un n° FINESS direct à 9 chiffres : "750100026" (détection automatique du format)

Au clic sur un résultat, le formulaire se remplit automatiquement avec tous les champs disponibles : nom, type, FINESS, SIRET, adresse, code postal, ville, téléphone, capacité, latitude, longitude. L'établissement apparaît immédiatement sur la /carte après enregistrement.

Chantier 2 — Géolocalisation utilisateur

Modal de demande de permission au login

Nouveau composant <GeolocPrompt /> monté globalement dans le layout. Apparaît une fois après le login (avec un délai de 800ms pour ne pas bloquer le rendu initial).

Design soigné :

  • Icône ti-map-pin dans une pastille circulaire 70px avec gradient vert→sarcelle
  • Animation de pulsation autour de l'icône (3 cercles concentriques qui se dilatent à l'infini)
  • Animation slide-up + fade-in à l'arrivée du modal (35 ms cubic-bezier)
  • Backdrop semi-transparent rgba(20,33,49,.55) avec fade-in 250 ms
  • 2 boutons : "Plus tard" (ghost) et "Activer la géolocalisation" (gradient vert avec shadow)
  • Encart "Confidentialité" listant : position stockée dans navigateur, jamais transmise serveur, choix modifiable
  • Gestion d'erreurs : permission refusée navigateur, position indisponible, timeout

Logique de persistance

3 états stockés dans localStorage sous la clé aveho_geoloc_choice :

  • "accepted" : l'user a accepté → on récupère la position en silence à chaque visite
  • "declined" : l'user a refusé → on ne redemande plus
  • "denied_browser" : permission bloquée par le navigateur (réponse système)
  • (rien) : premier login → on affiche le modal

La position est cachée dans aveho_geoloc_last_pos avec un timestamp (validité 24h).

Marqueur "Ma position" sur la carte

Sur /carte, si la position user est disponible :

  • Marqueur bleu pulsant (cercle bleu 24px avec halo animé 16% opacité qui se dilate à 160% en boucle 2s)
  • Z-index 1000 pour rester au-dessus des étabs et camions
  • Popup au clic : icône 📍, "Ma position", lat/lng formatés à 5 décimales, mention "Position partagée uniquement avec votre navigateur"
  • Inclus dans fitBounds() de la carte → la vue zoomée englobe automatiquement ta position en plus des étabs

Bouton "Centrer sur ma position"

Nouveau chip " Ma position" dans la barre des filtres carte. Au clic :

  • Si position connue → map.flyTo(pos, zoom=13, duration=1s) (animation fluide vol vers ma position)
  • Si position pas connue → déclenche un navigator.geolocation.getCurrentPosition() en live, sauvegarde dans localStorage, et zoome dessus
  • Gestion d'erreurs : permission refusée, géoloc non disponible → alert claire

Procédure d'application — PowerShell

  1. Aucun SQL à appliquer — cette version est 100% code applicatif (les colonnes latitude/longitude ajoutées en 0.54 sont réutilisées)
  2. Décompresser le zip 0.55.0 par-dessus C:\aveho-ec-app\
  3. Installer + lancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm run dev
  4. Tester l'import FINESS :
    • Aller dans Menu → Fiche étab.
    • Dans l'encart vert en haut, taper "hopital cochin" → quelques résultats apparaissent (HOPITAL COCHIN TARNIER APHP, EFS COCHIN, IFSI Cochin...)
    • Cliquer "HOPITAL COCHIN TARNIER APHP" → le formulaire se remplit automatiquement avec adresse, GPS, FINESS 750100026, SIRET
    • Tester avec un n° FINESS direct : taper "750100026" → recherche exacte
    • Tester avec une ville : "Bordeaux" → liste les étabs avec "Bordeaux" dans leur raison sociale
  5. Tester la géoloc :
    • Vider les localStorage du site (F12 → Application → Local storage → Clear)
    • Rafraîchir → modal "Activer la géolocalisation ?" apparaît après 800ms avec icône pulsante
    • Cliquer "Activer" → le navigateur demande la permission système
    • Accepter → modal disparaît
    • Aller sur /carte → ta position apparaît en marqueur bleu pulsant 📍
    • Cliquer le bouton "Ma position" en haut → la carte vole vers ta position avec animation
  6. Tester le refus :
    • Vider à nouveau le localStorage
    • Rafraîchir → modal apparaît
    • Cliquer "Plus tard" → modal disparaît, choix mémorisé
    • Rafraîchir plusieurs fois → le modal ne réapparaît plus
    • Sur la carte, cliquer "Ma position" quand même → propose une nouvelle demande de permission

Notes techniques importantes

Limite réseau de la sandbox de dev

L'API FINESS a été testée en direct (curl vers tabular-api.data.gouv.fr) — elle répond correctement avec les bonnes données pour "hopital cochin", "ehpad bordeaux", etc.

En revanche, depuis l'environnement sandbox de dev (où la prébuild est lancée), data.gouv.fr est inaccessible (502 timeout). Ceci n'affectera pas la production — Vercel et ta machine locale ont un accès internet normal.

Refonte FINESS prévue été 2026

L'ANS (Agence du Numérique en Santé) prépare une nouvelle version de FINESS pour l'été 2026. Atlasanté a annoncé que le référentiel t_finess continuera à être maintenu. Si jamais le RID change, il suffira de modifier la constante TABULAR_BASE dans app/api/finess/route.js.

Performance

Le cache 1h côté serveur Next.js fait que les requêtes répétées (même recherche dans l'heure) sont servies depuis le cache, sans appel à data.gouv.fr. Si tu remarques des résultats obsolètes, attends ≤1h ou redéploie.
