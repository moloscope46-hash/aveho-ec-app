Résumé

Version polish UX, aucun patch SQL. 3 chantiers ciblés sur la qualité d'usage. Build clean, 844 tests verts, runtime dev validé sur 3 routes (réflexe 6).

3 modules livrés :
AP Nouveau composant <VersionCheck /> dans le layout : poll /api/version toutes les 5 min, compare avec localStorage, affiche un toast vert "Mise à jour disponible" si différence détectée. Boutons "Recharger" (hard reload + clear localStorage) et "Plus tard" (snooze 1h).
AR Enrichissement de la page /patient/[id] existante (déjà 378 lignes) avec : 5ᵉ KPI RGPD (consenti / refus / à recueillir avec couleur) + nouveau bloc "Consentements RGPD" listant tous les consentements du patient avec statut et date.
AW Drawer mobile (déjà existant en CSS) enrichi avec : swipe-to-close gesture (touchstart/move/end avec seuil -80px), indicateur "← Glissez pour fermer" en haut visible uniquement sur ≤ 768px, transform en live suivant le doigt.

Chantiers livrés

AP Vérification de version dispo

  • Nouvel endpoint API /api/version (route.js) :
    • Renvoie { version, buildId, timestamp }
    • Lit la version depuis package.json
    • dynamic = "force-dynamic" pour éviter le cache statique
  • Composant <VersionCheck /> monté dans le layout root :
    • Premier check 10s après mount (laisser l'UI se monter)
    • Poll toutes les 5 minutes
    • Compare avec localStorage["aveho_app_version"]
    • Premier passage → enregistre sans alerter (évite faux positif au 1er load)
    • Si version différente et pas snoozé → affiche toast vert en bas à droite avec gradient
    • Bouton "Recharger" → efface localStorage + window.location.reload() (hard reload pour vider cache navigateur)
    • Bouton "Plus tard" → snooze 1h (aveho_version_snooze_until)
  • UX : toast persistant (pas auto-dismiss), animation slide-up, role="alert" + aria-live="polite" pour les lecteurs d'écran
  • Best-effort : si le fetch échoue (offline), pas d'erreur visible

AR Vue 360° patient enrichie

  • La page /patient/[id] existait déjà avec 378 lignes (header, KPIs matériels, DI, historique audit). Pour ne rien casser, j'ai juste ajouté ce qui manquait.
  • Chargement : ajout d'un 7ᵉ Promise.all sur consentements_rgpd filtré par patient_id, tri date_signature desc
  • 5ᵉ KPI tile dans la grille existante :
    • Icône shield + couleur sémantique :
      • Au moins 1 consenti → vert (#5aa05a)
      • Refus → rouge (#c0392b)
      • Aucun consentement → orange (#EF9F27)
    • Label : "RGPD (OK)" / "RGPD (Refus)" / "RGPD (à recueillir)"
  • Nouveau Panel "Consentements RGPD" entre le bandeau et le bloc Matériels (uniquement si consents.length > 0) :
    • Liste de chaque consentement dans une card horizontale
    • Fond vert (#eef9ef) si a_consenti, rouge (#fef0ee) sinon
    • Affiche : statut + libellé du template + date signature + date expiration si présente
  • Aucun changement sur les blocs existants (Matériels, DI, Historique, etc.)

AW Drawer mobile — swipe-to-close

  • Le drawer mobile existait déjà avec un CSS transform: translateX(-104%) et transition. Mais sans gesture tactile : seul le bouton X ou le clic sur l'overlay le fermait.
  • State + handlers touchstart/touchmove/touchend sur la <nav class="menu-drawer"> :
    • onTouchStart : enregistre la position X de départ
    • onTouchMove : tracke le delta, ignore si dx ≥ 0 (swipe droite)
    • onTouchEnd : si delta < -80px → setOpen(false)
  • Feedback visuel live pendant le swipe :
    • transform: translateX(${touchDelta}px) appliqué en inline style
    • transition: none pendant le swipe pour réactivité instantanée
    • Au relâchement, retour à la transition CSS normale (snap fluide)
  • Indicateur "← Glissez pour fermer" en haut du drawer :
    • Visible uniquement sur écran ≤ 768px (CSS media query .swipe-hint)
    • Opacité 0.6 pour rester discret
    • pointer-events: none et aria-hidden pour ne pas interférer
  • Seuil -80px : assez large pour éviter les faux positifs (tap accidentel) sans demander un swipe énorme
