Résumé

Sur le terrain, un soignant qui survole une liste de patients veut souvent juste vérifier la chambre, le statut RGPD, ou s'il y a une DI en cours, sans avoir à cliquer puis revenir. La 0.38 ajoute un popover discret qui apparaît au survol du nom et donne ces informations instantanément.

Zero friction. Sur desktop : survol 500ms → popover apparaît. Sur tactile : tap = navigation directe (pas de hover natif sur mobile). Pas de fetch supplémentaire au hover : toutes les données sont déjà chargées avec la liste.

1. Comportement du composant

Sur desktop (souris)

  • Survol > 500ms → popover apparaît avec animation fade-in (.15s)
  • Souris sort du trigger → délai 150ms avant disparition (laisse le temps de bouger vers le popover)
  • Souris entre dans le popover → annule la fermeture (utilisateur peut interagir avec le contenu)
  • Clic court → navigation directe vers /patient/{id}

Sur tactile (téléphone, tablette)

  • Détection via window.matchMedia("(pointer: coarse)")
  • Pas de hover natif → on désactive le popover
  • Tap = navigation directe (comportement inchangé par rapport à avant la 0.38)
  • Permet d'éviter les bugs UX type "popover collé après tap"

2. Positionnement intelligent

Le popover (320×280 max) est positionné en position: fixed en fonction du trigger :

  1. Position par défaut : sous le trigger, aligné à gauche
  2. Si trop à droite (déborderait) : aligne à 16px du bord droit
  3. Si trop en bas (déborderait) : remonte au-dessus du trigger
  4. Si vraiment trop petit viewport : clamp à 16px du haut

Le calcul se fait à l'apparition (au moment du hover), donc fonctionne même si la page a scrollé entre temps.

4. Préchargement compteurs DI/achats

Pour afficher des compteurs sans fetch supplémentaire au hover (sinon délai désagréable), les données sont chargées en parallèle de la liste patients :

// Dans /patients : Promise.all parallèle non bloquant
Promise.all([
  supabase.from("interventions")
    .select("patient_id, statut")
    .eq("etablissement_id", auth.etabId)
    .not("statut", "in", "(\"Clôturée\",\"Refusée\")"),  // DI actives uniquement
  supabase.from("achats")
    .select("patient_id, statut")
    .eq("etablissement_id", auth.etabId)
    .gte("created_at", new Date(Date.now() - 90 * 86400000).toISOString()),  // 90 derniers jours
]).then(...)

Si le fetch échoue (offline, RLS), le hover affiche juste la preview sans les compteurs. Pas de plantage.

5. Intégration dans /patients (préserve l'existant)

Le wrap est minimal — uniquement autour du nom prenom. Les badges RGPD et les étiquettes restent sibling dans la même cellule. Conséquences :

  • Hover sur le nom → popover apparaît
  • Hover sur les badges (RGPD, étiquettes) → aucun popover, comportement inchangé
  • Clic sur "RGPD à recueillir" → continue d'ouvrir la modale ConsentementRGPD (stopPropagation préservé)

6. Helpers internes

computeAge(dateNaissance)

Calcul d'âge robuste qui prend en compte le mois/jour pour ne pas afficher 31 ans à quelqu'un qui aura son anniversaire demain.

  • Retourne null si date invalide, future, ou > 130 ans (sécurité)
  • Gère le cas anniversaire passé / à venir cette année

statutColor(statut)

Mapping statut DI → couleurs cohérentes avec le reste de l'app (6 statuts + fallback).

Limites volontaires

  • Pas de fetch async au hover : performance garantie, mais limité aux données déjà en mémoire
  • Dernière DI non affichée par défaut : nécessiterait un fetch supplémentaire de l'intervention la plus récente. Possible en 0.39+ si besoin.
  • Préview uniquement dans /patients : pourra être étendu à d'autres listes (patients dans une DI, dans un achat, etc.) en 0.39+
  • Pas de panneau latéral : l'option "Clic latéral → fiche complète" évoquée dans le brief a été remplacée par un popover central pour rester cohérent avec les autres modales Aveho. Plus simple, moins intrusif.

Procédure d'application

  1. Pas de SQL à appliquer.
  2. Pas de redéploiement Edge Function.
  3. Décompresser le zip par-dessus C:\aveho-ec-app\.
  4. Nettoyer le cache + npm install + tests + dev : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test       # 536 passed
npm run dev
  5. Tester sur desktop :
    • Aller dans /patients
    • Passer la souris sur le nom d'un patient pendant ~500ms
    • Le popover apparaît avec : nom, âge, chambre, étiquettes, statut RGPD, compteurs DI/achats
    • Déplacer la souris vers le popover → il reste ouvert
    • Sortir → fade-out après 150ms
    • Clic court sur le nom OU le bouton "Voir la fiche complète" → navigation
  6. Tester sur mobile (ou émulation responsive F12) :
    • Tap sur le nom → navigation directe (pas de popover, comportement standard)
