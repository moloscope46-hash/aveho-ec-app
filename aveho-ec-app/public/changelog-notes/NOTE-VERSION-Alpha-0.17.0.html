3. Drag tactile Kanban

3.1 Le problème (piège 0.14)

La vue Kanban des DI livrée en 0.14 utilisait HTML5 Drag-and-Drop natif (draggable, onDragStart, onDragOver, onDrop). Sur écrans tactiles (téléphones, tablettes), ces événements ne sont pas déclenchés par le navigateur — le doigt fait défiler la page au lieu de glisser la carte.

3.2 La solution (sans dépendance)

Plutôt qu'ajouter @dnd-kit/core (40+ KB) ou react-dnd, j'ai implémenté un drag maison via Pointer Events. Les Pointer Events sont supportés par tous les navigateurs modernes et unifient souris + tactile + stylet en une seule API.

3.3 Architecture

  1. onPointerDown sur une carte : capture du pointeur, calcul de l'offset clic vs coin de la carte, position de départ enregistrée dans un ref.
  2. onPointerMove sur la grille (parent) : si déplacement > 6px, on entre en mode drag. La position du ghost suit le pointeur (translaté de l'offset). On utilise document.elementFromPoint() pour détecter quelle colonne est survolée (recherche le plus proche [data-kanban-col]).
  3. onPointerUp : si le drag a été déclenché et qu'on est sur une colonne valide, on update le statut côté Supabase avec rollback optimiste en cas d'erreur. Si pas de drag (juste un tap), on route vers /interventions.
  4. Annulation : si la fenêtre perd le focus ou que le pointeur est annulé (notif iOS, alt-tab), on reset.

3.4 Ghost-card pendant le drag

Pendant le drag, une copie de la carte est rendue en position: fixed qui suit le pointeur. Légère inclinaison (rotate(2deg)) et ombre forte pour le distinguer. La carte d'origine reste en place avec opacity: 0.3.

La colonne survolée passe en bordure pointillée colorée + fond légèrement teinté.

3.5 Précautions

  • touchAction: "none" sur les cartes et la grille pendant le drag pour empêcher le scroll natif
  • userSelect: "none" pour éviter la sélection de texte sur long-press
  • Seuil de 6px avant de déclencher le drag — un simple tap n'active rien
  • Le routeur n'est appelé que si dragRef.current.started est faux au moment du onClick — pas de routage parasite après un drop

4. Échéance DI saisissable

La colonne interventions.due_date a été créée en 0.16.1 et était déjà lue par la page /calendrier. Il manquait juste l'UI pour saisir cette date au moment de créer une DI.

Dans app/interventions/page.js, le bloc "Niveau d'urgence" a été passé en fld-row à 2 colonnes, avec un input type="date" à droite pour "Échéance souhaitée". Le champ est optionnel (la DI peut être créée sans).

À la sauvegarde, due_date est joint au payload (null si vide). La DI apparaît ensuite dans /calendrier à sa date d'échéance plutôt qu'à sa date de création.

5. Pastilles d'activité utilisateurs

5.1 Vue exploitée

La vue SQL v_user_activity (créée en 0.16.0) agrège par user_id le nombre d'actions, la dernière activité, et les compteurs 7j / 30j. La page Utilisateurs fait désormais un SELECT sur cette vue au chargement (en plus du SELECT sur membres_structure) et stocke le résultat dans un map {user_id: activity}.

5.2 Affichage dans la liste

Chaque ligne de membre affiche désormais :

  • vert si dernière activité < 10 min (considéré "en ligne")
  • orange si dernière activité < 24h (actif récemment)
  • gris sinon ou si aucune activité enregistrée

Sous le nom du membre, un libellé "il y a X" indique la dernière activité (à l'instant / il y a N min / il y a N h / il y a N j / il y a N sem / il y a +30 j).

5.3 Helper relativeTime

Fonction utilitaire relativeTime(iso) définie dans la page Utilisateurs. 5 paliers pour rester lisible. Pour la 0.17.1, on pourra l'extraire dans lib/format.js et la réutiliser sur le Journal, les notifications, etc.

8. Procédure d'application

  1. Pas de SQL : la 0.17.0 n'introduit aucune nouvelle table ni colonne. Tout passe par le code.
  2. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local)
  3. Lancer : 
    cd C:\aveho-ec-app
npm install
npm run dev
  4. Tester :
    • /interventions/kanban sur desktop : drag à la souris OK (même qu'avant)
    • /interventions/kanban en mode responsive iPhone (F12 → toggle device toolbar) : drag tactile, le ghost suit le doigt, ça change de colonne
    • /interventions → bouton "Nouvelle DI" : un champ "Échéance souhaitée" apparaît à droite de l'urgence
    • /calendrier : les DI avec due_date apparaissent à leur date d'échéance
    • /utilisateurs : pastille colorée à gauche de chaque nom + "il y a X" sous le nom
  5. Mise en ligne Vercel : 
    cd C:\aveho-ec-app-01
robocopy C:\aveho-ec-app C:\aveho-ec-app-01 /E /PURGE /XD .git node_modules .next
git add . ; git commit -m "Aveho EC 0.17.0 - drag tactile + due_date + activité" ; git push

10. Roadmap 0.17.1 & 0.18

0.17.1 — Notifications & intégrations

  1. Push notifications VAPID — chantier service worker. Génération des clés VAPID, déploiement de la fonction Edge send-push, ajout du composant <NotificationOptIn> dans les paramètres.
  2. Webhook Teams — relais des notifs critiques (DI urgentes, achats validés) vers un canal Teams via la URL webhook configurée dans les paramètres collectivité.
  3. Webhook Slack — équivalent pour les collectivités utilisant Slack.
  4. Helper relativeTime extrait vers lib/format.js, réutilisé dans Journal, NotifBell, etc.
  5. Tri du Kanban par échéance — option pour trier les cartes par due_date au lieu de date de création.

0.18 — Refactor, qualité, dette

  1. Tests unitaires — Vitest sur les helpers critiques (canDo, fmtDate, statutClass, relativeTime).
  2. Audit accessibilité (a11y) — passe sur les modales, contrastes, focus visible, aria-labels.
  3. Refactor pdfPreview.js — remplacer document.write() par un blob URL + iframe propre.
  4. Dépréciation role text — suppression de la colonne legacy après migration complète vers role_id.
  5. Extraction de hooks — useStructureData, useFiltres, etc. pour réduire la duplication.
  6. Optimisations performance — virtualisation des listes longues, lazy loading des images, code-splitting.
