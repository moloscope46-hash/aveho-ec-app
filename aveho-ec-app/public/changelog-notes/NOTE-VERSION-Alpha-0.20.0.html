3. Recherche full-text Postgres

3.1 Le problème

La recherche actuelle (GlobalSearch + Crud filter) utilise ILIKE '%terme%'. Sur une petite base ça marche, mais :

  • Pas accent-insensitive natif ("Léa" ne trouve pas "lea" sans transformation)
  • Pas de ranking — les meilleurs résultats ne remontent pas en premier
  • Scan séquentiel sur 5000+ lignes → lenteur visible
  • Pas de recherche multi-termes intelligente

3.2 La solution : tsvector + GIN + unaccent

Postgres a un moteur full-text natif très puissant. Trois ingrédients :

  1. Extension unaccent : transforme "Léa" en "lea" à l'indexation et à la requête
  2. Config FTS aveho_fr : french + unaccent. Stemming français (chambres → chambre, malade → malad)
  3. Colonne tsvector générée : Postgres maintient automatiquement à jour le vecteur de recherche à chaque INSERT/UPDATE
  4. Index GIN : recherche O(log n) au lieu de O(n)

3.3 Exemple concret

Avant (ILIKE) :

select id, nom, prenom from patients 
where nom ilike '%dupont%' or prenom ilike '%dupont%';
-- Scan séquentiel, ~50ms sur 5000 lignes

Après (RPC full-text) :

select * from search_patients('dupont', 10);
-- Index GIN, ~2ms même sur 100 000 lignes
-- ET trouve "Dupont", "DUPONT", "Dupond" (stemming)

3.4 Démo accent-insensitive

"lea" → trouve "Léa Martin"
"EHPAD" → trouve "ehpad les tilleuls"
"dupont" → trouve "DUPONT", "Dupont"
"lit medic" → trouve "Lit médicalisé Hill-Rom"

3.5 Fallback côté code

GlobalSearch appelle d'abord supabase.rpc("search_patients", ...). Si la RPC n'existe pas (patch SQL pas encore appliqué), on tombe gracieusement sur l'ancienne requête ilike. Aucune casse si tu n'appliques pas immédiatement le patch SQL.

4. Notifs push regroupées

4.1 Le problème

Avant : si 5 DI urgentes sont créées en 2 min (cas d'une panne d'établissement), l'utilisateur reçoit 5 notifications dans son téléphone. Spam.

4.2 La solution : tag + getNotifications + renotify

Le service worker (public/sw.js) interroge maintenant self.registration.getNotifications({ tag }) à chaque push reçu. Si une notif avec le même tag est déjà affichée :

  1. Lit le compteur précédent (stocké dans data.count)
  2. L'incrémente
  3. Ferme l'ancienne
  4. Affiche une nouvelle avec titre "DI urgente créée (3)" et body "3 notifications du même type. Dernière : DI-1234..."
  5. renotify: true : vibre/sonne pour signaler l'arrivée

4.3 Tag par event_type

lib/events.js transmet désormais event_type à send-push, qui le passe en tag dans le payload. Les events groupés par catégorie :

  • di_urgente : toutes les DI urgentes
  • achat_a_valider : tous les achats à valider
  • signalement : tous les signalements

Ainsi 3 DI urgentes + 2 achats à valider donnent 2 notifs visibles (une par catégorie avec compteur) au lieu de 5.

5. Recherche dans liste membres

Dans /utilisateurs onglet Membres, ajout d'un input de recherche en haut à droite du FilterBar (via le rightSlot du composant). Filtre live sur :

  • Nom affiché
  • Poste / fonction
  • Téléphone
  • Nom du rôle

Recherche client-side (les membres sont déjà chargés). Bouton X pour effacer. Message d'état dédié si aucun résultat ("Aucun membre trouvé pour ...").

6. Patch SQL 0.20.0

Le script aveho-PATCH-vers-0.20.sql (111 lignes) effectue :

  1. Extension unaccent via create extension if not exists
  2. Config FTS aveho_fr : copie de french + mapping unaccent en plus du french_stem. Idempotent via un bloc DO check.
  3. Colonnes search_vector tsvector generated stored sur patients et materiels
  4. Index GIN sur les deux vecteurs
  5. 2 fonctions RPC : search_patients(q text, lim int) et search_materiels(q text, lim int)

100% idempotent (if not exists partout, create or replace function, check de la config FTS avant création). Rejouable.

Inclut des requêtes de vérification en commentaire à la fin du fichier.

8. Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.20.sql → Run. Idempotent.
  2. Vérifier avec les requêtes en fin de fichier : 
    select * from search_patients('dupont', 5);
select * from search_materiels('lit', 5);
  3. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local).
  4. Re-déployer l'Edge Function send-push (modifiée pour accepter event_type/tag) : 
    supabase functions deploy send-push
  5. npm install + tests + dev : 
    cd C:\aveho-ec-app
npm install
npm test       # 67 passed
npm run dev
  6. Pousser sur Vercel comme d'habitude.
