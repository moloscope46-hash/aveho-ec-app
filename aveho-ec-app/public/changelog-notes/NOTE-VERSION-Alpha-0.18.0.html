4. Refactor pdfPreview blob URL

4.1 Le problème

Deux helpers utilisaient document.write() qui génère un warning Chrome "document.write() is deprecated" et qui est mal supporté par les CSP modernes. Pas bloquant, mais gênant à terme.

  • lib/pdfPreview.js : iframe.contentDocument.write(html)
  • lib/exportPdf.js : w.document.write(html) dans une nouvelle fenêtre

4.2 La solution : blob URL

Construction d'un Blob avec le HTML, puis URL.createObjectURL(blob) pour obtenir une URL temporaire. Cette URL est ensuite passée à iframe.src ou à window.open().

// Avant
iframe.contentDocument.open();
iframe.contentDocument.write(html);
iframe.contentDocument.close();

// Après (Alpha 0.18.0)
const blob = new Blob([html], { type: "text/html" });
const blobUrl = URL.createObjectURL(blob);
iframe.src = blobUrl;

Nettoyage mémoire avec URL.revokeObjectURL(blobUrl) à la fermeture du preview (ou après 30 s pour la fenêtre de print, le temps d'impression).

4.3 Avantages

  • Plus de warning Chrome
  • Compatible CSP strict (le blob est local, pas d'injection cross-origin)
  • Comportement identique pour l'utilisateur (preview A4 + impression)

5. Audit a11y

5.1 Modale unifiée (ui.js)

Le composant <Modal> partagé reçoit 4 améliorations :

  • role="dialog" et aria-modal="true" sur le conteneur
  • aria-labelledby pointant vers l'ID du titre (généré dynamiquement à partir du titre)
  • Focus initial sur le premier élément focusable à l'ouverture
  • Focus trap : Tab et Shift+Tab cyclent dans la modale, ne sortent pas vers l'arrière-plan
  • ESC ferme la modale (déjà partiellement en place, désormais consolidé)
  • Restauration du focus sur l'élément précédent à la fermeture
  • aria-hidden="true" sur les icônes décoratives
  • aria-label plus descriptif sur le bouton X ("Fermer la fenêtre")

5.2 Focus visible accessible (CSS)

Ajout d'un style global :focus-visible qui rend le focus clavier clairement visible :

button:focus-visible,
a:focus-visible,
input:focus-visible,
select:focus-visible,
textarea:focus-visible,
[tabindex]:focus-visible {
  outline: 2px solid #7CC8C8;
  outline-offset: 2px;
  border-radius: 4px;
}

Variante "fond foncé" pour les boutons sur navy/teal : outline blanc + offset 3px pour rester visible.

5.3 Skip-link

Ajout d'un lien "Aller au contenu principal" en début de page (caché jusqu'au focus). Permet aux utilisateurs clavier de sauter directement le menu et la TopBar.

5.4 NotifBell

Les lignes de notification deviennent navigables au clavier : role="button", tabIndex={0}, gestion de Enter et Space. Le bouton supprimer passe de <i> à <button> avec aria-label.

6. NotifBell mutualisé

NotifBell avait une fonction locale relDate(iso) presque identique à relativeTime(iso) de lib/format.js. Suppression du doublon, utilisation du helper partagé. Bonus : le hover sur une notification montre maintenant la date complète (heure + date) en title.

8. Procédure d'application

  1. Pas de SQL — aucun changement de schéma en 0.18.0.
  2. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local).
  3. Installer la nouvelle dépendance dev (Vitest) : 
    cd C:\aveho-ec-app
npm install
  4. Vérifier les tests : 
    npm test
    Tu dois voir Test Files 2 passed (2) — Tests 34 passed (34).
  5. Lancer le dev : 
    npm run dev
  6. Tester :
    • Ouvrir une modale (ex. /utilisateurs → Infos utilisateur). Tab et Shift+Tab restent dans la modale.
    • Échap ferme la modale.
    • Tab depuis le début de page → le skip-link apparaît, Entrée saute au contenu principal.
    • NotifBell : Tab navigue dans les notifications, Entrée/Espace ouvre celle focusée.
    • Imprimer une liste (/maintenance par exemple) : plus de warning document.write dans la console.
  7. Mise en ligne Vercel : pousser sur C:\aveho-ec-app-01 comme d'habitude.
