Chantiers livrés

N Dashboard statistiques DI

  • 6 vues SQL calquées sur le modèle activité (0.31) :
    • v_stats_di_global : total, ce mois, mois dernier, % urgent, % résolu, nb_ouvertes, nb_7j/30j
    • v_stats_di_par_type : top types avec nb_urgent et nb_30j
    • v_stats_di_par_urgence : split urgent/normal
    • v_stats_di_heatmap : création par dow×heure sur 90j
    • v_stats_di_top_demandeurs : join avec v_users_emails pour avoir les emails (created_by côté DI)
    • v_stats_di_par_mois : 12 mois glissants avec generate_series
  • Page /statistiques-interventions avec KPIs + tendance + StackedBarChart + Heatmap + Gauge taux résolution + DonutChart urgence + top types (barres horizontales) + top demandeurs (podium 🥇🥈🥉)
  • Lien ajouté au menu TopBar (Administration)
  • Permissions admin uniquement (cohérent avec les autres dashboards)

M Vue calendrier mensuelle maintenances

  • Toggle Liste / Calendrier dans la toolbar (segmented control)
  • Composant <CalendrierMaintenance> : grille 7 colonnes (Lun-Dim) avec offset correct pour les mois qui ne démarrent pas un lundi
  • Navigation : boutons précédent / mois actuel / suivant
  • Cellules : numéro du jour, max 3 maintenances visibles + "+N" si overflow, mini-pills colorées par statut
  • Aujourd'hui : cellule en surbrillance bleue (bordure + bg)
  • Click sur une maintenance → ouvre la modale d'édition existante
  • Légende couleurs des statuts en bas

L Notification temps réel Supabase

  • Subscribe au channel notif:{structureId} avec filtre postgres_changes sur INSERT de notifications
  • Filtre côté Supabase via structure_id=eq.${structureId} → pas de fuite cross-structure
  • Update du state en tête de liste avec déduplication par id (au cas où le polling 60s aurait déjà chopé la notif)
  • Animation cloche : shake + couleur orange pendant 3s (keyframes aveho-bell-shake)
  • Toast natif via Notification API si permission === "granted" ET document.hidden === true (utilisateur sur un autre onglet)
  • Tag de notif = id → pas de toast doublon si la même notif arrive 2× (par exemple via push + realtime)
  • Cleanup automatique du channel à l'unmount
  • Le polling 60s existant reste en place comme filet de sécurité (au cas où la connexion Realtime soit perdue)

K Duplication templates RGPD multi-établissements

  • Nouveau bouton building-community sur chaque template (à côté de "dupliquer en nouvelle version")
  • Visible uniquement si etablissements.length > 0
  • Modale avec liste cochable des établissements (multiselect avec Set)
  • Source désactivée : si le template source est déjà spécifique à un etab, cet etab apparaît grisé avec "(source)" pour éviter de dupliquer sur lui-même
  • Boutons Tout sélectionner / Tout désélectionner en bas (visible si > 1 etab)
  • Action : insère N nouveaux consent_templates en un INSERT bulk Supabase, chacun avec is_active=false et un nom "{source} (copie)"
  • L'admin doit ensuite activer manuellement chaque copie par établissement (évite l'écrasement involontaire)

J Heatmap temporel sur /audit

  • RPC SQL get_audit_heatmap(structure_id, action, entite, jours) retourne (jour_semaine, heure, nb_actions)
  • Tous les paramètres action/entité sont optionnels (NULL = pas de filtre)
  • security invoker → respecte les RLS du user (admin uniquement)
  • UI : nouveau panneau Heatmap au-dessus du tableau, alimenté avec les mêmes filtres que la liste
  • Couleur violette (#5e4a8c) pour distinguer des heatmaps activité (bleu) et RGPD (vert)
  • Note "(filtrée)" affichée si filtreAction ou filtreEntite actif
  • Chargement silencieux : si RPC absente côté SQL, fallback vide sans message d'erreur

A CRUD récurrences maintenance

  • Onglets dans /maintenance : "Maintenances planifiées" (existant) + nouveau "Récurrences automatiques"
  • Compteurs intégrés aux onglets
  • Composant <RecurrencesPanel> avec :
    • 6 KPIs catégories : En retard (rouge), ≤ 7j (orange urgent), ≤ 30j (bleu), OK (vert), Sans date, Inactives
    • Tableau : Matériel · Type · Fréquence (jours) · Dernière · Prochaine due · Statut · Actions
    • Bouton "Faite" vert : marque comme réalisée aujourd'hui ET recalcule automatiquement prochaine_due à +N jours
    • Bouton modifier + bouton supprimer
  • Modale CRUD : sélection matériel, type (Préventive/Calibration/Vérification/Autre), fréquence jours, dernière réalisée (optionnelle), prochaine due (auto-calculée si vide), actif checkbox, notes
  • Calcul automatique : si l'utilisateur renseigne derniere_realisee mais pas prochaine_due, le système calcule via getTime() + freq*86400000 (DST-safe leçon de la 0.41)

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.43.sql → Run (idempotent)
  2. Vérifier : 
    -- Vues stats DI
select * from v_stats_di_global 
where structure_id='aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa';

select * from v_stats_di_heatmap 
where structure_id='aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa' limit 5;

-- RPC heatmap audit
select * from get_audit_heatmap(
  'aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa'::uuid, null, null, 30);
  3. Activer Realtime sur la table notifications (Supabase Dashboard → Database → Replication → activer pour public.notifications). Si déjà activée → pas d'action.
  4. Décompresser le zip par-dessus C:\aveho-ec-app\.
  5. Nettoyer le cache + npm install + tests + dev : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test       # 710 passed
npm run dev
  6. Tester :
    • /statistiques-interventions → nouveau dashboard DI avec heatmap, donut, top types, podium demandeurs
    • /maintenance → toggle Liste/Calendrier dans la toolbar · onglet "Récurrences automatiques" en haut
    • Ouvrir un autre onglet du navigateur sur /accueil, dans un 2ᵉ onglet faire une action qui crée une notif → l'onglet 1 doit recevoir la notif instantanément (cloche orange qui shake)
    • /parametres-rgpd → bouton building-community sur un template → modale multiselect → "Tout sélectionner" → Dupliquer
    • /audit → heatmap violette en haut de la page · changer le filtre action/entité → la heatmap se met à jour
