Chantiers livrés

AM Dashboard direction multi-structures

  • 2 nouvelles vues SQL :
    • v_direction_par_structure : 1 ligne par structure avec 10 KPIs (DI total, DI ce mois, DI ouvertes, DI urgentes, % résolu, patients, matériels, users actifs 30j, maintenances retard, signalements ouverts, dernière activité)
    • v_direction_totaux : agrégation cross-structures via membres_structure, restreinte à user_id = auth.uid()
  • Page /direction réservée Administrateur ou permission manage_collectivite
  • 8 KPIs principaux en grille responsive avec border-left colorée
  • Tableau détail par structure affiché uniquement si l'user a > 1 structure
  • Couleurs sémantiques :
    • DI urgentes > 0 → rouge avec compteur "(⚠ N)"
    • Maintenances retard > 0 → rouge gras
    • % résolu : vert ≥ 80, orange 50-79, rouge < 50
  • Sécurité : les vues utilisent les RLS existantes sur les tables sous-jacentes

AN Page /webhooks dédiée

  • L'infrastructure webhook existait depuis la 0.17.1 (colonnes webhook_teams_url, webhook_slack_url, webhook_filters sur structures) mais aucune page dédiée ne la mettait en valeur
  • 3 sections :
    1. Configuration : réutilise <WebhookConfig /> existant (URLs + checkboxes filtres + bouton tester chaque webhook config)
    2. Testeur libre : champ URL + message custom → envoi via Edge Function send-webhook. Auto-détection Teams vs Slack via pattern URL (matche .office.com, teams.microsoft, sinon Slack format). Feedback success/erreur en ligne.
    3. Documentation : 2 panneaux côte à côte Teams / Slack avec étapes pas-à-pas pour obtenir une URL incoming webhook + liens vers docs officielles
  • Lien menu dans TopBar Administration
  • Permission : Administrateur ou manage_collectivite

AB Push API câblé sur cron + digest

  • L'Edge Function send-push existait mais n'était utilisée que dans auto-archive-consents et notifierAuteurSignalement (ajouté en 0.46)
  • 2 nouveaux câblages :
    • maintenance-daily-cron : pour chaque notif J-7 maintenance proche, push browser additionnel best-effort. L'utilisateur reçoit donc : notif in-app + push browser (s'il s'est abonné)
    • weekly-stats-digest : après envoi de l'email récap, push court "X DI, Y signalements, Z achats cette semaine"
  • 4 emplacements actifs maintenant : auto-archive-consents · notifierAuteurSignalement · maintenance-daily-cron · weekly-stats-digest
  • Best-effort partout : try/catch silencieux, l'absence de subscription ne bloque jamais le reste du flux

AH ConflictResolver — diff visuel word-level

  • Avant : le composant montrait juste les 2 valeurs côte à côte sur fond coloré (bleu = ma version, orange = serveur)
  • Maintenant : nouveau composant <DiffValue> qui :
    • Pour les valeurs courtes (< 20 chars) : affichage simple (inchangé)
    • Pour les valeurs longues (textareas, descriptions) : diff word-level
      • Tokenize les 2 strings (mots + espaces + ponctuation)
      • Marque les tokens uniques à chaque côté
      • Côté local : rouge + barré sur les mots supprimés
      • Côté serveur : vert sur les mots ajoutés
  • Algorithme : pas un vrai diff LCS (trop lourd pour l'usage), juste un check d'appartenance par set. Suffisant pour résoudre des conflits de descriptions de DI ou de signalements
  • Aucune dépendance ajoutée

AG Page /offline polie

  • Avant : le service worker renvoyait juste new Response("Hors-ligne", 503) — texte brut sans style
  • Nouvelle page app/offline/page.js avec :
    • Design gradient navy/bleu pleine page
    • Icône Wi-Fi qui change selon navigator.onLine (cyan quand en ligne, orange quand offline)
    • Message dynamique : différent selon online/offline
    • Bouton "Réessayer" / "Recharger la page" selon l'état
    • Panneau "Disponible en local" listant ce qui reste accessible (patients récents, catalogue, création DI offline, panier)
    • Indicateur live "En ligne / Hors connexion" avec dot pulsant
    • Auto-detect du retour de connexion via online / offline events + intervalle 5s
  • Service Worker mis à jour :
    • Version bumped aveho-ec-0.6 → aveho-ec-0.47
    • Précache de /offline à l'install
    • networkFirst() retourne /offline en fallback pour les routes HTML (req.mode === "navigate")

AL InstallBanner refonte

  • Avant : juste un titre + sous-titre + boutons
  • Ajout d'une grille 3 colonnes de bénéfices visuels entre le header et les boutons :
    • 🚀 Plus rapide (ti-rocket)
    • 📡 Hors-ligne (ti-wifi-off)
    • 🔔 Notifs push (ti-bell-ringing)
  • Chaque chip : icône cyan + label court + fond glassmorphism subtle
  • Nouveau composant interne <BenefitChip> en fin de fichier
  • Aucun changement de comportement : tous les états persistés (dismissed, snoozed) restent identiques

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.47.sql → Run. Le patch finit par notify pgrst, 'reload schema'.
  2. Vérifier : 
    -- Vue par structure (test sans filtre, RLS gère les accès)
select structure_nom, nb_di_ce_mois, nb_maint_retard
from v_direction_par_structure
limit 5;

-- Totaux du user courant
select * from v_direction_totaux where user_id = auth.uid();
  3. Décompresser le zip par-dessus C:\aveho-ec-app\.
  4. Le service worker a changé (version bump) : pour forcer son rechargement après installation, vider le cache navigateur ou hard reload (Ctrl+F5)
  5. Redéployer les Edge Functions modifiées : 
    supabase functions deploy maintenance-daily-cron
supabase functions deploy weekly-stats-digest
  6. Cache + tests + dev (PowerShell — pas de &&) : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test
npm run dev
    Attendu : 822 tests verts.
  7. Tester :
    • AM : /direction → 8 cards de KPIs + tableau si multi-structures
    • AN : /webhooks → 3 sections, tester l'envoi avec un faux webhook (devrait renvoyer une erreur claire)
    • AH : provoquer un conflit offline → modifier le même champ ailleurs → reconnecter → ConflictResolver montre maintenant le diff word-level pour les valeurs longues
    • AG : DevTools → Network → Offline → naviguer vers une route non cachée → page /offline polie s'affiche
    • AL : vider le localStorage du banner → recharger → la grille des 3 bénéfices apparaît
