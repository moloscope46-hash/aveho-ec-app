🤝 1. Partenaires RPPS — table dédiée

Cas d'usage

Référencer des professionnels de santé qui interagissent avec votre structure mais qui n'ont PAS de compte Aveho :

  • Prescripteurs : médecins traitants des patients, médecins hospitaliers prescripteurs de DM
  • Intervenants : IDE libéraux qui passent au domicile, kinésithérapeutes, sages-femmes
  • Autres : pharmaciens, dentistes, etc.

Page /partenaires-rpps

  • Accessible depuis le menu TopBar → section Établissement → Mes partenaires RPPS
  • 3 KPIs en haut : Partenaires actifs / Prescripteurs / Intervenants
  • Filtres : Tous / Prescripteurs / Intervenants + recherche par nom/prénom/profession/RPPS/commune
  • Bouton violet " Ajouter un partenaire depuis RPPS" → ouvre RppsSearch

Ajout automatique

  1. Clic sur le bouton → modale RppsSearch (API FHIR ANS officielle)
  2. Recherche par nom / RPPS / profession / CP
  3. Clic sur un praticien → insertion automatique avec :
    • Classification auto : Médecin → est_prescripteur=true, Infirm/Kin/Sage → est_intervenant=true
    • Détection doublon par RPPS → message "Déjà partenaire" si présent
    • Tous les champs (nom, prénom, profession, spécialité, adresse, tél, etc.) pré-remplis

Cartes partenaires

  • Avatar violet avec icône user-circle
  • Badges colorés : PRESCRIPTEUR · INTERVENANT · RPPS 1000…
  • Clic → modale détails avec coordonnées cliquables (tel: + mailto:) + bouton Archiver

🗄 SQL Patch 0.55.30

-- HOTFIX
alter table etablissements add column if not exists groupement_id uuid;
create index idx_etablissements_groupement on etablissements(groupement_id) where groupement_id is not null;

-- Crée la table groupements si absente (avec RLS)
do $$ begin
  if not exists (select 1 from pg_tables where tablename = 'groupements') then
    create table groupements (id uuid primary key, structure_id uuid, nom text, ...);
    -- + RLS member_rw
  end if;
end $$;

-- Nouvelle table partenaires_rpps
create table partenaires_rpps (
  id uuid primary key default gen_random_uuid(),
  structure_id uuid not null references structures(id),
  rpps text, adeli text, civilite text,
  nom text not null, prenom text,
  profession text, specialite text, mode_exercice text,
  adresse text, cp text, commune text,
  telephone text, telephone_mobile text, email text,
  notes text, tags text[],
  est_prescripteur boolean, est_intervenant boolean,
  etablissement_ids uuid[],
  created_at, created_by, updated_at, archive
);

-- Contrainte unicité par (structure_id, rpps) where archive = false

🏢 4. RPC ajout utilisateur au bâtiment

2 nouvelles RPCs côté SQL :

  • add_user_to_etablissement(p_user_id, p_etablissement_id)
  • remove_user_from_etablissement(p_user_id, p_etablissement_id)

Vérifient :

  • L'établissement existe et appartient à une structure
  • L'appelant a le droit utilisateurs_write OU parametres_admin sur cette structure
  • L'utilisateur cible est bien membre de la structure

Insert idempotent avec ON CONFLICT DO NOTHING. Delete clean. Toutes deux security definer avec search_path = public.

→ Ces RPCs pourront être utilisées dans la fiche groupement (0.55.31) pour ajouter/retirer un user d'un bâtiment d'un simple clic.
