Résumé

Audit + nettoyage avant d'enrichir. La recherche globale existait depuis la 0.14 mais avait deux instances montées : une dans layout.js (palette Ctrl+K invisible) et une dans TopBar.js (conditionnée par auth.etabId, donc qui disparaissait quand aucun établissement sélectionné).

Le doublon causait deux problèmes invisibles. 1) Quand etabId devenait null, l'instance TopBar disparaissait et tu avais l'impression que la recherche avait disparu — alors que le Ctrl+K du layout fonctionnait toujours. 2) Sur les pages avec etabId, les 2 instances écoutaient Ctrl+K en parallèle, donc le raccourci toggle 2 fois (ouvre puis ferme instantanément). On ne le voyait pas mais ça flickait dans le DOM.

1. Diagnostic du doublon

Audit avec grep :

$ grep -rln "GlobalSearch" app/
app/TopBar.js          # Ligne 80 : <GlobalSearch etabId={auth.etabId} />
app/GlobalSearch.js    # Le composant lui-même
app/layout.js          # Ligne 37 : <GlobalSearch />  ← l'original

Architecture après fix

  • layout.js : <GlobalSearch /> sans props, monté en permanence dans <body>. Unique instance qui écoute Ctrl+K et l'event custom.
  • TopBar.js : juste un bouton 🔍 avec badge ⌘K. Au clic, dispatch window.dispatchEvent(new CustomEvent("aveho:open-search")).
  • GlobalSearch.js : ajout d'un listener window.addEventListener("aveho:open-search", ...) en plus du keydown Ctrl+K.
// TopBar.js — bouton visible
<button
  className="tb-icon"
  onClick={() => window.dispatchEvent(new CustomEvent("aveho:open-search"))}
  aria-label="Recherche globale (Ctrl+K)"
>
  <i className="ti ti-search" />
  <kbd>⌘K</kbd>  <!-- badge en bas à droite -->
</button>

// GlobalSearch.js — listener event custom
function onOpenSearch() { setOpen(true); }
window.addEventListener("aveho:open-search", onOpenSearch);

3. Historique de recherche

Stockage simple dans localStorage sous la clé aveho:search-history :

  • Sauvegarde au clic ou Enter sur un résultat
  • Maximum 6 entrées, le plus récent en tête
  • Dédoublonné sur le couple (type, id) — re-cliquer remonte en tête plutôt que d'ajouter une entrée
  • Affiché en bas de l'écran "tape au moins 2 caractères" avec icône
  • Clic sur une entrée historique → navigue directement (sans re-fetch)
  • Bouton "Effacer" pour vider l'historique

Pas de données sensibles stockées : juste {type, id, titre, sub, href}. RAS pour le RGPD.

4. Pourquoi pas de SQL

Tout est côté front. La recherche utilise les tables existantes et les RPC search_patients / search_materiels qui étaient déjà en place (créés en 0.20 avec full-text français). Pas besoin d'ALTER TABLE ou de nouvelle vue.
