Personnalisation complète. Chaque utilisateur a maintenant son propre espace de travail dans Aveho : ses filtres préférés sont mémorisés, il reçoit uniquement les notifs qu'il veut, et il visualise son activité personnelle. Plus de bruit, plus de friction.

1. useStickyState

API

// Drop-in replacement de useState
const [fStatut, setFStatut] = useStickyState("", "interventions:fStatut");
const [filters, setFilters] = useStickyState({}, "patients:filters");

// 3e élément = reset
const [filters, setFilters, resetFilters] = useStickyState({}, "patients:filters");

Caractéristiques

  • Scopé par userId : clé localStorage aveho:{userId}:{key}. Alice et Bob sur le même appareil n'écrasent pas leurs filtres.
  • Fallback "anon" si pas de userId (utile en login screen)
  • Auto-cleanup : si la valeur devient vide ("", null, [], {}), l'entrée localStorage est supprimée plutôt que de stocker "vide"
  • Re-chargement automatique au changement d'utilisateur (clé recomposée)
  • Robuste : try/catch silencieux (quota localStorage dépassé, etc.)
  • JSON par défaut : opt-out avec { json: false } pour stocker des strings brutes
  • Scope global possible : { scope: "global" } pour partager entre users

Heures silencieuses

Plage horaire (ex: 22h00-07h00) pendant laquelle les notifs reçues seront silencieuses (pas de son ni vibration). Les notifs restent visibles dans la cloche au réveil. Supporte le passage minuit.

Stockage

-- Table user_notification_preferences
-- 1 ligne par user, jsonb pour prefs + quiet_hours

{
  "user_id": "uuid-de-alice",
  "prefs": {
    "di": true,
    "achat": false,           // Alice ne veut pas les notifs achats
    "consent_auto_archive": true  // Mais veut l'archivage mensuel
  },
  "quiet_hours": { "start": "22:00", "end": "07:00" }
}

Filtrage côté Edge Function

Quand send-push est appelée avec un event_type :

  1. Récupère les targets (push_subscriptions) de la structure
  2. Bulk fetch des préférences pour tous les userIds concernés (1 seul appel SQL, pas N)
  3. Filtre la liste : exclut les users qui ont explicitement désactivé ce type
  4. Envoie aux restants
  5. Retour enrichi : { sent, failed, cleaned, filtered }

RPC user_accepts_notif

Fonction SQL utilitaire user_accepts_notif(user_id, event_type) qui retourne true si le user accepte ce type (par défaut true si pas de préférence enregistrée). Utilisable depuis d'autres Edge Functions ou côté front pour vérification.

3. Dashboard /profil

KPIs personnels

Compteurs basés sur created_by / demandeur_id / user_id selon la table :

  • DI créées + sous-compteurs urgentes / clôturées
  • Achats demandés + à valider
  • Transferts créés
  • Signalements postés

Mes 15 dernières actions

Lecture de audit_events filtrée par user_id de la structure. Affichage :

  • Badge coloré par type d'action (creer=vert, modifier=bleu, supprimer=rouge, valider=vert, refuser=rouge, soumettre=orange, etc.)
  • Icône de l'entité (intervention, commande, transfert, signalement, patient, materiel)
  • Numéro de l'entité si disponible (DI-1234, CMD-5678, etc.)
  • Time relative ("il y a 2h") avec tooltip date complète au survol

Composants existants conservés

  • Identité + collectivité + rôle
  • Modification nom d'affichage
  • Changement mot de passe
  • Infos session (email, ID, permissions)

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.29.sql → Run.
  2. Vérifier : 
    -- La table existe ?
select count(*) from user_notification_preferences;

-- Le RPC fonctionne ?
select user_accepts_notif(auth.uid(), 'di');
-- → true (pas de pref → accepte tout)
  3. Redéployer send-push (modifiée pour filtrage) : 
    cd C:\aveho-ec-app
supabase functions deploy send-push
  4. Décompresser le zip par-dessus C:\aveho-ec-app\.
  5. npm install + tests + dev : 
    npm install
npm test       # 242 passed
npm run dev
  6. Test sticky filters :
    • Aller dans /interventions
    • Filtrer par statut "En cours"
    • F5 (refresh) → le filtre est toujours actif
    • Se déconnecter, se reconnecter avec un autre user → le filtre n'est pas conservé pour lui
  7. Test préférences notif :
    • Aller dans /profil → section "Mes notifications"
    • Désactiver "Workflow achats"
    • Activer "Heures silencieuses" 22h-07h → Enregistrer
    • Demander à un collègue de soumettre une demande d'achat → tu ne dois PAS recevoir de notif push
  8. Test dashboard /profil :
    • Aller dans /profil
    • Voir tes KPIs personnels (DI créées, achats, etc.)
    • Voir tes 15 dernières actions avec badges colorés
