📱 Fix 1 — StatusIcons mobile : 1 bouton + bottom-sheet

Avant : 7 icônes alignées horizontalement dans la TopBar prenaient toute la largeur sur petit écran et débordaient. CSS responsive cachait les 3 dernières mais ce n'était pas idéal.

Après :

  • Desktop (>768px) : 7 icônes inline avec popover individuel au clic (comportement actuel)
  • Mobile (≤768px) : 1 seul bouton "bouclier" à côté du panier, avec une petite pastille colorée en haut à droite indiquant l'état global :
    • 🟢 vert : tout est OK
    • 🟡 ambre : des features non configurées
    • 🔴 rouge : des features refusées
  • Au clic → bottom-sheet (slide-up) plein écran avec :
    • Header gradient avec compteur "X/7 actifs"
    • Liste scrollable des 7 features avec icône colorée + nom + badge ACTIF/REFUSÉ/INACTIF + description
    • Bouton Autoriser (notif/géoloc) ou Gérer dans Profil (empreinte/face) sur chaque ligne où c'est applicable

Détection mobile

Via un hook custom useIsMobile() qui écoute window.matchMedia("(max-width: 768px)") en live, donc bascule automatique entre les 2 layouts si l'user redimensionne sa fenêtre (resize mode tablette ↔ desktop).

🐛 Fix 2 — Boutons "Gérer" / "Autoriser" qui ne réagissaient pas

Symptôme : Cliquer sur "Gérer" ou "Autoriser" dans le popover ne déclenchait rien (ni redirection, ni demande de permission).

Cause

Le bouton était à l'intérieur du popover, et le clic se propageait au backdrop qui fermait le popover avant que l'action ait le temps de s'exécuter.

Fix

// Avant
<button onClick={() => f.action.fn()}>{f.action.label}</button>

// Après
<button
  type="button"
  onClick={(e) => {
    e.stopPropagation();  // empêche la propagation au backdrop
    f.action.fn();
  }}
>{f.action.label}</button>

// Pour gotoProfil : ferme proprement puis navigate
function gotoProfil() {
  setOpen(null);
  setModalOpen(false);
  setTimeout(() => router.push("/profil"), 50);  // laisse le state se mettre à jour
}

⚡ Fix 3 — 503 transient sur /profil

Le SW renvoyait parfois 503 pour des fetches network qui auraient pu réussir en retry. Notamment sur /profil qui charge plein de RPCs Supabase.

Fix dans le SW

// 0.55.21 : retry 1x avec petit délai (transient network errors)
try {
  await new Promise(r => setTimeout(r, 100));
  const res2 = await fetch(req);
  if (res2.ok) { cache.put(req, res2.clone()); return res2; }
} catch (_) {}

Fallback offline amélioré

Si /offline.html n'est pas en cache (cas d'une 1ère visite offline), on renvoie maintenant un HTML 200 inline avec un bouton "Réessayer" plutôt qu'un 503 brut qui poluait la console.

⚠ Note sur le warning Banner not shown

Le warning Banner not shown: beforeinstallpromptevent.preventDefault() called peut continuer à apparaître chez certains utilisateurs. C'est un warning informatif de Chrome, pas une erreur bloquante.

On l'a réduit en 0.55.20 (preventDefault conditionnel) mais il peut subsister sur la première installation. Chrome documente ce comportement comme normal pour les sites avec banner custom (cf. BeforeInstallPromptEvent dans Web.dev).
