Résumé

La 0.34 sort enfin le template RGPD du code source pour le mettre en base de données. Chaque collectivité peut maintenant avoir son propre formulaire de consentement, adapté à son contexte (clauses spécifiques, partenaires, télé-suivi, etc.).

Audit RGPD préservé. Un template déjà utilisé pour signer un consentement est immuable (UI + RLS). Pour le faire évoluer, on crée une nouvelle version (v1.1, v1.2…) qui devient le template actif. Les anciens consentements gardent leur référence et leur texte intégral pour audit 10+ ans.

🩹 Hotfix appliqués

Hotfix #1 — Erreur SQL 22P02 (roles.systeme)

Symptôme : ERROR: 22P02: invalid input syntax for type boolean: "admin" à l'exécution du patch SQL.

Cause : J'avais supposé que roles.systeme était un text ('admin', 'lecture') parce que le code JS dans lib/useAuth.js le compare comme tel. En réalité c'est un BOOLEAN (rôle non supprimable). Côté JS la comparaison === "admin" renvoie toujours false mais le code retombe sur d'autres conditions, donc ça marche en pratique. En SQL strict, ça plante.

Fix : Les policies RLS détectent maintenant l'admin via :

r.nom = 'Administrateur'
or r.droits::text ilike '%manage_roles%'
or r.droits::text ilike '%manage_collectivite%'
or coalesce(r.permissions_json::text, '') ilike '%manage_roles%'
or coalesce(r.permissions_json::text, '') ilike '%manage_collectivite%'

Le cast ::text + ilike '%xxx%' sur le jsonb permet de gérer aussi bien le format array ["manage_roles","write"] que le format objet {"module": ["manage_roles"]}.

Hotfix #2 — Modal qui ne s'ouvre pas

Symptôme : Clic sur "Créer mon template" ou "Nouvelle version" → rien ne se passe à l'écran. Pas d'erreur visible.

Cause : Le composant Modal de app/ui.js exige open={true} pour s'afficher (if (!open) return null;). Ma page passait juste <Modal> sans cette prop. La modale s'auto-fermait instantanément. Aussi, j'utilisais large mais la signature attendait size="lg" (widths sm:380, md:520, lg:720).

Fix :

- <Modal title="..." onClose={...} large>
+ <Modal open={true} title="..." onClose={...} size="lg">

Appliqué sur les 2 modales de la page (éditeur + preview).

1. SQL — Table consent_templates

create table consent_templates (
  id uuid primary key,
  structure_id uuid not null references structures(id),
  version text not null,
  is_active boolean default false,
  contenu_md text not null,
  nom text,
  description text,
  created_at timestamptz default now(),
  created_by uuid references auth.users(id),
  activated_at timestamptz,
  unique (structure_id, version)
);

Trigger 1 seul actif par structure

Quand on active un template (is_active = true), un trigger BEFORE INSERT/UPDATE désactive automatiquement les autres templates actifs de la même structure.

Référence depuis consentements_rgpd

alter table consentements_rgpd
  add column template_id uuid 
  references consent_templates(id) on delete set null;

Les anciens consentements ont template_id = NULL. Les nouveaux pointent vers la version exacte utilisée. texte_consentement conserve toujours le texte intégral final (substitué) pour relire 10 ans après.

3. Page /parametres-rgpd

Pourquoi le template par défaut n'apparaît pas dans la liste

C'est par design. Le template par défaut est hardcodé dans le code (lib/rgpd.js), pas en base de données. Le tableau liste uniquement les templates personnalisés. Pour le voir : clic "Créer mon template" → le contenu pré-rempli est le template par défaut Aveho.

Restriction admin

Accessible uniquement avec permission gerer_roles ou manage_collectivite ou rôle Administrateur.

Règles d'édition

  • Brouillon vierge (0 utilisation, non actif) → modifiable
  • Brouillon utilisé (≥1 utilisation) → bloqué, faire une nouvelle version
  • Template actif → bloqué, faire une nouvelle version
  • Suppression : impossible (préservation audit)

Modale éditeur (2 colonnes)

  • Gauche : version, nom, description, contenu markdown (textarea fixed-width)
  • Droite : variables cliquables (clic = copie clipboard) + preview live avec données mockées
