1. Résumé exécutif

L'Alpha 0.10 livre cinq chantiers de la roadmap 0.9 : un module complet de maintenance préventive du matériel avec planification et statuts, une vue semaine sur le calendrier DI complémentaire à la vue mensuelle, un filtre par étiquette sur la liste Patients (logique suite des étiquettes 0.9), un mode kiosque pour affichage écran en salle de pause, et un mode lecture seule pour les sessions de formation.

Cette version introduit 1 nouvelle table SQL (maintenances) avec son script de migration 14_maintenance.sql. Sans ce script, la page Maintenance ne fonctionnera pas mais le reste de l'app continue normalement.

3. Maintenance préventive NOUVEAU

3.1 Modèle SQL

Nouvelle table maintenances (RLS activée, scope collectivité) :

maintenances (
  id, structure_id, etablissement_id, materiel_id,
  type,              -- ex: "Révision annuelle", "Contrôle sécurité"
  date_prevue,       -- date planifiée
  date_realisee,     -- renseignée quand effectuée
  statut,            -- "Planifiée" | "À faire" | "Faite" | "En retard" | "Annulée"
  intervenant,       -- nom du tech / prestataire (libre)
  notes,
  assignee_id        -- utilisateur assigné (optionnel)
)

3.2 Page Maintenance

Nouvelle page /maintenance accessible depuis le menu Espace Collectivité. Affiche :

  • 4 KPIs cliquables en haut : En retard, À faire, Planifiée, Faite — clic pour filtrer la liste sur ce statut
  • Tableau ordonné par date prévue avec colonnes Date, Matériel, Type, Intervenant, Statut
  • Bouton ⊙ "Marquer comme faite" sur chaque ligne non encore terminée — raccourci pour mettre le statut à Faite avec date du jour

3.3 Calcul automatique du statut "En retard"

Une maintenance dont date_prevue est passée et qui n'est ni Faite ni Annulée passe automatiquement en En retard au rendu — pas besoin de cron ou de trigger SQL. Le calcul est fait côté client par une petite fonction statutEffectif() à chaque affichage.

3.4 Types de maintenance pré-remplis

Le sélecteur Type propose 7 valeurs courantes : Révision annuelle, Contrôle sécurité, Étalonnage, Nettoyage approfondi, Mise à jour firmware, Remplacement de pièces, Autre. Le champ est texte libre donc tu peux saisir n'importe quoi.

3.5 Cas d'usage métier

  • Lit médicalisé : révision annuelle + remplacement pièces d'usure
  • Concentrateur O2 : contrôle sécurité Bureau Veritas annuel obligatoire
  • Pompe à perfusion : étalonnage périodique du débit
  • Scope / monitoring : mise à jour firmware constructeur

4. Calendrier vue semaine NOUVEAU

La page Calendrier livrée en 0.9 avait une vue mensuelle. La 0.10 ajoute une vue semaine complémentaire, sélectionnable via un toggle en haut à droite.

Différences entre les vues

Persistance

Le choix de vue n'est pas persisté en localStorage volontairement. Quand tu reviens sur la page, tu repars sur la vue Mois par défaut. Si tu veux changer ça (ex: vue semaine par défaut), dis-le moi.

5. Filtre par étiquette sur Patients NOUVEAU

Suite logique des étiquettes livrées en 0.9. Dans le panneau Filtres avancés de la page Patients, un nouveau sélecteur Étiquette apparaît automatiquement si au moins une étiquette est définie dans la collectivité. Sinon, le sélecteur reste caché.

Combinabilité

Le filtre étiquette se combine avec les autres filtres existants (nom, service, chambre, état). Exemple : "Tous les patients chroniques du service 2A actuellement présents" = combinaison des 3 filtres.

Bouton "Effacer"

Le bouton Effacer du panneau de filtres remet aussi l'étiquette à zéro. La condition d'affichage du bouton a été étendue pour détecter le filtre étiquette actif.

6. Mode kiosque / présentation NOUVEAU

6.1 Activation

Dans Paramètres → Apparence → section Mode kiosque / présentation, un bouton Activer le mode kiosque bascule l'interface en mode plein écran épuré.

6.2 Effets visuels

  • TopBar masquée (logo, menu, panier, cloche)
  • Largeur étendue à 1400px au lieu de 1200px
  • Titre H1 zoomé à 48px (au lieu de 32px)
  • KPIs zoomés : tuiles plus grandes, valeurs à 48px
  • Petit badge "MODE KIOSQUE — Échap pour sortir" en haut à droite (semi-transparent, visible au survol)

6.3 Sortie

Trois moyens de sortir du mode kiosque :

  • Touche Échap n'importe quand
  • Retourner à /parametres et cliquer à nouveau (le bouton devient un toggle)
  • Vider le localStorage du navigateur

6.4 Cas d'usage

Affichage sur grand écran dans une salle de pause, vitrine d'établissement, écran de coordination en salle de réunion. Avec le mode foncé livré en 0.7, ça donne un rendu très propre type tableau de bord opérationnel.

7. Mode lecture seule NOUVEAU

7.1 Principe

Dans Paramètres → Apparence (en bas), une case à cocher Activer le mode lecture seule. Quand elle est activée :

  • La fonction auth.can() renvoie false pour toutes les actions d'écriture : ecrire, supprimer, valider, commander, gerer_roles
  • Tous les boutons "Nouveau", "Modifier", "Supprimer", "Valider" disparaissent automatiquement (ils sont conditionnés à auth.can() partout)
  • Un badge orange discret "LECTURE SEULE" apparaît en bas à droite de chaque page pour rappeler le mode

7.2 Cas d'usage : sessions de formation

Pendant une formation utilisateurs, le formateur peut activer le mode et naviguer dans l'app pour tout montrer (créer, modifier, supprimer en visuel) sans risque de toucher aux vraies données de la collectivité. Les apprenants voient la même interface mais avec les boutons grisés/cachés.

7.3 Différence avec un rôle "Lecture seule"

Le mode est côté navigateur (localStorage) — il ne touche pas le rôle réel dans Supabase. Un utilisateur peut donc avoir un rôle "Administrateur" en base mais s'auto-bloquer en mode lecture pour une démo. C'est volontairement local et réversible. Pour un vrai rôle Lecture seule en base, il faudrait créer le rôle dans la table roles ce que je n'ai pas fait — dis-moi si tu en as besoin.

7.4 Limite assumée

Le mode lecture seule ne bloque pas les requêtes HTTP au niveau Supabase — il masque juste les boutons et empêche les fonctions d'écriture côté front. Un utilisateur malveillant avec la console développeur pourrait quand même envoyer des requêtes (modulo la RLS Supabase qui reste active selon son vrai rôle). C'est un mode "garde-fou pédagogique", pas une sécurité.

10. Procédure de mise à jour depuis Alpha 0.9

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans Supabase SQL Editor : exécute supabase/14_maintenance.sql.
    Sans ce script, la page Maintenance échouera. Le reste de l'app fonctionne normalement.
  4. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  5. Tests rapides :
    • Va sur /maintenance : tu vois les 3 maintenances démo (Révision annuelle, Contrôle sécurité en retard, Étalonnage)
    • Clique sur le KPI En retard : la liste se filtre dessus
    • Clique sur l'icône d'une maintenance non terminée : passe à Faite avec date du jour
    • Sur /calendrier, clique le toggle Semaine : les cases s'agrandissent, toutes les DI deviennent visibles
    • Sur Patients, ouvre les Filtres avancés : si tu as des étiquettes, le sélecteur Étiquette apparaît
    • Sur Paramètres → Apparence : clique Activer le mode kiosque → la TopBar disparaît, les KPIs sont énormes. Appuie sur Échap pour sortir.
    • Toujours sur Paramètres → coche Activer le mode lecture seule → la page se recharge, tous les boutons "Nouveau", "Modifier", "Supprimer" disparaissent. Badge orange en bas à droite. Décoche pour revenir en mode normal.
  6. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.10"
git push

12. Roadmap suggérée pour Alpha 0.11

Suggestions issues du métier maintenance + des reports précédents :

  1. Lien Maintenance ↔ DI — créer automatiquement une DI quand une maintenance passe en retard
  2. Maintenances récurrentes — quand une maintenance "Révision annuelle" passe à Faite, créer auto la suivante à +1 an
  3. Notifications Maintenance — alerte cloche J-7 avant échéance, J+1 si en retard
  4. Export PDF planning Maintenance — liste des maintenances à venir pour un prestataire
  5. Maintenances dans le calendrier DI — fusionner les deux types d'évènements dans la même vue
  6. Tags par matériel (similaire aux étiquettes patients : "Critique", "Hors service", "À surveiller")
  7. Notifications push navigateur (chantier dédié VAPID)
  8. Module signalements anonymes (boîte à idées / problèmes de l'équipe terrain)
