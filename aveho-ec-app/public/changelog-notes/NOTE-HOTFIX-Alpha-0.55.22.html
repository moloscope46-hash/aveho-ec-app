🛡 Fix 1 — getDeviceName plus respectueux de la privacy

Symptôme : Dans la modale d'opt-in biométrique, le champ "Appareil" était pré-rempli avec "Windows" tout court, donnant l'impression qu'Aveho remontait le hostname réel de la machine.

Avant

if (/Windows/.test(ua)) return "Windows";
if (/Macintosh/.test(ua)) return "Mac";
if (/Android/.test(ua)) {
  // extrait le modèle exact : "Android (Pixel 6)"
  ...
}

Après

if (/iPhone/.test(ua)) return "Mon iPhone";
if (/iPad/.test(ua)) return "Mon iPad";
if (/Android/.test(ua)) return "Mon téléphone Android";  // sans modèle
if (/Macintosh/.test(ua)) return "Mon Mac";
if (/Windows/.test(ua)) return "Mon ordinateur (Windows)";
if (/Linux/.test(ua)) return "Mon ordinateur (Linux)";
return "Mon appareil";

Avantages :

  • Plus naturel ("Mon Mac" plutôt que juste "Mac")
  • Pas de modèle exact remonté pour Android (Pixel 6, Samsung Galaxy, etc.)
  • Privacy par défaut : aucune info sensible révélée
  • L'user peut toujours éditer le champ avant validation

👥 Fix 2 — Icônes bio toujours visibles dans /utilisateurs

Symptôme : Sur la page Gestion des utilisateurs, on ne voyait pas qui avait activé l'empreinte ou la détection faciale, car les icônes étaient affichées seulement si activées (et invisibles sinon).

Fix

Les 2 icônes (empreinte + face) sont maintenant toujours affichées à côté du nom de chaque user, avec une couleur qui indique l'état :

  • 🟢 Vert (fond vert clair + bordure verte) : méthode activée par cet user
  • ⚪ Gris (fond gris pâle + bordure grise) : méthode non activée

Tooltip au hover : "Empreinte digitale activée" ou "Empreinte digitale non activée" (idem pour face).

Pourquoi

Comme ça l'admin voit clairement à l'œil :

  • Quel user a configuré la sécurité biométrique (vert)
  • Quel user n'a pas encore (gris) → cible pour rappels formation
  • Quel mix de méthodes par user (empreinte seule, face seule, les deux, aucune)
