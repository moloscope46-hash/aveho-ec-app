Y pg_stat_statements + dashboard /admin-perf

  • SQL : create extension if not exists pg_stat_statements (déjà pré-installé sur Supabase, juste à activer)
  • RPC get_top_slow_queries(limit) en security definer avec :
    • Anonymisation des requêtes : remplace les littéraux 'abc' par ?, les $1/$2 par $N, les nombres par N → pas de fuite de données métier dans l'audit
    • Filtre des queries inutiles (pg_stat_statements lui-même, pg_catalog, COMMIT/BEGIN/SET)
    • Tri par mean_exec_time desc
  • RPC bonus reset_query_stats() pour vider les compteurs après une optim et mesurer son impact
  • Page /admin-perf réservée aux administrateurs avec :
    • Sélecteur du nombre de requêtes (10/20/50/100)
    • Boutons Recharger / Reset stats (Reset utilise dialogs.confirm() du chantier P)
    • Pills coloré par classification : Rapide (vert, <10ms), Moyen (bleu, 10-100ms), Lent (orange, 100-1000ms), Très lent (rouge, ≥1000ms)
    • Colonnes : Vitesse · Requête anonymisée (tronquée + tooltip) · Appels · Moyenne · Total · Lignes/appel
  • Lien menu ajouté dans TopBar (Administration)

  • Colonne checkbox ajoutée à gauche du tableau patients
  • Checkbox header "Tout sélectionner" qui ne coche que les lignes filtrées (respecte la recherche)

    • Compteur en gauche : "N patient(s) sélectionné(s)"
    • 3 actions à droite : Export CSV · Supprimer · Tout désélectionner
  • Export CSV bulk : BOM UTF-8 + CRLF + séparateur ; + escape correct. Colonnes : Nom, Prénom, Chambre, Bâtiment, Date d'entrée. Nom de fichier patients-export-YYYY-MM-DD.csv
  • Suppression bulk via delete().in("id", [...]). Confirm natif avec compteur + warning irréversible. Permission supprimer vérifiée.
  • State sélection via Set (pour add/delete O(1))

U Calendrier signatures RGPD

  • Nouveau panneau en bas de /statistiques-rgpd
  • Composant <CalendrierSignatures> avec grille 7 colonnes, navigation mois prev/today/next
  • Chargement des consentements du mois affiché via consentements_rgpd filtré par date_signature entre 1er du mois et 1er du mois suivant
  • Groupement par jour côté front : { total, oui, non } pour chaque date

  • Tooltip au hover : "X signatures le YYYY-MM-DD (✓ oui · ✗ non)"
  • Légende "Moins → Plus" en bas
  • Aujourd'hui en surbrillance bordure bleue

P dialogs.confirm() / alert() singleton

  • Approche : composants ConfirmModal / AlertModal (créés en 0.45) exposés via un singleton global avec promesses
  • Nouvelle utility lib/dialogs.js avec :
    • dialogs.confirm({ title, message, variant, icon }) → renvoie Promise<boolean>
    • dialogs.alert(message | options) → renvoie Promise<void>
    • État interne via listeners pour synchroniser le composant host
  • <DialogsHost /> à mettre une seule fois dans app/layout.js — c'est fait
  • Utilisation type : 
    import { dialogs } from "@/lib/dialogs";
const ok = await dialogs.confirm({
  title: "Supprimer ce patient ?",
  message: "Cette action est irréversible.",
  variant: "danger",
});
if (ok) doDelete();
  • Premier usage dans /admin-perf sur le bouton Reset stats
  • Migration progressive : les pages restantes (66 confirm() natifs à remplacer) seront migrées dans les prochaines versions

Q Push browser API câblé sur signalements

  • L'infra Push existait déjà (table push_subscriptions depuis 0.17.1, Edge Function send-push depuis 0.29) mais n'était utilisée que par auto-archive-consents
  • Ajout d'un 5ème étape dans notifierAuteurSignalement : appel POST /functions/v1/send-push avec payload { userId, title, body, url }
  • Best-effort : si l'auteur n'a pas activé les push (pas de subscription en base), la fonction renvoie OK sans erreur. Les autres canaux (email + notif in-app) restent fonctionnels.
  • Bénéfice : l'auteur peut être notifié même si Aveho est fermé (Service Worker reçoit le push en arrière-plan)
  • À étendre dans la 0.47 : câblage send-push dans les autres helpers (maintenance-daily-cron, send-digest…)

  • 4 étapes :
    1. Menu principal (.menu-burger) — "Voici le menu, accède à toutes les sections"
    2. Cloche notifications (.notif-btn) — "Tes notifications en temps réel"
    3. Logo / dashboard ([href='/accueil']) — "Reviens ici pour tes KPIs"
    4. Conclusion (center) — "Tu peux refaire ce tour depuis ton profil"
  • UX :
    • Overlay sombre rgba(20,33,49,0.75) qui couvre toute la page
    • Spotlight cyan animé pulse autour de l'élément cible
    • Tooltip en dessous de la cible (ou centré si "center")
    • Indicateur "ÉTAPE N / 4" en eyebrow
    • Boutons Précédent / Suivant + lien "Passer le tour" en bas à gauche
  • Persistance : localStorage["aveho_onboarding_done"] ne déclenche le tour qu'à la 1ère connexion
  • Re-lançable via resetOnboarding() appelé depuis le bouton "Refaire la visite" dans /profil
  • Auto-démarré sur /accueil avec délai 1.5s pour laisser l'UI se monter
  • A11y : role="dialog", aria-modal="true", aria-labelledby

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.46.sql → Run. Le patch finit par notify pgrst, 'reload schema'.
  2. Vérifier : 
    -- Extension activée
select extname from pg_extension where extname = 'pg_stat_statements';

-- RPC accessible
select * from get_top_slow_queries(5);
-- → 5 requêtes lentes (peut être vide si stats fraîchement reset)
  3. Décompresser le zip par-dessus C:\aveho-ec-app\.
  4. Cache + tests + dev (PowerShell — pas de &&) : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test
npm run dev
    Attendu : 793 tests verts.
  5. Tester :
    • Y : aller sur /admin-perf → voir le top 20 des requêtes lentes avec pills colorées
    • X : /patients → cocher 2-3 patients → bandeau bleu apparaît → cliquer "Export CSV"
    • U : /statistiques-rgpd → tout en bas, calendrier mensuel des signatures avec heatmap verte
    • W : /profil → 4 sections rétractées par défaut, cliquer pour ouvrir
    • P : sur /admin-perf, cliquer "Reset stats" → modale ConfirmModal stylée (pas de confirm() natif laid)
    • Q : répondre à un signalement nominatif → l'auteur reçoit notif in-app + push si abonné
    • T : se déconnecter, supprimer localStorage["aveho_onboarding_done"] dans DevTools, relogger → tour démarre automatiquement sur /accueil
