Date : 31 mai 2026 Version : v0.55.35-alpha Tests : 1246 verts (+23)

❌ Le bug 0.55.34

Logs serveur :

GET /api/rpps?q=+&ville=gramat&limit=50
→ 502 FHIR API HTTP 403

Quand le user faisait une recherche par ville seule (sans nom), le composant envoyait q=" " (espace) à l'API ANS. L'API rejette family= comme paramètre invalide → 403.

Le proxy renvoyait alors un 502 brutal, ce qui crashait le composant frontend.

✅ Le fix 0.55.35

1. Validation côté client

Dans RppsSearch : le param q est envoyé uniquement si au moins 2 caractères non-whitespace. Sinon le serveur reçoit une URL propre sans family vide.

2. Bascule intelligente Practitioner → PractitionerRole

Si l'utilisateur cherche par ville/CP seul (sans nom 2 lettres min.), le proxy bascule sur l'endpoint FHIR PractitionerRole qui supporte les filtres géographiques natifs :

GET /PractitionerRole
    ?location.address-city=Gramat
    &location.address-postalcode=46500
    &_include=PractitionerRole:practitioner
    &_count=50

On récupère les rôles avec leurs praticiens inclus en une seule requête.

3. Fallback gracieux (200 au lieu de 502)

Si l'API ANS continue de retourner une erreur (rate-limit, maintenance), le proxy renvoie maintenant HTTP 200 avec ok: false et un message lisible dans le body :

{
  "ok": false,
  "error": "API ANS HTTP 403. Vérifie tes critères ou réessaie plus tard.",
  "results": []
}

Le composant frontend affiche un message clair au lieu de crasher.

4. Erreur 400 explicite si critères insuffisants

Si vraiment aucun critère valide (q vide, pas de ville/CP/profession), le serveur renvoie 400 avec : "Précise au moins un nom (2 lettres min.) ou un n° RPPS."

🪄 Bonus : Auto-rattachement RPPS → FINESS

Extraction FINESS depuis l'API FHIR

La fonction normalizePractitioner extrait désormais 2 nouveaux champs depuis PractitionerRole.organization :

  • finess : N° à 9 chiffres extrait de Organization/123456789
  • organization_name : nom de l'établissement depuis organization.display

Auto-pré-sélection dans /annuaire-rpps

Quand tu cliques sur "Rattacher à un étab" depuis un résultat RPPS qui a un FINESS :

  1. L'app cherche dans etablissements (Mes) si un étab a ce FINESS → match !
  2. Sinon cherche dans etablissements_partenaires (table dédiée 0.55.31)
  3. Si trouvé → pré-sélection avec badge vert :

Auto-rattachement détecté !
Le FINESS 750712184 du praticien correspond à Hôpital Saint-Joseph. Tu peux valider directement, ou changer ci-dessous.

Si pas de match → banner ambre informatif : "FINESS détecté X mais aucun étab dans ta base. Choisis manuellement."

💡 Pour l'erreur 'kind is not defined'

Cette erreur côté client venait probablement d'un résidu d'ancien bundle Vercel (un build partiellement cassé qui n'a pas été remplacé). Le rebuild de cette version :

  • Bumpe le SW à 0.55.35 (force la mise à jour du cache navigateur)
  • Régénère tout le bundle
  • Devrait écraser tout résidu

Si l'erreur persiste après déploiement :

  1. Vide complètement le cache navigateur (Ctrl+Shift+Suppr)
  2. Ouvre la page en mode incognito pour tester sans cache
  3. Sur Vercel : "Redeploy" sans cache (settings → caches → clear)
