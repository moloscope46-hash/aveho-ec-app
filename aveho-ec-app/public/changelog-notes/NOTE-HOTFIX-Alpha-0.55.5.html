🐛 Fix critique — Carte vide sur Edge / Brave

Symptôme

La page /carte affichait le bandeau de stats en haut mais la zone Leaflet restait grise vide. Console pleine de :

Tracking Prevention blocked access to storage for 
  https://unpkg.com/leaflet@1.9.4/dist/leaflet.css
Tracking Prevention blocked access to storage for 
  https://unpkg.com/leaflet@1.9.4/dist/leaflet.js
Tracking Prevention blocked access to storage for 
  https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@2.47.0/tabler-icons.min.css

Cause racine

Microsoft Edge (et Brave, Firefox strict, certaines configs de Chrome) ont une fonction "Tracking Prevention" qui bloque l'accès aux ressources de domaines tiers connus comme CDN — y compris unpkg.com et cdn.jsdelivr.net. Ces CDN sont marqués comme "potential trackers" même quand on charge juste du JS/CSS open source.

Résultat : Leaflet ne se chargeait pas → window.L restait undefined → la carte ne s'initialisait jamais. Les icônes Tabler ne se chargeaient pas non plus → certains pictos invisibles.

Fix structurel — Tout bundler avec Next

Solution standard : héberger les libs dans le bundle Next via npm plutôt que de dépendre de CDN externes.

1. Leaflet (~150 KB)

// app/carte/page.js — Avant (CDN)
const cssLink = document.createElement("link");
cssLink.href = "https://unpkg.com/leaflet@1.9.4/dist/leaflet.css";  // ❌ bloqué Edge
const script = document.createElement("script");
script.src = "https://unpkg.com/leaflet@1.9.4/dist/leaflet.js";

// Après (dynamic import depuis node_modules)
useEffect(() => {
  (async () => {
    await import("leaflet/dist/leaflet.css");      // ✅ bundlé par Next
    const L = (await import("leaflet")).default;
    // Fix webpack pour les icônes marqueur par défaut
    delete L.Icon.Default.prototype._getIconUrl;
    L.Icon.Default.mergeOptions({...});
    window.L = L;
    setLeafletReady(true);
  })();
}, []);

2. Tabler icons (~280 KB)

// app/layout.js — Avant
<link rel="stylesheet" href="https://cdn.jsdelivr.net/.../tabler-icons.min.css" />  // ❌

// app/globals.css — Après
@import "@tabler/icons-webfont/tabler-icons.css";  // ✅ bundlé

Coût

Le bundle initial gagne en taille (~400 KB de plus en gzip), mais c'est compensé par :

  • Plus aucune dépendance externe au runtime
  • Marche complètement offline (mode PWA renforcé)
  • Pas de risque qu'un CDN tombe
  • Compatible tous navigateurs y compris ceux avec Tracking Prevention
  • Performances réseau souvent meilleures (même origine = moins de DNS lookups + connexions HTTP/2 réutilisées)

Réflexe 19 ajouté

Jamais de CDN tiers en prod pour des libs critiques. Edge/Brave/Firefox strict bloquent unpkg.com, jsdelivr.net, cdnjs.cloudflare.com via Tracking Prevention. Toujours bundler via npm + Next webpack. Fonts Google sont OK (largement whitelistées).

Usage

  • Multi-sélection : sélectionne plusieurs groupes en même temps (chips qui se colorent)
  • Compteur dans le bouton : "Filtres catégories 2"
  • "Tout effacer" pour reset
  • Filtres + recherche texte se combinent : "EHPAD à Bordeaux" = catégorie EHPAD + query "bordeaux"
  • Si seul un filtre est actif (sans query), l'API renvoie quand même les résultats (minimum 3 caractères désactivé)

Filtrage côté API

La route /api/finess accepte maintenant ?categories=ehpad,hopitaux et combine les codes FINESS en filtre categ_code__in. Tout est filtré côté serveur data.gouv.fr — pas de gaspillage de bande passante.

🌍 France + DOM-TOM — Confirmation

Le référentiel t_finess Atlasanté couvre toute la France métropolitaine et tous les DOM-TOM (Guadeloupe 971, Martinique 972, Guyane 973, Réunion 974, Mayotte 976, etc.). Aucun filtrage géographique n'est appliqué côté serveur Aveho — les résultats remontent partout.

Un libellé "France + DOM-TOM" avec icône ti-map-2 est ajouté à droite de la barre de filtres pour le rendre explicite à l'utilisateur.

Pour rechercher spécifiquement dans un DOM, l'utilisateur tape simplement le nom de la ville/territoire dans la query (ex : "Saint-Denis Réunion" ou "Fort-de-France").
