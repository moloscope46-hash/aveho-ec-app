3. Branchement Resend

3.1 Architecture

La 0.23 avait livré l'email HTML brandé Aveho mais avec un console.log à la place de l'envoi réel. La 0.24 remplace ça par un appel HTTP à l'API Resend :

POST https://api.resend.com/emails
Authorization: Bearer {RESEND_API_KEY}

{
  "from": "Aveho RGPD ",
  "to": ["dpo@etablissement.fr"],
  "subject": "[Aveho RGPD] 3 consentements à renouveler",
  "html": "...",
  "tags": [
    { "name": "type", "value": "consent_renouvellement" },
    { "name": "structure_id", "value": "..." }
  ]
}

3.2 Configuration requise

2 secrets Supabase à configurer :

# 1. Créer un compte Resend (gratuit jusqu'à 100 emails/jour)
# 2. Vérifier le domaine d'envoi (DNS DKIM/SPF)
# 3. Créer une clé API
# 4. Dans Supabase Dashboard → Project Settings → Edge Functions → Secrets
supabase secrets set RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
supabase secrets set RESEND_FROM_EMAIL="Aveho RGPD "

3.3 Mode dégradé

Si RESEND_API_KEY n'est pas configuré, la fonction ne plante pas. Elle log un warning et ajoute à errors[] du résultat. Les push et webhooks continuent de fonctionner normalement. Ça permet de déployer la 0.24 sans Resend dans un premier temps et de le brancher quand le compte est prêt.

3.4 Tags Resend

Chaque email est tagué avec type=consent_renouvellement et structure_id=.... Ça permet sur le dashboard Resend de filtrer/analyser les envois par type et par client. Utile pour debug et facturation.

4. Auto-archivage 6 mois

4.1 Pourquoi

Sans auto-archivage, les consentements expirés s'accumulent dans la liste "actifs" et polluent la vue. Au bout de quelques années, un EHPAD peut avoir des centaines de consentements expirés qui restent "actifs" alors qu'ils ne valent plus rien juridiquement. L'auto-archivage les déplace automatiquement dans "Archivés" sans perdre l'historique.

4.2 Fonctionnement

  1. Le 1er du mois à 4h UTC, pg_cron appelle auto-archive-consents
  2. La fonction lit v_consents_a_auto_archiver qui liste les consentements signés non archivés expirés depuis > seuil_jours
  3. Elle appelle la RPC auto_archive_consents_expires() qui :
    • Met archive = true sur tous ces consentements
    • Ajoute une note "Auto-archivé le DD/MM/YYYY (expiré depuis plus de N jours)"
    • Retourne un agrégat par structure pour les notifications
  4. Envoie une notif push aux structures concernées : "X consentements auto-archivés"

4.3 Configuration du seuil

Stocké dans structures.parametres.auto_archive_apres_jours. Par défaut 180 (6 mois). Configurable par collectivité — TODO UI : pour l'instant, modification manuelle en SQL :

update structures
set parametres = jsonb_set(parametres, '{auto_archive_apres_jours}', '365'::jsonb)
where id = 'xxx';

(L'UI dans /parametres sera ajoutée en 0.25+ si besoin — pour l'instant le défaut 6 mois convient à tous les usages PSAD courants.)

4.4 Réversibilité

L'auto-archivage est réversible. Depuis /consentements avec le filtre "Archivés", clic sur l'icône ti-archive-off pour désarchiver. La note "Auto-archivé le ..." reste pour traçabilité.

5. Export CSV audit annuel

5.1 Workflow utilisateur

  1. Admin va dans /consent-verifications
  2. Clic sur le bouton vert "Export CSV" en haut à droite
  3. Téléchargement immédiat d'un fichier CSV nommé audit-verifications-rgpd-{collectivite}-{YYYY-MM-DD}.csv
  4. Le fichier s'ouvre directement dans Excel français (séparateur ;, BOM UTF-8)

5.2 Format du CSV

ColonneExemple
Date vérification2026-05-30 14:23:11
RésultatValide / Invalide
PatientMarie Dupont
Consent. signé le2026-05-30
Consent. expire le2029-05-30
Statut consent.signe
Consent. archivéNon
Origine IP82.65.123.45
NavigateurChrome
SystèmeWindows
Hash fournia1b2c3...
Hash attendua1b2c3...

5.3 Caractéristiques techniques

  • Pas de limite 500 lignes contrairement à l'affichage tableau (export complet)
  • BOM UTF-8 (\uFEFF en tête) → Excel ouvre directement en UTF-8 sans demander
  • Séparateur ; → Excel FR détecte automatiquement
  • Échappement RFC 4180 : valeurs avec ;, guillemets ou retours ligne sont entourées de "..." et les guillemets internes sont doublés
  • Filtré par structure automatiquement (RLS au niveau de la vue)
  • Vue SQL plate v_audit_verifications_export avec formatage des dates ISO et colonnes "Oui"/"Non" plutôt que booleans

6. Patch SQL 0.24.0

Le script aveho-PATCH-vers-0.24.sql (156 lignes) effectue :

  1. Backfill auto_archive_apres_jours = 180 dans structures.parametres
  2. Fonction RPC auto_archive_consents_expires() SECURITY DEFINER + GRANT authenticated. CTE pour structures_config + a_archiver + archive_result, retourne un agrégat (structure_id, collectivite_nom, count, exemple_consent_ids)
  3. Vue v_consents_a_auto_archiver pour preview de ce qui sera archivé
  4. Vue v_audit_verifications_export plate avec dates formatées et booléens en Oui/Non

Idempotent (create or replace, not exists). Rejouable sans risque.

10. Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.24.sql → Run.
  2. Vérifier : 
    -- Backfill seuil archivage ?
select id, nom, parametres->>'auto_archive_apres_jours' as seuil
from structures;
-- Toutes les structures doivent avoir seuil = 180
  3. Déployer la nouvelle Edge Function : 
    cd C:\aveho-ec-app-01
supabase functions deploy auto-archive-consents
  4. Redéployer send-renouvellement-rappels (modifiée pour Resend) : 
    supabase functions deploy send-renouvellement-rappels
  5. Programmer le cron mensuel dans Supabase SQL Editor (voir section 7.2)
  6. (Optionnel) Configurer Resend pour les emails DPO (voir section 7.4)
  7. Décompresser le zip par-dessus C:\aveho-ec-app-01\
  8. npm install + tests + dev : 
    npm install
npm test       # 139 passed
npm run dev
  9. Tester :
    • Aller dans /consent-verifications → bouton "Export CSV" en haut à droite
    • Cliquer → fichier CSV téléchargé, ouvrir dans Excel → toutes colonnes lisibles
    • Forcer une expiration ancienne en SQL puis appel manuel du cron → vérifier que le consentement est passé en "archivé"
  10. Pousser sur Vercel via git.
