🐛 Fix 1 — ReferenceError 'kind is not defined'

Symptôme

Uncaught ReferenceError: kind is not defined
    at onClick (page-53a1c3b2bd23e903.js:1:72869)

Au clic sur le titre d'une version ou une évolution dans le changelog, l'app plantait.

Cause

Dans la 0.55.16, j'ai introduit openNote(v, kind, color, ...) mais utilisé kind au lieu de v.kind dans le onClick. La variable color était bien déclarée localement dans la map, mais kind non.

Fix

// Avant (bug)
onClick={() => v.noteFile && openNote(v, kind, color, v.titre || "")}

// Après (fix)
onClick={() => v.noteFile && openNote(v, v.kind, color, v.titre || "")}

Même fix appliqué sur le onClick des <li> d'évolutions.

🐛 Fix 2 — SQL view error 42P16

Symptôme

ERROR: 42P16: cannot change name of view column "created_at" to "auth_method"
HINT: Use ALTER VIEW ... RENAME COLUMN ... to change name of view column instead.

Lors de l'exécution du patch 0.55.17, la mise à jour de v_my_webauthn_credentials échouait.

Cause

Postgres refuse de faire CREATE OR REPLACE VIEW si la nouvelle définition change l'ordre ou les noms des colonnes existantes. La vue 0.55.13 avait l'ordre id, user_id, ..., created_at, ..., et on essayait d'insérer auth_method entre user_agent et created_at.

Fix

-- DROP nécessaire car CREATE OR REPLACE refuse de réordonner les colonnes
drop view if exists v_my_webauthn_credentials;

create view v_my_webauthn_credentials as
select
  wc.id,
  wc.user_id,
  wc.credential_id,
  wc.device_name,
  wc.user_agent,
  wc.auth_method,  -- nouvelle position
  wc.created_at,
  wc.last_used_at,
  wc.active,
  count(*) over (partition by wc.user_id) as total_devices
from webauthn_credentials wc
...

🧪 Fix 3 — Bouton 'Tester' sur chaque carte de version

Demande utilisateur : pouvoir lancer les tests depuis le changelog par version. C'est différent des tests Vitest qui tournent côté Node (en CI). Ici on a un système de smoke tests in-browser qui vérifient que les features livrées dans une version fonctionnent bien dans ce navigateur, cette session.

Architecture

  • Fichier app/changelog/smoke-tests.js qui exporte VERSION_TESTS : un objet { version: async () => results[] }
  • Chaque test renvoie { name, ok, msg, error? }
  • Bouton vert "Tester" à côté du bouton SQL sur chaque carte de version qui a des smoke tests
  • Modale qui affiche les résultats avec compteur OK/échec, liste avec icônes check/x, bouton Relancer
