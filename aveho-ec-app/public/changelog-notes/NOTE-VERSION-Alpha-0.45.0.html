Résumé

5 chantiers sans nouvelle table ni vue SQL — uniquement du front + Edge Functions. Pas de patch SQL, donc pas de risque de hotfix sur noms de tables comme les 4 dernières versions. Build clean, 759 tests verts.

5 modules livrés (zéro SQL) :
B Helper notifierAuteurSignalement appelé à chaque première réponse sur un signalement nominatif : crée la notif in-app, envoie l'email via send-email, marque reponse_notifie=true.
K 3 nouvelles subscriptions Realtime dans /accueil : maintenances, transferts, commandes — chacune avec son toast distinct.
L Nouvelle Edge Function weekly-stats-digest qui envoie tous les lundis matin un récap hebdomadaire aux admins de chaque structure (skip si aucune activité).

N Nouveau dossier app/modals/ avec ConfirmModal + AlertModal + hooks useConfirm() et useAlert() — remplacent les confirm() et alert() natifs (a11y + cohérence visuelle).

Chantiers livrés

B Notif email auteur signalement

  • Helper côté JS notifierAuteurSignalement(supabase, signalementId, authorUserId, titre, reponse) en fin de app/signalements/page.js
  • Déclenché uniquement à la première réponse d'un signalement nominatif (created_by non NULL — opt-in patient depuis 0.32)
  • 4 actions séquentielles :
    1. Récupère l'email via la vue v_users_emails (try/catch silencieux si non accessible)
    2. Crée une notification in-app dans notifications (TOUJOURS, indépendamment de l'email — la NotifBell en 0.43 la fera apparaître via Realtime)
    3. Met signalements.reponse_notifie = true pour empêcher les doublons
    4. Appelle l'Edge Function send-email avec un HTML brandé incluant la réponse en blockquote
  • Best-effort : si une étape plante (RPC indisponible, email service down…), l'erreur est loggée en console mais le save du signalement n'est pas bloqué
  • Compatible avec le trigger SQL de la 0.41 qui remet automatiquement reponse_notifie à false si la réponse est modifiée → on peut renotifier sur modification de réponse

K Realtime étendu — maintenances, transferts, commandes

  • Réutilise le hook useRealtimeTable créé en 0.44
  • 3 nouvelles subscriptions dans app/accueil/page.js :
    • maintenances INSERT → toast teal foncé (#5a8f8f) "Maintenance planifiée le DD/MM/YYYY"
    • transferts INSERT → toast bleu (#185FA5) avec icône truck-delivery
    • commandes INSERT → toast teal foncé avec icône shopping-cart
  • Total Realtime actif sur l'accueil : 6 tables (DI, signalements, achats, maintenances, transferts, commandes) + notifications dans la NotifBell = 7 channels parallèles, chacun filtré par structure_id
  • Couleurs distinctes par catégorie d'événement pour distinguer en un coup d'œil le type de notification reçu

L Cron weekly-stats-digest

  • Nouvelle Edge Function supabase/functions/weekly-stats-digest/index.ts
  • Logique :
    1. Pour chaque structure, identifier les admins (rôle "Administrateur" via membres_structure)
    2. Calculer 4 KPIs sur les 7 derniers jours : nb DI (dont urgentes), nb signalements, nb achats (dont brouillons), nb maintenances en retard
    3. Si aucune activité (les 4 KPIs à 0) → skip l'envoi (anti-spam)
    4. Sinon, envoyer un email HTML brandé à chaque admin via send-email
  • Email HTML : gradient navy→bleu en header, 4 cards KPI avec border-left coloré (rouge si maintenances en retard, sinon bleu)
  • Lien direct vers /accueil pour explorer en détails
  • Programmation pg_cron à ajouter manuellement (cf section "Procédure")
  • Cas particulier : utilise service_role côté serveur, donc v_users_emails est accessible sans grant supplémentaire

N Refactor — modales réutilisables

  • Nouveau dossier app/modals/ avec index.js
  • 4 nouveaux exports :
    • <ConfirmModal> — composant remplaçant confirm() natif
      • Header couleur selon variant (rouge pour danger, bleu sinon)
      • Boutons Confirmer / Annuler personnalisables (labels et variants)
    • useConfirm() — hook programmatique : 
      const { confirm, ConfirmModalElement } = useConfirm();
if (await confirm({ title: "Sûr ?", variant: "danger" })) doDelete();
return <>{ConfirmModalElement}<button onClick={...}>Supprimer</button></>
    • <AlertModal> — équivalent accessible de alert() avec 3 variants (primary/success/danger)
    • useAlert() — hook équivalent à useConfirm mais pour les alertes
  • Pas encore migré dans les pages : c'est juste l'infrastructure. Dans les prochaines versions, on remplacera progressivement les confirm() et alert() natifs par ces nouveaux composants
  • Bénéfices :
    • A11y : focus trap, ESC pour fermer, role=dialog (héritage du composant Modal)
    • Cohérence : même apparence brandée que les autres modales du produit
    • Personnalisation : icônes, couleurs, labels — impossible avec les natifs
    • Synchrone-like via Promise : const ok = await confirm({...})

Procédure d'application

  1. Aucun SQL à exécuter 🎉 — tu peux passer directement à l'étape suivante.
  2. Activer Realtime sur les 3 nouvelles tables (Supabase Dashboard → Database → Replication) :
    • public.maintenances
    • public.transferts
    • public.commandes
  3. Déployer la nouvelle Edge Function : 
    supabase functions deploy weekly-stats-digest
  4. Programmer le cron weekly-stats-digest dans Supabase SQL Editor (une seule fois) : 
    select cron.schedule(
  'weekly-stats-digest',
  '0 7 * * 1',   -- tous les lundis à 7h UTC
  $$ select net.http_post(
       url := 'https://VOTRE_PROJET.supabase.co/functions/v1/weekly-stats-digest',
       headers := jsonb_build_object(
         'Authorization', 'Bearer VOTRE_SERVICE_ROLE_KEY'
       )
     ); $$
);
  5. Décompresser le zip par-dessus C:\aveho-ec-app\.
  6. Nettoyer le cache + npm install + tests + dev : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test       # 759 passed
npm run dev
  7. Tester :
    • B : sur /signalements, créer un signalement avec "Tracer mon nom" coché → en compte admin, répondre → l'auteur reçoit un email + une notif in-app
    • K : ouvrir /accueil dans un onglet, créer une maintenance/transfert/commande dans un autre → toast en bas à droite avec la couleur appropriée
    • L : tester manuellement le cron : 
      curl -X POST https://<projet>.supabase.co/functions/v1/weekly-stats-digest \
  -H "Authorization: Bearer <service_role_key>"
# → JSON avec emailsEnvoyes: N
      Les admins doivent recevoir l'email récap.
    • J : sur /tags-materiel, naviguer au clavier (Tab) jusqu'à un bouton de suppression → outline cyan visible, lecteur d'écran annonce "Supprimer"
    • N : pas testable directement (infrastructure, pas encore migré dans les pages)
