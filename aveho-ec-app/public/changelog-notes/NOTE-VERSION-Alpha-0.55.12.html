🎯 Contexte — Pourquoi cette refonte

Le système d'invitation précédent reposait sur admin.auth.admin.inviteUserByEmail() qui créait un auth.users directement, puis renvoyait l'utilisateur sur Supabase pour qu'il définisse son mot de passe via un magic link. Limitation : pas de page custom, pas de pré-remplissage des infos, pas de policy stricte sur le mot de passe.

Cette refonte introduit un token d'invitation maison dans la table invitations existante, et une page publique /inscription/[token] où l'utilisateur :

  • Voit ses infos pré-remplies (email, rôle, structure)
  • Complète son nom, prénom, téléphone, mobile, fonction
  • Choisit son mot de passe avec une jauge de force live et une policy stricte (12+ caractères, complexité, blacklist commune)
  • Reçoit un email de bienvenue chaleureux après finalisation
  • Est connecté automatiquement et redirigé vers /accueil

Vue v_users_complete

Combine auth.users + membres_structure + roles en une vue unique pour faciliter la page admin (au lieu de faire 3 JOINs côté client) :

create or replace view v_users_complete as
select ms.user_id, ms.structure_id, ms.role_id, r.nom as role_nom,
       ms.nom_affiche, ms.nom, ms.prenom, ms.telephone, ms.mobile,
       ms.poste, ms.fonction_detail, ms.photo_url, ms.notes,
       ms.date_arrivee, ms.actif, ms.archive, ms.restreint_services,
       ms.preferences,
       u.email, u.last_sign_in_at, u.created_at as user_created_at,
       u.email_confirmed_at,
       (u.email_confirmed_at is not null) as email_verifie
from membres_structure ms
left join auth.users u on u.id = ms.user_id
left join roles r on r.id = ms.role_id;

🔐 Chantier Sécurité — Policy mot de passe stricte

Nouveau fichier lib/passwordPolicy.js

Validateur JavaScript symétrique à la RPC SQL validate_password_policy. Règles :

  • Longueur min 12 caractères (bonus si 16+)
  • Au moins 1 majuscule, 1 minuscule, 1 chiffre, 1 caractère spécial
  • Pas dans la blacklist : password, azerty, motdepasse, 123456, qwerty, admin, aveho, soleil…
  • Pas seulement un mot répété (ex: "azertyazerty")

Renvoie un score 0-5 avec label : Très faible / Faible / Moyen / Fort / Excellent.

Helper generateSecurePassword(16) qui génère un mot de passe aléatoire conforme (sans confusion l/I/1/0/O).

Nouveau composant app/PasswordInput.js

Input mot de passe réutilisable partout dans l'app avec :

  • Toggle œil pour afficher/masquer
  • Jauge de force en 5 segments colorés (rouge → vert)
  • Liste des règles non respectées en chips ambre dynamiques
  • Bouton "Générer un mot de passe sûr" (icône dé)
  • Indicateur ✓ Conforme quand toutes les règles passent

Pages équipées

  • /inscription/[token] : choix du mot de passe initial
  • /profil : changement de mot de passe (était min 6 char, maintenant policy stricte)

📧 Chantier Edge functions

invite-user — réécrit

Avant : utilisait admin.auth.admin.inviteUserByEmail() qui créait un user incomplet dans auth.users.

Après : ne touche plus à auth.users. Reçoit simplement l'inviteLink custom depuis l'app et l'envoie par email via Resend. Le user n'est créé dans auth.users qu'au moment où il valide son inscription via /inscription/[token].

Avantages : pas de comptes orphelins en cas d'invitation jamais utilisée, contrôle total sur la UX d'activation, pas de magic link Supabase à styliser.

Soumission

1. Validation côté client (PasswordPolicy + match confirmation)
2. supabase.auth.signUp(email, password)

3. supabase.rpc("accept_invitation", { token, user_id, nom, prenom, ... })

4. supabase.functions.invoke("welcome-user")
   → mail de bienvenue (non bloquant)
5. router.push("/accueil")

🐛 Bonus fix — Carte par-dessus menu drawer

Symptôme : sur /carte, quand on ouvrait le menu latéral via le burger de la TopBar, les contrôles Leaflet (boutons +/-, marqueurs) passaient au-dessus du menu drawer. Très gênant en utilisation mobile.

Cause : Leaflet utilise des z-index élevés par défaut (1000 pour les contrôles), supérieurs au menu drawer (z-index: 49).

Fix : créer un stacking context contraint sur le container Leaflet avec z-index: 0 + isolation: isolate. Tous les éléments Leaflet sont alors plafonnés à l'intérieur de ce contexte et ne peuvent plus dépasser le menu (z-index 49).

.carte-leaflet-container,
.leaflet-container {
  z-index: 0 !important;
  isolation: isolate;
}
.leaflet-control { z-index: 10 !important; }
