1. Résumé exécutif

L'Alpha 0.4 connecte enfin les pièces posées dans les versions précédentes : les notifications de la 0.3 se créent maintenant automatiquement à chaque transfert, DI urgente, invitation. Les libellés métier saisis dans Paramètres se répercutent dans l'UI ("Patient" devient "Résident" pour un EHPAD). Et une nouvelle page Historique d'actions permet de consulter qui a fait quoi, quand — un audit log immutable basé sur une nouvelle table SQL.

Priorisation transparente : 5 chantiers livrés sur 8 de la roadmap 0.4. Les 3 reportés en Alpha 0.5 (RLS étanche, mode hors-ligne, domaine email) le sont pour les mêmes raisons qu'en 0.2 et 0.3 : ce sont des chantiers spécialisés qui méritent d'être traités isolément. La sécurité RLS notamment ne doit jamais être bâclée.

3. Notifications automatiques NOUVEAU

En 0.3, la table notifications existait mais n'était peuplée que par les inserts de démo. En 0.4, l'app crée des notifications automatiquement à chaque action significative :

Action déclencheurType de notifVisible par
Création d'un transferttransfertTous les membres de la collectivité
Transfert passé à "Validé"transfertTous les membres
Transfert passé à "Reçu"transfertTous les membres
Création d'une DI urgentediTous les membres (urgence "Urgent" uniquement)
Envoi d'une invitationinvitationTous les membres

La cloche de la TopBar (introduite en 0.3) affiche le badge animé dès qu'une nouvelle notif apparaît, avec polling toutes les 60s.

4. Audit log + page Historique NOUVEAU

4.1 Nouvelle table SQL audit_log

Table immutable (pas de UPDATE ni DELETE possible côté RLS) qui trace toute opération significative :

create table audit_log (
  id uuid primary key,
  structure_id uuid,
  etablissement_id uuid,
  user_id uuid, user_email text,    -- snapshot email même si user supprimé
  action text,         -- 'creer','modifier','supprimer','valider','recevoir','inviter'
  entite text,         -- 'patient','materiel','transfert','di','invitation',...
  entite_id uuid,
  details jsonb,       -- payload libre (numéro, ancien/nouveau statut, ...)
  created_at timestamptz
);

4.2 Page /historique

Accessible depuis menu Administration → Historique. Affiche les 200 dernières actions de la collectivité, avec :

  • 4 KPIs : total tracé, 7 derniers jours, utilisateurs actifs (7j), suppressions
  • Filtre par action (création, modification, suppression…)
  • Filtre par entité (patient, matériel, transfert…)
  • Tableau chronologique avec date, utilisateur, action colorée, entité (badge typé), détails JSON

5. Libellés métier appliqués NOUVEAU

En 0.3, la page Paramètres permettait de saisir des libellés personnalisés ("Résident" au lieu de "Patient") mais ils étaient juste stockés. En 0.4, ils sont effectivement appliqués via le hook useLibelles.

5.1 Le hook

import { useLibelles } from "../../lib/useLibelles";

const { lbl } = useLibelles(auth.structureId);

// Au lieu d'écrire "Patient" en dur :
<h1>{lbl("patient", "Patient")}</h1>
// -> affiche "Résident" si l'EHPAD a configuré le libellé, sinon "Patient"

// Le hook gère pluriel et majuscules automatiquement
lbl("patients", "Patients")  // -> "Résidents"
lbl("PATIENT")               // -> "RÉSIDENT"

5.2 Couverture en 0.4

La page Patients est entièrement adaptée (titre, KPI, bouton "Nouveau", modales, message de suppression). Les autres pages (Mon établissement, Interventions…) seront adaptées en 0.5 si tu confirmes que cette approche te convient.

6. Export PDF NOUVEAU

Un bouton Export PDF apparaît à côté du bouton CSV (déjà introduit en 0.3) sur toutes les listes Crud.

Choix technique : impression navigateur plutôt qu'une lib PDF

J'ai choisi de m'appuyer sur la fonction Imprimer → Enregistrer en PDF du navigateur plutôt que d'embarquer une lib (jsPDF ~150 Ko, pdfmake ~400 Ko). Avantages :

  • Bundle léger (aucun ajout)
  • Mise en page A4 propre via CSS @page
  • L'utilisateur garde le contrôle (peut choisir d'imprimer papier ou de sauver en PDF)

Inconvénient assumé : nécessite une popup, donc on demande à l'utilisateur d'autoriser les popups au premier export.

Format produit

  • En-tête Aveho avec eyebrow "AVEHO — ESPACE COLLECTIVITÉ" en teal + ligne de séparation
  • Titre du document + sous-titre (date d'export)
  • Tableau Aveho-stylé (en-têtes navy, lignes alternées)
  • Pied de page avec date de génération et nombre de lignes

8. Helper events.js — centralisation

Plutôt que dupliquer les inserts d'audit + notifs dans 10 pages, j'ai créé un helper centralisé lib/events.js :

import { logEvent } from "../../lib/events";

await logEvent(supabase, auth, {
  action: "creer",              // creer, modifier, supprimer, valider, recevoir, inviter
  entite: "transfert",          // patient, materiel, transfert, di, ...
  entite_id: nouveauTransfert.id,
  details: { numero: "TRF-1042", motif: "Réappro" },
  // Si notif=true, crée aussi une notification visible dans la cloche
  notif: true,
  titre: "Nouveau transfert à valider",
  message: "Transfert TRF-1042 créé : 30 boîtes de gants...",
  lien: "/transferts",
});

Ce helper fait deux choses en une :

  1. Insère dans audit_log (toujours)
  2. Insère dans notifications (si notif: true)

Avantages : un seul point de modification si on veut changer le comportement (ex: webhook Slack en plus), garantie que les deux inserts vont toujours ensemble, code des pages métier reste simple.

11. Procédure de mise à jour depuis Alpha 0.3

1 script SQL à exécuter (l'audit log) :

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans Supabase SQL Editor : exécute supabase/10_audit.sql
  4. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  5. Tests à faire :
    • Créer un transfert → la cloche doit clignoter avec une notif
    • Aller dans Administration → Historique → tu dois voir l'action loggée
    • Va dans Paramètres, mets "Résident" dans "Terme pour Patient" → enregistre, ouvre la page Patients → le titre doit dire "Résidents"
    • Sur une liste, clique Export PDF → une fenêtre s'ouvre avec mise en page A4, puis la boîte d'impression du navigateur
  6. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.4"
git push

13. Roadmap Alpha 0.5

  1. RLS étanche par établissement — priorité absolue, en chantier dédié
  2. Application des libellés métier sur les autres pages (Mon établissement, Interventions, Vue globale, etc.)
  3. Notifications ciblées (envoi à un utilisateur précis plutôt qu'à tous, ex: "tu as été assigné à cette DI")
  4. Logs de connexion dans audit_log (qui s'est connecté, quand)
  5. Mode hors-ligne PWA
  6. Domaine email pro (dès que tu en as un)
  7. Filtres temporels sur l'historique (sélecteur de période, recherche par date)
  8. Page de profil utilisateur (modifier son nom, changer son mot de passe, préférences personnelles)
