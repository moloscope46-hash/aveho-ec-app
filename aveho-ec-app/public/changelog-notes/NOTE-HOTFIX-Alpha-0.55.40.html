Hotfix 0.55.40 — Fix erreur SQL 42P17 'functions in index expression must be marked IMMUTABLE' date_trunc() retiré de l'index · les 2 autres index suffisent pour les performances

Date : 31 mai 2026 Version : v0.55.40-alpha Tests : 1319 verts (+6)

❌ Le bug

ERROR: 42P17: functions in index expression must be marked IMMUTABLE

Lors de l'exécution du patch 0.55.39, PostgreSQL a refusé l'index :

create index idx_api_usage_month
  on api_usage_log(api_name, date_trunc('month', created_at));

Pourquoi ?

PostgreSQL exige que les fonctions utilisées dans une expression d'index soient marquées IMMUTABLE (toujours le même résultat pour les mêmes inputs).

date_trunc() appliqué à un timestamptz n'est pas IMMUTABLE car le résultat dépend du fuseau horaire de la session (qui peut changer). C'est marqué STABLE seulement.

✅ La correction

L'index idx_api_usage_month est supprimé. Il était redondant : les 2 autres index suffisent largement.

Pourquoi les perfs restent identiques

La requête principale de la vue v_api_usage_current_month est :

SELECT api_name, COUNT(*) ...
FROM api_usage_log
WHERE created_at >= date_trunc('month', now())
GROUP BY api_name;

L'index existant idx_api_usage_api(api_name, created_at desc) est utilisé par PostgreSQL en index range scan : il scanne uniquement les rows avec created_at >= début_mois, ce qui est très rapide. Pas besoin d'index spécifique sur la fonction.

Patch 0.55.40 100% idempotent

  1. drop index if exists idx_api_usage_month (silencieux si pas créé)
  2. Recrée tout le reste du patch 0.55.39 avec IF NOT EXISTS partout
  3. Tu peux le rejouer même si 0.55.39 a partiellement échoué
