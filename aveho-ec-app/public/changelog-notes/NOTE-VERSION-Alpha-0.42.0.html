Chantiers livrés

I Templates RGPD par établissement

  • Colonne SQL consent_templates.etablissement_id (nullable) avec FK + index
  • Vue SQL refondue v_consent_template_actif :
    • Avant : 1 ligne par structure_id (1 template global par structure)
    • Après : 1 ligne par (structure_id, etablissement_id) avec résolution de priorité via row_number() over (partition by ... order by priorite)
    • Priorité 1 : template etab-spécifique actif
    • Priorité 2 : template structure (etab NULL) actif — fallback automatique
    • Ligne supplémentaire avec etablissement_id NULL pour les patients sans établissement
  • JS loadActiveTemplate accepte un 2e paramètre etablissementId. Si fourni → filtre .eq("etablissement_id", id), sinon → .is("etablissement_id", null)
  • ConsentementRGPD passe automatiquement patient.etablissement_id au load
  • UI /parametres-rgpd : nouveau sélecteur "Portée du template" (Global / [liste etabs]). Désactivé en édition d'un template existant pour préserver les signatures existantes

J Digest — historique des envois

  • Composant <DigestHistory> : lit notification_digest_log (créée en 0.40) limité aux 10 derniers du user
  • Intégré dans /profil juste après <DigestPreferences>
  • Colonnes : Date, Type (pill violet pour hebdo, orange pour quotidien), Contenu résumé (compteurs par catégorie), Statut (envoyé/erreur avec tooltip)
  • État vide : message engageant qui invite à activer un mode ou utiliser le bouton test (chantier J de la 0.41)

K Page /audit dédiée

  • Nouvelle route /audit réservée aux administrateurs
  • 5 filtres avancés : période (7/30/90/all), utilisateur, action, entité, recherche libre (sur email + entite_id)
  • Pagination serveur 50 lignes par page (range Supabase + count exact)
  • Tableau : Date, Action (pill colorée), Entité, ID tronqué, Utilisateur, Détails tronqués
  • Drill : clic sur une ligne → modale avec détail complet + JSON formatté dans un <pre> dark
  • Export CSV : réutilise la mécanique de la 0.39 (BOM UTF-8 + CRLF + séparateur ;) limité à 5000 lignes
  • Pills d'action colorées : creer/valider en vert, supprimer/refuser en rouge, modifier en bleu, recevoir en violet, etc.

L Timeline DI sur fiche patient

  • Le tableau simple des DI dans /patient/[id] devient une timeline verticale
  • Dots colorés à gauche selon le statut (utilise COULEUR_DI existante avec halo blanc)
  • Cards : numéro DI, date, badge "Urgent" si applicable, statut pill, type + matériel avec parc
  • Filtre par matériel : si plus d'1 type de matériel dans les DI du patient, sélecteur apparaît (libellés uniques triés)
  • Select Supabase enrichi : materiels(id,libelle,num_serie,num_parc) pour avoir les détails dans la timeline
  • Hover : bordure bleue + cursor pointer → clic ouvre la page interventions

M Mode présentation TV de service

  • Nouvelle route /presentation/interventions — accessible direct par URL pour un écran fixe
  • Pas de TopBar ni navigation, pleine page, fond gradient navy → teal
  • Header : titre AVEHO TV + horloge live HH:MM (refresh 1s) + date longue + indicateur dernière maj
  • Auto-refresh configurable via ?refresh=30 (défaut 60s, minimum 10s)
  • Filtre établissement via ?etab=<uuid> pour dédier un écran à un site
  • Tri intelligent : urgents d'abord (section dédiée avec animation pulse rouge), puis autres par date desc
  • Cards XL : numéro DI (20px), patient + chambre, matériel, type, date — police 14-20px pour lisibilité à distance
  • État vide : grosse icône check verte + "Aucune DI en cours · Tout est traité 👍"
  • Bouton "Plein écran" discret en bas à droite (Fullscreen API navigateur)
  • Limite 30 entrées pour rester lisible sur écran
  • Suspense boundary autour de useSearchParams (requis Next 14 pour le prerender)
