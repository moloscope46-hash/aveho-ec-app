🐛 Le bug

Tu as lancé npm test après le déploiement 0.57.20 et 1 test fail sous Windows :

AssertionError: v_users_emails ne doit être utilisé qu'à 1 endroit (signalements):
  expected 2 to be 1

Cause

Mon test 0.57.20 parcourait app/ et excluait app/changelog/versions-data.js via :

if (full.includes("changelog/versions-data")) continue;

Mais sous Windows, fs.readdirSync + path.join() retournent un path avec \ :

OSfull.includes("changelog/versions-data")
Linux/macOSapp/changelog/versions-data.js✅ true → fichier exclu
Windowsapp\changelog\versions-data.js❌ false → fichier compté

Résultat : sous Linux v_users_emails est compté 1 fois (signalements seulement), sous Windows il est compté 2 fois (signalements + versions-data.js qui le documente). Test fail.

✅ Fix : normaliser AVANT .includes()

// 0.57.21
for (const item of fs.readdirSync(dir, { withFileTypes: true })) {
  const full = path.join(dir, item.name);
  const fullNorm = full.replace(/\\/g, "/");   // ← AJOUT : normalise d'abord
  if (item.isDirectory()) { ... }
  else if (item.name.endsWith(".js")) {
    if (fullNorm.includes("changelog/versions-data")) continue;  // ✓ Linux ET Windows
    if (fullNorm.includes("changelog/lib")) continue;            // ✓ Linux ET Windows
    if (src.includes("v_users_emails")) count++;
  }
}

🛡️ Audit anti-régression : ce bug ne reviendra plus jamais

C'est la 3ème occurrence du même bug Windows path dans le marathon. Pour qu'il ne revienne jamais, j'ai ajouté un test qui parcourt TOUS les fichiers __tests__/*.js et détecte le pattern dangereux :

it("Aucun test ne fait .includes() sur un path raw issu de path.join()", () => {
  const violations = [];
  for (const file of listTestFiles()) {
    const src = fs.readFileSync(file, "utf-8");
    if (!src.includes("readdirSync")) continue;

    // Pattern dangereux : variable.includes("...") avec / dans la string
    const danger = /\b(full|fpath|filePath|fullPath)\.includes\(["'][^"']*\/[^"']*["']\)/g;
    const matches = src.match(danger) || [];

    for (const m of matches) {
      // Vérifier qu'il y a une normalisation .replace(/\\/g, "/") quelque part
      const hasNormalize = /\.replace\(\/\\\\\/g\s*,\s*["']\/["']\)/.test(src);
      if (!hasNormalize) {
        violations.push({ file: path.basename(file), match: m });
      }
    }
  }
  expect(violations).toEqual([]);  // ← FAIL si bug Windows réintroduit
});

Si un futur dev (ou moi-même) écrit un test qui fait full.includes("/api/...") sans normaliser d'abord, ce test échoue. C'est exactement ce qu'il fallait depuis 0.57.17.

📜 Règle d'or pour les tests qui manipulent des paths

Quand on manipule un path issu de path.join(), path.resolve() ou fs.readdirSync :

  1. TOUJOURS faire .replace(/\\/g, "/") en PREMIER
  2. PUIS utiliser .includes(), .split(), .replace() avec des slashes forward
// ❌ MAUVAIS (cassé sous Windows)
const full = path.join(dir, file);
if (full.includes("/api/")) { ... }
const apiPath = full.replace("/route.js", "");

// ✅ BON
const full = path.join(dir, file);
const fullNorm = full.replace(/\\/g, "/");
if (fullNorm.includes("/api/")) { ... }
const apiPath = fullNorm.replace("/route.js", "");
