PlanningCalendar multi-sources

📅 refacto du useEffect de fetch avec 3 sources en parallèle via Promise.allSettled

  1. interventions (déjà existant)
  2. planning_events (table créée 0.62.128) avec titre + description + type + date_debut/fin + equipe_id + couleur + icone + lieu + tout_journee
  3. tournees avec numero + date_planifiee + chauffeur_user_id + statut. Tous mappés vers le format event commun avec préfixe id (intv-, evt-, tour-) pour éviter collisions. Couleur et icône depuis EVENT_TYPES ou depuis l item planning_events si custom

NotifSounds (lib/notifSounds.js)

🔔 helpers complets pour sons + notifications natives. 5 sons distincts générés via Web Audio API (pas de fichier requis) : info (2 tons aigus), success (3 tons ascendants), warning (2 tons graves descendants), error (2 tons très graves longs), urgent (3 tons aigus alternants). Notification API native : showNativeNotif avec icon /icons/icon-192.png + badge + body + link + auto-close 8s + onclick → focus window + redirect. requestNotifPermission avec gestion granted/denied/default. Préférences localStorage : { sound, native } sauvegardés. notify() combine son + native

NotifBellEnhanced avec son + native

🔔 setUnreadCount enrichi pour détecter les NOUVELLES notifs (count > prev && prev > 0). Si détecté → dynamic import notifSounds et notify() avec titre + body + type info. Résultat : quand une nouvelle notif arrive, l user entend un son et reçoit une notification native du navigateur (même si l app est en background ou minimisée)

NotifCenter avec footer prefs

🔔 nouveau composant NotifPrefsFooter en bas du panel. 3 boutons

  1. Son ON/OFF avec icône volume/volume-off et couleur teal si actif
  2. Native ON/OFF avec icône bell/bell-off et couleur navy si actif + badge ✕ rouge si permission denied
  3. Test pour jouer un son de succès. Synchronisation : toggle persiste en localStorage et déclenche requestNotifPermission si activation native sans permission
