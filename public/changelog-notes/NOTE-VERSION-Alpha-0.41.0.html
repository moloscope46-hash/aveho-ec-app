Résumé

6 chantiers en une version, sélectionnés directement dans la roadmap. Audit préalable : tous les modules existaient (heatmap RGPD, DigestPreferences, Kanban, signalements, maintenance, accueil), on a enrichi. Build clean, 639 tests verts.

6 modules livrés d'un coup :
I Clic sur cellule heatmap signatures → modale avec les patients qui ont signé sur ce créneau (RPC dédiée).
J Bouton "Envoyer un test maintenant" dans /profil qui déclenche la Edge Function send-digest.
K DIPreview ajouté à la vue Kanban (en plus de la liste tableau de la 0.39).
H Signalements : filtre catégorie, tri récents/votes avec sticky state, transition auto Nouveau → En cours quand l'admin répond pour la 1ère fois.
L Maintenances : panneau "Stats par type" (vue SQL) + table SQL récurrences pour futurs rappels automatiques.
A Accueil : nouveau widget "À traiter" qui agrège DI ouvertes / achats à valider / signalements / renouvellements RGPD / maintenances. Affiché en premier par défaut.

Chantiers livrés

I Drill-down heatmap signatures RGPD

  • RPC SQL get_rgpd_heatmap_drill(structure_id, jour_semaine, heure, limit) reproduisant la mécanique de get_heatmap_drill (chantier 0.37 pour l'activité) mais pour consentements_rgpd
  • Retourne id, patient_id, patient_nom_prenom, finalites_acceptees, version_template, created_at, jour_label sur 90j
  • security invoker → respecte les RLS du user
  • UI : la prop onCellClick du composant <Heatmap> est exploitée → ouvre une modale avec :
    • État loading avec spinner
    • État erreur (rouge)
    • État vide (texte gris italique)
    • État data : tableau Date / Patient / Finalités (count) / Version template
  • Hint UX en bas de la heatmap : "Clique sur une cellule colorée pour voir le détail"

J Digest — test depuis /profil

  • Bouton "Envoyer un test maintenant" dans <DigestPreferences>
  • États : idle / busy (spinner) / résultat (vert ou rouge, auto-hide 6s)
  • POST à /functions/v1/send-digest avec body { user_id, force_send: true } + token session
  • Edge Function patchée pour accepter force_send :
    • Si user_id fourni mais pas de pref existante → crée une pref temporaire "quotidien" via lookup users_structures
    • Avec force_send, ne skip pas même si hasContent === false (utile pour tester le format sur un environnement vide)
  • Le bouton fonctionne indépendamment du mode choisi (même si "Jamais") → permet de prévisualiser à tout moment

K DIPreview dans Kanban

  • Le DIPreview de la 0.39 ne fonctionnait que dans la liste tableau /interventions
  • Extension : wrap du numéro DI dans chaque carte Kanban
  • Select Supabase enrichi : materiels(id,libelle,num_serie,num_parc,num_lot), patients(id,nom,prenom,chambre,date_naissance,numero_dossier)
  • Le hover affiche le popover complet (statut, urgence, patient, matériel) sans quitter le drag-drop

H Signalements — workflow avancé

  • Filtre catégorie : select alimenté dynamiquement par les catégories existantes (extraction via Set + tri alpha)
  • Sélecteur de tri : "Plus récents" (défaut) ou "Plus de votes"
    • Tri par votes avec tiebreak sur created_at desc
    • Sticky state (localStorage) sur catégorie et tri
  • Transition auto Nouveau → En cours :
    • Quand l'admin répond pour la 1ère fois (avant : modal.reponse null, après : remplie)
    • Et que le statut était Nouveau et que l'admin n'a pas explicitement choisi un autre statut
    • Logique côté JS (pas trigger SQL) pour rester non-destructif sur l'historique
  • Trigger SQL trg_signal_notif_reponse : marque reponse_notifie = false sur changement de réponse, pour que la future notif au demandeur (opt-in created_by) puisse être déclenchée
  • Bouton "Effacer filtres" étendu à 3 critères

L Maintenances — stats par type + récurrences

  • Vue SQL v_stats_maintenances : group by structure_id + type avec :
    • nb_total, nb_30j, nb_7j
    • nb_cloturees, nb_en_cours
    • duree_moy_jours (avg sur les clôturées : cloturee_le - created_at)
  • UI : panneau "Stats par type" entre KPIs et toolbar, 6 cartes max, format : {type} · {nb_total} en gros · +{nb_7j} en vert · {duree_moy_jours}j moy.
  • Chargement silencieux : si la vue n'existe pas → tableau vide (pas d'erreur visible)
  • Table SQL maintenance_recurrences créée (id, structure_id, materiel_id, type, libelle, frequence_jours, derniere_realisee, prochaine_due, actif) avec RLS et indexes
    • Préparation pour les rappels automatiques (UI à venir en 0.42+)

A Accueil — widget "À traiter"

  • Nouveau widget atraiter dans la liste des widgets configurables (depuis 0.6)
  • Position par défaut : en premier (avant kpis) car c'est l'info la plus actionnable au quotidien
  • 5 compteurs agrégés chargés en parallèle silencieux (try/catch global) :
    1. DI ouvertes (interventions hors Clôturée/Refusée)
    2. Achats à valider
    3. Maintenances à faire ou en retard
    4. Signalements nouveaux
    5. Renouvellements RGPD à 30 jours (vue 0.40)
  • Filtrage zéros : si un compteur est à 0, l'item n'est pas affiché. Si tous à 0, le widget entier est masqué (zen accueil)
  • Clic sur chaque item → navigation vers le module correspondant
  • Personnalisation : intégré au panneau "Personnaliser" existant — l'utilisateur peut décocher ou réordonner
  • Préservation du dashboard fournisseur (promos/commandes) qui existait déjà

Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.41.sql → Run (idempotent).
  2. Vérifier : 
    -- RPC drill
select * from get_rgpd_heatmap_drill(
  'aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa'::uuid, 1, 14, 20);

-- Table récurrences
select count(*) from maintenance_recurrences;

-- Vue stats maintenances
select * from v_stats_maintenances 
where structure_id='aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa';

-- Trigger signalements
select tgname from pg_trigger 
where tgrelid='signalements'::regclass;
  3. Redéployer la Edge Function send-digest (la patch supporte force_send) : 
    supabase functions deploy send-digest
  4. Décompresser le zip par-dessus C:\aveho-ec-app\.
  5. Nettoyer le cache + npm install + tests + dev : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test       # 639 passed
npm run dev
  6. Tester :
    • /accueil → nouveau widget "À traiter" en haut (si des items non-zero existent)
    • /profil → bouton "Envoyer un test maintenant" sous Récap email → ouvre un email test
    • /statistiques-rgpd → cliquer sur une cellule colorée de la heatmap signatures → modale avec liste des patients
    • /interventions/kanban → hover sur un numéro DI dans une carte → preview complet
    • /signalements → filtre catégorie dispo si signalements catégorisés · select tri "Plus récents/Plus de votes"
    • Répondre à un signalement Nouveau → passe automatiquement à "En cours"
    • /maintenance → panneau "Stats par type" entre KPIs et toolbar (si maintenances existent)
