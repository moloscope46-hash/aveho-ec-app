🦊 Pourquoi tester cross-browser ?

Les utilisateurs d'Aveho EC ne sont pas tous sur Chrome. Selon les retours :

  • ~60% Chrome / Edge (Chromium)
  • ~15% Safari sur iPhone (WebKit)
  • ~10% Firefox
  • ~15% autres mobiles (Samsung, Brave...)

Tester uniquement sur Chromium (comme on faisait jusqu'à 0.57.12) laisse les bugs Safari/iOS passer entre les mailles. Or, Safari iOS a des comportements spécifiques (WebAuthn, font-display, ResizeObserver, CSS :has()) qui peuvent casser une app pour 15% des users.

0.57.13 étend Playwright à 5 environnements et lance la suite E2E sur chacun :

  • Chromium Desktop Chrome — référence
  • Firefox Desktop Firefox — vérifie les API standards
  • WebKit Desktop Safari — révèle les bugs iOS/macOS
  • Mobile Chrome Pixel 5 viewport 393×851
  • Mobile Safari iPhone 13 viewport 390×844

🔧 Adaptations cross-browser

1. Test biométrie browser-aware (login.spec.js)

// 0.57.12 — strict 2 boutons
test("affiche les boutons biométrie", async ({ page }) => {
  await page.goto("/login");
  await expect(page.locator("button.btn-primary").filter(...))
    .toHaveCount(2);
});

// 0.57.13 — tolère 0 ou 2 en WebKit (WebAuthn non dispo headless)
test("affiche les boutons biométrie", async ({ page, browserName }) => {
  await page.goto("/login");
  const count = await page.locator("button.btn-primary")
    .filter({ hasText: /Se connecter avec/ }).count();
  if (browserName === "webkit") {
    expect([0, 2]).toContain(count);  // 0 OK en headless Safari
  } else {
    expect(count).toBe(2);  // strict pour Chromium et Firefox
  }
});

2. Retry Firefox NS_BINDING_ABORTED (smoke-all-pages.spec.js)

// Firefox throw parfois NS_BINDING_ABORTED si les navigations s'enchaînent vite
let response;
try {
  response = await page.goto(path);
} catch (e) {
  if (browserName === "firefox" && e.message.includes("NS_BINDING_ABORTED")) {
    await page.waitForTimeout(500);
    response = await page.goto(path);  // Retry
  } else {
    throw e;
  }
}

3. Filtre BROWSERS env var

# Tester uniquement Chromium (rapide, pour le dev)
BROWSERS=chromium npm run test:e2e

# Desktop seulement
BROWSERS=chromium,firefox,webkit npm run test:e2e

# Mobile seulement (Pixel 5 + iPhone 13)
BROWSERS=Mobile npm run test:e2e

# Tous les 5 (par défaut)
npm run test:e2e

🦊 Particularités documentées par browser

WebKit (Safari)

  • 🚫 WebAuthn / biométrie non dispo en headless → les boutons Empreinte/Visage ne s'affichent pas (mais OK en Safari réel)
  • 🚫 Pas de Service Worker pour des origins http en headless (OK en headed/iOS)
  • ✅ CSS :has() supporté nativement
  • ✅ font-display: swap via next/font fonctionne

Firefox

  • ⚠️ Peut throw NS_BINDING_ABORTED lors de navigations rapides successives → retry automatique
  • ⚠️ font-display: swap peut se comporter différemment de Chrome (Quicksand reste OK)
  • ⚠️ Pas de support WebGL2 headless dans certains environnements
  • ✅ Tous les tests applicatifs passent (11/11)

Chromium

  • ✅ Référence pour tous les comportements
  • ✅ WebAuthn fonctionne en mode headless si on l'enable (désactivé par défaut)
  • ✅ Le plus rapide à lancer (~3s par browser launch)

🎬 Comment lancer les tests cross-browser

Installation initiale

# Télécharge les 3 browsers (~300 MB total)
npx playwright install chromium firefox webkit

Lancer tous les tests sur tous les browsers

npm run test:e2e
# → 74 tests × 5 environnements = 370 exécutions

Lancer juste un browser (dev rapide)

BROWSERS=chromium npm run test:e2e

Lancer mobile seulement

BROWSERS=Mobile npm run test:e2e
# Pixel 5 + iPhone 13

UI interactive avec debug visuel

npm run test:e2e:ui
