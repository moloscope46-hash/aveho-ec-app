📋 Les 6 sujets traités

📨 Sujet 1 — security.txt + politique de divulgation (RFC 9116)

Pourquoi ? Les chercheurs en sécurité ne savaient pas comment nous contacter pour signaler des vulnérabilités. Le standard RFC 9116 définit un fichier /.well-known/security.txt qu'ils peuvent retrouver automatiquement.

Fichiers créés :

  • public/.well-known/security.txt : Contact, Expires 2027, langues fr/en
  • public/.well-known/policy.html : Politique complète (SLA 72h accusé + 14j évaluation, périmètre, pratiques interdites, mention légale protection chercheurs bonne foi)

🔐 Sujet 2 — clearUserData étendu (sb-* + IndexedDB WebAuthn)

Pourquoi ? Audit du logout post-0.57.35 → 2 vecteurs manquaient :

  • Les clés sb-<projet>-auth-token de Supabase (devraient être nettoyées par signOut() mais defense-in-depth)
  • L'IndexedDB aveho-webauthn avec les credentials face/empreinte (sur device partagé, user B peut potentiellement les voir)
// 0.57.37 - SENSITIVE_LS_PREFIXES inclut maintenant "sb-"
const SENSITIVE_LS_PREFIXES = [
  "aveho:", "aveho_", "ville:", "etab-photo-",
  "sb-",  // ← NEW : Supabase Auth tokens defense-in-depth
];

// NEW : purge IndexedDB biométrie (mode deepClean uniquement)
export async function clearWebauthnDb() {
  return new Promise((resolve) => {
    const req = indexedDB.deleteDatabase("aveho-webauthn");
    req.onsuccess = () => resolve(true);
    req.onerror = () => resolve(false);
  });
}

// Signature avec options.deepClean
export async function clearUserData(options = {}) {
  const ls_purged = purgeLocalStorage();
  const sw_cleared = await clearSwCache();
  // ⚠️ Biométrie purgée UNIQUEMENT si deepClean=true
  // (sinon l'user perd sa face/empreinte à chaque logout normal)
  const bio_cleared = options.deepClean === true
    ? await clearWebauthnDb() : false;
  return { ls_purged, sw_cleared, bio_cleared };
}

🔗 Sujet 3 — Audit Referer leak + rel="noopener noreferrer"

Pourquoi ? Vérifier qu'aucun lien externe ne fuite le path complet (qui pourrait contenir des tokens d'invitation, IDs de patient, etc.) via le header Referer.

État existant : Referrer-Policy: strict-origin-when-cross-origin déjà configuré au niveau HTTP (envoie seulement l'origin, pas le path). Audit des 15 liens target="_blank" :

  • 13/15 avaient déjà rel="noopener noreferrer" ✅
  • 2/15 (rpps-dump + mail-diagnostic) avaient juste noopener → fix → uniformisé à 100%

+ LINT anti-régression : aucun futur target="_blank" sans noopener ne passera le test.

🛡️ Sujet 4 — CSP enrichie : base-uri + manifest-src

Pourquoi ? La CSP report-only existait mais 2 directives manquaient :

DirectiveRisque évité
base-uri 'self'Anti <base href="evil.com"> hijack : un XSS qui injecte une balise base détournerait TOUS les liens relatifs vers le serveur de l'attaquant
manifest-src 'self'Anti spoofing manifest PWA malveillant

Mode Content-Security-Policy-Report-Only conservé. Le passage à enforce est prévu après observation des CSP reports en prod sur quelques semaines.

🔐 Sujet 5 — SRI (Subresource Integrity) sur 3 scripts CDN externes

Pourquoi ? 3 scripts JavaScript étaient chargés depuis CDN sans vérification d'intégrité. Si jsdelivr est compromis (supply-chain attack) ou si DNS hijacking, un script malveillant s'exécute dans le contexte authentifié de notre app.

🔑 Sujet 6 — 2FA TOTP (Supabase Auth MFA) — Foundation prête

Pourquoi ? Aveho EC n'avait pas de 2FA. Pour la prod réelle, un 2e facteur (Google Authenticator, Authy, 1Password, etc.) est essentiel pour les comptes admin et les utilisateurs sensibles.

Fichiers créés (prêts à activer)

FichierContenu
lib/mfa.js (160 lignes)6 fonctions exportées wrappant les APIs Supabase Auth MFA
app/components/MfaSetup.jsComposant React 3 états (idle / verifying / active)

Les 6 fonctions du helper lib/mfa.js

enrollTotp(supabase)Lance l'enrollment, retourne QR code SVG + secret
verifyTotpEnrollment(supabase, factorId, code)Valide le code 6 chiffres → factor verified
listMfaFactors(supabase)Liste les factors actifs de l'user
checkMfaRequired(supabase)Au login : faut-il demander un code TOTP ?
challengeAndVerifyTotp(supabase, factorId, code)Challenge + verify au login (AAL aal1 → aal2)
unenrollMfaFactor(supabase, factorId)Désactiver le 2FA

⚠️ Pour activer (étapes Supabase)

  1. Dashboard Supabase → Authentication → Multi-Factor Authentication → Enable TOTP
  2. Intégrer <MfaSetup /> dans app/profil/page.js
  3. Appeler checkMfaRequired() dans le flow login après signInWithPassword
  4. Si challengeRequired → afficher un input 6 chiffres → challengeAndVerifyTotp()

🔒 2 nouveaux LINT anti-régression (20e + 21e)

// LINT 20 : Aucun target=_blank sans noopener (anti tabnabbing)
const matches = src.matchAll(/target=["']_blank["']/g);
for (const m of matches) {
  const context = src.substring(m.index - 100, m.index + 200);
  if (!context.includes("noopener")) violations.push(...);
}

// LINT 21 : Aucun script CDN externe sans SRI (anti supply-chain)
const matches = src.matchAll(/\.src\s*=\s*["']https:\/\/(cdn\.|unpkg|cdnjs)[^"']+\.js["']/g);
for (const m of matches) {
  const after = src.substring(m.index, m.index + 500);
  if (!after.includes("integrity")) violations.push(...);
}
