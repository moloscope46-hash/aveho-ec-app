🐛 Le bug

Erreur observée :
GET /rest/v1/mutuelles?select=*&order=nom.asc 400 (Bad Request)
ERROR: 42703: column "nom" does not exist

Suite à un audit des colonnes effectives en base via information_schema.columns, on découvre que la table mutuelles n'a PAS les colonnes que mon code 0.56.4 attendait. Les vrais noms :

  • nom → en réalité raison_sociale
  • code_postal → en réalité cp
  • type → en réalité type_organisme

2 nouvelles colonnes utilisables aussi : nom_court (diminutif) et code_orgcomp.

Fix appliqué

Page /admin/referentiels-sante

  • Helper getNom(item) qui résout nom||raison_sociale
  • Query .order("raison_sociale") pour mutuelles (gardé nom pour caisses)
  • EditModal : label "Raison sociale *" + champs nom_court + code_orgcomp
  • fillFromBAN remappe cp pour mutuelles, code_postal pour caisses

API /api/mutuelles

  • POST accepte body.raison_sociale OU body.nom (fallback rétrocompat)
  • PUT remappe automatiquement {nom} → {raison_sociale}, {code_postal} → {cp}, {type} → {type_organisme}

SQL 0.56.10 patch corrigé

(select raison_sociale from mutuelles where id = v_patient.mutuelle_id)
   as mutuelle_nom;

Sans ce fix, le dashboard patient affichait "Non renseignée" pour la mutuelle même si le patient en avait une.
