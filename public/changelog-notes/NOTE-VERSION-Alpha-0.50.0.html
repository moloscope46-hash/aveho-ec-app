🎂 Cap des 50 versions

0.50.0 marque la 50ème livraison d'Aveho EC (en comptant les versions majeures + hotfix). De 0.15.6 à 0.50.0, on a couvert le PSAD/FBM en profondeur : RGPD complet, PWA offline-first, multi-établissements, signalements anonymes, dashboard direction, audit log granulaire, push notifications, recherche globale ⌘K, mode lecture seule, onboarding contextualisé, et bien d'autres. Cette version célèbre le cap avec une page /changelog dédiée pour rappeler le chemin parcouru.

Résumé

4 chantiers fonctionnels + la page changelog d'office, 1 patch SQL (table annonces + colonnes workflow achat). Build clean, 893 tests verts (+24), test runtime validé sur 7 routes.

5 modules livrés :
🎂 Bonus Page /changelog avec timeline visuelle de 13 versions (0.44 → 0.50) — pastilles colorées (vert=actuelle, orange=hotfix, bleu=majeure), chip code par chantier, cible du badge version dans la TopBar.
AO Annonces internes : <AnnoncesBanner /> sticky en haut sous la TopBar (info/warning/critique avec couleurs sémantiques) + page admin /annonces avec CRUD complet (titre, message, niveau, plage de dates, état actif/inactif). Chaque user peut dismisser individuellement (table annonces_dismissees).
AS Workflow achat à double validation : nouveau champ seuil_double_validation dans la modale (admin only). Si budget_estime > seuil → statut intermédiaire "Validée (1/2)" + bouton "Valider en 2nde lecture" pour un autre user (séparation des pouvoirs, le 1er valideur ne peut pas faire la 2nde).
AT Filtres audit avancés : bouton "Avancés" qui déroule un panneau avec inputs date Du/Au — si renseignés, ils écrasent le filtre période. Badge "ON" sur le bouton quand actifs.
AA Migration confirm() phase 2 : 11 nouveaux confirm() natifs migrés vers dialogs.confirm() sur 7 pages (patients, utilisateurs, maintenance, consentements, ConsentementRGPD, etablissement/edition, NotificationPreferences). Plus un resetAll rendu async automatiquement.

AS Workflow achat — double validation

  • 4 colonnes ajoutées à achats :
    • seuil_double_validation numeric(10,2) — au-delà, 2nd valideur requis
    • second_valideur_id uuid — référence auth.users
    • date_second_validation timestamptz
    • workflow_etape text — "demande" / "premiere_valid" / "double_valid_attente" / "double_valid"
  • Index idx_achats_workflow_etape
  • Vue v_achats_a_valider avec colonnes calculées etape_valid_courante + necessite_double_validation (booléen)
  • UI modale d'édition : nouveau champ "Seuil double validation (€)" — visible uniquement pour managers (isManager), placeholder explicatif
  • Fonction valider() enrichie :
    • Si budget_estime > seuil_double_validation → statut "Validée (1/2)" + dialog mentionnant "2ème validation requise"
    • Sinon → statut "Validée" classique
    • Action audit log dédiée : "valider_premiere" ou "valider" selon le cas
  • Nouvelle fonction validerSecondeFois() :
    • Guard "séparation des pouvoirs" : si l'user a déjà donné la 1ère validation → alert refus
    • Sinon : passe le statut à "Validée" + remplit second_valideur_id + date_second_validation
    • Action audit "valider_seconde"
  • Bouton UI "Valider en 2nde lecture" affiché uniquement si statut === "Validée (1/2)" et user a permission

AT Filtres avancés audit log

  • 2 nouveaux states : dateDebut, dateFin, plus showAvances pour le toggle du panneau
  • Logique query :
    • Si dateDebut renseignée → écrase le filtre période
    • Si dateFin renseignée → ajoute q.lte("created_at", dateFin + "T23:59:59Z") (inclusif)

  • UI :
    • Bouton "Avancés" avec icône chevron + badge "ON" quand des dates sont définies
    • Panneau dépliable en gris pâle avec 2 inputs type="date" labellés "Du" et "Au"
    • Message d'info en bas du panneau
  • resetFiltres() étendu pour effacer aussi les dates et remettre période à "30"
  • Deps useEffect mises à jour pour re-fetcher quand dates changent
  • Zéro SQL requis — la table audit_log a déjà tout ce qu'il faut

Procédure d'application — PowerShell

  1. Appliquer le patch SQL (Supabase Studio → SQL Editor) :
    • Copier-coller le contenu de aveho-PATCH-vers-0.50.sql
    • Run — durée ~2-3 secondes (tables petites)
    • Vérifier : select * from annonces; → 0 ligne (table vide). select numero, workflow_etape from v_achats_a_valider limit 3; → renvoie les commandes existantes avec colonnes calculées.
  2. Décompresser le zip par-dessus C:\aveho-ec-app\
  3. Installer & lancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test
npm run dev
    Attendu : 893 tests verts.
  4. Tester :
    • 🎂 Changelog : clic sur le badge v0.50.0 en haut → la page timeline s'ouvre, version actuelle en vert
    • AO Annonces : aller dans menu Administration → Annonces → créer une annonce de niveau "info" → recharger n'importe quelle page → la bannière apparaît en haut sous la TopBar. Clic sur la croix → elle disparaît.
    • AS Workflow : créer une commande achat avec budget 5000€, mettre seuil_double_validation à 1000€, soumettre, valider → statut passe à "Validée (1/2)" → un autre user clique "Valider en 2nde lecture" → statut "Validée" complet
    • AT Filtres audit : /audit → cliquer "Avancés" → entrer des dates → liste filtrée par cette plage
    • AA Migration : sur /utilisateurs, /maintenance, /consentements → cliquer une action de suppression → modale stylée ConfirmModal (plus de confirm() natif laid)
