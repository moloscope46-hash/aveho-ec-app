Hotfix 0.55.32 — Fix erreur 42703 sur migration etablissements → partenaires La table etablissements peut ne pas avoir toutes les colonnes attendues (cp, latitude, longitude, groupement_id) selon la structure cliente. Migration via to_jsonb() pour tolérer schéma variable.

Date : 31 mai 2026 Version : v0.55.32-alpha Tests : 1185 verts (idem 0.55.31)

❌ Le bug de la 0.55.31

ERROR: 42703: record "e" has no field "cp"
CONTEXT: SQL statement "insert into etablissements_partenaires (
    structure_id, nom, type, adresse, cp, ville, latitude, longitude, ...
)
values (
    e.structure_id, e.nom, e.type, e.adresse, e.cp, e.ville, e.latitude, e.longitude, ...
)"

La boucle utilisait for e in select * from etablissements puis accédait à e.cp, e.latitude, etc. Si la colonne n'existe pas sur ta table, plantage immédiat.

✅ La solution 0.55.32

Passage à un accès jsonb tolérant :

for e in
  select to_jsonb(t) from etablissements t
  where t.est_partenaire = true
    and not exists (
      select 1 from etablissements_partenaires ep
      where ep.link_to_etablissement_id = t.id
    )
loop
  begin
    insert into etablissements_partenaires (...)
    values (
      (e->>'structure_id')::uuid,
      e->>'nom',
      e->>'cp',                   -- NULL si pas de colonne cp
      nullif(e->>'latitude', '')::numeric,   -- NULL si vide
      ...
    );
  exception when others then
    raise notice 'Migration partenaire échouée (id=%) : %', e->>'id', SQLERRM;
    -- continue avec les autres
  end;
end loop;

Bénéfices :

  • Si une colonne n'existe pas, e->>'nom_colonne' renvoie NULL au lieu de planter
  • Le bloc EXCEPTION continue la boucle même si une ligne échoue (le log NOTICE permet de savoir laquelle)
  • Marche sur n'importe quelle variation de schéma etablissements
