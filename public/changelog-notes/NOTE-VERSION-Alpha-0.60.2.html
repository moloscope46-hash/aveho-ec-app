⚠ Erreurs corrigées

ERROR 42703: column m.code_postal does not exist (LINE 46 v_magasins_disponibles)
GET articles?est_catalogue_magasin=eq.true → 400 Bad Request
GET etablissements_partenaires?est_fournisseur=eq.true → 400 Bad Request
GET bilans-sav → 503 Service Unavailable

Cause : tu n'as pas appliqué tous les SQL des versions 0.59.5 → 0.60.1, donc certaines colonnes/tables manquent. La vue v_magasins_disponibles plante car magasins.code_postal n'existe pas encore.

Solution : applique le SQL hotfix HOTFIX-aveho-0.60.2-tout-en-un.sql. Il crée TOUT dans l'ordre correct (ALTER avant les vues) et est 100% idempotent.

🔥 1. SQL hotfix tout-en-un

Le fichier remplace tous les SQL précédents et crée tout ce qui pourrait manquer :

SectionContenu
1. MagasinsALTER avec code_postal, ville, telephone, email, responsable, etablissement_rattache_id, etc.
2. ArticlesALTER ADD COLUMN magasin_id, article_magasin_id, est_catalogue_magasin, stock_actuel
3. PartenairesALTER ADD COLUMN est_fournisseur, magasin_id
4. Demandes internesCREATE + ALTER avec type_demande, bilan_sav_id, panne_description, validee_par, etc.
5. Bilans SAVCREATE bilans_sav + points + articles + executions
6. Droits magasinCREATE etablissements_magasins_droits + ALTER membres_structure (magasin_fournisseur_id UNIQUE)
7. Vuesv_magasin_di + v_magasins_disponibles (APRÈS tous les ALTER)

👥 2. Nouvelle page /collaborateurs-fournisseurs (EC)

Côté EC, nouvelle vue dédiée aux users magasin. Liste tous les utilisateurs tagués "Utilisateur Magasin" avec leur magasin rattaché. Cards avec :

  • Avatar + identité + rôle
  • Badge teal si rattaché : nom magasin, code, ville, agence rattachée
  • Badge amber si pas rattaché
  • Email + téléphone

Recherche par nom/email. 4 stat tiles (users magasin, rattachés, sans magasin, magasins définis). Lien ajouté au menu Groupement.

🔒 3. Cantonnement des vues magasin

Nouveau hook useMagasinContext

const magasinCtx = useMagasinContext();
// Retourne :
// {
//   magasin,              // L'entité magasin du user
//   etablissement,        // L'agence à laquelle le magasin est rattaché

//   etablissementId,
//   isUserMagasin,        // true si rôle = utilisateur_magasin
//   isRattache,           // true si magasin défini
//   loading
// }

Sur /magasin, le reload des DI est maintenant filtré par magasin_id du user. Un user magasin ne voit que ses propres DI/SAV/transferts.
