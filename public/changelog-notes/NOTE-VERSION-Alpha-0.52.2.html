Architecture

Le contenu (65 entrées, 40 KB) est dans un fichier de données séparé pour ne pas alourdir la page :

app/changelog/
├── page.js              ← composant React (logique + UI)
└── versions-data.js     ← export ALL_VERSIONS (40 KB)

Le fichier versions-data.js a été généré automatiquement par un script Python qui :

  1. Liste toutes les NOTE-VERSION-Alpha-*.html et NOTE-HOTFIX-Alpha-*.html dans /mnt/user-data/outputs/
  2. Parse chaque note pour extraire :
    • Le titre + sous-titre du header (regex sur <h1><small>)
    • Les chantiers (regex sur <span class="chantier-letter"> + texte qui suit)
  3. Nettoie les badges méta (KB du zip, nombre de tests, etc.)
  4. Trie en ordre décroissant version-aware
  5. Exporte en JSON dans le fichier JS

Bénéfices opérationnels

  • Vue d'ensemble du projet : voir d'un coup d'œil tout ce qui a été fait, sans naviguer entre 65 notes HTML
  • Recherche rapide : "j'avais bien fait l'export CSV des audits ?" → recherche "audit" → on voit les versions concernées
  • Historique pour clients/équipe : la page est accessible depuis le badge version de la TopBar, peut être partagée en démo
  • Auto-maintenance : pour la 0.53, j'ajouterai juste l'entrée correspondante dans versions-data.js, le rendu est automatique

Procédure d'application — PowerShell

  1. Décompresser le zip 0.52.2 par-dessus C:\aveho-ec-app\
  2. Installer + lancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm run dev
  3. Tester :
    • Cliquer sur le badge version v0.52.2 dans la TopBar → la page /changelog s'ouvre
    • Vérifier les 3 stats en haut (57 versions, 8 hotfix, 65 total)
    • Cliquer "Hotfix" → ne reste que les 8 hotfix
    • Taper "annonces" dans la recherche → la 0.50 et la 0.51 (stats annonces) remontent
    • Faire défiler tout en bas → arriver à la 0.1 (première version Vercel)
  4. 1er chargement : grâce au bump SW automatique (réflexe 15), tu verras le toast vert "Mise à jour disponible — Version 0.52.2-alpha" apparaître 10 secondes après chargement. Cliquer "Recharger" → SW se met à jour proprement, plus besoin de Clear site data manuel.

Test du nouveau workflow SW (sans Clear site data)

Avec le hotfix 0.52.1 + le bump auto :

  1. Tu es actuellement sur la 0.52.1 avec SW aveho-ec-0.52.1
  2. Tu décompresses la 0.52.2 → le fichier public/sw.js contient VERSION = "aveho-ec-0.52.2"
  3. Au chargement de la page, le navigateur compare le hash du SW : différent → re-télécharge
  4. Le nouveau SW invalide les anciens caches → re-télécharge les chunks neufs
  5. VersionCheck détecte que /api/version renvoie 0.52.2 vs 0.52.1 en localStorage → toast vert "Recharger"
  6. Tu cliques → SW unregistered + reload → tout est propre

Si ça marche cette fois, le 15ᵉ réflexe est validé en production. Sinon, on diagnostique ensemble.
