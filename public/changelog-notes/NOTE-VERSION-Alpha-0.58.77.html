🩺 Diagnostic des 400 dans tes logs

Failed to run sql query: ERROR: 42703: column e.numero does not exist
LINE 205:   e.numero AS etage_numero,

Cause : le SQL 0.58.75 contenait CREATE TABLE IF NOT EXISTS etages (... numero INTEGER ...). Mais une table etages existait déjà dans ta DB (créée par un autre process avant) sans la colonne numero. Donc le CREATE n'a rien fait (IF NOT EXISTS), et plus tard la vue v_depots_hierarchie a essayé d'accéder à e.numero → 42703.

Conséquence : la transaction a échoué, plusieurs tables/colonnes ne se sont pas créées, d'où la cascade de 400 sur batiments.couleur, groupements (404), etages.numero, etc.

✅ Le fix : SQL 0.58.77 idempotent

Script de récupération à appliquer en l'état (safe à relancer même si partiellement appliqué) :

📄 public/sql/migration-0.58.77-fix-idempotent-recovery.sql

Ce qu'il fait :

  • ALTER TABLE etages : ADD COLUMN IF NOT EXISTS numero, structure_id, batiment_id, nom, couleur, icone, notes, actif, timestamps — rattrape la table existante
  • CREATE TABLE IF NOT EXISTS groupements + RLS — vu le 404 dans tes logs
  • CREATE TABLE IF NOT EXISTS groupement_etablissements + RLS
  • ALTER TABLE chambres + services : ADD etage_id
  • ALTER TABLE depots : tous les ALTER de 0.58.75 en mode IF NOT EXISTS (rejoue safe)
  • ALTER TABLE transferts : idem (rejoue safe)
  • ALTER TABLE batiments : ADD couleur, icone si manquants
  • DROP + CREATE VIEW v_depots_hierarchie propre une fois etages.numero présent

100% safe à relancer plusieurs fois. Si tu as déjà appliqué partiellement, ça complète juste ce qui manque.

🔇 SW : 503 silencieuse au lieu de throw

Le SW ligne 183 (await fetch(req)) re-throwait l'erreur native quand le réseau échouait sans cache. Résultat : Uncaught (in promise) TypeError: Failed to fetch dans la console à chaque échec réseau.

Fix : on retourne une Response(503) avec body JSON { offline: true }. L'appelant (Supabase client) reçoit une 503 propre au lieu d'un network error → il gère son fallback sans polluer la console.

// 0.58.77 — SW networkFirst catch
return new Response(
  JSON.stringify({ error: 'Service indisponible', offline: true }),
  { status: 503, headers: { 'Content-Type': 'application/json' } }
);
