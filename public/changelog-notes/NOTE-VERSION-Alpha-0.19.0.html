3.1 Tests canDo (18 tests)

La fonction canDo(role, action) est centrale : elle décide si un utilisateur peut écrire, supprimer, inviter, gérer les rôles, etc. Toute régression ici cassera silencieusement des fonctionnalités entières. Les tests couvrent :

  • Rôles système : Administrateur peut tout, Lecture seule peut rien
  • Raccourcis : systeme: "admin" et systeme: "lecture"
  • null/undefined : ne peut rien faire (sécurité par défaut)
  • Format Array : ["write", "delete"] + wildcard *
  • Format Objet par module : { stock: ["read","write"], patients: ["read"] }
  • Compatibilité legacy : fallback sur droits et permissions si permissions_json absent
  • Cas réels : admin de structure (Cédric), formateur, observateur

3.2 Tests parseCSVText (15 tests)

L'import CSV est utilisé pour les patients, prescripteurs, articles, etc. Une régression peut corrompre des données en base. Les tests couvrent :

  • Séparateurs : virgule (US) et point-virgule (FR Excel)
  • BOM UTF-8 : retrait du préfixe \uFEFF
  • Guillemets : entourant cellule, échappés (doublés), contenant retour ligne
  • Lignes vides : ignorées
  • Retours ligne : Windows (\r\n) et Unix (\n)
  • Cas limites : chaîne vide, en-tête seul, cellule manquante, trim
  • Cas réels : import patients FR avec point-virgule, import prescripteurs avec virgules dans les noms entre guillemets

5.3 pageSize configurable

Le composant <Crud> (utilisé sur les pages Patients, Matériels, Articles, Dépôts, etc.) propose désormais un sélecteur de taille de page : 25 / 50 / 100 / Tout. Affiché dès qu'il y a plus de 25 lignes.

  • Par défaut : 50 (comme avant)
  • Sur mobile, l'utilisateur peut passer à 25 pour réduire la charge
  • Sur desktop avec une grosse collectivité, l'utilisateur peut afficher tout pour utiliser Ctrl+F natif du navigateur

5.4 content-visibility: auto

Ajout de la règle CSS content-visibility: auto sur les tr de tables. Le navigateur ne rend les rangées qu'au scroll (out-of-viewport = skip layout/paint). Sur une liste de 200+ lignes, le scroll devient nettement plus fluide.

table tbody tr {
  content-visibility: auto;
  contain-intrinsic-size: auto 48px;
}

L'attribut contain-intrinsic-size indique au navigateur la hauteur approximative d'une rangée non rendue, ce qui évite les sauts de scrollbar. Compatible Chrome 85+, Firefox 125+, Safari 18+. Pas de fallback nécessaire — sur les anciens navigateurs, le rendu normal est utilisé.

7. Procédure d'application

  1. Pas de SQL. Aucun changement de schéma.
  2. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local)
  3. npm install + tests + dev : 
    cd C:\aveho-ec-app
npm install
npm test       # vérifie : Tests 67 passed (67)
npm run dev
  4. Tester :
    • Activer le mode sombre via /parametres → onglet Thème → Sombre. Tous les composants doivent être lisibles (texte clair sur fond foncé).
    • Ouvrir une fiche matériel ou patient → DevTools Network : le chunk ficheToPdf n'apparaît que quand on clique sur Imprimer.
    • Liste matériels avec > 25 items : le sélecteur pageSize apparaît. Tester 25 / 50 / 100 / Tout.
    • Liste matériels avec > 100 items (si tu as les données) : scroll fluide grâce à content-visibility.
  5. Pousser sur Vercel comme d'habitude (C:\aveho-ec-app-01 + git push).
