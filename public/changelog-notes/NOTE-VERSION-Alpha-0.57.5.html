🔧 Fix 1 — Helper lib/useAsyncEffect

Nouveau hook utilitaire qui résout les problèmes récurrents des useEffect async :

  • ✅ try/catch automatique → pas d'UnhandledPromiseRejection
  • ✅ AbortController pour annuler les fetches en cours au démontage
  • ✅ Flag isMounted pour ignorer les setState après démontage (évite warning React)
  • ✅ Logging unifié via lib/logger en cas d'erreur
// Usage :
useAsyncEffect(async ({ signal, isMounted }) => {
  const data = await fetch(url, { signal }).then(r => r.json());
  if (!isMounted()) return;  // composant démonté entre temps
  setData(data);
}, [deps]);

À utiliser pour tous les futurs useEffect async — les anciens ont été patchés manuellement avec try/catch (plus simple à diff).

🩹 Fix 3 — Patches manuels (cas complexes)

app/patient/[id]/page.js — useEffect géant avec nested promises

Cette page chargeait 7 ressources en parallèle via Promise.all, puis 2 autres (caisse + mutuelle) en parallèle. Aucun try/catch englobant + 2 .then() sans .catch(). Si l'une rejette, Promise.all du nested fait crasher tout :

// Avant
const promises = [];
if (p?.caisse_id) {
  promises.push(
    supabase.from("caisses_assurance_maladie")...
      .then(r => setCaisseInfo(r.data || null))   // ← pas de catch
  );
}
// si caisse_id n'existe pas → promise reject → Promise.all reject
//                          → loading reste à true infiniment

// Après
const promises = [];
if (p?.caisse_id) {
  promises.push(
    supabase.from(...)
      .then(r => setCaisseInfo(r.data || null))
      .catch(() => {})  // 0.57.5 : ignore si caisse pas trouvée
  );
}
// + try/catch englobant le useEffect entier avec finally setLoading(false)

app/achats/page.js — notifyValideurs.then APRÈS le try/catch englobant

Le try/catch couvrait l'await import mais pas la promise qui s'exécute après :

// Avant — bug subtil
try {
  const { notifyValideurs } = await import("../../lib/notifyValideurs");
  notifyValideurs(...).then(({ sent, errors }) => { ... });
  // ↑ cette promise s'exécute APRÈS le try/catch, pas couverte !
} catch (e) { ... }

// Après
try {
  const { notifyValideurs } = await import("../../lib/notifyValideurs");
  notifyValideurs(...)
    .then(({ sent, errors }) => { ... })
    .catch((e) => logger.warn("notifyValideurs a échoué :", e?.message));
} catch (e) { ... }

🔥 Fix 5 — Fuite mémoire WebHID (SignaturePad)

La lib de signature pad branchait un listener inputreport sur le device HID lors du connect, mais ne le retirait jamais au démontage du composant.

Si l'utilisateur quitte la page de signature avec un signpad encore connecté → le listener reste actif en mémoire + reçoit les events fantômes du device → erreurs JS dans la console + memory leak qui grossit à chaque ouverture.

Fix

const hidListenerRef = useRef(null);  // 0.57.5 : pour cleanup

async function connectHid(device) {
  try {
    if (!device.opened) await device.open();
    setHidDevice(device);
    setHidStatus("connected");
    device.addEventListener("inputreport", handleHidInput);
    // 0.57.5 : on garde une réf pour cleanup
    hidListenerRef.current = { device, listener: handleHidInput };
  } catch (e) { ... }
}

useEffect(() => {
  // ... init
  return () => {
    // 0.57.5 : cleanup au démontage
    if (hidListenerRef.current) {
      const { device, listener } = hidListenerRef.current;
      try { device.removeEventListener("inputreport", listener); }
      catch {}  // device peut déjà être déconnecté
      hidListenerRef.current = null;
    }
  };
}, []);

Bonus : .catch() sur navigator.hid.getDevices() pour gérer browser ancien / permission refusée proprement (avant : UnhandledPromiseRejection silencieux).
