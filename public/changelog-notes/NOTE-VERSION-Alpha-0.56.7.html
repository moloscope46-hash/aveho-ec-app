🎯 Le concept

Au fil du temps, plusieurs personnes saisissent des établissements/groupements/médecins avec des variantes de nom (« CH de Toulouse » vs « Centre Hospitalier Toulouse » vs « C.H. Toulouse »). Sans détection automatique, ces doublons s'accumulent et faussent les stats, les prescriptions, et la lisibilité.

Cette page lance une analyse fuzzy sur tes 3 référentiels principaux et te liste les paires suspectes triées par score de similarité décroissant, avec actions claires pour traiter chaque cas.

🔍 Stratégie de détection

CibleScore 100% (certain)Score 95%Score variable
Établissements SIRET identique FINESS identique Similarité nom + bonus si même CP
Groupements — — Similarité du nom
Médecins RPPS identique — Similarité nom + prénom concaténés

La similarité fuzzy est calculée par l'extension PostgreSQL pg_trgm (trigrammes) — extrêmement rapide grâce à l'index GIN qu'on crée sur chaque colonne nom. Pas besoin de Levenshtein côté JS, tout se fait en SQL.

🎛 Slider de seuil ajustable

Tu peux régler le seuil de similarité entre 30% et 95% via un slider. Le seuil par défaut est différent selon la cible :

  • Établissements : 55% (plus permissif car les noms peuvent varier beaucoup)
  • Groupements : 60%
  • Médecins : 60%

Baisser le seuil = plus de paires détectées mais plus de faux positifs. Monter le seuil = paires plus sûres mais on peut rater des doublons écrits différemment.

🙈 Marquage "non-doublon"

Quand 2 entités se ressemblent mais sont réellement distinctes (ex : « EHPAD Les Tilleuls Marseille » vs « EHPAD Les Tilleuls Toulouse »), tu cliques « Marquer non-doublon » :

  • Saisis une raison (optionnelle) via prompt
  • La paire est stockée dans la table doublons_ignores
  • Elle ne réapparaîtra plus dans les détections futures (filtre via NOT EXISTS dans les RPC)
  • La structure_id, la cible et qui a ignoré (auth.uid()) sont tracés

Astuce : si tu te trompes et que tu veux qu'une paire réapparaisse, fais un DELETE FROM doublons_ignores WHERE ... en SQL.

🗄 Schéma SQL

Extension activée

create extension if not exists pg_trgm — fournit la fonction similarity(a, b) (0 à 1) et l'opérateur % de comparaison floue.

3 index GIN trigramme

  • idx_etablissements_nom_trgm sur etablissements.nom
  • idx_groupements_nom_trgm sur groupements.nom
  • idx_medecins_nom_trgm sur medecins_prescripteurs.nom

Sans ces indexes, la jointure self-join sur N×N paires serait extrêmement lente. Avec, c'est quasi-instantané même sur des milliers d'entités.

Table doublons_ignores

Contraintes intelligentes : check (entity_id_1 < entity_id_2) garantit qu'on ne stocke jamais (A,B) et (B,A) séparément + unique (struct, cible, id_1, id_2).

5 RPC security definer

  • detecter_doublons_etablissements(seuil, max)
  • detecter_doublons_groupements(seuil, max)
  • detecter_doublons_medecins(seuil, max)
  • ignorer_doublon(cible, id_1, id_2, raison)
  • doublons_stats(seuil_etab, seuil_grp, seuil_med)

⚠️ Limites connues

  • Fusion manuelle : la page détecte mais ne fusionne pas automatiquement. Pour fusionner, il faut faire manuellement : UPDATE prescriptions SET etablissement_id = X WHERE etablissement_id = Y; DELETE FROM etablissements WHERE id = Y; (ou via une fonctionnalité de fusion dédiée dans une version future)
  • Performance : sur très gros volumes (10k+ entités), la jointure self-join peut devenir lente. Les index GIN aident mais limite à ~50k entités confortablement
  • Faux positifs inévitables : certains noms se ressemblent vraiment (ex: « EHPAD Saint-Joseph » est présent dans plein de villes). C'est pour ça qu'on a le bouton "Marquer non-doublon"
  • pg_trgm est anglo-saxon : il fonctionne par trigrammes (3 caractères glissants), ce qui marche bien en français mais peut donner des scores plus bas sur des mots accentués différemment
