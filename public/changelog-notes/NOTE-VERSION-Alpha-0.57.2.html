🎯 Le composant SqlModal

La modale d'affichage du SQL d'une version était 180 lignes de JSX + 50 lignes de logique directement dans page.js. Elle est désormais dans son propre fichier SqlModal.js qui gère tout seul :

  • Le fetch du fichier SQL depuis /public/changelog-sql/...
  • Le cache via useRef({}) pour ne pas refetch à chaque ouverture
  • Le handler ESC pour fermer
  • La copie clipboard avec feedback "Copié !" 2s
  • L'affichage du nombre de lignes / Ko en footer
  • Le lien Télécharger

Le parent ne fait plus que passer les props :

// 0.57.2 : 180 lignes de JSX → une seule ligne dans page.js
<SqlModal sqlModal={sqlModal} onClose={() => setSqlModal(null)} />

Bénéfices

  • page.js plus court et plus lisible (1603 → 1363, -15%)
  • SqlModal testable isolément
  • SqlModal réutilisable ailleurs si besoin
  • Le cache fetch + ESC sont encapsulés (pas de pollution du parent)

📦 Le module lib/helpers.js

4 helpers utilitaires sortis de page.js et déplacés dans app/changelog/lib/helpers.js :

  • ICONS_BY_CODE — constantes pour Fix (rouge), NEW (vert), BONUS (violet), • (gris)
  • getCodeMeta(code) — résout {color, label} depuis un code de chantier
  • versionKey(s) — split "0.57.2" en [0, 57, 2]
  • compareVersions(a, b) — tri ordre version

Ces helpers seront réutilisables par les futurs sous-composants extraits (NoteModal, FilterPanel, etc.)

🐛 Fix bonus : imports tabs/ corrigés

Héritage de la refacto 0.57.1 : 2 imports dynamiques dans tabs/ avaient le mauvais nombre de ../ :

  • TabAudit.js : import("../../../../lib/bulletinsStorage") → manquait 1 niveau
  • TabPrescriptions.js : import("../../../../lib/prescriptionsStorage") → idem

Le code dans tabs/ est 5 niveaux de profondeur par rapport à lib/ (app/patient/[id]/edit/tabs/ → lib/), donc il faut ../../../../../lib/...

Le bug aurait crashé au runtime au moment du download de bulletin ou de prescription. Détecté en build avec Next 15 qui affiche des warnings plus stricts. Corrigé.
