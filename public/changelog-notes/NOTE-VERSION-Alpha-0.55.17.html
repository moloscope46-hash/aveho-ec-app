🎯 Le concept

La version 0.55.13 a introduit la connexion par empreinte (Touch ID, capteur Android, Hello). Cette 0.55.17 ajoute la détection faciale (Face ID, Hello caméra) comme méthode séparée.

L'user peut activer indépendamment :

  • L'empreinte uniquement (devices Android, Mac Touch ID, anciens iPhone)
  • La détection faciale uniquement (iPhone X+ Face ID)
  • Les deux (Windows Hello qui propose les deux, ou par préférence)

🛠 Architecture pragmatique

WebAuthn unifié + séparation logique

Techniquement, WebAuthn (le standard utilisé en 0.55.13) gère déjà les 2 méthodes côté OS — Face ID, Touch ID, Hello, empreinte Android passent tous par navigator.credentials.create() avec authenticatorAttachment: "platform". C'est l'OS qui choisit la méthode disponible.

Pour l'user, on sépare logiquement les 2 méthodes via une colonne auth_method sur la table webauthn_credentials. À l'activation, l'user déclare s'il veut configurer empreinte ou face, et on crée 2 credentials WebAuthn distincts si les 2 sont activées.

Pourquoi 2 credentials et pas 1 ?

  • L'user peut révoquer indépendamment (ex. : désactiver juste le face mais garder l'empreinte)
  • Sur les devices supportant les 2, on peut afficher 2 boutons dédiés au login
  • Les icônes dans /utilisateurs sont plus parlantes

🗄 Chantier SQL — Patch 0.55.17

Colonne auth_method

alter table webauthn_credentials
  add column if not exists auth_method text not null default 'empreinte';

-- Check constraint (empreinte | face)
alter table webauthn_credentials
  add constraint wac_auth_method_check 
  check (auth_method in ('empreinte', 'face'));

-- Index pour les requêtes par méthode
create index if not exists idx_wac_user_method 
  on webauthn_credentials(user_id, auth_method) 
  where active = true;

Vue v_users_auth_methods (pour /utilisateurs)

create or replace view v_users_auth_methods as
select 
  ms.user_id,
  ms.structure_id,
  ms.nom_affiche,
  exists(select 1 from webauthn_credentials wc 
         where wc.user_id = ms.user_id 
         and wc.auth_method = 'empreinte' 
         and wc.active = true) as has_empreinte,
  exists(select 1 from webauthn_credentials wc 
         where wc.user_id = ms.user_id 
         and wc.auth_method = 'face' 
         and wc.active = true) as has_face,
  (...total_devices) as total_devices
from membres_structure ms;

Vue v_my_webauthn_credentials mise à jour

Inclut maintenant auth_method dans le SELECT pour que la page /profil affiche le bon badge par credential.

🎨 UI — Modale opt-in refondue

Au lieu d'un seul bouton "Activer maintenant", la modale affiche désormais 2 cards :

  • Empreinte digitale (icône bleu) — Touch ID, capteur Android, Hello empreinte
  • Détection faciale (icône violet) — Face ID iPhone/iPad, Hello caméra

Chaque card a son bouton "Activer" indépendant. Si l'OS supporte les 2 (iPad Pro, Hello), l'user peut activer les deux successivement.

Un badge RECOMMANDÉ apparaît sur la méthode probablement compatible avec l'appareil (Face ID sur iPhone récent, etc.).

Badge ACTIVÉE avec un check vert quand la méthode est déjà configurée.

Bouton "Terminer" (vert) si les 2 méthodes sont activées, sinon "Plus tard" (skip 7j).

🔓 Login — 1 bouton par méthode

Quand l'user saisit son email, on lit l'IndexedDB pour voir les méthodes activées sur ce device. On affiche un bouton dédié pour chaque :

  • Détection faciale : gradient violet (#7a6fb0 → #bfa9e0), icône face-id 24px
  • Empreinte : gradient bleu/teal (#185FA5 → #7CC8C8), icône fingerprint 22px

Au clic, authenticateBiometric({ method }) filtre sur le credential correspondant et déclenche le bon prompt OS.

👥 Page /utilisateurs — Icônes par user

Dans la liste des membres, on charge maintenant v_users_auth_methods pour chaque user. À côté du nom_affiche, on affiche :

  • Pastille ronde bleue avec icône empreinte si has_empreinte = true
  • Pastille ronde violette avec icône face-id si has_face = true

Tooltip "Empreinte digitale activée" / "Détection faciale activée" au hover.

Discret mais visible, permet aux admins de savoir quels users ont configuré quoi.

🔄 Migration IndexedDB

Ancien format vs nouveau format

Avant 0.55.17 — clé email avec credential plat :

{ email, credential_id, refresh_token, user_id, device_name, created_at }

Depuis 0.55.17 — méthodes en sous-objets :

{
  email,
  empreinte: { credential_id, refresh_token, user_id, device_name, created_at },
  face:      { credential_id, refresh_token, user_id, device_name, created_at }
}

Migration automatique

La fonction normalizeStorage() détecte l'ancien format et le convertit à la volée vers { empreinte: {...} } (l'empreinte était la seule méthode possible avant). Le user enregistré en 0.55.13 ne perd pas son activation.

À la prochaine écriture (réactivation, login, etc.), l'entrée est sauvegardée au nouveau format.

⚠ Notes de compatibilité

  • Sur iPhone X+ : Face ID est le platform authenticator par défaut. Le bouton "Empreinte" n'est pas dispo (pas de capteur empreinte).
  • Sur Mac Touch ID : seul l'empreinte est dispo (pas de Face ID sur Mac).
  • Sur Windows Hello : les 2 peuvent être disponibles selon la config.
  • Sur Android : généralement empreinte uniquement (la plupart des téléphones n'ont pas de Face ID sécurisé).
  • Sur Firefox : support WebAuthn partiel — la modale se cache proprement si pas dispo.
