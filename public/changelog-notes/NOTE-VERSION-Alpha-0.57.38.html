🚨 Bug CORS send-digest — diagnostic + fix

🔧 Le bug

Erreur observée :

profil:1 Access to fetch at 'https://rnvlzddgxiuslgljkobm.supabase.co/functions/v1/send-digest'
from origin 'https://aveho-ec-app.vercel.app' has been blocked by CORS policy:
Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.

Cause : Dans supabase/functions/_shared/auth.ts, le pattern regex ALLOWED_ORIGIN_PATTERNS était trop strict :

// AVANT 0.57.38 - pattern restrictif
const ALLOWED_ORIGIN_PATTERNS = [
  /^https:\/\/aveho-ec-app-[a-z0-9-]+-fleos-projects\.vercel\.app$/,
];
// ↑ Matche seulement les previews "aveho-ec-app-XXX-fleos-projects"
//   mais ton domaine principal "aveho-ec-app.vercel.app" était bien
//   dans ALLOWED_ORIGINS... donc le bug venait d'ailleurs.

Hypothèse retenue : Le helper _shared/auth.ts n'a peut-être pas été correctement uploadé avec chaque déploiement de fonction. Quand on fait supabase functions deploy send-digest, Supabase upload aussi _shared, mais il peut y avoir des cas où la dernière version n'a pas pris.

✅ Le fix

Pattern élargi pour matcher TOUS les sous-domaines vercel.app commençant par "aveho-ec-app" :

// 0.57.38 - pattern élargi
const ALLOWED_ORIGIN_PATTERNS = [
  /^https:\/\/aveho-ec-app[a-z0-9-]*\.vercel\.app$/,
];
// ↑ Matche :
//   - aveho-ec-app.vercel.app (principal)
//   - aveho-ec-app-git-main-XXX.vercel.app (preview Git)
//   - aveho-ec-app-XXX-fleos-projects.vercel.app (preview Vercel)
⚠️ Pour que ce fix prenne effet :
  1. Dézipper le nouveau zip 0.57.38
  2. Redéployer les 11 Edge Functions (commandes en haut de cette note)
  3. Tester depuis /profil → bouton "Envoyer maintenant" du Digest

📊 Sujet 1/3 — Audit logs centralisé (security events)

Le problème

L'app avait audit_log mais uniquement pour les events métier (créations, modifications). Aucune trace des events sécurité :

  • Tentatives de login échouées
  • Blocages rate-limit
  • Accès refusés aux pages admin
  • Bots détectés par honeypot
  • Exports massifs de données

→ Impossible d'analyser une attaque a posteriori, pas de visibilité côté admin.

Requête SQL pour analyser les events sécurité

SELECT created_at, user_email, action, details
FROM audit_log
WHERE entite = 'security_event'
ORDER BY created_at DESC
LIMIT 50;

-- Top 10 emails avec le plus de tentatives échouées (anti-bruteforce)
SELECT user_email, COUNT(*) as nb_failed
FROM audit_log
WHERE entite = 'security_event'
  AND action = 'login_failed'
  AND created_at > NOW() - INTERVAL '24 hours'
GROUP BY user_email
ORDER BY nb_failed DESC
LIMIT 10;

🤖 Sujet 2/3 — Honeypot anti-bot login

Pourquoi ?

Les bots automatisés naïfs remplissent TOUS les champs d'un formulaire, même ceux invisibles. En ajoutant un champ piège invisible, on détecte instantanément ces bots — sans friction pour les humains.

Le helper lib/honeypot.js (115 lignes)

// Hook React
export function useHoneypot(fieldName = "website_url") {
  const [value, setValue] = useState("");
  return {
    honeypotProps: {
      type: "text",
      name: fieldName,
      value,
      onChange: (e) => setValue(e.target.value),
      style: {
        position: "absolute", left: "-9999px",
        width: "1px", height: "1px", opacity: 0,
        pointerEvents: "none",
      },
      tabIndex: -1,
      autoComplete: "off",
      "aria-hidden": "true",
    },
    isBot: () => value.length > 0,
    getHoneypotValue: () => value,
  };
}

Intégration login

// 1. Hook au top du composant
const { honeypotProps, isBot } = useHoneypot("website_url");

// 2. Check AVANT signIn
async function submit() {
  if (isBot()) {
    // Log silencieux + délai 800-1200ms + erreur générique
    await auditHoneypotTriggered(supabase, { userEmail: email }, {
      honeypot_value_length: getHoneypotValue().length,
    });
    await new Promise((r) => setTimeout(r, 800 + Math.random() * 400));
    setErr("Erreur de validation. Réessaie.");
    return;
  }
  // ... flow normal
}

// 3. Dans le JSX, AVANT l'email
<input {...honeypotProps} />

Limites assumées

  • Stoppe seulement les bots naïfs qui remplissent tout aveuglément
  • Les bots sophistiqués lisent le CSS et skipent les champs display:none
  • Pour ces derniers : le rate-limit serveur Supabase + le rate-limit client de 0.57.36 restent la défense principale
