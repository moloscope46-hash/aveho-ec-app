🛡️ Anti-régression

Nouveau test : pour chaque sqlFile référencé dans versions-data, vérifier qu'il existe physiquement dans public/changelog-sql/. Si un dev ajoute un sqlFile sans copier le fichier, le test fail.

it("Chaque sqlFile dans versions-data correspond à un fichier physique", () => {
  const matches = [...src.matchAll(/"sqlFile":\s*"([^"]+\.sql)"/g)];
  const referenced = [...new Set(matches.map(m => m[1]))];
  const physical = new Set(fs.readdirSync("public/changelog-sql"));
  const missing = referenced.filter(f => !physical.has(f));
  expect(missing).toEqual([]);
});

🛡️ 3. Endpoint /api/csp-report

Nouvel endpoint pour collecter les violations CSP que les browsers détectent en prod. Quand une directive est violée (script bloqué, image bloquée...), le browser POST automatiquement un rapport JSON ici.

Sécurité du endpoint

  • Public par design : les browsers envoient sans credentials d'auth
  • Rate limit strict : 30 reports/min par IP → anti-flood
  • Nettoyage mémoire : setInterval qui purge les vieux buckets toutes les minutes → anti memory-leak
  • Logs propres : utilise lib/logger qui redacte les valeurs sensibles
  • Silent fail : répond toujours 204 No Content, même si flood → pas d'info à l'attaquant
  • Support 2 formats : legacy csp-report + Reporting API moderne
  • Whitelisté dans le LINT anti-régression (avec /version et /health)

CSP mise à jour

const CSP_DIRECTIVES = [
  "default-src 'self'",
  // ... 11 autres directives
  "frame-ancestors 'self'",
  "report-uri /api/csp-report",  // ← NEW 0.57.24
];

Maintenant tu peux voir dans les logs Vercel les violations CSP qui se produisent en prod (utile pour décider quand basculer en CSP enforcing).
