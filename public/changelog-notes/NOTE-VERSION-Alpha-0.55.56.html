Version 0.55.56 — Plan B RPPS : fallback automatique sur dump local Si l'API ANS plante (403, timeout, vide) → bascule transparente sur la copie locale du référentiel

Date : 31 mai 2026 Version : v0.55.56-alpha Tests : 1628 verts (+29) SQL : 2 patches

🎯 Le problème

L'API ANS officielle (gateway.api.esante.gouv.fr) bloque les IP Vercel en production avec un 403 Forbidden. Résultat sur la carte et la recherche praticien : "API ANS bloquée" partout, expérience cassée.

Demander à l'ANS de whitelister l'IP Vercel prendrait des semaines. Solution : avoir une copie locale du dump open data + fallback automatique transparent.

🔄 Comment ça marche

1. Requête /api/rpps L'app fait sa recherche normale comme avant (q=DUPONT, profession=Médecin…)
2. Tentative ANS La route appelle l'API ANS officielle (FHIR). Si OK → résultats avec source: "ANS FHIR"
3. Détection KO Si l'ANS répond 403/timeout/5xx OU répond OK mais 0 résultat utile…
4. Fallback dump local Appel RPC search_rpps_local() sur la table rpps_dump Supabase. Résultats avec source: "dump_local" + fallback_reason

Côté UI rien ne change : les résultats arrivent normalement, juste le badge "source" indique d'où ils viennent. Transparence totale pour l'utilisateur.

🗄 Architecture

Table rpps_dump

23 colonnes : RPPS (PK), nom, prénom, civilité, profession, spécialité, mode d'exercice, lieu (raison sociale, FINESS, adresse complète, INSEE commune, coords GPS), date d'extrait du dump source.

Indices

  • Full-text français (GIN to_tsvector) sur nom + prénom
  • Par profession, spécialité, CP, ville (lower), INSEE, coords
  • Index partiels where not null pour économiser l'espace

Fonctions RPC

RPCRôle
search_rpps_local(q, profession, cp, ville, limit)Recherche fallback côté serveur
rpps_dump_status()Statut : nb records, date extrait, dernier seed, âge en jours
upsert_rpps_dump_batch(rows jsonb)Insère 5 000 lignes en 1 appel (ON CONFLICT DO UPDATE)
rpps_dump_truncate()Vide la table avant un seed complet
rpps_dump_meta_update()Marque le statut idle/seeding/completed/failed

🛠 Pilotage : /admin/rpps-dump

Nouvelle page admin avec 4 sections :

  1. État du dump : KPI colorés (vert si frais < 60 jours, ambre si vieux, rouge si vide). Records, date d'extrait, dernier seed, âge en jours, statut, message
  2. Upload + seed CSV :
    • Téléchargement du dump depuis annuaire.sante.fr (~500 Mo mensuel)
    • Upload du fichier (parseur côté navigateur, supporte ;/,/\t auto-détection)
    • Mapping flexible des colonnes : trouve automatiquement RPPS, nom, prénom, profession, etc. dans les en-têtes
    • Truncate de la table avant seed pour repartir propre
    • Insertion par batchs de 5 000 lignes via RPC upsert_rpps_dump_batch
    • Progress bar live + log dépliable
  3. Test du fallback : tape une query, vois si la réponse a source: "ANS FHIR" ou "dump_local" + raison du fallback
  4. Pédagogie workflow : récap de comment ça marche

Accès : menu Administration → Dump RPPS (Plan B) (ti-database-import vert).

📋 Procédure de seed (1ère fois)

  1. Décompresser le zip, jouer les 2 patches SQL : 
    aveho-PATCH-vers-0.55.56.sql           -- table + indices + RPC search/status
aveho-PATCH-vers-0.55.56-rpc.sql       -- RPC upsert batch + truncate + meta update
  2. Push GitHub + redéploiement Vercel
  3. Aller sur annuaire.sante.fr/web/site-pro/extractions-publiques → télécharger le dump RPPS complet (CSV ~500 Mo)
  4. Aller dans l'app sur /admin/rpps-dump
  5. Cliquer "Parcourir" → sélectionner le CSV → "Lancer le seed"
  6. Attendre 3 à 10 minutes selon la taille (progress bar live)
  7. Test fallback : recherche "DUPONT" → vérifier que source: "dump_local" apparaît (ou ANS si débloqué)

Note : à refaire mensuellement (1× / mois suffit). Le ON CONFLICT DO UPDATE upserte propre — pas de doublons.
