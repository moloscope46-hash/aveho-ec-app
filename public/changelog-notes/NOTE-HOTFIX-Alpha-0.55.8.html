🐛 Diagnostic — Pourquoi la carte ne s'affichait pas en prod

Symptôme

Sur aveho-ec-app.vercel.app/carte : bandeau "4 mes étabs · 1 partenaires · 12 camions" affiché normalement, mais zone Leaflet en gris uni. En local dev : marchait. En prod : cassé.

Diagnostic via console F12 (merci Cédric ✌)

console.log("Leaflet présent ?", !!window.L);
// → true  ✓ Leaflet chargé

console.log("Map ref ?", document.querySelector("#map, .leaflet-container"));
// → null  ✗ aucune map Leaflet créée

// Mais le div container existe bien :
document.querySelectorAll('div').forEach(d => {
  if (d.className.includes('leaflet')) console.log('TROUVÉ:', d);
});
// → <div class="carte-leaflet-container" style="width:100%;background:rgb(227,233,238);display:block">

// Test manuel : créer la map à la main dans la div
const div = document.querySelector('.carte-leaflet-container');
const m = window.L.map(div).setView([46.5, 2.5], 6);
window.L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png').addTo(m);
// → ✓ La carte s'affiche !

Cause racine

L'ancien code avait 2 useEffect séparés :

  1. useEffect A — charge Leaflet (CSS + JS) → setLeafletReady(true)
  2. useEffect B — quand leafletReady change → crée la map avec L.map(mapRef.current)

En dev (Next dev server), l'ordre était : commit DOM puis effects → mapRef.current existait toujours quand B s'exécutait.

En prod buildée (avec optimisations webpack/React), l'ordre des effects et du commit DOM est différent : setLeafletReady(true) pouvait déclencher B avant que React n'ait commit la div → mapRef.current === null → return silencieux → carte jamais créée.

Classic race condition entre Leaflet (chargement async) et React (commit DOM async).

✅ Fix — Un seul useEffect patient

Tout est fusionné dans un seul useEffect qui :

  1. Charge Leaflet (CSS + JS) via dynamic import si pas déjà fait
  2. Attend activement que mapRef.current existe (boucle 50 × 60ms = max 3s)
  3. Crée la map + tileLayer + 3 layerGroups
  4. Marque setLeafletReady(true) → déclenche le 2e effect qui anime les camions

Code clé

useEffect(() => {
  if (typeof window === "undefined") return;
  let cancelled = false;
  
  (async () => {
    // 1. Charger Leaflet si pas déjà fait
    if (!window.L) {
      await import("leaflet/dist/leaflet.css");
      const L = (await import("leaflet")).default;
      delete L.Icon.Default.prototype._getIconUrl;
      L.Icon.Default.mergeOptions({ ... });
      window.L = L;
    }
    if (cancelled) return;

    // 2. ⏳ ATTENTE PATIENTE de mapRef.current (la clé du fix)
    let tries = 0;
    while (!mapRef.current && tries < 50) {
      await new Promise(r => setTimeout(r, 60));
      tries++;
    }
    if (cancelled || !mapRef.current) {
      console.error("[Carte] mapRef.current null après 3s, abandon");
      return;
    }
    if (mapInstanceRef.current) return;  // déjà init (HMR)

    // 3. Créer la map
    const L = window.L;
    const map = L.map(mapRef.current, { center: [46.7, 2.4], zoom: 6 });
    L.tileLayer("...").addTo(map);
    etabsLayerRef.current = L.layerGroup().addTo(map);
    camionsLayerRef.current = L.layerGroup().addTo(map);
    userPosLayerRef.current = L.layerGroup().addTo(map);
    mapInstanceRef.current = map;
    drawUserPosition();
    
    // 4. Marquer prêt → déclenche anim camions
    setLeafletReady(true);
  })();
  
  return () => { cancelled = true; };
}, []);

Pourquoi ça marche maintenant

  • Le while garantit qu'on n'init la map qu'une fois mapRef.current est posé
  • 3s max d'attente — bien plus que les ~100ms réels que React met à commit
  • cancelled évite double init en cas d'unmount rapide (HMR)
  • Un seul useEffect = pas de race entre 2 effects asynchrones

Réflexe 20 ajouté

Init lib qui dépend de DOM ref → un seul useEffect avec attente active de la ref. Le pattern "useEffect A pose un flag → useEffect B utilise la ref" est cassé en prod (ordre commit/effects différent). Toujours encapsuler dans un seul effect async qui boucle while (!ref.current) await sleep(50) jusqu'à max ~3s.
