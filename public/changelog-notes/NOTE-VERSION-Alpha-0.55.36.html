📸 1. Composant EtabPhoto — récupération auto via Wikipedia

Pourquoi Wikipedia plutôt que Google Places ?

  • Gratuit (Google Places facture par requête, ~$17 / 1000 req)
  • Pas de clé API à gérer/sécuriser
  • CORS OK avec origin=*
  • ~95% des hôpitaux, EHPAD et grosses cliniques sont sur Wikipedia FR avec photo
  • Les cabinets et petits commerces ne le sont pas → fallback gradient propre

L'API en un seul appel

https://fr.wikipedia.org/w/api.php
  ?action=query
  &generator=search          ← cherche par texte
  &gsrsearch=Hopital+Saint-Joseph+Paris
  &gsrlimit=1                ← 1 résultat suffit
  &prop=pageimages           ← inclut le thumbnail
  &pithumbsize=600           ← taille lisible bannière
  &format=json
  &origin=*                  ← CORS

Réponse : on extrait pages[0].thumbnail.source qui est l'URL de l'image.

⚡ 2. Cache 2 niveaux (mémoire + localStorage 7 jours)

  1. Mémoire RAM via Map() globale : évite les requêtes parallèles concurrentes pendant la session (si 5 cartes affichent le même étab, 1 seul fetch)
  2. localStorage avec TTL 7 jours : persiste entre rechargements/sessions
  3. Cache aussi les échecs (URL vide) pour ne pas re-demander "Hôpital X" qui n'est pas sur Wikipedia

Clé cache : nom|ville. Stockée en aveho:etab-photo:Hôpital Saint-Joseph|Paris.

🌀 Skeleton loader pendant la requête

Avant que la photo arrive, on affiche un skeleton animé (gradient 90deg qui défile) pour éviter le saut de mise en page :

@keyframes skeleton {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}

Le composant gère 3 états : loading (skeleton) · photo trouvée (image cover) · fallback (gradient + icône).
