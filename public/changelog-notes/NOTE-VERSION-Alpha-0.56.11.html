🔴 Bug 1 — CORS Edge Function invite-user

Erreur observée :
Access to fetch at 'functions/v1/invite-user' from origin 'aveho-ec-...vercel.app' has been blocked by CORS policy: Response to preflight request doesn't pass access control check: No 'Access-Control-Allow-Origin' header is present on the requested resource.

L'Edge Function invite-user ne gérait pas le preflight CORS. Quand l'app Vercel envoyait un POST cross-origin, le navigateur envoyait d'abord un OPTIONS qui était refusé (405) sans headers → blocage CORS définitif.

Fix appliqué

const CORS_HEADERS = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Methods": "POST, OPTIONS",
  "Access-Control-Allow-Headers": "authorization, x-client-info, apikey, content-type",
  "Access-Control-Max-Age": "86400",
};

const JSON_HEADERS = { "Content-Type": "application/json", ...CORS_HEADERS };

Deno.serve(async (req) => {
  if (req.method === "OPTIONS") {
    return new Response(null, { status: 204, headers: CORS_HEADERS });
  }
  // ... toutes les autres responses utilisent JSON_HEADERS
});

⚠️ Action requise : redéployer la fonction

cd C:\aveho-ec-app
supabase functions deploy invite-user

Sans ce redéploiement, le fix n'est pas actif en production. Le fichier corrigé est dans supabase/functions/invite-user/index.ts.

🟡 Bug 2 — Scanner QR (removeChild + play interrupted)

Erreurs observées :
NotFoundError: Failed to execute 'removeChild' on 'Node': The node to be removed is not a child of this node.
Cannot clear while scan is ongoing, close it first.
AbortError: The play() request was interrupted because the media was removed from the document.

Le composant QrScanner utilise html5-qrcode qui manipule directement le DOM video. Le cleanup useEffect appelait scanner.stop().finally(clear) mais html5-qrcode pouvait être dans un état intermédiaire (STATE_STARTING) → clear plantait + React démontait avant que la promesse stop soit résolue → removeChild échouait + play() interrompu.

Fix appliqué

Vérification de l'état via scanner.getState?.() avant chaque action :

const state = scanner.getState?.();
if (state === 2 || state === 3) {
  // STATE_SCANNING=2 ou STATE_PAUSED=3 → stop puis clear
  scanner.stop().then(() => scanner.clear()).catch(...);
} else {
  // Déjà stoppé ou pas démarré → clear direct (idempotent)
  scanner.clear().catch(() => {});
}

3 endroits corrigés : cleanup useEffect, callback onResult avec autoStop, switchCamera.

🟡 Bug 3 — Service Worker 503 Offline

Erreur observée :
qr:1 Failed to load resource: the server responded with a status of 503 (Offline)

Le SW interceptait les navigations vers /scan/qr et le 503 venait du fallback offline. Or le serveur répondait normalement — le 503 était une fausse alerte du SW.

Fix appliqué

Dans networkFirst, on retourne désormais la réponse réseau quelle que soit son statut (404, 500, etc.). Le fallback offline n'arrive plus que sur vraie panne réseau (catch). Avant, certaines réponses non-ok étaient remplacées par un 503 fictif.

Erreur observée : function max(uuid) does not exist. PostgreSQL n'a pas de fonction max() pour les UUID. Remplacé par sous-requête ORDER BY date_prescription DESC NULLS LAST LIMIT 1 qui prend la valeur de la prescription la plus récente. Plus propre et cohérent.
