🩹 2. Fix 404 prod membres_equipe

La table membres_equipe n'existe pas dans la base actuellement. Le composant UserAttachmentsInfo introduit en 0.58.36 provoquait un fetch 404 visible dans la console à chaque navigation.

Cause du bug : Supabase ne throw pas — il retourne { data: null, error }. Le try/catch ne catch jamais l'erreur, donc le fetch a déjà fait son 404 avant qu'on ne sache qu'il a échoué.

// 0.58.41 - app/components/UserAttachmentsInfo.js
useEffect(() => {
  if (!userId) return;

  // (a) Si on a déjà eu une erreur, on ne refetche pas dans cette session
  try {
    if (sessionStorage.getItem('av-attachments-disabled') === 'true') return;
  } catch {}

  let alive = true;
  (async () => {
    try {
      const { data: memb, error: e1 } = await supabase
        .from('membres_equipe')
        .select('equipe_id, equipes(id, nom, ...)');

      if (e1) {
        // (b) Erreur Supabase capturée correctement (table absente, RLS, etc.)
        //  → flag sessionStorage pour empêcher tout refetch dans la session
        try { sessionStorage.setItem('av-attachments-disabled', 'true'); } catch {}
        return;
      }
      if (!memb) return;
      // ... reste du code
    } catch {}
  })();
  return () => { alive = false; };
}, [userId]);

Résultat : le 404 reste visible une seule fois au premier load. Après, plus rien — le flag av-attachments-disabled bloque toutes les tentatives. Et au logout, le préfixe av- garantit la purge.

🩹 3. Fix build Vercel SSG : 3 pages

Erreur Vercel :

Error: @supabase/ssr: Your project's URL and API key are required to create a Supabase client!
Export encountered an error on /statistiques-activite/page
Export encountered an error on /consentements/page
Export encountered an error on /parametres/page
⨯ Next.js build worker exited with code: 1

Cause : createClient() appelé au top du composant React. Au prerender SSG, Next 15 exécute le module sans accès aux env vars → KO.

⚠ Piège évité : export const dynamic = "force-dynamic" ne fonctionne PAS dans un Client Component ("use client"). C'est uniquement pour les Server Components.

Solution : pattern Inner + Suspense wrapper (identique à 0.58.34 pour /etablissements).

// 0.58.41 - app/statistiques-activite/page.js (+ /consentements + /parametres)
"use client";
import { useEffect, useState, Suspense } from "react";  // ← +Suspense
import { createClient } from "../../lib/supabase";

// 1) Wrapper export default : empêche le SSG bail-out
export default function StatistiquesActivite() {
  return (
    <Suspense fallback={null}>
      <StatistiquesActiviteInner />
    </Suspense>
  );
}

// 2) Composant Inner : exécuté uniquement en CSR
function StatistiquesActiviteInner() {
  const supabase = createClient();  // ← maintenant OK (côté client)
  // ... tout le code existant inchangé
}

3 pages patchées : /statistiques-activite · /consentements · /parametres

📋 Pattern à retenir pour la suite

Pour les Client Components qui appellent createClient() ou useSearchParams() au top-level :

Pattern Fonctionne ?
❌ export const dynamic = "force-dynamic"NON (server component only)
❌ export const revalidate = 0NON (server component only)
✅ Inner + Suspense wrapperOUI (utilisé ici + 0.58.34)
✅ useState(null) + useEffect lazyOUI (alternative plus lourde)
