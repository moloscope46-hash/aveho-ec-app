🎯 Le concept

Quand Claude OCR une ordonnance et extrait un RPPS de prescripteur, on ne se contente pas de le stocker en texte brut. On le vérifie automatiquement contre l'annuaire ANS officiel (avec fallback dump local de 0.55.56), et :

  • Si le RPPS existe et les données OCR concordent → badge vert "Médecin vérifié"
  • Si le RPPS existe mais nom/spécialité différent → badge ambré "Divergences" avec comparaison côte à côte + bouton "Utiliser les données officielles"
  • Si le RPPS n'existe pas → badge rouge "RPPS inconnu" + recommandation vérif manuelle
  • Si le RPPS est invalide (pas 11 chiffres) → message clair

En plus, on construit un annuaire local de tous les médecins vus, enrichi à chaque ordonnance, avec stats de prescription auto-calculées par trigger SQL.

📋 Workflow complet

1. OCRClaude extrait RPPS + nom + spécialité de l'ordonnance
2. Affichage liveRppsVerifyBadge dans /scan/prescription
3. API vérifCompare OCR vs ANS (ou dump si ANS KO)
4. Créationupsert dans medecins_prescripteurs + link sur prescription

🩺 Composant RppsVerifyBadge

Réutilisable partout où on a un RPPS à vérifier. 5 états visuels avec des couleurs distinctes :

StatutAffichageAction proposée
LOADINGSpinner gris—
MATCHBadge vert + détails dépliablesVoir détails officiels
DIVERGENCESBadge ambré + comparaison OCR vs ANSBouton "Utiliser données officielles"
NOT FOUNDBadge rougeVérification manuelle
INVALIDBadge rouge (mauvais format)Corriger le RPPS

Le badge se déclenche automatiquement dès qu'un RPPS valide (11 chiffres) est saisi. Pas besoin de cliquer un bouton "vérifier".

🗄 Table medecins_prescripteurs

Cache local des médecins vus via OCR. 18 colonnes structurées :

  • Identification : rpps, nom, prenom, civilite
  • Profession : profession_libelle, specialite_libelle
  • Lieu d'exercice : raison_sociale_lieu, finess, adresse, cp, ville, code_insee_commune, telephone, email, latitude, longitude
  • Vérification : source_verification ('ANS FHIR' / 'dump_local' / 'manuel'), date_verification, est_verifie
  • Stats : nb_prescriptions, premiere_prescription_date, derniere_prescription_date

Contrainte unique intelligente

UNIQUE NULLS NOT DISTINCT (rpps, structure_id) — permet de créer plusieurs médecins sans RPPS (libéraux non identifiés, médecins étrangers, etc.) tout en évitant les doublons quand un RPPS est connu.

Trigger automatique

À chaque INSERT/UPDATE/DELETE sur prescriptions, le trigger trg_prescriptions_refresh_medecin recalcule automatiquement nb_prescriptions + dates première/dernière sur le médecin lié. Pas besoin de gérer ça côté app.

🤝 RPC upsert intelligent

upsert_medecin_from_ocr() applique la logique suivante :

  1. Priorité 1 : recherche par rpps + structure_id (clé forte)
  2. Priorité 2 : recherche par nom + prenom case-insensitive (clé faible)
  3. Si trouvé : UPDATE avec coalesce() pour enrichir les champs vides sans écraser les données existantes (sauf pour la vérification, où on garde la plus récente)
  4. Sinon : INSERT nouveau

Comportement : si tu scannes 3 ordonnances du Dr Martin avec des données partiellement différentes, le médecin sera enrichi à chaque passage sans perdre les informations précédemment validées.

⚠️ Limites

  • La vérification dépend de l'API ANS ou du dump local (Plan B 0.55.56). Si aucun des deux n'a de données pour ce RPPS, le statut sera "not_found"
  • La comparaison nom/spécialité est tolérante aux accents et à la casse, mais peut signaler des divergences sur des orthographes proches (ex : "MARIE-CLAUDE" vs "Marie Claude")
  • Les médecins sans RPPS (libéraux étrangers, anciens dossiers) restent dans l'annuaire mais ne peuvent pas être vérifiés automatiquement
