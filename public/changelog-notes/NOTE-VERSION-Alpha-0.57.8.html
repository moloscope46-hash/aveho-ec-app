🎨 Fix 1 — Quicksand via next/font

Avant 0.57.8, la police Quicksand était chargée via un <link> vers Google Fonts CDN dans le head. Problèmes :

  • 🔴 Round-trip réseau bloquant avant que le browser puisse rendre la page avec la bonne police
  • 🔴 FOUT/FOIT possible : la police par défaut s'affiche d'abord, puis swap → layout shift quand la police custom arrive
  • 🔴 Dépendance d'un service tiers (Google) qui peut être bloqué par certains FAI / firewall

Avant

// app/layout.js (Server Component)
export default function RootLayout({ children }) {
  return (
    <html lang="fr">
      <head>
        <link
          href="https://fonts.googleapis.com/css2?family=Quicksand:wght@400;500;600;700&display=swap"
          rel="stylesheet"
        />
        ...

Après

// app/layout.js (Server Component)
import "./globals.css";
import { Quicksand } from "next/font/google";

const quicksand = Quicksand({
  subsets: ["latin"],
  weight: ["400", "500", "600", "700"],
  display: "swap",
  variable: "--font-quicksand",
});

export default function RootLayout({ children }) {
  return (
    <html lang="fr" className={quicksand.variable}>
      <head>
        {/* Plus de <link> Google Fonts : next/font fait l'inline auto */}
        ...

Avantages :

  • ✅ Police téléchargée au build time et servie depuis le domaine Vercel (= même CDN que l'app)
  • ✅ Inline preload automatique dans le HTML généré
  • ✅ font-display: swap optimisé pour ne pas bloquer le rendu
  • ✅ 0 dépendance externe → aucun blocage CDN
  • ✅ Variable CSS --font-quicksand exposée pour usage dans globals.css

Particularité Next 15 : ssr:false interdit dans Server Component

Next 15 a une nouvelle restriction : next/dynamic avec ssr: false n'est plus autorisé dans un Server Component (= layout.js par défaut). Solution : déplacer les imports dynamic dans un Client Component séparé qui est monté depuis layout.js.

// app/LazyLayoutChrome.js
"use client";

import dynamic from "next/dynamic";

const InstallBanner = dynamic(() => import("./InstallBanner"), { ssr: false });
const KeyboardHelp = dynamic(() => import("./KeyboardHelp"), { ssr: false });
const VersionCheck = dynamic(() => import("./VersionCheck"), { ssr: false });
const AnnoncesBanner = dynamic(() => import("./AnnoncesBanner"), { ssr: false });
const FocusMode = dynamic(() => import("./FocusMode"), { ssr: false });
const GeolocPrompt = dynamic(() => import("./GeolocPrompt"), { ssr: false });
const BiometricOptInModal = dynamic(() => import("./BiometricOptInModal"), { ssr: false });
const FloatingActionBar = dynamic(() => import("./FloatingActionBar"), { ssr: false });

export default function LazyLayoutChrome() {
  return (
    <>
      <InstallBanner />
      <KeyboardHelp />
      ...
    </>
  );
}

🌐 Fix 3 — Preconnect Supabase

Ajout d'un tag <link rel="preconnect"> vers Supabase dans le head. Anticipe :

  • DNS lookup
  • TCP connection
  • TLS handshake

...en parallèle du téléchargement du HTML/JS de la page, plutôt que séquentiellement quand la 1ère requête arrive. Gain : ~100ms sur le TTFB de la 1ère query Supabase.

{process.env.NEXT_PUBLIC_SUPABASE_URL && (
  <link
    rel="preconnect"
    href={process.env.NEXT_PUBLIC_SUPABASE_URL}
    crossOrigin="anonymous"
  />
)}

Le tag est conditionnel : ne se rend que si la variable d'env est définie au build (sécurité pour dev/CI).
