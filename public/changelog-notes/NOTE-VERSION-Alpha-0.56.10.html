🎯 Le concept

Jusqu'à maintenant, pour avoir une vue d'ensemble santé d'un patient il fallait jongler entre plusieurs onglets de sa fiche d'édition (Sécu, Prescriptions, Médecin). La 0.56.10 introduit une page dashboard dédiée à /patient/[id]/dashboard qui consolide tout en une seule vue :

  • Header carte patient avec avatar initiales + âge calculé + ID administratif
  • Alertes contextuelles en haut (droits expirent, ALD sans commentaire, pas de caisse, prescriptions à renouveler...)
  • 5 KPI synthétiques (prescriptions, médicaments, médecins, renouvelables, dernière ordonnance)
  • Section Statut administratif (caisse rattachée, mutuelle, ALD/C2S/AME) avec badges expiration colorés
  • Liste des médicaments actuellement prescrits (statut active, dédupliqués par DCI)
  • Liste des médecins prescripteurs avec ContactActions tel/mail/GPS

🚨 Alertes contextuelles automatiques

5 types d'alertes générés automatiquement par la RPC patient_dashboard_alertes avec 3 niveaux de sévérité :

CRITIQUE
Droits sécu expirés depuis X jours
WARNING
Droits expirent dans <= 30 jours
WARNING
Aucune caisse renseignée
INFO
ALD sans commentaire renseigné
INFO
Prescription renouvelable > 60 jours

📊 4 RPC SQL agrégées

RPCRetour
patient_dashboard_summary 17 champs : compteurs prescriptions, médicaments, médecins, flags ALD/C2S/AME, droits + jours_avant_fin calculés, noms caisse/mutuelle
patient_dashboard_medicaments_actifs Liste dédupliquée par DCI (préférée) ou nom commercial via row_number() over partition, avec dernier dosage + posologie + nb_prescriptions (window count)
patient_dashboard_medecins Médecins groupés par nom case-insensitive, avec ville/tel/email récupérés depuis medecins_prescripteurs si lié (0.56.5), badge vérifié agrégé via bool_or
patient_dashboard_alertes 0 à 10 alertes contextuelles (sécu, mutuelle, ALD, caisse, renouvellement)

Toutes les RPC sont SECURITY DEFINER avec vérification d'accès via membres_structure. Chargées en parallèle depuis la page front pour temps de chargement minimal.

📐 Layout de la page

1. Header patient (gradient bleu marine)

Avatar circulaire 56px avec initiales (prénom[0] + nom[0]) + nom complet + âge calculé (365.25j) + métadonnées (n° dossier, date naissance, sexe, n° sécu en mono). Boutons "Éditer la fiche" et "Vue matériel" pour navigation rapide.

2. Alertes (si > 0)

Panneau ambré en haut avec composant AlerteRow par alerte. 3 niveaux visuels distincts (rouge critique / ambré warning / bleu info) + icône appropriée + badge sévérité en pill.

3. KPI dashboard (grid 5 cards)

Prescriptions (mis en évidence violet big) + Médicaments uniques + Médecins distincts + Renouvelables + Dernière ordonnance date. Chaque card affiche valeur principale + sub-label.

4. Statut administratif (3 StatutCards)

Caisse : nom + type + droits sécu jusqu'au + jours restants colorés. Badge MANQUANT rouge si null.
Mutuelle : nom + tiers payant actif + droits mutuelle.
Régimes spéciaux : Pills ALD rouge / C2S ambré / AME violet ou message vide italique + commentaire ALD si renseigné.

5. Médicaments actuellement prescrits

Bouton "Scanner une ordonnance" en haut. Liste avec dosage en code mono violet + badges DCI vert + Renouvelable vert + ×N si plusieurs prescriptions + posologie italique + commentaire ambré ALD.

6. Médecins prescripteurs

Liste avec badge Vérifié vert (si RPPS validé via ANS) + spécialité pill violet + ville + ContactActions intégrés (tel/mail/GPS depuis lib ContactActions de 0.56.4).

🔗 Intégration

Bouton "Dashboard santé" (icône ti-clipboard-heart) ajouté sur la fiche patient existante /patient/[id]/page.js juste avant "Édition complète". Permet d'accéder rapidement à la vue consolidée santé depuis la vue 360° matériel existante, sans casser le workflow existant.

Le dashboard reste accessible aussi directement via URL /patient/{uuid}/dashboard — pratique pour ajouter ce lien dans d'autres parties de l'app (notification, recherche globale, etc.).

🎨 Composants réutilisables ajoutés

  • Kpi : card KPI avec label uppercase + value gros + sub optionnel, prop big pour mise en évidence
  • Pill : badge arrondi coloré pour ALD/C2S/AME
  • StatutCard : card statut administratif avec badge expiration auto-coloré
  • AlerteRow : ligne d'alerte 3 niveaux (critique/warning/info) avec icônes appropriées
  • MedicamentRow : ligne médicament riche avec dosage mono + badges + posologie italique
  • MedecinRow : ligne médecin avec badge Vérifié + ContactActions intégrés

Ces composants sont locaux à la page dashboard pour l'instant. S'ils sont réutilisés ailleurs (ex: dashboard structure, vue famille), ils pourront être extraits dans un module app/dashboards/components.js en 0.56.11+.

⚠️ Limites connues

  • Dashboard non-éditable : la page est en lecture seule. Pour modifier les infos, l'utilisateur doit retourner sur la fiche d'édition (un bouton est prévu en haut)
  • 5 alertes max dans la catégorie "renouvellement" (limite codée en dur dans la RPC pour ne pas surcharger l'UI si beaucoup de prescriptions anciennes)
  • Pas de personnalisation des seuils : 30 jours pour les alertes droits sécu/mutuelle, 60 jours pour renouvellement. Configurables en 0.56.X+ si demande
  • Médecins sans medecin_prescripteur_id : si une prescription a été créée avant la 0.56.5 (sans lien vers la table medecins_prescripteurs), les champs ville/tel/email seront vides dans le dashboard. La RPC fallback retourne les infos disponibles mais sans ContactActions complets
