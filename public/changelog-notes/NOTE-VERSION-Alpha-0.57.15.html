🎭 Notes HTML : 4 versions couvertes

Pourquoi tester plusieurs notes HTML ? Parce qu'elles utilisent toutes le même template visuel (header avec dégradé, KPI cards, sections, footer). Si quelqu'un modifie le template sans intention, ça doit fail sur les 4 baselines simultanément.

  • NOTE-VERSION-Alpha-0.55.0.html — Première note avec template moderne
  • NOTE-VERSION-Alpha-0.56.20.html — Hardening sécurité (style identique attendu)
  • NOTE-VERSION-Alpha-0.57.0.html — Next 15 migration (dégradé bleu→vert)
  • NOTE-VERSION-Alpha-0.57.12.html — E2E Playwright (dégradé navy→violet→teal)

Chaque note a un dégradé différent dans son header (couleur unique par version), donc une régression CSS partagée serait détectée si la structure du header change (padding, margin, font-size, alignement) tout en gardant les couleurs personnalisées.

📐 Pattern : test.describe imbriqués pour les viewports

test.describe("Visual regression — Viewports multiples", () => {
  test.skip(({ browserName }) => browserName !== "chromium", "...");
  test.beforeEach(async ({ context }) => {
    await setupPopupsSkip(context);
  });

  // Sous-describe avec viewport spécifique
  test.describe("Tablette iPad (1024×768)", () => {
    test.use({ viewport: { width: 1024, height: 768 } });

    test("/login tablette landscape", async ({ page }) => {
      await page.goto("/login");
      await page.waitForLoadState("networkidle");
      await prepareForScreenshot(page);
      await expect(page).toHaveScreenshot("login-tablet-landscape.png", {
        fullPage: true,
        maxDiffPixels: 150,
      });
    });

    test("/mentions-legales tablette landscape", async ({ page }) => {
      // Hérite du viewport du describe parent
      ...
    });
  });

  test.describe("Mobile petit (iPhone SE 375×667)", () => {
    test.use({ viewport: { width: 375, height: 667 } });
    test("/login iPhone SE", async ({ page }) => { ... });
  });

  test.describe("Desktop large (1920×1080)", () => {
    test.use({ viewport: { width: 1920, height: 1080 } });
    test("/login desktop large", async ({ page }) => { ... });
  });
});

Le test.use({ viewport }) dans un describe imbriqué s'applique à tous les tests qui suivent dans CE describe. Permet d'éviter la duplication du setupPopupsSkip et du browserName !== "chromium" skip.

📑 Sections clipped pour les pages longues

Les screenshots fullPage sur des pages longues (5000+ px) sont instables : font-rendering subpixel produit ~10-30 px de variance entre 2 runs. Solution : clip sur les zones stables.

Pattern 1 : Clip absolu (zone fixe)

// Top de la page : header + 1ère section (stable)
await expect(page).toHaveScreenshot("mentions-section-editeur.png", {
  clip: { x: 0, y: 0, width: 1280, height: 1100 },
  maxDiffPixels: 200,
});

Pattern 2 : Scroll + viewport visible

// Scroll en bas, puis screenshot du viewport actuel (pas fullPage)
await page.evaluate(() => window.scrollTo(0, document.body.scrollHeight));
await page.waitForTimeout(300);
await expect(page).toHaveScreenshot("mentions-section-footer.png", {
  // Pas de clip ni de fullPage : capture le viewport tel quel
  maxDiffPixels: 200,
});
