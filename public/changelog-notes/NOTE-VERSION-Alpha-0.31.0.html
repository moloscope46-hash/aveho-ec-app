Résumé

La 0.31.0 ajoute le dashboard "qui fait quoi" de la collectivité. Pendant que la 0.30 répondait aux questions du DPO sur la conformité RGPD, la 0.31 répond à celles du manager / responsable :

  • Qui sont les utilisateurs les plus actifs ?
  • Qui sont les meilleurs validateurs ?
  • À quels moments de la semaine l'activité est-elle la plus forte ?
  • Quels établissements sont les plus dynamiques ?
  • Comment évolue l'activité jour par jour ?
Visibilité globale sur l'usage réel. Avant la 0.31, le manager pouvait voir l'activité d'un user dans son /profil personnel. Maintenant, /statistiques-activite donne une vue d'ensemble : qui pousse l'app, qui valide les workflows, quand les équipes sont actives. Utile aussi pour identifier les utilisateurs en difficulté (peu d'actions) ou les power users à valoriser.

1. Vues SQL d'agrégation

Toutes les vues s'appuient sur audit_log qui est la source de vérité unique. Pas de double comptabilité avec les tables métier — ce qui n'est pas tracé dans audit_log ne compte pas (et inversement, tout y est).

v_stats_activite_par_user

Une ligne par utilisateur × structure. Compteurs par entité créée (DI, achats, transferts, patients, matériels, maintenances) et par action workflow (validations, refus, réceptions, modifications). Compteurs glissants 7j / 30j / total + dernière action.

v_stats_activite_par_etab

Par établissement : DI, achats, transferts, maintenances, nb users distincts actifs, total actions 30j.

v_stats_activite_par_jour

90 jours glissants × structure (via generate_series). Une ligne par jour même sans activité. Compteurs DI / achats / transferts / signalements / total.

v_stats_activite_heatmap

Matrice jour de la semaine × heure sur les 90 derniers jours. Utilise extract(dow from created_at) (0=dim, 1=lun, ..., 6=sam) et extract(hour from created_at). Optimisé pour le composant Heatmap front.

v_stats_activite_top_actions

Top 20 des couples (action, entité) sur 90j. Pour identifier les flows dominants. Ex: "creer/intervention" 250 fois, "valider/achat" 80 fois.

2. Composant <Heatmap>

API

<Heatmap 
  data={[
    { jour_semaine: 1, heure: 9, nb_actions: 25 },
    { jour_semaine: 1, heure: 10, nb_actions: 42 },
    ...
  ]}
  color="#185FA5"
  cellSize={18}
/>

Caractéristiques

  • SVG natif — pas de lib externe, cohérent avec les autres charts
  • Réordonnancement : PostgreSQL renvoie 0=dim..6=sam, le composant affiche Lun→Dim (convention française)
  • Échelle logarithmique d'opacité : log10(nb+1) / log10(max+1). Évite que les pics extrêmes (200 actions à 14h le lundi) écrasent les autres valeurs. Une heure à 10 actions reste bien visible même si le max est à 200.
  • Tooltips natifs via <title> SVG : "Mer 14h : 23 actions"
  • Légende automatique en bas : dégradé moins → plus + valeur max
  • Responsive : scroll horizontal sur mobile (largeur min 600px)
  • Header heures affiché toutes les 3h pour la lisibilité (0h, 3h, 6h, 9h, 12h, 15h, 18h, 21h)

3. Page /statistiques-activite

Restriction admin

Même règle que /statistiques-rgpd : permission gerer_roles ou manage_collectivite ou rôle système admin / Administrateur.

Sélecteur période 7/30/90 jours

Boutons en haut de page qui recomposent tous les KPIs, le total d'actions, les utilisateurs actifs et le top utilisateurs en temps réel. Pas de re-fetch SQL : tout est calculé côté front à partir des données déjà chargées (les vues stockent les 3 compteurs nb_actions_7j, nb_actions_30j, nb_actions_total).

Sections affichées

  1. 4 KPIs : Utilisateurs actifs, Actions totales, Établissements actifs, Moyenne actions/user
  2. Podium top 3 : cartes colorées or/argent/bronze avec icône trophy/award/medal, email tronqué intelligemment, nb d'actions sur la période
  3. Suite du top (4-10) en jauges horizontales avec valeur relative au top 1
  4. 3 panneaux top par catégorie : Top demandeurs DI (bleu), Top demandeurs achats (orange), Top valideurs (vert) — chacun en jauges
  5. Heatmap 7×24 sur 90 jours glissants
  6. BarChart activité jour par jour sur la période sélectionnée
  7. Tableau par établissement avec couleurs cohérentes par type d'action
  8. Tableau complet utilisateurs (jusqu'à 50) avec scroll horizontal mobile : DI / Achats / Transferts / Validations / Modifs / 7j / 30j / Total / Dernière (time relative)
