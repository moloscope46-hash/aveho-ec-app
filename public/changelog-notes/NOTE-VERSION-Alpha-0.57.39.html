🔍 Diagnostic du bug en prod

Le symptôme

Sur /patient/[id] en prod : crash JavaScript Uncaught ReferenceError: Lbl is not defined dans le bundle minifié 515-23b922f2ca00f063.js.

La cause racine

app/patient/[id]/edit/tabs/TabSecu.js importait uniquement { Field, FieldSelect, Toggle } depuis ./_helpers, mais utilisait <Lbl> 2 fois dans le JSX (lignes 36 et 84).

// AVANT 0.57.39
import { Field, FieldSelect, Toggle } from "./_helpers";
//        ↑↑↑ Lbl manque ici !

function TabSecu({ ... }) {
  return (
    <>
      <Lbl>Caisse d'affiliation</Lbl>             // ← crash
      ...
      <Lbl>Organisme complémentaire</Lbl>        // ← crash
    </>
  );
}

Pourquoi ça n'avait pas crashé en dev ?

  • En dev Next.js, certains imports/exports sont mis en cache et le HMR peut masquer ce genre d'erreurs
  • En build prod minifié, chaque chunk est strictement encapsulé → Lbl introuvable → crash
  • Les erreurs 400 Supabase qui suivaient (consentements_rgpd + interventions) étaient des conséquences du crash React : useEffect annulés en plein vol → paramètres undefined dans les queries

✅ Le fix

Fix 1/2 : TabSecu.js (bug en prod)

// 0.57.39 - Lbl ajouté dans l'import
import { Lbl, Field, FieldSelect, Toggle } from "./_helpers";
//          ↑↑↑ NEW : Lbl maintenant disponible

Fix 2/2 : maintenance/page.js (bug latent)

Trouvé via audit exhaustif : app/maintenance/page.js utilisait <IconButton> 3 fois sans l'importer. Pas encore crashé en prod mais aurait crashé dès qu'un user avec droits "ecrire" ouvrait /maintenance.

// AVANT 0.57.39
import { PageHead, Panel, StateMsg, Modal, Btn } from "../ui";

// 0.57.39
import { PageHead, Panel, StateMsg, Modal, Btn, IconButton } from "../ui";
//                                              ↑↑↑↑↑↑↑↑↑↑↑

🔒 22e LINT anti-régression CRITIQUE

Le plus important de cette release : un test qui empêche définitivement ce genre de bug d'arriver à nouveau.

// __tests__/v057-39-hotfix-lbl-iconbutton.test.js
const UI_COMPONENTS = new Set([
  "PageHead", "Panel", "StateMsg", "Modal", "Btn",
  "IconButton", "FilterBar", "Pill", "Spinner",
  "Empty", "ErrorBox",
]);
const HELPER_COMPONENTS = new Set([
  "Lbl", "Field", "FieldSelect", "FieldCheckbox",
  "Toggle", "KvBlock",
]);

it("Aucun composant connu utilisé sans import", () => {
  for (const page of findPages()) {
    const src = fs.readFileSync(page, "utf-8");

    // 4 patterns d'import reconnus :
    // (a) import X from
    // (b) import { A, B } from
    // (c) import X, { A, B } from
    // (d) export (default) (function|const|class) X

    const imported = collectImports(src);
    const used = collectJsxUsage(src, ALL_KNOWN);

    for (const comp of used) {
      if (!imported.has(comp)) violations.push(...);
    }
  }
  expect(violations).toEqual([]);
});

Si un futur dev (humain ou IA) ajoute <PageHead /> dans une page sans importer PageHead → npm test FAIL avant le push. Le bug ne peut plus arriver en prod.
