🐛 Bug 1 — Renvoyer invitation 400

Erreur observée :
{ "ok": false, "error": "inviteLink manquant (doit être fourni par l'app appelante)", "diagnostic": "missing_invite_link" }

La fonction relancerInvitation dans app/utilisateurs/page.js appelait supabase.functions.invoke("invite-user") sans inclure le lien d'inscription dans le body, alors que l'Edge Function le rend obligatoire.

Fix appliqué

// 0.56.13 : reconstruction de l'inviteLink depuis i.token
const siteUrl = window.location.origin;
const inviteLink = `${siteUrl}/inscription/${i.token}`;

await supabase.functions.invoke("invite-user", {
  body: { email, nom, collectivite, role, etablissements, inviteLink }
});

Bonus : gestion propre du retour error/data avec lecture du context.body pour afficher le détail Resend si erreur.

🐛 Bug 2 — Colonnes caisses mal nommées

Erreurs identifiées via SQL audit :
La table caisses_assurance_maladie utilise type_caisse (pas type) et cp (pas code_postal). Même problème que pour mutuelles (cf 0.56.12).

Fix appliqué

  • Page referentiels-sante : affichage caisses utilise item.type_caisse || item.type. Init création utilise type_caisse: "CPAM". Form select écrit dans entity.type_caisse. Field code postal utilise cp
  • API /api/caisses : POST insère type_caisse + cp avec mapping depuis les anciens noms. PUT remappe automatiquement
  • SQL 0.56.10 : (select type_caisse from caisses_assurance_maladie...) au lieu de (select type ...)
  • fillFromBAN simplifié : un seul set avec cp pour les 2 tables (les 2 utilisent cp en réalité)
