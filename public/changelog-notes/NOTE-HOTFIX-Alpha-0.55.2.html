Pourquoi le 0.55.1 n'a pas suffi

Le hotfix 0.55.1 a corrigé uniquement le badge NEW dans le drawer menu. Mais le mismatch d'hydratation venait de plusieurs sources dans TopBar :

  • Le badge NEW (fixé en 0.55.1)
  • Le compteur panier dans les menu-tiles ({cnt > 0 && <span>...</span>} où cnt vient de localStorage)
  • Le bouton de recherche globale ({auth && <button>...</button>})
  • Le switch d'établissement ({auth && auth.etablissements?.length && ...})
  • La cloche de notifications ({auth && <NotifBell />})
  • Le bouton panier (avec compteur dynamique)
  • Le menu utilisateur ({auth && <UserMenu />})

Précision sur le message d'erreur React

Le message "Expected server HTML to contain a matching <i> in <span>" signifie :

« React s'attendait à trouver un <i> à l'intérieur d'un <span> à cette position (basé sur le rendu CLIENT), mais le HTML envoyé par le serveur n'en a pas. »

Donc : côté client il y a un <span><i/></span> (l'icône mt-ic du menu-tile) là où côté serveur il y a juste <span>NEW</span> (le badge NEW). La position du <span> dans le <button> est différente selon que showNew est true ou false.

Le fix structurel — guard mounted partout

const [mounted, setMounted] = useState(false);
useEffect(() => { setMounted(true); }, []);

// Tous les éléments dépendant de auth ou du panier 
// sont maintenant entourés par {mounted && ...} :
{mounted && auth && <button className="tb-icon">...</button>}
{mounted && auth && auth.etablissements?.length > 0 && (...)}
{mounted && auth && <NotifBell ... />}
{mounted && (
  <button className="tb-icon" onClick={...}>
    <i className="ti ti-shopping-cart" />
    {cartCount > 0 && <span className="tb-badge">{cartCount}</span>}
  </button>
)}
{mounted && auth && <UserMenu auth={auth} />}

// Dans le drawer :
const cnt = mounted && it.count === "cart" ? cartCount : 0;
const showNew = mounted && isPageNew(it.p);

✅ Validation par diff SSR vs DOM

Test exécuté en mode production (npm run start) avec curl sur 3 pages — vérification que le HTML rendu côté serveur ne contient AUCUN élément dynamique :

=== /etablissement/fiche ===
  tb-icon dans le HTML SSR : 0  ✓
  badges NEW dans HTML SSR : 0  ✓
=== /changelog ===
  tb-icon dans le HTML SSR : 0  ✓
  badges NEW dans HTML SSR : 0  ✓
=== /carte ===
  tb-icon dans le HTML SSR : 0  ✓
  badges NEW dans HTML SSR : 0  ✓

Donc au premier render après hydratation, le DOM client est identique au HTML serveur (mounted=false des deux côtés) → plus AUCUN mismatch possible. Une fois mounted passe à true via useEffect (qui ne s'exécute QUE côté client), les éléments apparaissent sans erreur React.

Réflexe 18 confirmé

Le réflexe ajouté en 0.55.1 reste pertinent et même renforcé :

Tout composant qui dépend de navigator, window, localStorage, ou de tout état async (auth, panier, fetch initial) doit être guard par un state mounted. Sinon → mismatch hydratation garanti dès que le SSR diffère du DOM client après hydratation.
