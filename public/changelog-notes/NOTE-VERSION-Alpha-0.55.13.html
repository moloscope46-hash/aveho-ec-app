🎯 Le concept

Sur mobile, taper un mot de passe à chaque connexion est fastidieux. Après cette version, l'utilisateur peut activer la connexion par empreinte digitale (ou Face ID, Touch ID, empreinte Android, Windows Hello) en 1 clic.

Le flow :

  1. L'user se connecte une première fois avec son mot de passe (depuis mobile)
  2. Une modale apparaît automatiquement 1,5s après : « Activer la connexion par empreinte ? »
  3. Il clique "Activer" → l'OS prompte son empreinte → c'est validé
  4. À la prochaine connexion, dès qu'il saisit son email, un bouton « Se connecter avec mon empreinte » apparaît
  5. 1 tap + empreinte → connecté en moins d'une seconde

🛠 Architecture pragmatique

Approche retenue

Le standard WebAuthn complet impose une vérification serveur des signatures (CBOR + COSE keys + ECDSA/RSA verify), ce qui nécessite une Edge function complexe avec lib @simplewebauthn/server. Pour Aveho, on a opté pour une approche plus pragmatique inspirée des apps banque PWA :

Le credential WebAuthn sert de preuve de présence physique (l'OS valide l'empreinte côté navigateur, sans réseau).
Après cette preuve, on rétablit la session Supabase via un refresh_token stocké localement dans IndexedDB (protégée par l'origin du site).

Sécurité

  • L'empreinte ne quitte jamais l'appareil (l'OS la garde dans le Secure Enclave / TPM)
  • navigator.credentials.get() ne réussit que si l'empreinte est validée par l'OS
  • IndexedDB est isolée par origin (un autre site ne peut pas y accéder)
  • Si quelqu'un vole le téléphone déverrouillé, il doit aussi avoir l'empreinte → double facteur naturel
  • Le refresh_token tourne automatiquement (Supabase) — chaque utilisation regénère un nouveau token
  • Si le refresh_token expire (inactivité prolongée), l'IndexedDB locale est purgée et on force le re-login password

Limites assumées

  • Pas de vérification de signature serveur (pas nécessaire pour notre niveau de sensibilité)
  • Chaque appareil enregistre son propre credential — pas de synchronisation entre devices (c'est voulu pour la sécurité)
  • Pour activer sur un nouvel appareil, l'user doit d'abord se connecter avec son mot de passe

🗄 Chantier SQL — Patch 0.55.13

Table webauthn_credentials

create table if not exists webauthn_credentials (
  id              uuid primary key default gen_random_uuid(),
  user_id         uuid references auth.users(id) on delete cascade,
  structure_id    uuid references structures(id) on delete cascade,
  credential_id   text not null,        -- base64url du rawId WebAuthn
  device_name     text,                  -- "iPhone de Marie"
  user_agent      text,                  -- aide à identifier l'appareil
  created_at      timestamptz default now(),
  last_used_at    timestamptz,
  active          boolean default true,
  unique (user_id, credential_id)
);

RLS

  • SELECT/INSERT/UPDATE/DELETE propre user (user_id = auth.uid())
  • SELECT admin structure (pour audit + révocation)

RPC

  • update_webauthn_last_used(p_credential_id text) — mise à jour atomique du timestamp à chaque login bio
  • revoke_webauthn_credential(p_credential_uuid uuid) — désactivation avec garde-fou ownership

Vue

v_my_webauthn_credentials — liste des credentials actifs du user courant avec total_devices via window function.

📱 Chantier UI — Le flow utilisateur

1. Modale opt-in post-login

Composant BiometricOptInModal monté dans le layout global. S'affiche automatiquement après une connexion réussie si :

  • Mobile détecté (userAgent ou maxTouchPoints + viewport étroit)
  • WebAuthn supporté + platform authenticator dispo
  • Pas de credential déjà enregistré pour cet email sur ce device
  • User n'a pas refusé/skippé il y a moins de 7 jours (localStorage)

Design : modale plein écran sur mobile, gradient bleu, icône empreinte 72px, 3 arguments ("Connexion rapide", "Plus sécurisé", "Mot de passe toujours possible"), input éditable pour le nom de l'appareil, boutons "Activer maintenant" / "Plus tard".

2. Bouton sur /login

Apparaît au-dessus du champ mot de passe dès que l'email saisi a un credential local enregistré. Bouton gradient bleu/teal avec icône empreinte 22px et hauteur tactile 48px.

Au clic : navigator.credentials.get() → l'OS prompte l'empreinte → refresh session Supabase → redirect /vue-globale.

3. Section /profil → Connexion par empreinte

Composant BiometricSection dans une CollapsibleSection :

  • Bandeau d'état de l'appareil courant (vert si activé, jaune sinon)
  • Bouton "Activer maintenant" si pas encore activé
  • Liste des appareils enregistrés (avec dates ajout + dernière utilisation)
  • Badge "CET APPAREIL" sur celui dont l'user_agent matche
  • Bouton "Désactiver" par appareil (confirm + RPC revoke)

🧪 Test à faire

Prérequis : utiliser un téléphone (iPhone/iPad avec Touch ID ou Face ID, ou Android récent avec empreinte). HTTPS obligatoire pour WebAuthn → tester sur aveho-ec-app.vercel.app (pas en localhost).

  1. Sur ton mobile, ouvre aveho-ec-app.vercel.app
  2. Connexion classique email + mot de passe
  3. Après quelques secondes, la modale "Activer la connexion par empreinte ?" apparaît
  4. Personnalise le nom de l'appareil ("iPhone Cédric") → "Activer maintenant"
  5. L'OS prompte l'empreinte → tu valides
  6. Message "Empreinte activée !" → modale se ferme
  7. Va dans Profil → Connexion par empreinte → tu vois ton device dans la liste
  8. Test du login : déconnecte-toi → reviens sur /login
  9. Saisis ton email → le bouton "Se connecter avec mon empreinte" apparaît automatiquement (gradient bleu/teal)
  10. Clic → empreinte → tu es connecté instantanément sur /vue-globale ✓
  11. Test révocation : dans Profil → liste appareils → "Désactiver" → confirme → l'appareil disparaît, prochain login devra utiliser mot de passe

⚠ Notes de compatibilité

  • HTTPS obligatoire : WebAuthn ne marche qu'en HTTPS (ok sur Vercel, KO en localhost — fallback gracieux : bouton caché)
  • Safari iOS : supporte Touch ID + Face ID depuis iOS 14
  • Chrome Android : supporte empreinte digitale
  • Edge/Chrome desktop : Windows Hello supporté mais l'utilité est moindre
  • Firefox : support partiel — la modale opt-in détecte et se masque proprement si pas dispo
