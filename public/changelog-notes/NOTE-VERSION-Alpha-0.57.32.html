🛡️ Les 3 protections cumulées

1️⃣ Validation UUID stricte (anti path-traversal)

Avant le fix, buildPath assemblait directement les IDs dans le chemin Supabase Storage. Si demain quelqu'un appelait buildPath("../other-structure", ...), le path serait "../other-structure/patientId/..." → traversée de path possible.

// AVANT 0.57.32
export function buildPath(structureId, patientId, originalFilename) {
  const ts = Date.now();
  const safe = sanitizeFilename(originalFilename);
  return `${structureId}/${patientId}/${ts}-${safe}`;
  //       ↑↑↑↑↑↑↑↑↑↑↑↑
  //       Si structureId = "../other-structure", path traversal !
}

// 0.57.32 - validation stricte
const UUID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

function isValidUuid(id) {
  return typeof id === "string" && UUID_RE.test(id);
}

export function buildPath(structureId, patientId, originalFilename) {
  if (!isValidUuid(structureId)) {
    throw new Error("structureId invalide (UUID requis)");
  }
  if (!isValidUuid(patientId)) {
    throw new Error("patientId invalide (UUID requis)");
  }
  // ... safe
}

2️⃣ Whitelist MIME (anti upload HTML/JS/exe)

Avant : contentType: file.type || "application/octet-stream" → on acceptait n'importe quel type, y compris HTML/JS qui pouvaient ensuite être servis via signed URL (XSS via download).

// 0.57.32 - whitelist stricte
const ALLOWED_MIMES = [
  "image/jpeg", "image/png", "image/webp", "image/gif", "application/pdf"
];

const mime = file.type || "application/octet-stream";
if (!ALLOWED_MIMES.includes(mime)) {
  return { error: `Type de fichier non supporté : ${mime}` };
}

3️⃣ Taille max 10 MB (anti-DoS + facturation)

Avant : pas de check. Un attaquant pouvait uploader des fichiers énormes (DoS + facturation Supabase Storage qui explose).

// 0.57.32 - limite stricte
const MAX_FILE_SIZE = 10 * 1024 * 1024;  // 10 MB

if (file.size > MAX_FILE_SIZE) {
  return { error: `Fichier trop volumineux (max ${MAX_FILE_SIZE / 1024 / 1024} MB)` };
}
