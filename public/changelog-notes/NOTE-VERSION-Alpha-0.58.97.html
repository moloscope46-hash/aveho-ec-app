🐛 Bug #1 : React error #418 (hydration mismatch sur /profil)

La section "Mode de démarrage" dans /profil lisait localStorage.getItem('av-launch-mode') directement dans le JSX. Server (sans localStorage) → rendait vide. Client → rendait du texte. Différent = crash hydratation.

- {typeof window !== 'undefined' && (
-   <> Mode actuel : <b>{localStorage.getItem('av-launch-mode') === 'mobile' ? '📱' : '💻'}</b></>
- )}
+ const [launchMode, setLaunchMode] = useState(null);
+ useEffect(() => { setLaunchMode(localStorage.getItem('av-launch-mode')); }, []);
+ {launchMode !== null && <> Mode actuel : <b>...</b></>}

🐛 Bug #2 : useEffect manquant dans l'import

Le fichier app/mobile/patient/new/page.js utilisait useEffect mais l'import était resté à import { useState }. Conséquence : chaque build Vercel échouait à la fin du prerender avec ReferenceError: useEffect is not defined. Cédric était bloqué en 0.58.92 avec tous ses fix successifs (0.58.93→0.58.96) jamais déployés.

- import { useState } from "react";
+ import { useState, useEffect } from "react";

📋 Pattern à retenir

Jamais lire localStorage / window / Date.now() directement dans le rendu JSX. Toujours initialiser un state vide puis le remplir dans un useEffect. Le useEffect ne tourne que côté client → SSR initial reste vide → pas de mismatch.
