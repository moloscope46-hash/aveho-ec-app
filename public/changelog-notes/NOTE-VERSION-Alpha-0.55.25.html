🗄 Patch SQL 0.55.25

Colonnes ajoutées sur invitations

alter table invitations
  add column if not exists etablissement_ids uuid[] default '{}'::uuid[],
  add column if not exists groupement_id uuid,
  add column if not exists lock_assignment boolean not null default true,
  add column if not exists matricule text,
  add column if not exists date_arrivee date,
  add column if not exists notes_admin text;

Colonnes ajoutées sur membres_structure

alter table membres_structure
  add column if not exists matricule text,
  add column if not exists date_naissance date,
  add column if not exists contact_urgence_nom text,
  add column if not exists contact_urgence_tel text,
  add column if not exists adresse text,
  add column if not exists specialite text,
  add column if not exists diplome text,
  add column if not exists date_fin_contrat date,
  add column if not exists locked_fields jsonb not null default '{}'::jsonb;

Vue v_user_complete

Combine membres_structure + compteurs webauthn (bio_devices_count, has_empreinte, has_face) pour faciliter les requêtes admin.

RPC reset_user_password

Vérification admin via droits.parametres_admin, journalisation dans app_logs, retourne l'email pour qu'on puisse l'envoyer via Edge Function ou Supabase Dashboard.

RPC get_invitation_full

Version étendue de get_invitation_preview qui ramène en plus etablissement_ids, lock_assignment, matricule, date_arrivee. Fallback automatique côté JS sur l'ancienne RPC si SQL pas passé.

📨 UI invitation enrichie

Bloc "Rattachement aux établissements"

Dans la modale "Inviter un utilisateur", après le rôle, un nouveau bloc apparaît avec :

  • Pills cliquables pour chaque établissement de la structure — clic pour sélectionner/désélectionner, fond bleu si sélectionné
  • Checkbox "Verrouiller le rattachement" (cochée par défaut) avec sous-texte explicatif : "L'utilisateur verra les établissements mais ne pourra pas les modifier"

Bloc "Informations RH"

  • Champ Matricule (ex. 0042) pour les structures qui en utilisent un
  • Champ Date d'arrivée (date picker) pour pré-remplir la date d'embauche
  • Champ Notes internes textarea visible uniquement par les admins

📝 Page d'inscription : champs lockés visibles

Quand le user reçoit son lien et arrive sur /inscription/[token], il voit maintenant :

  • Email + rôle (déjà avant) + matricule + date d'arrivée si pré-remplis
  • Si etablissement_ids non vide → nouveau bloc "Rattachement aux établissements" :
    • Badge bleu VERROUILLÉ avec icône cadenas si lock_assignment=true
    • Liste des établissements en pills (lecture seule, icône check vert)
    • Message explicatif : "Ces rattachements ont été définis par l'administrateur et ne peuvent pas être modifiés"
    • Si lock_assignment=false → message alternatif : "Vous pourrez ajuster ces rattachements depuis votre profil"

👤 Fiche utilisateur enrichie

Dans la modale d'info user (page /utilisateurs → clic sur un user), 2 nouvelles sections dépliables (<details>) :

📇 Informations RH étendues

  • Matricule interne + Date de naissance
  • Spécialité (ex. Cardiologie) + Diplôme (ex. IDE Bac+3)
  • Adresse postale sur une ligne
  • Contact d'urgence (nom) + (tél)
  • Date de fin de contrat (CDD, intérim, etc.)

🛠 Actions administrateur

Bloc dépliable jaune avec :

  • Bouton rouge "Réinitialiser mot de passe" — déclenche la RPC reset_user_password, vérifie les droits admin et journalise dans app_logs
  • Bouton bleu "Envoyer un email" — ouvre mailto:{email}
