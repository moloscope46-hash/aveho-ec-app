❌ Les bugs 0.55.36

Bug 1 : Version 0.1 hardcoded dans le login

Le popup de connexion affichait Version Alpha 0.1 en dur depuis des mois, alors qu'on est en 0.55.36. Bug visuel embarrassant.

Bug 2 : RPPS 'lacroix' renvoie 403

GET /api/rpps?q=lacroix&limit=50
→ API ANS HTTP 403

L'API ANS rejette certains noms via le paramètre family= avec un 403 (peut-être un caractère interdit, peut-être un filtre interne). Sur des noms similaires (DUPONT, MARTIN…) ça marche, mais sur Lacroix ça plante.

2. Retry FHIR : name= si family= plante

// 1ère requête (family)
GET /Practitioner?family=lacroix
→ 403 Forbidden

// 2ème tentative auto (name) si 403/400 et q ≥ 2 chars
GET /Practitioner?name=lacroix
→ 200 OK

Le paramètre FHIR name= est plus permissif et cherche dans l'ensemble des champs name (family + given). Beaucoup plus tolérant que family=.

Si même name= échoue : message clair "API ANS HTTP 403. Essayez avec un autre nom ou ajoutez un critère (ville, profession)."

📍 AddressAutocomplete INSEE partout

Composant existant réutilisé

Le composant AddressAutocomplete.js existe depuis 0.54.0 et utilise l'API BAN INSEE (api-adresse.data.gouv.fr, gratuite, sans clé). Il était utilisé uniquement dans /etablissement/fiche.

Intégrations 0.55.37

  1. /etablissements-partenaires (modale création/édition) : le champ "Adresse" devient autocomplété. À la sélection d'une suggestion, remplit automatiquement adresse + cp + ville + latitude + longitude (utiles pour la carte et le GPS)
  2. /utilisateurs (fiche détaillée user, onglet info personnelle) : le champ "Adresse postale" devient autocomplété

Sur chaque champ, un badge vert discret "(autocomplétée INSEE)" à côté du label pour rassurer l'utilisateur que la donnée sera propre.

Pourquoi BAN INSEE plutôt que Google Places ?

  • Gratuit, libre accès, sans clé API
  • Couverture France exhaustive (toutes les adresses de la Base Adresse Nationale)
  • Données officielles (gouvernementales)
  • Données structurées : code postal, ville, lat/lng séparés
