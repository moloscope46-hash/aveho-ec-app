🔧 BUG FIX #1 : 504 Gateway Timeout SW silencé

Symptôme prod observé :

Failed to load resource: the server responded with a status of 504 (Gateway Timeout)

Le SW retournait explicitement Response('', { status: 504 }) ce qui ajoutait une ligne d'erreur supplémentaire dans la console.

Fix 0.58.24 : remplacer le return new Response(... 504 ...) par throw e. Le browser logge alors UNE SEULE fois "Failed to load" (au lieu du combo 504 + FetchEvent error).

❌ AVANT 0.58.24
Failed to load resource: 504
FetchEvent network error response
→ 2 erreurs visibles
✅ APRÈS 0.58.24
Failed to load resource
→ 1 seule erreur native
→ Next.js retry tout seul
// 0.58.24 - public/sw.js
// AVANT - 504 explicite (bruyant)
return new Response('', {
  status: 504,
  statusText: 'Gateway Timeout',
  headers: { 'Content-Type': 'text/plain' },
});

// APRÈS - throw natif (silencieux)
try {
  // ... fetch + retry + fallback offline HTML ...
} catch (e) {
  throw e;  // re-throw, browser logge naturellement
}

🔧 BUG FIX #2 : 403 audit_log RLS géré

Symptôme prod observé :

POST https://rnvlzddgxiuslgljkobm.supabase.co/rest/v1/audit_log 403 (Forbidden)

La RLS Supabase sur la table audit_log rejette les inserts depuis le client authentifié. Le client Supabase JS log automatiquement avant que le code puisse catcher.

Fix 0.58.24 — DOUBLE :

  • Côté code (lib/events.js) : détecte le 403 RLS (code 42501) et log UNE SEULE FOIS un warning diagnostic au lieu d'un stack trace bruyant.
  • Côté base (à exécuter en SQL Editor) : nouveau fichier scripts/SQL-FIX-audit_log-rls-0.58.24.sql qui crée la policy audit_log_insert_v2 correcte.
// 0.58.24 - lib/events.js (silent + diagnostic)
try {
  const { error } = await supabase.from('audit_log').insert({...});
  if (error) {
    // Spécifiquement pour 403 RLS : log discret (warn) sans stack
    if (error.code === '42501' || /forbidden|policy|RLS/i.test(error.message || '')) {
      // ⚠ Affiché UNE SEULE FOIS (via window._audit_log_warned_)
      if (typeof window !== 'undefined' && !window._audit_log_warned_) {
        window._audit_log_warned_ = true;
        console.warn(
          '[audit_log] RLS bloque les inserts. ' +
          'Exécutez scripts/SQL-FIX-audit_log-rls-0.58.24.sql en base.'
        );
      }
    } else {
      logger.warn('logEvent - audit échoué :', error.message);
    }
  }
} catch (e) {
  logger.warn('logEvent - audit exception :', e?.message || e);
}

🛠 SQL à exécuter en base — FIX DÉFINITIF du 403

⚠ ACTION REQUISE : ouvrir le SQL Editor Supabase et exécuter ce script. Sans ça, le 403 continuera (juste silencé côté code).

Projet Supabase : rnvlzddgxiuslgljkobm

-- scripts/SQL-FIX-audit_log-rls-0.58.24.sql

-- 1. Drop des anciennes policies INSERT (au cas où)
DROP POLICY IF EXISTS "audit_log_insert_authenticated" ON audit_log;
DROP POLICY IF EXISTS "audit_log_insert" ON audit_log;
DROP POLICY IF EXISTS "Authenticated users can insert audit_log" ON audit_log;

-- 2. Créer la policy INSERT permissive mais sécurisée
CREATE POLICY "audit_log_insert_v2" ON audit_log
FOR INSERT
TO authenticated
WITH CHECK (
  -- L'user_id doit correspondre à l'utilisateur connecté
  user_id = auth.uid()
  AND
  -- La structure_id doit appartenir à l'user (via membres_structures)
  EXISTS (
    SELECT 1 FROM membres_structures
    WHERE membres_structures.user_id = auth.uid()
      AND membres_structures.structure_id = audit_log.structure_id
      AND (membres_structures.archive IS NULL OR membres_structures.archive = false)
  )
);

-- 3. Activer RLS si pas déjà actif
ALTER TABLE audit_log ENABLE ROW LEVEL SECURITY;

-- 4. Vérification
SELECT policyname, cmd, with_check
FROM pg_policies WHERE tablename = 'audit_log';

// 0.58.24 - app/profil/page.js
import { isPresentationMode, togglePresentationMode } from '../../lib/presentationMode';

function PresentationModeToggle() {
  const [isOn, setIsOn] = useState(false);
  useEffect(() => {
    setIsOn(isPresentationMode());
    // Sync avec le shortcut Ctrl+Shift+P qui dispatch cet event
    function onChange(e) { setIsOn(e?.detail?.on ?? isPresentationMode()); }
    window.addEventListener('av-presentation-mode-change', onChange);
    return () => window.removeEventListener('av-presentation-mode-change', onChange);
  }, []);

  return (
    <NeonButton
      variant={isOn ? 'amber' : 'violet'}
      icon={isOn ? 'ti-presentation-analytics' : 'ti-presentation'}
      onClick={() => setIsOn(togglePresentationMode())}
    >
      {isOn ? 'Désactiver le mode présentation' : 'Activer le mode présentation'}
    </NeonButton>
  );
}

// Dans /profil onglet Sécurité, après 'Ma session' :

  <PresentationModeToggle />
  <p>💡 Raccourci : <kbd>Ctrl+Shift+P</kbd></p>
</Panel>
