LockBanner dans composant Crud générique (app/crud.js)

🔒 ajout prop optionnelle lockResource (ex: "materiel", "patient"). Quand fournie : hook useEditLock(lockResource, modal?.id, !!lockResource && !!modal?.id) actif. JSX LockBanner placé en haut du modal-body juste avant les err display. Imports ajoutés via sed. Bénéfice : toutes les pages utilisant le Crud générique peuvent activer l anti-collision en passant juste une prop, plus besoin de modifier la modal inline

/materiels avec lockResource

🔒 passage lockResource="materiel" au composant <Crud>. Tests : quand 2 users éditent le même matériel → bannière visible avec nom utilisateur + bouton Reprendre la main. Le 0.62.125 couvre maintenant 4 pages avec lock : patients, interventions, article/[id], materiels. TODO : ajouter lockResource sur les autres pages CRUD (interventions tableau, articles tableau, etc.) en passant juste la prop

addPdfFooter /statistiques-rgpd

📄 remplace la boucle for de footer pagination par addPdfFooter(doc, {type: "Rapport RGPD", structure: structureInfo, showLegal: true}). Try/catch avec fallback footer simple (Aveho EC — Rapport RGPD Page i/N). Permet de profiter des informations complètes structure (adresse, SIRET, RCS, contact) sans dupliquer le code de pagination

addPdfFooter /statistiques-activite

📄 même pattern. type="Rapport d activité", structure=getStructureFooterInfo(auth.structureId), showLegal=true. Fallback footer simple si lib/pdfFooter indisponible

TOAST WARNING si lock repris

🔔 modification de lib/useEditLock.js avec ref prevOwnLockRef initialisé à false. Dans tryAcquireLock

  1. Si existingLocks existe ET user_id différent du mien ET prevOwnLockRef.current était true → j ai perdu mon lock, dynamic import de toast.warn et affichage : "⚠️ Votre verrou d édition a été repris par {nom}. Vos modifications non sauvegardées pourraient être écrasées."
  2. Mise à jour prevOwnLockRef à chaque transition (ownLock=true → ref=true, ownLock=false → ref=false). Use case : Alice édite un patient, Bob arrive et fait takeover, Alice reçoit instantanément un toast warning au prochain refresh 30s
