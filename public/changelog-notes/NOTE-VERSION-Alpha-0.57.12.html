🎭 Pourquoi des tests E2E ?

Jusqu'à 0.57.11, Aveho avait 2584 tests Vitest unitaires qui vérifient les fichiers sources (imports, helpers, structure, regex matches). Mais aucun test ne lançait un vrai navigateur pour vérifier que les pages fonctionnent vraiment en bout-en-bout.

Playwright 1.60.0 était dans devDependencies mais inutilisé. Avec 0.57.12 c'est exploité à fond :

  • 74 tests E2E qui lancent Chromium headless et naviguent vraiment dans Aveho
  • Détection automatique des régressions UI (changement de classNames, sélecteurs cassés)
  • Validation que les features par version sont encore fonctionnelles
  • Workflow métier complet pour mode FULL (login → patient → commande → BL)

🚀 Comment lancer les E2E

Mode SMOKE (par défaut, sans Supabase)

# Première fois : installer Chromium
npx playwright install chromium

# Lancer tous les E2E
npm run test:e2e

# Un fichier
npx playwright test tests/e2e/login.spec.js

# Pattern
npx playwright test -g "Tabler Icons"

# UI interactive (mode debug)
npm run test:e2e:ui

Mode FULL (avec Supabase + credentials)

export E2E_MODE=FULL
export E2E_USER_EMAIL=ton_compte@example.com
export E2E_USER_PASSWORD=TonMotDePasse123!
export NEXT_PUBLIC_SUPABASE_URL=https://ton-projet.supabase.co
export NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbG...

npm run test:e2e

Tester contre Vercel directement

E2E_BASE_URL=https://aveho-ec-app.vercel.app \
E2E_MODE=FULL E2E_USER_EMAIL=... E2E_USER_PASSWORD=... \
npx playwright test

🛡️ Workflow métier complet (mode FULL)

Le fichier workflow-livraison-patient.spec.js teste un parcours utilisateur réel :

  1. Login avec credentials test (via loginHelper)
  2. Vérification redirection vers /accueil ou /vue-globale
  3. Navigation vers /patients
  4. Sélection du premier patient via locator a[href*='/patient/']
  5. Vérification présence des sections principales (identité, informations)
  6. Navigation /commandes + tentative bouton 'Nouvelle commande'
  7. Navigation /livraisons (BL)
  8. Test consentements RGPD accessibles depuis fiche patient
  9. Test audit log (/audit) affiche bien la trace de connexion

En mode SMOKE par défaut, ces tests sont skipped proprement avec test.skip(!isFullMode()) pour ne pas casser la CI sans credentials configurés.

📈 Bonus : audit Lighthouse complémentaire

J'ai relancé Lighthouse en parallèle pour confirmer les résultats post-0.57.11 :

PagePerfLCPFCPCLSTBTTTI

Constats clés

  • ✅ CLS = 0.000 partout (perfect)
  • ⚠️ FCP partout à 4.8s : le bottleneck commun est le téléchargement + parse JS sur localhost (sans brotli)
  • 📦 Sur /login le bundle non-compressé total = ~785 KB. Avec brotli en prod = ~150-200 KB
  • 🎯 En prod Vercel avec CDN + brotli : Perf attendue 85-95+, LCP 1.5-2.5s, TBT < 200ms

browserslist ajouté (modern browsers seulement)

Ajouté un browserslist dans package.json pour ne plus produire de polyfills pour les vieux browsers (IE11, etc.). Pas de gain mesurable car Next 15 utilise un polyfills minimal de toute façon. C'est quand même propre.

Verdict : tout ce qui peut être fait côté code l'a été lors du marathon perf 0.57.6 → 0.57.11. Le reste viendra du déploiement Vercel.
