📦 L'idée

Le fichier versions-data.js (309 KB, 161 versions, ~930 chantiers) était chargé statiquement par /changelog. 61% de son poids = les textes des chantiers (190 KB).

Mais en pratique :

  • L'affichage par défaut ne montre que les 5 premiers chantiers de chaque version (le reste est derrière "Voir les X autres")
  • 88 versions sur 161 ont plus de 5 chantiers (= des chantiers cachés derrière "Voir plus")
  • L'utilisateur clique rarement sur "Voir plus" pour toutes les versions

→ Idée : externaliser les chantiers > 5 dans un fichier JSON lazy-chargé.

⚡ Fix 3 — Fetch background dans page.js

Le useEffect au mount fetch chantiers-extra.json en background (non-bloquant). La page s'affiche d'abord avec les 5 premiers chantiers, puis se complète quand l'extra arrive (qq dizaines de ms).

const [ALL_VERSIONS, setAllVersions] = useState(VERSIONS_INDEX);
const [extraLoaded, setExtraLoaded] = useState(false);

useEffect(() => {
  let cancelled = false;
  (async () => {
    try {
      const res = await fetch("/changelog-data/chantiers-extra.json", {
        cache: "force-cache",  // versionné par déploiement
      });
      const extra = await res.json();
      if (cancelled) return;

      // Merge : enrichit chaque version avec ses chantiers cachés
      const augmented = VERSIONS_INDEX.map((v) => {
        const hidden = extra[v.v];
        if (!hidden || !hidden.length) return v;
        return { ...v, chantiers: [...v.chantiers, ...hidden] };
      });
      setAllVersions(augmented);
      setExtraLoaded(true);
    } catch (e) {
      // 0.57.7 : si fetch échoue (offline), on reste sur 5 chantiers max
      logger.warn("[changelog] fetch chantiers-extra failed:", e?.message);
    }
  })();
  return () => { cancelled = true; };
}, []);

Gestion du fallback : si le fetch échoue (offline, 404, etc.), l'UI reste fonctionnelle avec 5 chantiers max par version. Le bouton "Voir les X autres" affiche un état désactivé + tooltip "Chargement…" tant que l'extra n'est pas chargé.

⚠️ Pourquoi pas plus de gain ?

Sur disque, on économise ~95 KB (versions-data 309 KB vs versions-index 218 KB + extra 68 KB). Mais Vercel compresse en gzip avec un taux ≈ 4×, et les fichiers JSON très répétitifs se compressent encore mieux. Plus le fichier est "régulier", plus l'écart compressé est petit.

Architecture en place pour futurs gains plus agressifs :

  • Split par version (1 JSON par v-X.X.X) → fetch à la demande quand user expand
  • Index ultra-light (juste v + titre + date) → -200 KB encore
  • Pagination des versions affichées (lazy scroll)
