1 0.49.3 VersionCheck reload réel

Bug : tu as cliqué "Recharger" dans le toast vert "Mise à jour disponible". Tu te retrouvais toujours sur la même version (0.49.0 dans ton cas), alors que le nouveau code (0.49.2) était bien déployé.

Cause : la fonction reload() faisait juste :

localStorage.removeItem(STORAGE_KEY);
window.location.reload();

Mais le Service Worker continuait d'intercepter les requêtes HTML et de servir la version cachée. Donc même après reload, Chrome chargeait toujours la 0.49.0.

Solution — 4 étapes au lieu de 2 :

  async function reload() {
    if (typeof window === "undefined") return;
+   // 1) Unregister tous les Service Workers
+   if ("serviceWorker" in navigator) {
+     const regs = await navigator.serviceWorker.getRegistrations();
+     await Promise.all(regs.map(r => r.unregister()));
+   }
+   // 2) Effacer tous les caches CacheStorage
+   if ("caches" in window) {
+     const keys = await caches.keys();
+     await Promise.all(keys.map(k => caches.delete(k)));
+   }
    // 3) Effacer la version stockée
    localStorage.removeItem(STORAGE_KEY);
    localStorage.removeItem(SNOOZE_KEY);
    // 4) Reload
    window.location.reload();
  }

Try/catch silencieux partout — best-effort. Si l'unregister plante, le reload se fait quand même.

2 0.49.4 Dropdown coupé par overflow:hidden

Bug : clic sur l'avatar utilisateur en haut à droite → le dropdown s'ouvre mais il est "sous la page", masqué par le contenu en dessous.

Cause : pour résoudre le bug d'avatar hors écran mobile (0.49.1), j'avais ajouté overflow:hidden sur .topbar comme safety net. C'était une mauvaise idée : ça coupe tous les éléments positionnés en position:absolute ancrés dans la topbar — y compris :

  • .um-sheet (menu utilisateur)
  • .notif-panel (cloche notifications)
  • .gs-panel (recherche globale)

Le z-index:100 de ces éléments ne sert à rien quand le parent les clip.

Solution : retrait du overflow:hidden. Le débordement de l'avatar reste résolu par le max-width:900px qui cache le badge version (suffisant comme protection).

3 0.49.5 Bouton "Télécharger l'appli" toujours visible

Bug : le menu utilisateur ne montrait plus le bouton "Télécharger l'appli" entre "Paramètres" et "Déconnexion".

Cause : la condition canInstall était :

const canInstall = !installed && (installPrompt || iosCanInstall);

Donc le bouton n'apparaissait que si Chrome avait fourni un beforeinstallprompt ou si on était sur iOS Safari. Mais Chrome a un comportement capricieux : après mes bumps de SW en 0.47/0.48, Chrome considère qu'il a déjà tenté d'émettre l'event et arrête de le faire. Pour le ré-activer, il faut un Clear site data manuel.

Solution : afficher toujours le bouton (sauf si l'app est déjà installée), avec 3 comportements selon le contexte :

CasAction du clic
Chrome a fourni un prompt natifAppelle installPrompt.prompt() (comme avant)
iOS SafariAffiche les instructions "Bouton Partager → Sur l'écran d'accueil"
Chrome sans prompt (le cas qui posait souci)Affiche une modale d'aide avec les étapes adaptées au navigateur détecté

Nouveau composant : <InstallHelpModal /> ajouté en fin de UserMenu.js avec des instructions pour 5 navigateurs (Chrome, Edge, Firefox, Safari, autre).

Détection du navigateur par parsing navigator.userAgent — pas parfait mais largement suffisant pour ce besoin.

function detectBrowser() {
  const ua = window.navigator.userAgent;
  if (/Edg\//.test(ua)) return "edge";
  if (/Chrome\//.test(ua) && !/Edg\//.test(ua)) return "chrome";
  if (/Firefox\//.test(ua)) return "firefox";
  if (/Safari\//.test(ua) && !/Chrome\//.test(ua)) return "safari";
  return "other";
}

Pour les futures mises à jour

Désormais quand un toast "Mise à jour disponible" apparaîtra, un clic sur "Recharger" :

  1. Désinscrira tous les Service Workers
  2. Effacera tous les caches CacheStorage
  3. Effacera le localStorage version
  4. Forcera un reload de la page

Plus besoin de purger manuellement Chrome entre 2 versions. Le composant VersionCheck fait tout le travail.

Pour ma checklist

3 nouveaux réflexes à ajouter (la checklist en compte maintenant 13) :

11ᵉ réflexe — Quand un composant détecte une nouvelle version disponible, le reload doit unregister les Service Workers + caches.delete() avant location.reload(). Sinon le SW continue de servir la version cachée et l'utilisateur reste bloqué sur l'ancien build.

12ᵉ réflexe — Ne JAMAIS mettre overflow:hidden sur un conteneur qui héberge des dropdowns (position:absolute) destinés à dépasser visuellement (menu utilisateur, cloche notifications, etc.). L'overflow coupe leur affichage même si leur z-index est très élevé. Trouver une autre solution pour gérer le débordement (media query, max-width sur les enfants, etc.).

13ᵉ réflexe — Pour les API browser capricieuses (PWA install prompt, web push, geolocation…), toujours prévoir un fallback manuel visible. L'utilisateur doit avoir un chemin d'action même si l'event natif n'est pas émis.
