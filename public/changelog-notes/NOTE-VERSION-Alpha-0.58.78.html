🧹 CLEANUP : suppression définitive groupements/etages/groupement_etablissementsPlus que des tables existantes. Hiérarchie simplifiée à 4 niveaux.

Date : 6 juin 2026 Version : v0.58.78-alpha Type : Cleanup / Refactor SQL : 🔴 1 nouveau (DROP + ALTER)

🎯 Décision : on n'invente plus de tables

Les 3 tables que j'avais créées en 0.58.75 (groupements, groupement_etablissements, etages) causaient des erreurs SQL idempotentes en cascade chez toi (etages existait déjà sans numero, chambres sans numero, etc). Décision claire : on les supprime et on travaille uniquement avec les tables qui existent dans ta DB.

Garde : juste les colonnes UTILES qu'on a ajoutées sur depots, transferts, batiments qui n'impliquent pas de FK vers les tables supprimées.

🏗 Nouvelle hiérarchie (4 niveaux)

Bâtiment
table : batiments · structure_id, nom, couleur, icone
↓
Service
table : services · batiment_id, nom (plus de etage_id)
↓
Chambre
table : chambres · service_id, nom (.nom uniquement, jamais .numero)
↓
Magasin / Mobile
tables : magasins (existante) · mobile (niveau dépôt spécial sans rattachement fixe)

🗄 Le SQL — DROP + colonnes utiles

Fichier : public/sql/migration-0.58.78-cleanup-only-existing-tables.sql

Ce script :

  • DROP v_depots_hierarchie (vue), groupements, groupement_etablissements, etages (toutes avec CASCADE)
  • DROP COLUMN groupement_id et etage_id sur depots, chambres, services
  • ALTER depots : garde service_id, chambre_id, code, niveau_hierarchique, capacite_max, temperature_min/max, humidite_max, securise, couleur, icone, etc.
  • ALTER transferts : ajoute depot_source_id, depot_destination_id, chambre_source/dest_id, service_source/dest_id, materiel_id, scan_source, priorite, date_validation/reception
  • ALTER batiments : ajoute couleur, icone si manquants
  • CREATE OR REPLACE v_depots_hierarchie SIMPLIFIÉE : Bâtiment > Service > Chambre > Magasin (utilise UNIQUEMENT .nom, jamais .numero)

SAFE à relancer plusieurs fois — tous les DROP/ALTER en IF NOT EXISTS.
