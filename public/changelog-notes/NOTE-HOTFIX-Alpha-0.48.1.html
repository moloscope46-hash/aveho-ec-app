Patch 0.48.1 — Page offline statique Élimine les 8 erreurs 503 dans la console quand on est hors-ligne

Date : 31 mai 2026 Version : v0.48.1-alpha Tests : 844 verts (inchangé) Type : Polish UX, pas un bug bloquant

La page /offline livrée en 0.47 fonctionnait visuellement (capture utilisateur confirme : fond gradient, icône Wi-Fi off, message, bloc "Disponible en local", dot pulsant), mais la console montrait 8 erreurs 503 (Offline) chaque fois qu'elle s'affichait.

Cause

SW précachait /offline sans ses chunks Next

La page /offline était une page Next.js classique (app/offline/page.js) avec "use client", hooks useState/useEffect, animation CSS keyframes inline...

Le SW précachait juste l'URL /offline (le HTML), mais quand Next.js tentait d'hydrater la page côté client, il fallait :

  • /_next/static/css/app/layout.css ← 503
  • /_next/static/chunks/webpack.js ← 503
  • /_next/static/chunks/main-app.js ← 503
  • /_next/static/chunks/app-pages-internals.js ← 503
  • /_next/static/chunks/app/offline/page.js ← 503
  • /_next/static/chunks/app/layout.js ← 503
  • /icons/favicon-32.png ← 503
  • /icons/favicon-16.png ← 503

Ces chunks ont des noms hashés qui changent à chaque build, donc impossibles à pré-cacher de façon fiable.

Correction

Conversion en HTML statique pur dans /public/offline.html

Plus de Next.js runtime : tout est embarqué inline (CSS + un peu de JS vanilla pour réagir à navigator.onLine).

Bénéfices :

  • Zéro chunk JS/CSS à charger → zéro erreur 503
  • Mêmes fonctionnalités : icône Wi-Fi qui change selon online/offline, message contextualisé, bouton "Réessayer" / "Recharger", dot live pulsant, auto-refresh toutes les 5s
  • Mêmes styles : fond gradient navy, glassmorphism, badges teal · bloc "Disponible en local"
  • Plus rapide : un seul HTTP request pour le HTML (5163 bytes), tout inline
  • Compatible PWA : référence le manifest.json + les icônes Tabler depuis le CDN (qui peut aussi être cacheable séparément)

Procédure d'application

  1. Aucun SQL à modifier
  2. Décompresser le zip par-dessus C:\aveho-ec-app\
  3. Le SW a changé de version (aveho-ec-0.47 → aveho-ec-0.48.1) — il va se mettre à jour automatiquement au prochain chargement. Pour forcer immédiatement :
    • DevTools → Application → Service Workers → "Update on reload" coché
    • Puis hard reload (Ctrl+F5)
    • Ou DevTools → Application → Storage → "Clear site data"
  4. Tester :
    1. DevTools → Network → Throttling → Offline
    2. Naviguer vers une route quelconque (ex. /promotions)
    3. La page /offline.html doit s'afficher (même rendu visuel qu'avant)
    4. Plus aucune erreur 503 dans la console

Pour ma checklist

7ᵉ réflexe à ajouter : pour une page de fallback offline (ou tout asset servi via Service Worker), préférer du HTML statique pur dans /public/ plutôt qu'une page Next.js. Les chunks JS/CSS hashés sont impossibles à pré-cacher de manière fiable et créent des erreurs console quand on est offline.

Checklist complète (7 réflexes) :

  1. Pattern RLS avec mes_structures()
  2. Grep create table avant SQL
  3. Dates en ms (DST-safe)
  4. notify pgrst, 'reload schema' + grants en fin de patch
  5. Pas de crossover lib/ ↔ app/ via le layout
  6. Test npm run dev sur les pages modifiées avant package
  7. Page de fallback offline (SW) : HTML statique pur, pas de Next.js
