🩺 1. RPPS production — API FHIR ANS officielle

Plus de mock — données réelles

L'endpoint /api/rpps requête maintenant l'API FHIR Annuaire Santé de l'Agence du Numérique en Santé :

https://gateway.api.esante.gouv.fr/fhir/v2/Practitioner
  • Libre accès, sans clé ✓
  • ~1,7 million de praticiens (médecins, IDE, kinés, sages-femmes, pharmaciens, etc.)
  • Format FHIR R4 JSON
  • Cache 1h côté serveur via next: { revalidate: 3600 }

Endpoints utilisés

  • GET /Practitioner?family=DUPONT&_count=20 → recherche par nom
  • GET /Practitioner?identifier=10000000001 → recherche par RPPS exact
  • GET /PractitionerRole?practitioner=<id> → détails (profession + adresse)

Normalisation FHIR → format unifié

La fonction normalizePractitioner extrait depuis les ressources FHIR :

  • RPPS depuis identifier[] dont le system contient "rpps" ou "idnatps"
  • ADELI depuis identifier[] dont le system contient "adeli"
  • Civilité / nom / prénom depuis name[0].prefix/family/given
  • Profession depuis PractitionerRole.code[].coding[].display
  • Spécialité depuis PractitionerRole.specialty[].coding[].display
  • Téléphone / email depuis telecom[]
  • Adresse / CP / commune depuis location[0].address

🔍 2. Bouton 'Rechercher RPPS' à la création utilisateur

Dans la modale 'Créer un utilisateur', un nouveau bouton violet à côté du titre Identité :

  1. Clic sur "🩺 Rechercher RPPS" → modale RppsSearch (avec API FHIR ANS)
  2. Tape un nom ou un n° RPPS
  3. Clic sur un praticien → pré-remplissage automatique :
    • Prénom + Nom
    • Téléphone (si présent)
    • Fonction = profession RPPS
    • Champs RPPS dédiés : rpps, adeli, rpps_profession, rpps_specialite, rpps_mode_exercice
  4. Un badge violet apparaît au-dessus du formulaire : "Pré-rempli depuis RPPS : Médecin · Cardiologie · RPPS 10000000001"
  5. Bouton "Retirer" si on veut défaire le pré-remplissage

👤 3. Bloc 'Données RPPS' dans la fiche utilisateur

Dans la modale d'info user, un nouveau bloc violet est affiché uniquement si l'utilisateur a un RPPS associé :

  • Icône stéthoscope + titre "Données RPPS (annuaire ANS)"
  • Grille 2 colonnes : N° RPPS (mono) · N° ADELI (mono)
  • Ligne : Profession · Spécialité · Mode d'exercice

Les champs sont chargés depuis membres_structure.rpps/adeli/... via la vue v_user_complete mise à jour dans le patch SQL.

🔧 4. Fix vue-globale : filtre Mes/Partenaires/Tous

Avant

La page /vue-globale affichait tous les établissements sans distinction. Les partenaires (est_partenaire=true) y apparaissaient avec un comportement de "clic = entrer dans l'étab" qui n'a pas de sens pour un partenaire.

Maintenant

  • 3 boutons toggle en haut : Mes établissements (N) · Partenaires (N) · Tous (N) — avec compteurs dynamiques
  • Filtre par défaut : mine (cache les partenaires sur l'écran principal)
  • Les cartes partenaires ont un dégradé violet + badge "PARTENAIRE" + CTA "Voir la fiche partenaire" (mène à /etablissements?focus=<id>)
  • Les KPIs (totaux patients/matériel/DI/à régler) sont calculés sur le filtre actif
  • La requête SQL inclut maintenant structure_id dans le WHERE pour ne pas charger d'établissements d'autres structures

🗄 SQL Patch 0.55.29

alter table invitations
  add column if not exists rpps text,
  add column if not exists adeli text,
  add column if not exists rpps_profession text,
  add column if not exists rpps_specialite text,
  add column if not exists rpps_mode_exercice text;

alter table membres_structure
  add column if not exists rpps text,
  add column if not exists adeli text,
  add column if not exists rpps_profession text,
  add column if not exists rpps_specialite text,
  add column if not exists rpps_mode_exercice text;

create index idx_invitations_rpps on invitations(rpps) where rpps is not null;
create index idx_membres_rpps on membres_structure(structure_id, rpps) where rpps is not null;
