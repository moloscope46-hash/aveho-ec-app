🛡 Le système

Comment ça marche

  1. Au moment de créer un établissement (mes étab OU partenaire) → appel à la RPC check_etab_doublon
  2. La RPC scanne TOUTES les fiches de la structure (mes étab + partenaires) et matche sur FINESS, SIRET, SIREN, RPPS ou nom exact
  3. Si match trouvé → composant DoublonAlert s'affiche avec les fiches existantes et lien direct
  4. L'utilisateur peut Annuler ou si admin, Forcer avec commentaire (≥ 10 caractères obligatoire)
  5. Le commentaire + qui/quand est enregistré en base pour audit

🔐 Nouveau droit force_doublon_etab

Où l'activer

Menu Administration → Utilisateurs → Rôles & droits → édition d'un rôle → cocher Écriture sur le module "Forcer doublons étab (avec commentaire)".

Comportement

  • Sans le droit : le user voit l'alerte ambre mais ne peut PAS créer le doublon. Message : "Seul un admin peut forcer la création d'un doublon. Contactez votre référent."
  • Avec le droit : bouton "Créer quand même" → textarea commentaire obligatoire ≥ 10 caractères → enregistrement avec traçabilité complète

Implementation technique

Le droit utilise un format objet ciblé { module: "doublons", perm: "write" } dans PERMS. La fonction canDo() a été étendue pour vérifier UNIQUEMENT ce module précis (pas les autres "write" du système). Donc un user avec etablissement.write n'a PAS automatiquement force_doublon_etab.

🗄 SQL — patch 0.55.43

Colonnes ajoutées (etablissements + etablissements_partenaires)

  • doublon_force_commentaire : texte expliquant la raison
  • doublon_force_par : uuid → auth.users (qui a forcé)
  • doublon_force_at : timestamptz (quand)

Index pour lookup rapide

Sur les colonnes finess, siret, rpps filtrées par structure_id avec where colonne is not null → index partiels très efficaces.

RPC check_etab_doublon

Paramètres : p_finess, p_siret, p_siren, p_rpps, p_nom, p_exclude_id. Retourne :

{
  "ok": true,
  "found": true,
  "count": 2,
  "matches": [
    {
      "kind": "mine" | "partner",
      "id": "uuid",
      "nom": "...",
      "type": "...",
      "finess": "...", "siret": "...", "rpps": "...",
      "adresse": "...", "cp": "...", "ville": "...",
      "matched_on": "finess" | "siret" | "siren" | "rpps" | "nom",
      "created_at": "...",
      "doublon_force_commentaire": "...", // si déjà forcé
      "doublon_force_par": "uuid",
      "doublon_force_at": "..."
    }
  ]
}

Vue v_doublons_forces (audit admin)

Liste tous les doublons forcés (mine + partner) avec leur commentaire, auteur et date. Utile pour vérifier qui force quoi.

🎨 Composant DoublonAlert (réutilisable)

L'UI est claire :

  • Bandeau ambre avec icône triangle ⚠
  • Titre : "Doublon détecté : X fiche(s) déjà existante(s)"
  • Liste des fiches avec badge "Mon étab" (bleu) ou "Partenaire" (violet)
  • Nom + adresse + identifiants matchés mis en évidence
  • Lien direct vers la fiche existante (s'ouvre dans un nouvel onglet)
  • Si un précédent doublon a été forcé → commentaire affiché en italique avec icône message
  • 2 actions principales : Annuler / Créer quand même (si droit)

Utilisable n'importe où :

import DoublonAlert from "./components/DoublonAlert";
import { checkEtabDoublon } from "./lib/checkEtabDoublon";

const [doublons, setDoublons] = useState(null);

async function create() {
  const check = await checkEtabDoublon(supabase, {
    finess: form.finess,
    siret: form.siret,
    nom: form.nom,
  });
  if (check.found) { setDoublons(check); return; }
  // ... insert
}

<DoublonAlert
  doublons={doublons}
  canForce={auth.can("force_doublon_etab")}
  onCancel={() => setDoublons(null)}
  onForce={(commentaire) => { /* save avec commentaire */ }}
/>
