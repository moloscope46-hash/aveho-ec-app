🐛 Root cause : PageTransition avec willChange

1

Le wrapper qui englobe TOUTE l'app cassait silencieusement les position: fixed

Symptôme prod : sur mobile, quand on scroll en bas de page, cliquer sur le burger affichait l'overlay flou mais pas le menu. Les modales et popups idem — invisibles ou tronquées.
Cause : PageTransition avait willChange: 'opacity, transform'. Cette propriété CSS crée un containing block pour les enfants position: fixed. Conséquence : TOUS les overlays (menu burger, modales, drawers) étaient positionnés relativement à PageTransition (qui reste fixe en haut) au lieu du viewport. Quand l'user scrollait en bas, les overlays restaient logés tout en haut, hors écran.
// AVANT 0.58.19 - createstaining block global app
<PageTransition>
  <div style={{ willChange: 'opacity, transform' }}>   ← BUG !
    {/* TOUTE l'app rendue ici */}
    {children}
  </div>
</PageTransition>

// → TOUS les position:fixed enfants (menu, modale, drawer) sont
//   relatifs à ce <div>, PAS au viewport.

// 0.58.19 - willChange retiré
<PageTransition>
  <div>   ← Plus de containing block, fixed marche normalement
    {children}
  </div>
</PageTransition>

🛡 Renforcement : Portals pour tous les overlays

Pour empêcher ce bug de revenir si quelqu'un remet un willChange ou un transform sur un wrapper ailleurs, j'ai migré tous les overlays critiques vers React Portals qui rendent directement dans document.body.

📋 Bug instructif — règle d'or

Propriétés CSS qui créent un containing block pour position: fixed :

  • will-change: transform / filter / opacity
  • transform: ... (autre que none)
  • filter: ...
  • perspective: ...
  • backdrop-filter: ...
  • contain: layout / paint / strict
  • isolation: isolate

Règle : éviter ces propriétés sur les wrappers high-level qui englobent l'app. Pour les overlays critiques, toujours utiliser React Portals vers document.body.
