🚨 1. HOTFIX Service Worker (bug que tu as remonté)

L'erreur :

Failed to load resource: the server responded with a status of 400 ()
sw.js:168  Uncaught (in promise) TypeError: Failed to fetch
    at networkFirst (sw.js:168:23)

Cause : depuis 0.58.72 j'ai introduit api.qrserver.com pour générer les QR codes des matériels. Le SW interceptait tous les fetch HTTPS, y compris ceux vers qrserver.com → CORS bloquait → TypeError dans le SW.

Fix : array EXTERNAL_CDNS qui bypass complètement le SW pour 6 domaines tiers connus.

// public/sw.js — AVANT le routing networkFirst/cacheFirst
const EXTERNAL_CDNS = [
  'api.qrserver.com',       // 0.58.72 — QR matériel
  'cdn.jsdelivr.net',
  'unpkg.com',
  'fonts.googleapis.com',
  'fonts.gstatic.com',
  'cdnjs.cloudflare.com',
];
if (EXTERNAL_CDNS.includes(url.hostname)) {
  return;  // Le navigateur fait son fetch normal sans interception
}

⚙️ Workflow

  • 4 stats cards filtrables par statut (cliquables)
  • Multi-source/destination : dépôt OU service OU chambre (croisé)
  • 4 priorités : basse / normale / haute / urgente (boutons radio colorés)
  • 8 motifs : Réapprovisionnement, Retour location, Prêt inter-service, Échange matériel défectueux, Régularisation, Quarantaine, Envoi SAV, Retour SAV
  • Actions inline conditionnelles selon statut : Valider/Réceptionner/Annuler/Éditer
  • changeStatut() set automatiquement date_validation + valide_par (sur Validé) et date_reception + recu_par (sur Reçu)

🔗 Préset URL

  • /transferts?depot=X → modal new avec destination préremplie
  • /transferts?depot_source=X → modal new avec source préremplie
  • /transferts?materiel=UUID → modal new avec matériel précis (post-scan)

📱 Scan QR matériel

Dans le modal "Contenu", section Matériel a un bouton Scan qui redirige vers /scan/quick. Affichage visuel source → destination dans la liste avec icônes hiérarchiques.

🗄️ 5. SQL à appliquer (UN nouveau)

⚠ UN nouveau SQL — premier depuis tes 21 précédents :

📄 public/sql/migration-0.58.75-groupements-etages-depots-hierarchie.sql

Contenu :

  • 3 nouvelles tables : groupements (avec FINESS juridique + SIRET + couleur/icone), groupement_etablissements (lien composite avec rôle), etages (rattaché à batiments)
  • ALTER chambres + services : ADD etage_id pour la hiérarchie complète
  • ALTER depots : groupement_id, etage_id, service_id, chambre_id, code, niveau_hierarchique, capacite_max, temperature_min/max, humidite_max, securise BOOLEAN, responsable_id, adresse/ville, couleur/icone, notes, actif
  • ALTER transferts : depot_source_id, depot_destination_id, chambre_source/dest_id, service_source/dest_id, materiel_id, scan_source, priorite, date_validation/reception, valide_par/recu_par
  • Vue v_depots_hierarchie avec chemin_complet calculé : "Groupement > Bâtiment > Étage X > Service > Ch. N"
  • Tous RLS en DROP + CREATE (compat PG<17) · Indexes partiels pour perf

⚠ Sans ce SQL, les nouvelles pages /groupements, /depots, /transferts auront des SELECT 400 (colonnes manquantes). Applique-le AVANT de tester.
