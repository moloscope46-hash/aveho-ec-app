🏢 Chantier 1 — Renommage "Collectivité" → "Groupement"

Le terme "Collectivité" était ambigu (collectivité territoriale vs groupement d'établissements). Renommé "Groupement" partout dans l'UI :

  • Menu : section "Collectivité" → "Groupement"
  • Item menu : "Fiche collectivité" → "Fiche groupement"
  • Page /collectivite : titre, descriptions, breadcrumb, messages d'erreur, tooltips
  • Audit log : entité "groupement" au lieu de "collectivite"

Côté base de données : la table reste structures (rename d'une table = risque de casser RLS, refs, vues, etc.). C'est un renommage 100% UI/labels.

L'URL /collectivite reste aussi pour conserver les bookmarks utilisateurs. Une redirection 301 pourra être ajoutée plus tard si tu veux changer l'URL en /groupement.

📋 Chantier 2 — SQL Patch 0.55.6 (champs SIRENE sur structures)

18 nouveaux champs ajoutés à structures + 1 nouveau champ sur batiments + 1 index unique :

alter table structures
  add column if not exists siren text,
  add column if not exists siret text,
  add column if not exists adresse text,
  add column if not exists code_postal text,
  add column if not exists telephone text,
  add column if not exists email text,
  add column if not exists site_web text,
  add column if not exists latitude numeric(10,7),
  add column if not exists longitude numeric(10,7),
  -- Champs SIRENE enrichis
  add column if not exists nom_complet text,                  -- raison sociale officielle
  add column if not exists sigle text,
  add column if not exists activite_principale text,          -- code NAF/APE
  add column if not exists libelle_activite text,
  add column if not exists categorie_entreprise text,         -- TPE/PME/ETI/GE
  add column if not exists tranche_effectifs text,
  add column if not exists nature_juridique text,
  add column if not exists date_creation date,
  add column if not exists nombre_etablissements int,
  add column if not exists notes text;

create unique index if not exists ux_structures_siret 
  on structures (siret) where siret is not null;

-- 0.55.6 : rattachement bâtiment → établissement
alter table batiments
  add column if not exists etablissement_id uuid 
  references etablissements(id) on delete set null;

create index if not exists idx_batiments_etablissement 
  on batiments (etablissement_id);

notify pgrst, 'reload schema';

🔎 Chantier 3 — SIRENE dans Fiche Groupement

La page /collectivite est entièrement refondue (527 lignes) :

Bloc Import SIRENE (admin only)

En haut de la page, un encart ambre avec <SireneSearch />. Tape le nom du groupement (ex : "Domidep", "APHP"), un SIRET ou un SIREN → tous les champs sont pré-remplis automatiquement :

  • Identité : nom usuel, sigle, raison sociale, SIRET, SIREN
  • Activité : code APE/NAF, libellé activité, catégorie (TPE/PME/ETI/GE), tranche effectifs, nature juridique, date de création, nombre d'établissements
  • Adresse : adresse complète, CP, ville, latitude, longitude

5 panels d'édition

  1. Identité (icône ti-id-badge-2) — nom usuel, sigle, raison sociale, SIRET, SIREN
  2. Activité & structure (icône ti-briefcase) — code APE/NAF, libellé, catégorie (select TPE/PME/ETI/GE), tranche effectifs, nature juridique, date création, nb établissements
  3. Adresse du siège (icône ti-map-pin) — adresse, CP, ville, latitude, longitude
  4. Contact (icône ti-phone) — téléphone, email, site web, notes internes (textarea)

Tous les champs sont éditables mais read-only pour les non-admins (attribut disabled sur les inputs).

Le bouton "Enregistrer la fiche groupement" en bas appelle safeUpdate sur structures + logEvent avec source "sirene" ou "manuel".

🏗 Chantier 4 — Popup bâtiments par établissement

Liste d'établissements en cards cliquables

Sous la fiche groupement, les établissements rattachés sont affichés en cards 260px de large (grid responsive) :

  • Icône ti-building-hospital bleue (géré) ou ti-route teal (partenaire)
  • Nom + ville + type
  • Chips : PARTENAIRE / FINESS xxx / 🛏 N lits
  • Footer "Voir bâtiments →" (lien bleu)
  • Hover : élévation +2px + ombre douce

Popup arborescente au clic

Au clic sur une card, une modal s'ouvre intitulée "Bâtiments — [nom étab]" avec :

Bandeau de 5 stats

  • 🏭 Bâtiments — nombre de bâtiments rattachés (via batiments.etablissement_id)
  • 🪜 Étages
  • 🚪 Services
  • 🛁 Chambres
  • 🛏 Lits occupés (X/Y où Y = total et X = ceux avec patient_id)

TreeView arborescente

Affichage hiérarchique avec couleurs et indentations :

🏭 Bâtiment A   (3 étages)
   🪜 RDC   (2 services)
      🚪 Accueil       — 4 ch. · 8 lits · 6 occupés
      🚪 Salle de soins — 2 ch. · 0 lit
   🪜 1er étage   (1 service)
      🚪 Pavillon nord  — 12 ch. · 24 lits · 22 occupés
   🪜 2e étage   (2 services)
      …

Couleurs :

  • Bâtiment = bleu #185FA5
  • Étage = violet #7a6fb0
  • Service = vert #5aa05a
  • Chambre = teal #7CC8C8
  • Lit = ambre #EF9F27

Bouton "Éditer la hiérarchie"

En footer de la modal, redirige vers /etablissement/edition pour ajouter/modifier des bâtiments/étages/services/chambres/lits.

Loading optimisé

Les données sont chargées uniquement au clic (lazy) — pas au chargement initial de la page. 4 requêtes Supabase enchaînées avec in() pour ne pas faire de N+1 :

  1. select id, nom from batiments where etablissement_id = ?
  2. select * from etages where batiment_id in (...)
  3. select * from services where etage_id in (...)
  4. select * from chambres where service_id in (...) puis lits where chambre_id in (...)

🔎 Chantier 5 — SIRENE dans Fiche Établissement

Sur /etablissement/fiche, le bloc d'import a maintenant 2 onglets :

OngletCouleurCas d'usage
FINESS (établissements santé) Vert #5aa05a EHPAD, hôpitaux, MAS… qui ont un n° FINESS officiel
SIRENE (entreprises) Ambre #EF9F27 Sociétés sans FINESS, prestataires médicaux, fournisseurs, structures privées

Champs pré-remplis depuis SIRENE : nom, type, siret, adresse, code_postal, ville, latitude, longitude.

Pas de SIREN sur l'établissement (le SIREN est porté par le groupement). Pas de FINESS non plus si vient de SIRENE (puisque les entreprises commerciales n'en ont pas).

Procédure — PowerShell

  1. Appliquer le patch SQL aveho-PATCH-vers-0.55.6.sql dans Supabase > SQL Editor (18 colonnes + 1 index + 1 colonne batiments + 1 index)
  2. Décompresser le zip 0.55.6 par-dessus C:\aveho-ec-app\
  3. Relancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm run dev
  4. Vider cache navigateur + Service Worker (F12 → Application → Clear site data)
  5. Tester le renommage :
    • Menu hamburger : section "Groupement" (et plus "Collectivité")
    • Item "Fiche groupement" dans cette section
  6. Tester l'import SIRENE du groupement :
    • Aller dans Groupement → Fiche groupement
    • Bloc ambre en haut : "Import depuis l'Annuaire des Entreprises (SIRENE)"
    • Taper le nom de ton groupement (ex : ton SIREN si tu le connais)
    • Cliquer un résultat → tous les champs s'auto-remplissent (NAF, effectifs, NJ, date création, etc.)
    • Cliquer "Enregistrer la fiche groupement" en bas
  7. Tester la popup bâtiments :
    • Sur la même page /collectivite, scroller jusqu'à "Établissements du groupement"
    • Cliquer sur une card d'établissement
    • Popup "Bâtiments — [nom étab]" s'ouvre avec arbo bâtiments→étages→services→chambres→lits
    • Si l'étab n'a aucun bâtiment rattaché (cas initial), un lien "Édition hiérarchie" est affiché
  8. Tester SIRENE dans Fiche Établissement :
    • Aller dans Établissement → Fiche étab.
    • Bloc d'import a maintenant 2 onglets : FINESS (vert) et SIRENE (ambre)
    • Cliquer SIRENE → taper le nom d'une entreprise → import des champs disponibles
  9. Rattacher les bâtiments existants à leur étab (manuel ou SQL) : 
    -- Exemple : assigner tous les bâtiments existants à l'étab "Hôpital X"
update batiments
set etablissement_id = (select id from etablissements where nom = 'Hôpital X' limit 1)
where etablissement_id is null;
    Ou via l'interface /etablissement/edition dans une prochaine version qui permettra de rattacher visuellement.
