🎯 Pourquoi cette page ?

L'API ANS (Annuaire Santé Pratique) bloque souvent les IPs cloud par défaut. Quand tu tapes "Paris" dans /partenaires-rpps et que ça sort 0 résultat, deux causes possibles :

  1. L'IP sortante de Vercel est blacklistée par l'ANS (403 Forbidden)
  2. L'API ANS est down (maintenance, surcharge, timeout)

Sans diagnostic, tu ne peux pas savoir laquelle. D'où cette page : elle teste en direct l'API ANS depuis Vercel et te dit exactement ce qui se passe.

🔬 Comment ça marche

4 tests en parallèle (Promise.all)

  1. GET /Practitioner?family=DUPONT → recherche par nom
  2. GET /PractitionerRole?location.address-city=Paris → par ville
  3. GET /Practitioner?identifier=10000000001 → RPPS exact (test du chemin "lookup")
  4. GET api-adresse.data.gouv.fr/search?q=Paris → BAN pour contrôle (sait-on encore appeler des APIs gouvernementales ?)

Récupération de l'IP sortante

Via api.ipify.org?format=json côté serveur Vercel. C'est l'IP que voit l'ANS, donc celle qu'il faut faire whitelister.

Variables d'environnement Vercel

VERCEL_ENV (production / preview / development), VERCEL_REGION (cdg1=Paris, iad1=Washington, etc.), Node version.

Pour chaque test, on capture

  • HTTP status + statusText
  • Durée ms
  • Body brut (tronqué à 800 chars)
  • Headers de réponse (10 premiers)
  • Si JSON FHIR valide : total + nombre d'entries
  • Erreurs (timeout 10s, network, etc.)

📊 Les 4 codes de diagnostic

CodeCouleurSignification
OK🟢 vert3/3 endpoints ANS répondent. Tout marche.
PARTIAL🟠 ambre1-2 endpoints sur 3. Inspect par requête.
BLACKLISTED🔴 rouge≥ 2 retours 403. L'IP affichée est blacklistée par l'ANS.
DOWN🔴 rouge0 endpoint OK. L'ANS ne répond pas du tout.
OK_ANS_BAN_DOWN🟠 ambreANS OK mais BAN down — géocodage carte affecté.

Panneau pédagogique

Explique chaque code HTTP (200/403/0/400/500). Si blacklist, donne 3 solutions concrètes :

  1. Whitelist ANS : email à cyber@esante.gouv.fr avec l'IP affichée
  2. Proxy/relay : Cloudflare Workers en EU avec une IP française fixe
  3. Dump RPPS open data : import du fichier annuel data.gouv.fr (1,7M praticiens, mise à jour mensuelle) → recherche full-text en local sans dépendre de l'API ANS

🔜 Suite logique

Une fois le diagnostic fait, on saura quoi faire :

  • Si OK → bug applicatif côté requêtes, à corriger dans /api/rpps/route.js

  • Si DOWN → attendre que l'ANS revienne
