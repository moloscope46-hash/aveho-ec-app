🐛 Bug 1 — RPC patient_dashboard_* en 400

1

Le dashboard patient crashait sur RPC manquantes

Symptôme : 400 sur rpc/patient_dashboard_medicaments_actifs + autres → dashboard inutilisable
Cause : RPC pas (toutes) déployées en base + Promise.all qui crashait à la 1ère erreur. Fix : helper safeRpc() avec try/catch individuel → log warning au lieu de crash → dashboard s'affiche partiellement
// AVANT 0.58.18
const [{ data: s }, { data: m }, ...] = await Promise.all([
  supabase.rpc('patient_dashboard_summary', { p_patient_id }),
  supabase.rpc('patient_dashboard_medicaments_actifs', { p_patient_id }),  // ← 400
  ...
]);

// 0.58.18 - chaque RPC en try/catch
async function safeRpc(name, args) {
  try {
    const { data, error } = await supabase.rpc(name, args);
    if (error) {
      console.warn(`[patient_dashboard] RPC ${name} indisponible:`, error.message);
      return null;
    }
    return data;
  } catch (e) {
    console.warn(`[patient_dashboard] RPC ${name} a planté:`, e?.message || e);
    return null;
  }
}
const [s, m, med, a] = await Promise.all([safeRpc(...), safeRpc(...), ...]);

🐛 Bug 2 — SW "FetchEvent network error" sur /profil

2

Service Worker polluait la console avec faux network errors

Symptôme : The FetchEvent for "/profil" resulted in a network error response dans la console
Cause : Response.error() en fallback offline → Chrome interprète comme network error. Fix : remplacement par 504 propre avec body vide. Next.js retry quand même tout seul, plus de bruit console
// AVANT 0.58.18
return Response.error();   // ← Chrome console pollution

// 0.58.18
return new Response('', {
  status: 504,
  statusText: 'Gateway Timeout',
  headers: { 'Content-Type': 'text/plain' },
});

🛡 Hardening — lib/supabase.js défensif

3

Diagnostic clair si env Supabase manquant

Pourquoi : avant on passait undefined, undefined à createBrowserClient → erreurs cryptiques downstream. Fix : check explicite + log console clair
// 0.58.18 - guard + diagnostic
export function createClient() {
  const url = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const key = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;
  if (!url || !key) {
    if (typeof window !== 'undefined') {
      console.error(
        '[lib/supabase] NEXT_PUBLIC_SUPABASE_URL ou NEXT_PUBLIC_SUPABASE_ANON_KEY manquant. ' +
        'Vérifiez la config Vercel ou le .env.local.'
      );
    }
  }
  return createBrowserClient(url, key);
}

🔍 Bug "createClient is not defined" — à investiguer

Le bug persiste probablement car il vient d'un fichier qui utilise createClient sans l'importer. Sans shell pour grep, je n'ai pas pu localiser le fichier coupable.

Pour le trouver chez toi en 30 secondes :

cd C:\aveho-ec-app
# Cherche les fichiers qui USENT createClient sans l'IMPORTER
findstr /S /N "createClient" app\*.js lib\*.js | findstr /V "import.*createClient"
findstr /S /N "createClient" app\*.js lib\*.js | findstr /V "export function createClient"
# Le fichier qui apparaît dans les deux sans rien d'autre est le coupable

Puis ajoute en haut du fichier : import { createClient } from "../lib/supabase"; (en ajustant le chemin relatif selon le niveau du fichier).
