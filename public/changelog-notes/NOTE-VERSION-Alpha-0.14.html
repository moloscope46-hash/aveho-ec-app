3. Imprimer les fiches NOUVEAU

3.1 Contexte

Les fiches patient (0.13) et matériel (0.12) étaient consultables à l'écran mais non imprimables. La 0.14 ajoute un bouton Imprimer à côté du bouton Modifier sur chaque fiche, et un helper réutilisable lib/ficheToPdf.js.

3.2 Helper ficheToPdf

Deux fonctions exportées :

import { imprimerFichePatient, imprimerFicheMateriel } from "../../../lib/ficheToPdf";

// Patient
imprimerFichePatient({
  patient,         // l'objet patient avec ses relations (services, etablissements)
  etiquettes,      // tableau des étiquettes du patient
  materiels,       // tableau des matériels affectés
  interventions    // tableau des DI
});

// Matériel
imprimerFicheMateriel({
  materiel,        // l'objet matériel avec ses relations
  tags,            // tags appliqués
  maintenances,
  interventions,
  transferts
});

Les deux passent par openPdfPreview livré en 0.13 : pas d'impression directe, l'utilisateur voit l'aperçu et décide.

3.3 Format des fiches imprimées

  • A4 portrait, marges 12 mm
  • En-tête turquoise "AVEHO — FICHE PATIENT" ou "FICHE MATÉRIEL" + titre (nom du patient ou libellé matériel)
  • Bandeau d'identifiants (chambre, S/N, âge, dépôt, etc.)
  • Étiquettes ou tags en pastilles colorées
  • 4 KPIs en grille (matériels affectés / DI ouvertes / etc.)
  • Tableaux : matériels, DI, transferts (limités à 15 lignes par table avec compteur de surplus)
  • Footer "À classer dans le dossier patient/matériel"

3.4 Cas d'usage

  • Réunion d'équipe : imprimer la fiche d'un patient compliqué pour la passer à l'oral
  • Dossier papier obligatoire : pour les collectivités qui doivent garder une trace papier
  • Audit : remettre au prestataire la fiche matériel complète avec son historique
  • Transmission : passation entre services / équipes de nuit

4. Aperçu impression Stats NOUVEAU

L'export PDF des Statistiques (livré en 0.8) ouvrait une fenêtre et lançait l'impression. La 0.14 le fait passer par l'aperçu (modal fullscreen, boutons Annuler/Imprimer, sortie Échap).

C'était le seul export qui n'avait pas encore été migré. Désormais tous les exports PDF passent par l'aperçu : Maintenance (0.12), Stats (0.14), Fiche patient (0.14), Fiche matériel (0.14).

5. Recherche globale Cmd+K NOUVEAU

5.1 Activation

Depuis n'importe quelle page de l'app, appuie sur ⌘ K (Mac) ou Ctrl K (Windows/Linux). Une palette de recherche s'ouvre instantanément, l'input prend le focus automatiquement.

5.2 Sources de recherche

La recherche est parallèle sur 4 tables (Promise.all) et débouncée à 250ms :

  • Patients — recherche dans nom et prenom (badge bleu)
  • Matériels — recherche dans libelle, num_serie, num_parc, num_lot (badge turquoise)
  • Demandes d'intervention — recherche dans numero et type (badge rouge)
  • Signalements — recherche dans titre (badge violet)

5 résultats par source maximum, soit 20 résultats max au total. Les résultats portent leur badge "type" coloré + icône à gauche.

5.3 Navigation clavier

  • ↑↓ — sélectionner un résultat dans la liste
  • ↵ Enter — ouvrir le résultat sélectionné
  • Échap — fermer la palette sans rien faire
  • ⌘ K à nouveau — toggle (ferme la palette si déjà ouverte)

5.4 Liens directs vers les fiches

Cliquer sur un patient ou un matériel ouvre directement sa fiche 360° (livrées en 0.12/0.13). On peut donc en 2 frappes + un clic accéder à l'historique complet d'un équipement ou d'un patient depuis n'importe où dans l'app.

6. Vue Kanban DI NOUVEAU

6.1 Accès

Nouveau bouton "Vue Kanban" dans la toolbar de la page Interventions, à côté de "Nouvelle demande". Ouvre /interventions/kanban. La page propose aussi des boutons retour vers la vue liste et la vue calendrier (livrée en 0.9).

6.2 Quatre colonnes

  1. Nouvelle (rouge) — DI fraîchement créées, à dispatch
  2. En cours (orange) — DI prises en charge par un technicien
  3. Résolue (vert) — DI clôturées avec succès
  4. Annulée (gris) — DI annulées (matériel finalement OK, doublon, etc.)

Chaque colonne affiche son compteur (badge coloré rond) et son icône.

6.3 Cartes DI

Chaque carte affiche :

  • Numéro de la DI en gras
  • Badge d'urgence à droite (Faible/Normal/Haute/Critique)
  • Type (Panne, Maintenance préventive, Livraison, Reprise matériel)
  • Cible (libellé du matériel ou nom du patient)
  • Date de création
  • Bordure gauche colorée selon l'urgence (rouge pour Critique, etc.)

6.4 Drag & drop entre colonnes

Si tu as le droit "écrire" sur l'app, les cartes sont draggables. Glisse une carte d'une colonne à l'autre pour changer son statut :

  • Surbrillance dashed sur la colonne ciblée pendant le drag
  • Mise à jour optimiste de l'UI (instantanée à l'écran)
  • Persistance Supabase en arrière-plan via update
  • Rollback automatique si le droit est refusé

6.5 Responsive

Sur tablette (≤900px), la grille passe à 2 colonnes empilées. Sur mobile (≤560px), à 1 colonne. Le Kanban devient une liste verticale par statut sans drag (le drag tactile n'est pas géré côté HTML5 standard).

7. Étiquettes patient sur fiche VALIDÉ

La fiche patient livrée en 0.13 avait déjà du code pour afficher les étiquettes du patient via la table patient_etiquettes. La 0.14 confirme que ce code fonctionne correctement avec les données réelles (validation contre le SQL de la 0.9).

Les étiquettes s'affichent en pastilles colorées sous le nom dans l'entête de la fiche, comme prévu. Pour gérer les étiquettes (ajouter, retirer), il faut passer par la liste Patients qui a l'icône dédiée (livrée en 0.9).

10. Procédure de mise à jour depuis Alpha 0.13

Mise à jour simple : pas de SQL.

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  4. Tests rapides :
    • Sur une fiche patient ou matériel, clique Imprimer : la modale d'aperçu s'ouvre avec le rendu A4. Le bouton Imprimer lance l'impression de l'iframe.
    • Depuis n'importe quelle page, presse ⌘ K ou Ctrl K : la palette de recherche s'ouvre. Tape "lit" : tu vois apparaître les patients, matériels, DI qui matchent. Utilise les flèches pour naviguer, Entrée pour ouvrir.
    • Sur Interventions, clique Vue Kanban : tu vois les DI dans 4 colonnes par statut. Glisse une carte d'une colonne à l'autre.
    • Sur Statistiques, clique Export PDF : tu vois maintenant la modale d'aperçu au lieu d'une nouvelle fenêtre. Échap pour fermer.
  5. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.14"
git push

📌 Pièges connus (rétro-doc depuis 0.17.0)

Cette section a été ajoutée après les sessions de migration 0.15.6 et 0.16.1.

⚠️ Piège : Kanban HTML5 DnD ne marche pas sur mobile

La vue Kanban des DI (livrée en 0.14) utilisait le HTML5 Drag-and-Drop natif (draggable, onDragStart, etc.) qui n'est pas supporté sur écrans tactiles. Sur mobile, impossible de glisser une carte.

Corrigé en 0.17.0 : refonte avec Pointer Events (compatibles souris + tactile sans dépendance externe). Le ghost-card suit le doigt, la détection de colonne se fait via elementFromPoint.

⚠️ Piège : pas d'échéance saisissable sur les DI

La 0.14 introduit le Kanban DI mais ne permet pas de saisir une échéance (date prévue de résolution). La colonne interventions.due_date a été ajoutée en 0.15.6 (et complétée en 0.16.1 par un alter table propre), et la saisie via un champ date dans la modale DI a été livrée en 0.17.0.

⚠️ Piège : aperçu PDF document.write() (cumul depuis 0.13)

L'aperçu PDF utilise document.write() qui génère un warning navigateur. Cosmétique, mais à refactoriser. Reporté en 0.18.
