1. Résumé exécutif

L'Alpha 0.3 enrichit l'expérience utilisateur avec quatre fonctionnalités transversales très visibles dès l'arrivée sur l'appli : la cloche de notifications dans la TopBar, la barre de recherche globale qui cherche dans plusieurs entités d'un coup, l'export CSV sur toutes les listes, et une page Paramètres qui permet enfin de personnaliser les libellés métier (résident vs patient, logement vs chambre) et les préférences d'affichage.

Priorisation transparente — encore une fois : la roadmap 0.3 listait 8 chantiers. Cette version en livre 5, à fort impact UX immédiat. Les 3 reportés en Alpha 0.4 (RLS étanche, mode hors-ligne PWA, domaine email pro) sont reportés pour de bonnes raisons : la sécurité RLS mérite un atelier dédié, le hors-ligne est un gros chantier service worker, et le domaine email dépend de toi.

3. Notifications in-app NOUVEAU

Une cloche apparaît dans la TopBar avec un badge rouge animé qui pulse quand des notifications non lues sont présentes. Au clic, un panneau déroulant affiche jusqu'à 30 notifications avec :

  • Une icône colorée selon le type (système, transfert, DI, invitation, commande)
  • Un titre + message + date relative ("à l'instant", "il y a 2h", "hier")
  • Un point teal en marge gauche pour les notifications non lues
  • Click qui marque comme lu ET navigue vers le lien associé
  • Bouton "Tout marquer lu" en haut
  • Polling toutes les 60s pour rafraîchir

Modèle de données

Nouvelle table notifications avec RLS par collectivité :

create table notifications (
  id uuid primary key,
  structure_id uuid,        -- collectivité (RLS)
  user_id uuid,             -- destinataire (null = pour tous les membres)
  type text,                -- 'systeme','transfert','di','invitation','commande','stock'
  titre text, message text,
  lien text,                -- chemin relatif ex: '/transferts'
  lue boolean default false,
  created_at timestamptz
);

Comment créer une notification depuis l'app

// Insertion simple (ex: depuis advance() d'un transfert)
await supabase.from("notifications").insert({
  structure_id: auth.structureId,
  type: "transfert",
  titre: "Transfert reçu",
  message: `Le transfert ${r.numero} est arrivé à destination.`,
  lien: "/transferts"
});

4. Recherche globale NOUVEAU

Barre de recherche dans la TopBar (masquée sur mobile par manque de place). Tape 2+ caractères pour déclencher la recherche, avec un debounce de 300ms.

Cherche en parallèle dans 4 entités de l'établissement courant :

  • Patients : par nom ou prénom (max 5 résultats)
  • Matériel : par libellé, n° série, n° parc
  • Articles : par libellé ou référence
  • Commandes : par numéro

Les résultats apparaissent groupés par type avec une icône, et un clic navigue vers la page de l'entité. Si aucun résultat : message "Aucun résultat pour …".

5. Export CSV / Excel NOUVEAU

Un bouton Export CSV apparaît automatiquement dans la toolbar de toutes les listes qui utilisent le composant Crud générique (articles, matériels, dépôts, stock, et les établissements de la fiche collectivité).

Format produit

  • Encodage : UTF-8 avec BOM (Excel reconnaît les accents)
  • Séparateur : point-virgule (standard fr)
  • Échappement : guillemets pour les valeurs contenant ;, " ou \n
  • Nom de fichier : <table>.csv (ex: patients.csv)

Helper réutilisable

import { exportCSV } from "../../lib/export";

exportCSV("patients.csv", rows, [
  { key: "nom", label: "Nom" },
  { key: "prenom", label: "Prénom" },
  { key: "date_entree", label: "Entrée", render: (r) => fmtDate(r.date_entree) },
]);

Une colonne peut être exclue de l'export en lui ajoutant { skipExport: true }.

6. Paramètres collectivité NOUVEAU

Nouvelle page /parametres accessible aux administrateurs. 3 sections de réglages :

Libellés métier

Adaptez les termes à votre activité. Exemples :

  • Un EHPAD remplace "Patient" par "Résident", "Chambre" par "Logement"
  • Une clinique garde "Patient" mais renomme "Service" en "Pôle"

Préférences d'affichage

  • Devise : EUR / CHF / USD
  • Format des dates : Français / Anglais / ISO
  • Afficher ou non la section Promotions dans le menu

Notifications

  • Avertir d'un nouveau transfert à valider
  • Avertir d'une DI urgente
  • Avertir lorsqu'un invité rejoint la collectivité

Stockage

Tous ces paramètres vivent dans un champ JSON parametres ajouté à la table structures. Aucune nouvelle table — juste un alter table add column.

7. Droits étendus à toutes les pages

L'Alpha 0.2 avait introduit auth.can(action) et l'avait appliqué à la page Patients et toutes les pages utilisant Crud. La 0.3 étend ce filtrage à :

  • Transferts : bouton "Nouveau transfert" masqué sans ecrire, bouton "Passer au statut suivant" masqué sans valider_transfert
  • Interventions : bouton "Nouvelle DI" masqué sans ecrire
  • Crud (héritage 0.2) : + bouton Export CSV qui apparaît selon les lignes affichées

Restent à étendre en 0.4 : collectivite (CRUD établissements), utilisateurs (invitations).

10. Procédure de mise à jour depuis Alpha 0.2

Cette fois 2 scripts SQL à exécuter (08 et 09).

  1. Sauvegarde ton dossier C:\aveho-ec-app.
  2. Décompresse le nouveau zip par-dessus.
  3. Dans Supabase SQL Editor, exécute dans l'ordre :
    • supabase/08_notifications.sql
    • supabase/09_parametres.sql
  4. Dans PowerShell :
    cd C:\aveho-ec-app
npm install
npm run dev
  5. Test local : tu dois voir la cloche et la barre de recherche dans la TopBar, et l'entrée Paramètres dans le menu.
  6. Mise en ligne :
    git add .
git commit -m "Aveho EC Alpha 0.3"
git push

11. Chantiers reportés en Alpha 0.4 — pourquoi

ChantierRaison du report
RLS étanche par établissementReporté depuis 0.2. Sécurité critique qui nécessite un atelier dédié : politiques fines par établissement + tests d'accès systématiques par rôle. À livrer seul pour bien faire.
Mode hors-ligne PWAReporté depuis 0.2. Refonte complète du service worker avec stratégie cache adaptée (network-first / cache-first selon le type), gestion des conflits offline→online, indexedDB pour les données. Gros chantier.
Domaine email pro chez ResendReporté depuis 0.2. Dépend de toi : achète un domaine (.fr ~10€/an chez OVH/Gandi/IONOS), je te guide pour la vérification Resend et le changement d'expéditeur (1 ligne dans index.ts).

12. Roadmap Alpha 0.4

Reprise des 3 chantiers reportés + nouveaux chantiers issus des retours :

  1. RLS étanche par établissement (priorité 1 : sécurité)
  2. Création automatique des notifications : ajouter des inserts dans notifications à la création d'un transfert, d'une DI urgente, d'une invitation acceptée. Aujourd'hui la table existe mais elle n'est pas peuplée automatiquement.
  3. Application effective des libellés métier : faire que params.libelle_patient renomme réellement "Patient" en "Résident" partout dans l'UI.
  4. Export PDF en plus du CSV (bordereaux de commande, fiches patient, listes imprimables)
  5. Mode hors-ligne PWA
  6. Domaine email pro
  7. Droits sur les pages restantes : collectivité (CRUD établissements), utilisateurs (invitations)
  8. Historique d'actions : qui a fait quoi, quand (audit log)
