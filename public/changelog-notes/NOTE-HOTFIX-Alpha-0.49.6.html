Patch 0.49.6 — Avatar mobile (suite) Empêcher l'avatar utilisateur de sortir de l'écran sans casser les dropdowns

Date : 31 mai 2026 Version : v0.49.6-alpha Tests : 869 verts (inchangé) Build : clean

Le problème

En mode mobile, l'avatar utilisateur (la bille colorée à droite de la TopBar) sortait à droite de l'écran, alors qu'en mode desktop tout allait bien.

Causes en cascade :

  • En 0.49.4, j'avais retiré le overflow:hidden sur .topbar (qui coupait le dropdown du menu utilisateur).
  • Sans cette ceinture, les enfants de la topbar (qui sont en display:flex) ne se comprimaient plus assez sur mobile.
  • Conséquence : l'avatar utilisateur, dernier élément à droite, se faisait pousser hors écran.

Pourquoi le flex ne comprimait pas

Par défaut, un élément enfant d'un display:flex a un min-width:auto. Ce auto signifie : "ma largeur intrinsèque, c'est-à-dire la place dont j'ai besoin pour mon contenu — je ne peux pas être plus petit que ça".

Quand la somme des largeurs intrinsèques de tous les enfants dépasse la largeur du conteneur, deux comportements possibles :

  • Avec overflow:hidden sur le parent → les enfants sont coupés visuellement (ce qu'on avait avant la 0.49.4, mais ça cassait les dropdowns).
  • Sans overflow:hidden → les enfants débordent à l'extérieur du conteneur (ce qui se passait depuis la 0.49.4).

La vraie solution n'est ni l'un ni l'autre : il faut autoriser explicitement les enfants à se compresser en mettant min-width:0 dessus.

Correction CSS

- .topbar{...; z-index:40}
+ .topbar{...; z-index:40; max-width:100vw}
+ .topbar > *{min-width:0; flex-shrink:1}

  @media(max-width:480px){
    .etab-switch{display:none}
-   .topbar{gap:8px; padding:0 10px}
+   .topbar{gap:6px; padding:0 8px}
    .topbar .logo{font-size:18px}
+   /* Cacher le bouton recherche en mobile (accessible via Ctrl+K ou menu) */
+   .topbar .tb-icon[aria-label*="Recherche"]{display:none}
+   /* Avatar utilisateur reste à sa taille fixe (priorité visuelle) */
+   .um-btn{flex-shrink:0}
  }

Explication des 4 changements

RègleEffet
max-width:100vw sur .topbar Limite stricte au viewport. La topbar ne peut plus s'agrandir au-delà de la largeur écran.
min-width:0; flex-shrink:1 sur tous les enfants Autorise tous les enfants flex à se compresser sous leur largeur intrinsèque. Empêche le débordement horizontal.
display:none sur bouton recherche <480px Économise ~40px de largeur. La recherche reste accessible via Ctrl+K au clavier ou via le menu burger.
flex-shrink:0 sur .um-btn (avatar) L'avatar est le seul à NE PAS se compresser. Du coup il est garanti de rester visible avec sa taille de cercle 40×40. Tous les autres éléments se serrent pour lui faire place.

Pour ma checklist

14ᵉ réflexe — Sur un flex container avec beaucoup d'enfants (ex: topbar), toujours appliquer :

.container > * {
  min-width: 0;       /* Autorise la compression sous la largeur intrinsèque */
  flex-shrink: 1;     /* Permet aux enfants de rétrécir */
}

Et marquer l'élément critique avec flex-shrink:0 pour qu'il garde sa taille (ici, l'avatar utilisateur — c'est le point d'entrée du menu, il doit toujours être cliquable).

Si on ne le fait pas, le défaut min-width:auto empêche la réduction et on a soit un débordement horizontal (sans overflow:hidden), soit des éléments tronqués (avec).
