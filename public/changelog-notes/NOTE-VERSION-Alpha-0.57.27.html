🐛 1. Bug signalé : "pour l'empreinte digital il me dit session expirée"

Diagnostic

Les refresh_tokens Supabase ont une durée limitée (60 jours par défaut). Si le user se connecte toujours par mot de passe et jamais par empreinte, le refresh_token stocké pour la biométrie vieillit jusqu'à expiration.

Workflow buggué avant 0.57.27 :

  1. User enregistre son empreinte → stockage local IndexedDB : { refresh_token: "abc..." }
  2. User se connecte toujours par mot de passe pendant 60+ jours
  3. User essaie l'empreinte → supabase.auth.refreshSession({ refresh_token: "abc..." })
  4. Supabase répond : refresh_token expired (>60j)
  5. removeLocalCredential() + throw "Session expirée"
  6. User perd sa biométrie → doit re-enrôler à zéro

Chicken-and-egg : pour rafraîchir le refresh_token, il fallait pouvoir l'utiliser. Mais le seul moyen de l'utiliser, c'était la biométrie !

Fix : sync auto à chaque login mot de passe

Nouvelle fonction syncBiometricRefreshTokens() dans lib/webauthn.js appelée après chaque signInWithPassword réussi.

export async function syncBiometricRefreshTokens({ supabase, email }) {
  if (!email) return;
  try {
    const { data: { session } } = await supabase.auth.getSession();
    if (!session?.refresh_token) return;

    const emailKey = email.toLowerCase().trim();
    const raw = await dbGet(emailKey);
    const item = normalizeStorage(raw);
    if (!item) return;

    // Sync sur empreinte ET face si présentes
    let updated = false;
    for (const method of ["empreinte", "face"]) {
      if (item[method]?.refresh_token) {
        item[method].refresh_token = session.refresh_token;
        item[method].last_synced_at = new Date().toISOString();
        updated = true;
      }
    }
    if (updated) {
      await dbPut(item);
      logger.info("[WebAuthn] Refresh tokens biométriques synchronisés");
    }
  } catch (e) {
    // Non-bloquant : si ça échoue, on log mais on ne casse pas le login
    logger.warn("[WebAuthn] syncBiometricRefreshTokens fail:", e);
  }
}

Effet : tant que tu te connectes régulièrement (par n'importe quel moyen), ton refresh_token biométrique reste frais et ne peut pas expirer.

Bug secondaire fixé : erreur réseau confondue avec token expiré

Avant 0.57.27, TOUTE erreur lors de refreshSession (y compris coupure réseau de 5 sec) faisait removeLocalCredential() → l'user perdait sa biométrie pour rien.

Fix : distinguer les 2 cas.

const isExpiredToken =
  error?.status === 400 ||
  /refresh.*token|invalid_grant|expir/i.test(error?.message || "");

if (!isExpiredToken) {
  // Erreur réseau / autre → GARDE le credential, message neutre
  throw new Error("Connexion à Supabase impossible. Vérifiez votre réseau et réessayez.");
}

// Token vraiment expiré → on supprime + message clair
await removeLocalCredential(email, method);
throw new Error(
  "Votre " + METHOD_LABEL[method] + " n'est plus valide (inutilisée depuis longtemps). " +
  "Connectez-vous avec votre mot de passe, elle sera automatiquement réactivée."
);

🛡️ 2. Bonus sécurité : escape SQL wildcards ILIKE

Supabase JS client échappe les valeurs (parameterized queries) → pas de risque de vraie SQL injection. MAIS les caractères wildcards % et _ ne sont pas échappés.

Conséquences :

  • Un user peut envoyer prescripteur_nom = "%" → matche TOUT → scan exhaustif des prescriptions (potentiel DoS)
  • Ou nom = "_" → matche n'importe quelle string d'1 caractère

Nouvelle fonction escapeIlike()

// lib/validateInput.js
export function escapeIlike(s) {
  if (typeof s !== "string") return s;
  // Échapper \\ d'abord (sinon casse l'échappement des % et _)
  return s
    .replace(/\\/g, "\\\\")
    .replace(/%/g, "\\%")
    .replace(/_/g, "\\_");
}

// Usage dans 3 routes :
//  - prescriptions/search (3 ILIKE : medicament_nom, medicament_dci, prescripteur_nom)
//  - prescriptions/export-csv (1 ILIKE : prescripteur_nom)
//  - patients/from-ocr (2 ILIKE : caisses.nom, mutuelles.raison_sociale)
linesQuery = linesQuery.ilike("medicament_nom", `%${escapeIlike(body.medicament_query)}%`);

LINT anti-régression

it("Aucune route API ne fait .ilike(`%${...}%`) sans escapeIlike", () => {
  const violations = [];
  for (const f of findFiles("app/api")) {
    const src = fs.readFileSync(f, "utf-8");
    const matches = src.match(/\.ilike\(\s*"[^"]*"\s*,\s*`[^`]*\$\{[^}]+\}[^`]*`/g) || [];
    for (const m of matches) {
      if (!/escapeIlike/.test(m)) violations.push({ file: f, match: m });
    }
  }
  expect(violations).toEqual([]);   // ← FAIL si pattern dangereux revient
});

9ème LINT critique anti-régression. Garantit qu'aucune future route ne pourra introduire un ILIKE non sanitizé.
