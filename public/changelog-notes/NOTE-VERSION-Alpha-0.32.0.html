Résumé

Quick win pour terminer le sujet "tracker signalements perso" évoqué depuis la 0.29.1. Ajout d'un opt-in qui permet à l'utilisateur de cocher "Tracker dans mon profil" lors de la création d'un signalement. Sans cette case → anonymat strict comme avant.

Anonymat préservé par défaut. La colonne created_by est NULLABLE et reste NULL par défaut. Aucune backfill rétroactive. Les signalements existants restent anonymes. L'utilisateur doit cocher explicitement la case pour que son signalement soit rattaché à son profil — choix conscient et réversible (édition).

1. SQL — ajout created_by NULLABLE

alter table signalements
  add column if not exists created_by uuid 
  references auth.users(id) on delete set null;

-- Index conditionnel : performant pour les requêtes /profil
create index if not exists idx_signal_created_by 
  on signalements (created_by) 
  where created_by is not null;

-- Vue helper pour stats activité
create or replace view v_signalements_par_user as
select 
  structure_id, created_by as user_id,
  count(*) as nb_signalements_signes,
  count(*) filter (where statut = 'Nouveau') as nb_nouveaux,
  count(*) filter (where statut = 'Traité') as nb_traites,
  max(created_at) as dernier_signalement
from signalements
where created_by is not null
group by structure_id, created_by;

Choix techniques importants

  • NULLABLE strict : aucune contrainte NOT NULL, aucune valeur par défaut. NULL = anonyme.
  • ON DELETE SET NULL : si l'auteur est supprimé, le signalement reste mais redevient anonyme. Préserve la mémoire des signalements même après départ.
  • Index conditionnel : where created_by is not null → ne pas indexer les NULL (gain place + vitesse).
  • RLS inchangée : tout membre voit tous les signalements (anonymes et signés). Pas de surprise pour les admins.
  • Aucune backfill rétroactive : les signalements créés avant la 0.32 restent NULL → anonymes éternellement, même si l'auteur change d'avis.

2. UX — Checkbox opt-in

Dans le formulaire de création d'un signalement (/signalements), juste après le champ "Signature (optionnel)", un encart visuel apparaît :

┌─────────────────────────────────────────────┐
│ ☐ 👤 Tracker dans mon profil               │
│   Ce signalement apparaîtra dans tes stats  │
│   personnelles (/profil). Reste visible par │
│   tous les membres comme un signalement     │
│   classique.                                │
│   ✓ Anonymat préservé par défaut.          │
└─────────────────────────────────────────────┘

Comportement visuel

  • Décoché par défaut : encart gris pâle, fond gris, texte "Anonymat préservé par défaut" en vert.
  • Coché : encart bleu pâle, bordure teal, icône user-check bleue, message d'anonymat masqué.
  • Édition admin : la checkbox n'apparaît PAS — on ne peut pas changer created_by après coup, ce qui préserve la décision initiale de l'auteur.

Coexistence avec le champ signature texte

Le champ signature (text libre "Marie IDE service 2A") et le booléen trackPerso (created_by) sont indépendants :
