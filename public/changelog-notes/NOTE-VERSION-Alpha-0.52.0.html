Chantiers livrés

AK Logs applicatifs front

  • Nouvelle table app_logs avec colonnes : level (debug/info/warn/error), source (client/sw/cron), message, context (jsonb), user_agent, url, etc.
  • 2 index : un général (struct + created_at desc), un partiel (level warn/error + created_at desc)
  • RLS : select admin, insert tous authentifiés (les logs peuvent venir du SW sans structure connue)
  • Helper lib/appLog.js avec fonction logApp(supabase, auth, payload) — best-effort, silencieux si échec
  • Composant <GlobalErrorCapture /> monté dans le layout qui intercepte automatiquement :
    • window.addEventListener("error") → erreurs JS classiques avec stack trace
    • window.addEventListener("unhandledrejection") → promises rejetées non catchées
  • Page /app-logs :
    • Filtres : level, source, recherche libre (message + email)
    • Pagination 50 par page
    • Modal détail au clic avec context jsonb formaté
    • Accès réservé aux admins
  • Lien menu Administration "Logs applicatifs"

BD Métriques 7j sur page statut

  • 3 KPIs chargés en parallèle :
    • Actions tracées (count audit_log sur 7j)
    • Erreurs front (count app_logs où level=error sur 7j)
    • Connexions (count audit_log où action=connexion sur 7j)
  • Couleurs sémantiques : 0 erreur → vert, sinon rouge
  • Best-effort : si le patch SQL 0.52 n'est pas encore appliqué (app_logs n'existe pas), le panel ne s'affiche pas (catch silencieux)
  • Position : entre les services et l'historique des checks

BE Filtres audit prédéfinis (presets)

  • Nouvelle barre en haut de /audit avec 5 boutons en chips bleu pâle :
    • Mes actions — filtreUser = auth.user.id
    • Suppressions 24h — action=supprimer + periode=1
    • Modifs 24h — action=modifier + periode=1
    • Connexions 7j — action=connexion + periode=7
    • Validations 30j — action=valider + periode=30
  • Fonction applyPreset(name) qui reset d'abord tous les filtres puis applique la config du preset
  • Style chip arrondi avec border bleue + icône Tabler
  • Zéro SQL — utilise les colonnes existantes audit_log

BF Dashboard digest notifications

  • 2 nouvelles vues SQL :
    • v_digest_stats : par structure + type_digest, agrège sur 30 jours glissants nb_envoyes (filter succes=true), nb_erreurs, nb_total, taux_succes_pct, premier_envoi, dernier_envoi
    • v_digest_destinataires_uniques : count distinct user_id par type sur 30 jours
  • Page /digest-dashboard :
    • Cards par type de digest (quotidien=bleu, hebdo=violet) avec border-left coloré
    • Grille 2x2 : envoyés + erreurs + taux succès + destinataires uniques
    • Footer card : "Du X au Y" (premier et dernier envoi)
    • Panel erreurs récentes (10 dernières) si présentes — fond rouge pâle
    • Couleur taux : vert ≥ 95%, orange 80-94%, rouge < 80%
    • Accès admin uniquement
  • Lien menu Administration "Digests dashboard"

BG Mode focus (Esc Esc)

  • Composant <FocusMode /> auto-monté dans le layout
  • Détection double-Esc avec seuil < 500ms entre les deux appuis
  • Ignoré dans les inputs/textarea/contentEditable (l'user peut être en train de taper)
  • Effet du double-Esc :
    1. Cherche tous les .modal-bg et [role="dialog"] → clique leur bouton "Fermer"
    2. Cherche tous les .um-backdrop et .menu-overlay.open → clique pour fermer
    3. Blur l'élément actif (sortir du focus)
    4. Scroll en haut de page (smooth)
    5. Flash visuel 1.2s : pill vert "Mode focus — tout fermé" en haut centre
  • Reset du compteur après chaque double-Esc pour éviter triple-Esc parasite

G Recherche c: et f:

  • Nouveaux préfixes dans GlobalSearch (palette ⌘K) :
    • c:dupont → consentements RGPD avec ce nom (cherche dans patient_nom_prenom + patient_numero_dossier)
    • f:Bastide → fournisseurs (cherche dans achats.fournisseur, groupé distinct avec count des commandes)
  • Regex préfixe mise à jour : /^([pmdsatxcf]):(.*)$/i
  • Mapping : { c: "consent", f: "fournisseur" }
  • Affichage consent : nom patient + statut (✓ Consenti ou ✗ Refusé) + n° dossier + date signature
  • Affichage fournisseur : nom + count commandes + dernière commande
  • Lien fournisseur : /achats?fournisseur=... (préparation d'un filtre URL pour future itération)
  • Placeholder mis à jour pour mentionner les nouveaux préfixes
  • TYPES enrichis : consent (shield vert) + fournisseur (truck rouge foncé)

Procédure d'application — PowerShell

  1. Appliquer le patch SQL dans Supabase > SQL Editor
  2. Décompresser le zip par-dessus C:\aveho-ec-app\
  3. Installer & lancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm test
npm run dev
    Attendu : 944 tests verts.
  4. Tester :
    • AK : DevTools console → throw new Error("test") → aller dans Administration → Logs applicatifs → la ligne d'erreur doit apparaître
    • BD : Statut système → section "Métriques 7 derniers jours" avec 3 cards
    • BE : /audit → cliquer un des chips bleu pâle (ex: "Suppressions 24h") → les filtres s'appliquent automatiquement
    • BF : Administration → Digests dashboard → cards par type de digest + erreurs récentes si présentes
    • BG : ouvrir un modal (ex: nouvelle annonce) → appuyer 2 fois sur Esc rapidement → le modal se ferme + flash vert "Mode focus — tout fermé" + scroll en haut
    • G : Ctrl+K → taper c:dupont → consentements de patients Dupont. Taper f:Bastide → fournisseur Bastide avec count commandes
