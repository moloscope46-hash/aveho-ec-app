🎯 Le concept

Tu mets le google_place_id sur tes établissements (récupérable via /api/place ou directement depuis le résultat de Google Maps "Partager → Intégrer une carte"), et l'app :

  • Synchronise automatiquement toutes les 6h les avis Google de chaque établissement
  • Stocke jusqu'à 5 avis par établissement (limite Google) avec auteur, photo, note, contenu, réponse
  • Met à jour la note moyenne + nombre total d'avis sur chaque fiche
  • Te permet de voir tous les avis dans une page admin centralisée avec filtres et alertes critiques
  • Trace chaque run dans une table d'audit (qui a déclenché, combien d'étabs OK, durée, etc.)

📋 Architecture

1. Cron pg_cronToutes les 6h (0h/6h/12h/18h)
2. Edge Functionsync-google-reviews (Deno)
3. Google APIPlaces Details (max 5 avis par étab)
4. Upsert SQLDéduplication par (étab, auteur, date)

Toutes les étapes sont monitorées :

  • Status par établissement (ok / api_error / rate_limited / jamais sync)
  • Logs dans google_sync_logs avec details JSONB (per_etab array complet)
  • Rate limit Google respecté (200ms entre 2 appels + arrêt si OVER_QUERY_LIMIT)

Table etablissements_avis_google (14 colonnes)

1 ligne = 1 avis Google. Champs : auteur (nom + URL + photo profil), langue, rating 1-5, relative_time_description ("il y a 2 mois"), publish_time absolue, text_content, traduction, reply_text + reply_publish_time (réponse établissement si présente), raw_payload jsonb pour debug.

Contrainte unique NULLS NOT DISTINCT (etablissement_id, author_name, publish_time) pour déduplication propre lors des re-syncs.

Table google_sync_logs (audit)

1 ligne = 1 run cron ou manuel. Champs : trigger_source, etablissements_total/ok/errors, nouveaux_avis, duration_ms, details jsonb avec per_etab array.

🤖 Edge Function

Fichier supabase/functions/sync-google-reviews/index.ts :

  • Client Supabase service_role (bypass RLS pour pouvoir lire et écrire tous les établissements de toutes les structures)
  • Itère sur les établissements avec google_place_id non null
  • Pour chacun, appelle l'API Google places/details avec fields=name,rating,user_ratings_total,reviews&language=fr
  • Update statut + rating + nb avis sur l'établissement
  • Upsert batch des avis via la RPC upsert_avis_google_batch
  • Délai 200ms entre 2 établissements pour respecter le quota Google
  • Si OVER_QUERY_LIMIT détecté → arrêt immédiat de la boucle
  • Support body.etablissement_id pour synchroniser un seul établissement à la demande
  • Logs détaillés dans google_sync_logs

⏰ Cron Supabase 6h

Le SQL crée un job pg_cron :

cron.schedule(
  'sync-google-reviews-cron',
  '0 */6 * * *',  -- 0h / 6h / 12h / 18h
  $$
    select net.http_post(
      url := current_setting('app.settings.sync_google_reviews_url'),
      headers := jsonb_build_object(
        'Authorization', 'Bearer ' || current_setting('app.settings.service_role_key')
      ),
      body := jsonb_build_object('trigger_source', 'cron')
    );
  $$
);

L'URL de l'Edge Function et la service_role_key doivent être configurées une seule fois via ALTER DATABASE ou via le Vault Supabase. Voir la procédure ci-dessous.

⚠️ Limites connues

  • 5 avis max par établissement : limite imposée par l'API Google Places Details (pas contournable)
  • Pas d'historique des avis supprimés : si un avis disparaît de Google, il reste en base mais ne sera plus mis à jour
  • Quota Google : 100k requêtes/mois en gratuit, au-delà payant. Avec 50 étabs sync 4×/jour = 6000 req/mois (large marge)
  • Réponses établissement : actuellement reply_text est null car l'API Places Details ne renvoie pas les réponses propriétaires. Pour ça il faudrait l'API Business Profile (OAuth requis, plus complexe)
  • Coût clé Google : nécessite une clé Google Places API activée avec facturation configurée (gratuit jusqu'à 100k req/mois). Pense à restreindre la clé par IP/domaine dans la Google Cloud Console
