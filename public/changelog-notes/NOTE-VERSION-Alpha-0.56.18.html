📞 La nouvelle Panel "Coordonnées & contacts"

Sur la fiche patient (/patient/[id]), entre le header et les KPIs : une nouvelle section qui regroupe toutes les coordonnées du patient et de ses contacts, avec des boutons d'action cliquables (téléphone, email, itinéraire GPS, site web).

6 sections en grille responsive

📱 Patient
Portable + fixe + email + adresse
⚠️ Urgence
Nom + lien parenté + téléphone
💝 Personne de confiance
Nom + téléphone
🩺 Médecin traitant
Nom + RPPS + téléphone
🛡 Caisse
Nom + type + code org + adresse
🤝 Mutuelle
Raison sociale + AMC + adresse

Boutons d'action sur chaque section :

  • 📞 Appeler → tel: au tap, ouvre l'app téléphone
  • ✉️ Email → mailto:, ouvre client mail
  • 🗺 Itinéraire GPS → Google Maps avec destination latitude/longitude (ou adresse texte si pas de coords)
  • 🌐 Site web → ouvre le site dans un nouvel onglet

Les boutons n'apparaissent que pour les actions disponibles selon les données (pas de bouton mail si pas d'email).

🔑 Identifiants administratifs avec bouton Copier

Sous la grille, une sous-section avec les 4 identifiants administratifs principaux, chacun avec un bouton 📋 Copier :

  • Dossier — Numéro de dossier interne
  • IPP — Identifiant Permanent du Patient
  • N° Sécurité Sociale — affiché en police monospace
  • N° Adhérent mutuelle — affiché en police monospace

Au clic, le bouton change momentanément en "Copié !" avec une coche verte (feedback visuel 1.5s) puis revient à son état initial. Utilise navigator.clipboard.writeText().

🛠 Détails techniques

Chargement intelligent

Après le chargement principal du patient, deux requêtes parallèles sont lancées uniquement si nécessaire :

  • Si p.caisse_id existe → fetch caisses_assurance_maladie
  • Si p.mutuelle_id existe → fetch mutuelles

Pas de RPC — lecture directe, donc résistant aux bugs RPC.

Composants internes

  • CoordonneesPanel — composant principal, masqué si rien à afficher
  • CoordRow — ligne avec icône colorée, borderLeft coloré, label, sub, valeur, ContactActions size='sm'
  • IdRow — identifiant avec icône, label uppercase, valeur (mono optionnel), bouton Copier

Fix ContactActions cp ↔ code_postal

Le composant ContactActions utilise désormais entity.cp || entity.code_postal pour construire l'adresse passée à Google Maps. Les 2 tables mutuelles et caisses_assurance_maladie utilisent en réalité cp (et pas code_postal comme je supposais initialement). Ce fix garantit que le bouton GPS fonctionne maintenant correctement pour ces 2 référentiels santé.

Bonus : template_libelle retiré du rendu

Sur la liste des consentements RGPD, l'affichage de c.template_libelle est retiré (déjà retiré du select en 0.56.17, mais le span d'affichage subsistait). Pas d'erreur visible, juste un span undefined. Faudra une jointure vers consentements_templates dans une future version pour avoir le libellé du template.
