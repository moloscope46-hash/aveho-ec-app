Pourquoi c'est important

Le lib/logger :

  • 🛡️ Redacte automatiquement les valeurs sensibles : password, passwd, mot_de_passe, mdp, token, refresh_token, access_token, secret, api_key, apikey, credential_id
  • 🤫 Silencieux en production (sauf si flag aveho:debug-logs activé via localStorage) — plus rien dans la console des utilisateurs finaux
  • 🎯 Centralisé : on peut ajouter Sentry / Datadog / LogRocket plus tard sans toucher au code applicatif

Avant

console.error("[Carte] Erreur init Leaflet :", e);
console.warn(`[Carte RPPS] HTTP`, res.status);
console.log("[Carte RPPS]", prof, data.results.length, "résultats");

Après

import { logger } from "../../lib/logger";

logger.error("[Carte] Erreur init Leaflet :", e);
logger.warn(`[Carte RPPS] HTTP`, res.status);
logger.info("[Carte RPPS]", prof, data.results.length, "résultats");

🛡️ Fix 2 — try/catch sur 5 pages

5 pages identifiées par l'audit comme sans gestion d'erreur sur leurs appels Supabase. Si Supabase répond mal (timeout, erreur 500, déconnexion réseau) → la page restait coincée en loading infini.

PageAppels protégés
app/admin/bulletins-archive/page.jsRPC stats + select patients
app/journal/page.jsaudit_log + membres_structure
app/materiel/[id]/page.js6 appels Promise.all (materiels + tags + maintenances + interventions + transferts + materiel_tags)
app/tags-materiel/page.jsselect tags_materiel
app/page.js (racine)auth.getSession() avec .catch chaîné + fallback vers /login

Pattern utilisé

useEffect(() => {
  if (!auth.ready) return;
  (async () => {
    try {
      const [...] = await Promise.all([...]);
      setMat(m || null);
      // setters
    } catch (e) {
      // 0.56.22 : try/catch pour pas planter la page
      logger.error("[Materiel] load failed:", e);
    } finally {
      setLoading(false);   // <- toujours désactivé pour pas rester en loading infini
    }
  })();
}, [auth.ready, matId]);

Pour app/page.js (qui utilise une Promise chaînée) : .catch() avec fallback vers /login au lieu de rester sur l'écran "Chargement…" infini.
