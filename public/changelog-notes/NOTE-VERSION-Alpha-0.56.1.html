🎯 Le problème résolu

Jusqu'ici, quand tu scannais un bulletin de situation pour créer un patient, l'image originale était oubliée. L'OCR était fait, le texte brut conservé, mais pas le document source.

Or pour l'audit, la relecture en cas de doute, ou un re-OCR ultérieur (modèle plus récent), il faut garder le fichier original. C'est ce que résout cette version.

📦 Architecture Storage Supabase

Bucket privé bulletins-scannes

  • Privé (pas d'URL publique)
  • 10 Mo max par fichier
  • MIME autorisés : image/jpeg, image/png, image/webp, image/heic, application/pdf
  • 4 policies RLS (SELECT/INSERT/UPDATE/DELETE) qui isolent par structure_id

Convention de chemin

{structure_id}/{patient_id}/{timestamp}-{filename_safe}

La RLS lit le premier segment du path pour vérifier que le user appartient bien à la structure propriétaire du fichier.

Workflow d'archivage

  1. User scanne un bulletin → OCR Claude Vision → patient créé
  2. L'app upload automatiquement le fichier original dans le bucket
  3. Le patient est mis à jour avec bs_file_path, bs_file_mime, bs_file_size_kb
  4. Si l'archivage échoue (rare), le patient reste créé avec juste un warning ambré
  5. L'onglet Audit de la fiche affiche un preview signé (lien 1h)

🗄 Nouvelles colonnes patient

🔒 Confidentialité & sécurité

  • Bucket privé — aucun lien public accessible sur le web
  • RLS Supabase — un user d'une autre structure ne peut ni voir ni lister les fichiers de la tienne
  • URL signées avec createSignedUrl() — validité 1h, régénérée à chaque chargement de la page Audit
  • Pas de cache côté client (impossible de redonner un lien expiré)
  • Suppression : possible depuis la fiche patient (action admin, irréversible)

Nouvelle page admin pour voir d'un coup d'œil tous les bulletins archivés de ta structure :

  • 6 KPI : nb bulletins archivés, espace utilisé Ko/Mo, premier archive, dernier archive, tokens IN total, tokens OUT total
