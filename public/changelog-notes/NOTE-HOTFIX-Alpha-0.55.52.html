❌ Le bug

sw.js:137 Uncaught (in promise) TypeError:
Failed to execute 'put' on 'Cache':
Request scheme 'chrome-extension' is unsupported
    at networkFirst (sw.js:137:13)

La cause

Les extensions navigateur (LastPass, Dashlane, Grammarly, MetaMask, Honey, Bitwarden, etc.) injectent leurs propres content scripts dans toutes les pages que tu visites. Ces scripts font parfois des requêtes fetch() vers leurs propres ressources chrome-extension://abc123.../resource.js.

Ces requêtes passent par le Service Worker de la page (le nôtre), mais cache.put() refuse strictement les schémas autres que http/https → throw immédiatement.

✅ La correction (ceinture + bretelle)

1) Early return dans le handler fetch

self.addEventListener("fetch", (event) => {
  const req = event.request;
  if (req.method !== "GET") return;

  // 0.55.52 : bypass complet des schémas non-cachables
  if (!req.url.startsWith("http://") && !req.url.startsWith("https://")) {
    return;  // → le navigateur fait son fetch normal sans le SW
  }
  ...
});

Couvre : chrome-extension://, moz-extension://, safari-extension://, data:, blob:, file://, ws://, wss://.

2) Helper safeCachePut

async function safeCachePut(cache, req, res) {
  try {
    const url = (typeof req === "string" ? req : req.url) || "";
    if (!url.startsWith("http://") && !url.startsWith("https://")) return;
    if (res.type === "opaque" || res.type === "opaqueredirect") return;
    await cache.put(req, res);
  } catch (_) {
    // Silent fail — pas de noise dans la console
  }
}

Tous les appels cache.put() dans cacheFirst, networkFirst (success + retry), staleWhileRevalidate passent par ce wrapper.

Vérifie aussi :

  • Schéma de l'URL avant put
  • Type de response (skip opaque et opaqueredirect qu'on ne peut pas servir correctement)
  • Catch silencieux — aucun console.error pour ne pas polluer la console
