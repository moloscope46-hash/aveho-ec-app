1. Ciblage établissement sur les annonces

Avant : une annonce était visible par tous les membres de la structure, peu importe leur établissement courant.

Maintenant : chaque annonce peut être :

  • 🌍 Globale (etablissement_id null) — visible partout dans la structure
  • 🏥 Ciblée sur un établissement — visible uniquement quand l'user a cet établissement comme contexte courant

SQL ajouté (patch 0.52.5)

alter table annonces
  add column if not exists etablissement_id uuid 
    references etablissements(id) on delete cascade;

create index if not exists idx_annonces_etab on annonces (etablissement_id);

notify pgrst, 'reload schema';

UI page /annonces

  • Nouveau champ select dans la modale d'édition : "Cibler un établissement (optionnel)"
  • Option par défaut : "🌍 Toute la structure (par défaut)"
  • Options établissements : "🏥 Nom de l'établissement"
  • Nouvelle colonne "Cible" dans le tableau :
    • Si globale → chip gris "🌐 Toute la structure"
    • Si ciblée → chip bleu "🏥 Nom étab"

Filtrage côté AnnoncesBanner

  • Requête modifiée pour ne charger que :
    • etablissement_id IS NULL (globales) OU
    • etablissement_id = auth.etabId (correspondant à l'étab courant de l'user)
  • Si l'user change d'établissement courant via le menu, les annonces se rechargent automatiquement (deps useEffect incluant auth.etabId)

Procédure d'application — PowerShell

  1. Appliquer le patch SQL aveho-PATCH-vers-0.52.5.sql dans Supabase > SQL Editor (1 seconde — juste un ALTER TABLE + index)
  2. Décompresser le zip 0.52.5 par-dessus C:\aveho-ec-app\

  4. Tester ciblage étab annonces :
    • /annonces → Nouvelle annonce → choisir "🏥 Établissement X"
    • Switcher entre établissements via le menu user → la bannière ne s'affiche qu'avec X comme contexte courant
