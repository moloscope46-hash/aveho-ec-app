3. Push VAPID — Architecture

3.1 Flux complet

  1. L'utilisateur va dans /parametres et clique sur "Autoriser les notifications" dans le bloc Notifications avancées.
  2. Le navigateur demande la permission de notification. Si accordée, le composant <NotificationOptIn> appelle pushManager.subscribe() avec la clé VAPID publique.
  3. Le navigateur génère un endpoint unique (FCM pour Chrome, Mozilla pour Firefox, Apple pour Safari) et des clés p256dh + auth.
  4. Le composant insère cette subscription dans la table push_subscriptions avec l'user_id, le structure_id, et le user_agent.
  5. Quand un événement notifiable se produit (DI urgente, achat à valider, etc.), logEvent() dans lib/events.js appelle l'Edge Function send-push en fire-and-forget.
  6. send-push récupère toutes les subscriptions de la structure (vue v_push_targets), formate le payload, et appelle web-push.sendNotification() avec les clés VAPID privées.
  7. Le service worker (public/sw.js) reçoit l'événement push, affiche la notification via self.registration.showNotification(), et écoute le clic pour ouvrir l'URL.

3.2 Composant <NotificationOptIn>

5 états gérés :

  • idle : prêt à demander la permission. Bouton "Autoriser les notifications" affiché.
  • working : en cours d'inscription (anti-double-clic).
  • subscribed : déjà inscrit. Bouton "Envoyer un test" + bouton "Désactiver".
  • denied : permission refusée par le navigateur. Instructions pour réactiver.
  • unsupported : navigateur sans Service Worker ou Push API (vieux Safari, certains in-app browsers).

Le bouton "Envoyer un test" déclenche un push réel ciblé sur le user courant, ce qui permet de valider toute la chaîne (clés VAPID, service worker, navigation).

3.3 Nettoyage automatique

Si un endpoint retourne 410 (Gone) ou 404 lors d'un envoi (l'utilisateur a désinstallé la PWA, désactivé les notifs dans le système, etc.), send-push le détecte et le supprime de la base. Pas de spam des endpoints morts.

4. Webhooks Teams & Slack

4.1 Composant <WebhookConfig>

Affiché dans /parametres juste après l'opt-in push. Permet :

  • Saisir l'URL webhook Teams (workflow "Post to channel")
  • Saisir l'URL webhook Slack (incoming webhook)
  • Cocher les 3 filtres d'événements : DI urgentes, Achats à valider, Signalements
  • Bouton "Tester" par canal qui envoie un message de test
  • Sauvegarde dans structures.webhook_teams_url / webhook_slack_url / webhook_filters

4.2 Edge Function send-webhook

Reçoit en POST :

{
  structure_id: "uuid",
  channels: ["teams", "slack"],   // optionnel, défaut: les deux
  event_type: "di_urgente",       // pour le filtrage
  title: "DI urgente créée",
  message: "DI-1234 — Lit en panne",
  url: "https://app.aveho.fr/interventions",
  fields: { Établissement: "EHPAD Les Tilleuls", Urgence: "Critique" }
}

Construit deux payloads distincts :

  • Teams : MessageCard avec themeColor, sections, facts, et bouton OpenUri
  • Slack : Block Kit avec sections, fields en 2 colonnes, et bouton action

Avant l'envoi, vérifie le filtre webhook_filters[event_type]. Si false, l'envoi est ignoré (réponse { reason: "filtered_out" }).

4.3 Format Teams (extrait)

{
  "@type": "MessageCard",

}

4.4 Branchement automatique dans lib/events.js

Toute action passant par logEvent() avec notif: true ou notifType défini déclenche désormais en fire-and-forget les appels à send-push et send-webhook. Si les fonctions ne sont pas déployées ou que les configs sont absentes, les appels échouent silencieusement (warn console) sans perturber le flux applicatif.

5. Tri Kanban par échéance

Dans /interventions/kanban, ajout d'un toggle dans la barre d'actions :

  • Création (défaut) : ordre par created_at desc (le plus récent en haut)
  • Échéance : ordre par due_date asc avec nulls en bas (urgences temporelles en haut)

Chaque carte affiche maintenant son échéance si elle existe, avec icône calendrier. Si l'échéance est dépassée et que la DI n'est ni Résolue ni Annulée, la date passe en rouge.

6. Helper relativeTime extrait

Les fonctions locales relativeTime() et activityDot() de la 0.17.0 sont déplacées dans lib/format.js sous les noms relativeTime et activityDotColor. La page Utilisateurs les importe désormais au lieu de les redéfinir localement.

Disponibles pour réutilisation dans : NotifBell (timestamp des notifs), Journal, fiche patient (dernière visite), historique, etc.

7. Patch SQL 0.17.1

Le script aveho-PATCH-vers-0.17.1.sql (84 lignes) effectue :

  1. Table push_subscriptions avec colonnes endpoint / p256dh / auth / user_agent / last_used_at
  2. Index sur user_id et structure_id
  3. RLS : un user ne voit/écrit que ses propres subscriptions (3 policies)
  4. 3 colonnes sur structures : webhook_teams_url, webhook_slack_url, webhook_filters (jsonb avec defaults sains)
  5. Vue v_push_targets qui joint push_subscriptions avec membres_structure (filtre actif + non archivé)

100% idempotent (create if not exists, add column if not exists, create or replace, drop policy if exists).

8. Déploiement Edge Functions

Étape 1 — Générer les clés VAPID
Sur ton poste, dans un terminal : 
npx web-push generate-vapid-keys
Tu obtiens deux clés (publique et privée). Garde-les en sécurité.
Étape 2 — Configurer les secrets côté Supabase
supabase secrets set VAPID_PUBLIC_KEY=
supabase secrets set VAPID_PRIVATE_KEY=
supabase secrets set VAPID_SUBJECT=mailto:contact@aveho.fr
Étape 3 — Déployer les Edge Functions
cd C:\aveho-ec-app
supabase functions deploy send-push
supabase functions deploy send-webhook
Étape 4 — Exposer la clé publique au client
Dans .env.local (et dans les variables d'environnement Vercel) : 
NEXT_PUBLIC_VAPID_PUBLIC_KEY=
Étape 5 — Créer les webhooks Teams/Slack
Teams : dans le canal cible → Plus d'options → Connecteurs → Workflow Post to channel → URL générée
Slack : api.slack.com/apps → Create New App → From scratch → Incoming Webhooks → Add New Webhook to Workspace → URL générée

10. Procédure d'application complète

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.17.1.sql → Run. Idempotent.
  2. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local)
  3. Étape infra Supabase — voir section 8 (génération VAPID + déploiement fonctions + secrets)
  4. Étape .env.local — ajouter NEXT_PUBLIC_VAPID_PUBLIC_KEY=...
  5. Lancer : 
    cd C:\aveho-ec-app
npm install
npm run dev
  6. Tester : voir section 11
  7. Vercel : pousser sur C:\aveho-ec-app-01 + ajouter NEXT_PUBLIC_VAPID_PUBLIC_KEY dans les env vars du projet Vercel
