🚨 Le bug critique : Cross-tenant attack via Edge Functions

Le problème

4 Edge Functions Supabase appelables par le client (send-email, send-webhook, send-push, invite-user) avaient 3 problèmes critiques cumulés :

  1. CORS Access-Control-Allow-Origin: "*" — appelables depuis n'importe quel site malveillant
  2. Pas de check d'authentification — un attaquant non authentifié pouvait potentiellement les appeler directement
  3. Pas de vérification de membership structure_id — un user authentifié de la structure A pouvait envoyer des emails/push/webhooks ciblant la structure B

Scénario d'attaque concret

// User malveillant authentifié sur Aveho
POST https://<projet>.functions.supabase.co/send-email
Authorization: Bearer <son_propre_token_supabase>
{
  "structure_id": "<structure_concurrence>",
  "subject": "🚨 Vos données sont compromises",
  "body_html": "<p>Cliquez ici pour sécuriser votre compte : http://phishing.example</p>",
  // Pas de target_user_id → BROADCAST à TOUS les membres de la structure
}

// → Notre serveur Resend envoie l'email officiellement signé Aveho
//   à tous les membres de la structure concurrente
// → L'email arrive avec le domaine no-reply@aveho.fr (cleared SPF/DKIM)
// → L'attaque est extrêmement crédible

CVSS estimé : 7.5 HIGH (Network / Low complexity / Low privileges / Confidentiality+Integrity impact).

✅ Le fix : helper _shared/auth.ts centralisé

Création de supabase/functions/_shared/auth.ts (180 lignes) avec 5 helpers :

HelperRôle

buildCorsHeaders(req)Headers CORS dynamiques + Vary: Origin (cache CDN correct)

  const admin = authResult.admin!;

  // ... safe : seuls les membres de structure_id peuvent appeler

🐛 Bug bonus : MIME whitelist OCR generic

La route app/api/ocr/generic/route.js n'avait pas de whitelist MIME (les 2 autres routes prescription + bulletin-situation l'avaient depuis 0.57.26). Defense-in-depth qui manquait :

// AVANT 0.57.31
if (!media_type) media_type = "image/jpeg";
// ... media_type passé direct à Claude API

// 0.57.31 - whitelist stricte
const ALLOWED_MIMES = [
  "image/jpeg", "image/png", "image/webp", "image/gif", "application/pdf"
];
if (!ALLOWED_MIMES.includes(media_type)) {
  return Response.json(
    { ok: false, error: `Type MIME non supporté : ${media_type}` },
    { status: 400 }
  );
}

🔒 2 nouveaux LINT anti-régression critiques (13e + 14e)

LINT 13 : CORS Edge Functions restrictif

it("Edge Functions appelables par le client ont CORS restrictif (pas de '*')", () => {
  const CRON_FUNCTIONS = ["auto-archive-consents", "maintenance-daily-cron", ...];

  const violations = [];
  for (const fn of findEdgeFunctions()) {
    if (CRON_FUNCTIONS.includes(fn.name)) continue;
    const src = fs.readFileSync(fn.path, "utf-8");
    // Skip les commentaires (ils peuvent expliquer l'ancien pattern)
    const codeOnly = src.split("\n").filter(l => !/^\s*\/\//.test(l)).join("\n");
    if (/Access-Control-Allow-Origin["']?\s*:\s*["']\*["']/.test(codeOnly)) {
      violations.push(fn.name);
    }
  }
  expect(violations).toEqual([]);
});

LINT 14 : auth obligatoire sur Edge Functions client

it("Edge Functions appelables par le client utilisent _shared/auth.ts", () => {
  const violations = [];
  for (const fn of findEdgeFunctions()) {
    if (CRON_FUNCTIONS.includes(fn.name)) continue;
    const src = fs.readFileSync(fn.path, "utf-8");
    if (!/_shared\/auth\.ts/.test(src)) violations.push(fn.name);
  }
  expect(violations).toEqual([]);   // ← FAIL si nouvelle fn sans auth
});
