🩹 2. Fix 404 membres_equipe persistant

Bug : le 404 sur la table membres_equipe revenait à chaque session du navigateur. Le flag était stocké en sessionStorage donc reset à chaque ouverture du tab. Fix : flag passé en localStorage avec TTL 24h.

[Avant 0.58.51] GET https://[supabase]/rest/v1/membres_equipe?... 404 (Not Found) ↑ apparaît à CHAQUE ouverture du navigateur
[Après 0.58.51] (silencieux pendant 24h) ↑ 404 vu max 1 fois par 24h, re-essai automatique après
// 0.58.51 - app/components/UserAttachmentsInfo.js
useEffect(() => {
  if (!userId) return;
  
  // 0.58.51 : flag localStorage avec TTL 24h
  const FLAG_KEY = 'av-attachments-disabled-until';
  try {
    const until = parseInt(localStorage.getItem(FLAG_KEY) || '0', 10);
    if (until > Date.now()) return;  // flag actif, on skip
  } catch {}
  
  (async () => {
    const { data: memb, error: e1 } = await supabase
      .from('membres_equipe')
      .select('equipe_id, equipes(...)')
      .eq('user_id', userId);
    
    if (e1) {
      // 404 → flag actif pour 24h
      try {
        const next24h = Date.now() + 24 * 60 * 60 * 1000;
        localStorage.setItem(FLAG_KEY, String(next24h));
      } catch {}
      return;
    }
    // ...
  })();
}, [userId, etabId]);

💡 Note : si tu crées la table membres_equipe en base, le re-essai automatique se fait dans les 24h max suivant l'expiration. Pour une activation immédiate, l'user peut supprimer la clé av-attachments-disabled-until dans son localStorage.
