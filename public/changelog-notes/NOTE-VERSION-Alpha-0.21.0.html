1. Résumé exécutif

La 0.21.0 livre un module complet de consentement RGPD avec signature électronique. Conforme aux exigences réglementaires :

  • Document de consentement auto-rempli avec les infos patient + établissement + collectivité
  • Signature électronique sur tout appareil : tactile mobile, souris/trackpad desktop, stylet, ou pavé tactile externe USB via WebHID
  • Stockage sécurisé : image PNG dans un bucket Storage privé Supabase, accessible uniquement via URL signée temporaire ; hash SHA-256 en base pour garantir l'intégrité (détection altération)
  • Page de gestion /consentements : liste avec filtres (Actifs / Refusés / Archivés / Tous), recherche, visualisation, impression, archivage manuel
  • Traçabilité totale : qui a recueilli, depuis quel appareil, à quelle date, quel texte exact a été signé (gel pour audit)
Le consentement est immuable (RGPD). Pas de DELETE possible côté base, uniquement archivage via archive = true. Le texte du consentement signé est gelé dans la colonne texte_consentement pour traçabilité : même si on modifie le template plus tard, les consentements signés gardent leur version originale.

3. Workflow utilisateur

3.1 À la création d'un patient

  1. L'utilisateur ouvre /patients → bouton "Nouveau patient"
  2. Il remplit nom, prénom, date de naissance, N° dossier, médecin traitant, chambre, notes
  3. Il clique "Enregistrer" → le patient est créé en base
  4. Automatiquement, la modale <ConsentementRGPD> s'ouvre par-dessus
  5. Le document est pré-rempli avec les infos du patient et de l'établissement
  6. Le signataire choisit "Patient lui-même" ou "Représentant légal" (avec nom)
  7. Il coche les finalités optionnelles (les 3 obligatoires sont pré-cochées et non décochables)
  8. Il signe dans le pavé tactile
  9. Clic "Valider le consentement" → hash SHA-256 + upload Storage + ligne en base
  10. Retour à la liste patients avec le badge vert "RGPD" sur la ligne

3.2 Recueil différé ou re-signature

Sur la liste /patients, chaque ligne affiche un badge :

  • ✓ RGPD (vert) si signé
  • ⚠️ RGPD à recueillir (orange) si jamais signé, cliquable pour ouvrir directement la modale
  • ✗ RGPD refusé (rouge) si refusé

Plus une icône ti-shield-lock dans la colonne action pour ouvrir le module manuellement à n'importe quel moment.

3.3 Refus de consentement

Le bouton "Refuser" en bas de la modale enregistre un consentement avec statut = "refuse". Cela trace que le refus a bien été proposé et capturé, sans avoir besoin de signature. L'utilisateur garde la trace pour audit.

4. Pavé de signature

4.1 Technologies utilisées

  • Canvas HTML5 avec scaling devicePixelRatio (signature nette sur écrans Retina)
  • Pointer Events unifie souris + tactile + stylet en une seule API (compatibles tous navigateurs modernes)
  • Pression du stylet détectée si dispo (épaisseur de trait adaptative)
  • touchAction: none et userSelect: none pour empêcher scroll et sélection de texte pendant la signature
  • setPointerCapture pour garder le tracé même si le doigt sort un instant du canvas

4.2 Adaptation mobile

Sur mobile :

  • La modale prend toute la largeur de l'écran (max-height 100vh)
  • Le pavé fait min(window.innerWidth - 80, 400) × 180px pour rester confortable
  • Le bouton "Refuser" passe en pleine largeur (3e ligne)
  • Le scroll vertical est dans .consent-body, le header et le footer restent visibles

4.3 API exposée du composant

const padRef = useRef();
<SignaturePad ref={padRef} width={500} height={180} />

// Vérifier si signé

// Effacer

5. WebHID — Signpads externes USB

5.1 Détection

Au montage, le composant vérifie navigator.hid :

  • Si non disponible → message "Pavés externes non supportés par ce navigateur"
  • Si disponible → tente navigator.hid.getDevices() pour voir si un signpad déjà autorisé
  • Sinon → affiche bouton "Connecter un pavé tactile externe"

5.2 Vendors supportés (filters)

Vendor IDMarque
0x056aWacom (gamme STU, signature pads)
0x0403FTDI (signpads génériques USB-serial)
0x06a8Topaz Systems
0x162eScriptel

5.3 Limites WebHID

Compatibilité navigateur : Chrome, Edge, Opera (basés Chromium). Pas Firefox ni Safari à ce jour. Sur ces navigateurs, le composant tombe sur le mode souris/tactile classique sans message d'erreur.

Heuristique de mapping coordonnées : les signpads exposent des formats différents (resolution, ordre des octets). Le décodage actuel suppose 2 octets X + 2 octets Y little-endian sur 16 bits. Les Wacom STU sont OK ; pour d'autres modèles il faudra peut-être adapter le handleHidInput avec le datasheet du vendor.

HTTPS requis : WebHID ne fonctionne que sur HTTPS (sauf localhost en dev).

6. Stockage sécurisé

6.1 Bucket Supabase Storage

Bucket dédié signatures-rgpd créé via SQL :

  • Privé (pas d'URL publique)
  • Limite 5 MB par fichier
  • MIME autorisés : image/png uniquement
  • Policies RLS : seuls les utilisateurs authentifiés peuvent uploader/lire

6.2 Convention de nommage

Chemin : {structure_id}/{patient_id}/{timestamp}-{hash8}.png

Exemple : aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa/abc123.../1717012345000-d41d8cd9.png

Avantages :

  • Organisation par structure puis par patient (isolation logique)
  • Timestamp + hash → noms uniques garantis sans collision
  • Le hash8 sert d'index visuel rapide pour vérifier l'intégrité

6.3 Hash SHA-256

À chaque signature, on calcule le hash SHA-256 du PNG via crypto.subtle.digest() (Web Crypto API native, pas de lib). Le hash est stocké en colonne signature_hash de la table.

Garantie d'intégrité : si quelqu'un modifie l'image directement dans Storage, le hash ne correspondra plus → preuve d'altération. C'est le standard pour la signature électronique conforme.

6.4 URLs signées temporaires

Pour visualiser une signature, on génère une URL signée valide 300 secondes (5 min) via supabase.storage.from("signatures-rgpd").createSignedUrl(path, 300). Pas de stockage de tokens permanents, pas de fuite possible.

7. Template du consentement

7.1 Texte générique santé à domicile

Le template (variable TEMPLATE_CONSENTEMENT dans lib/rgpd.js) suit la structure RGPD recommandée :

  1. Responsable du traitement (collectivité + établissement)
  2. Personne concernée (patient)
  3. Nature des données collectées
  4. Finalités du traitement (avec cases cochées en temps réel)
  5. Base légale (consentement + contrat de soins + obligation légale)
  6. Destinataires (personnel, professionnels de santé, organismes payeurs)
  7. Durée de conservation (20 ans dossier médical, 10 ans facturation)
  8. Vos droits (accès, rectification, effacement, limitation, opposition, portabilité, retrait)
  9. Réclamation CNIL
  10. Signature avec nom du signataire et date

7.3 Variables remplacées

Les placeholders {{patient_nom_prenom}}, {{collectivite_nom}}, {{date_signature}}, etc. sont remplacés à l'exécution. Si une donnée manque (ex. pas de date de naissance saisie), le bloc est masqué proprement (pas de "né(e) le undefined").

8. Patch SQL 0.21.0

Le script aveho-PATCH-vers-0.21.sql (182 lignes) effectue :

  1. Table consentements_rgpd avec 25 colonnes (identité gelée, finalités, statut, hash, métadonnées forensic, audit)
  2. 5 index sur patient_id, structure_id, etablissement_id, statut, date_signature
  3. RLS : 3 policies (select / insert / update). Pas de delete (immutabilité RGPD).
  4. Trigger updated_at automatique
  5. Vue v_patient_consent_status : agrégat par patient (a_consenti, derniere_signature, compteurs)
  6. Bucket Storage signatures-rgpd : privé, 5 MB, PNG only
  7. 2 policies Storage : insert + select pour utilisateurs authentifiés

100% idempotent (if not exists, create or replace, on conflict do nothing). Rejouable.

11. Procédure d'application

  1. SQL d'abord dans Supabase → SQL Editor → coller aveho-PATCH-vers-0.21.sql → Run.
  2. Vérifier le bucket dans Storage : tu dois voir signatures-rgpd apparu (privé). Si le SQL n'a pas pu créer le bucket (versions Supabase plus anciennes), créer manuellement : Storage → New bucket → nom "signatures-rgpd", public NON.
  3. Décompresser le zip par-dessus C:\aveho-ec-app (garder .env.local).
  4. npm install + tests + dev : 
    cd C:\aveho-ec-app
npm install
npm test       # 87 passed
npm run dev
  5. Tester :
    • Créer un nouveau patient → la modale RGPD s'ouvre automatiquement
    • Tester la signature à la souris, valider → vérifier que le badge vert apparaît sur la liste
    • Mode mobile (F12 → device toolbar iPhone) : pavé adapté, signature au doigt
    • Si pavé externe Wacom STU dispo : cliquer "Connecter un pavé tactile externe" → choisir le périphérique → signer
    • Aller dans /consentements : la liste, les filtres, la recherche, la visualisation, l'impression
  6. Pousser sur Vercel comme d'habitude (l'app doit être en HTTPS pour WebHID en prod).
