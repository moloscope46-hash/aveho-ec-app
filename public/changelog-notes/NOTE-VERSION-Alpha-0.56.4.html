🎯 Le concept

Tu as déjà 105 caisses + 44 mutuelles seedées (depuis 0.55.46). Mais il manquait : une vraie interface admin pour les ajouter/modifier/supprimer, et des actions rapides pour les contacter (téléphone, mail, GPS, site web) depuis n'importe où dans l'app.

Maintenant : page /admin/referentiels-sante à 2 onglets + pastilles d'actions partout où une caisse ou mutuelle est affichée (admin + fiches patient).

🔘 Pastilles ContactActions

Le nouveau composant ContactActions affiche uniquement les actions disponibles selon les données renseignées :

📞 Appeler ✉ Email 📍 GPS 🌐 Web
  • Tel → ouvre l'app téléphone (tel:01234...) sur mobile/desktop
  • Email → ouvre l'app mail par défaut (mailto:...)
  • GPS → Google Maps directions avec coords lat/lng si dispo (précis), sinon adresse texte URL-encodée (fallback)
  • Web → ajoute automatiquement https:// si manquant, ouvre en nouvel onglet
  • Si aucune coordonnée n'est renseignée : message "Pas de coordonnées"
  • 3 tailles disponibles : sm (icône seule), md (icône+texte), lg (gros)

Sur /patient/[id]/edit, onglet Sécu & Mutuelle :

  • Sous le bloc Caisse d'affiliation rattachée → pastilles ContactActions (tel/mail/GPS/web de cette caisse)

L'utilisateur peut maintenant appeler/mailer/router vers le bon organisme directement depuis la fiche patient, sans aller chercher les coordonnées ailleurs.

🔌 API étendues

/api/caisses + /api/mutuelles

Les routes existantes ont été étendues avec POST + PUT + DELETE en plus du GET déjà présent.

MéthodeUsageBody
GETRecherche—
POSTCréationnom, code_organisme (caisse), tel/mail/web/lat/lng…
PUTMise à jourid + champs modifiés
DELETESuppression?id=...

Toutes les méthodes utilisent le Authorization: Bearer {token} pour respecter les RLS Supabase. POST détecte les doublons via le code PostgreSQL 23505 et retourne duplicate: true pour message UI clair.
