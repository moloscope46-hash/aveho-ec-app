🔍 Audit API RPPS

Le diagnostic

L'API ANS FHIR distingue STRICTEMENT les critères de recherche :

  • family=DUPONT → cherche le nom de famille
  • given=Marie → cherche le prénom
  • location.address-city=Paris → cherche par ville (via PractitionerRole)

Le bug : avant 0.55.45, on envoyait toujours family=Paris quand l'user tapait "Paris". Résultat : 0 praticien (personne ne s'appelle "Paris" en famille).

Test depuis le sandbox dev

$ curl https://gateway.api.esante.gouv.fr/fhir/v2/Practitioner?family=DUPONT
You're not allowed to access this resource (HTTP 403)

L'IP du sandbox Anthropic est blacklistée par l'ANS. En production sur Vercel (IP française), ça devrait passer. Le code détecte maintenant ce 403 et affiche un message clair.

⚡ Nouvelle logique de recherche

Recherche INTELLIGENTE en parallèle (Promise.all)

Quand l'user tape "Paris" :

// Avant (0.55.44)
GET /Practitioner?family=Paris  → 0 résultat

// Maintenant (0.55.45)
[Promise.all]
├── GET /Practitioner?name=Paris             → 5 personnes nommées Paris
└── GET /PractitionerRole?location.city=Paris → 47 praticiens exerçant à Paris
                                                + _include practitioner

Merge + dédup intelligent

  • Récupère tous les Practitioner et tous les PractitionerRole en parallèle
  • Indexe par id et lie chaque praticien à ses rôles (cabinets multiples)
  • Crée une entrée PAR rôle pour afficher toutes les adresses
  • Dédup par RPPS + cp + commune (un même praticien à plusieurs adresses reste, mais doublons exacts éliminés)

Limites remontées

  • Default : 20 → 50
  • Max : 100 → 200
  • Timeout : 8s → 12s

Headers + User-Agent

Ajout de User-Agent: Aveho-EC/0.55 sur les requêtes pour identifier proprement et éviter certains blocages anti-bot.

🗺 Carte RPPS améliorée

Reverse géocodage BAN INSEE

Au moment de fetch les RPPS pour la carte :

  1. Récupère le centre de la carte (lat/lng)
  2. Appel api-adresse.data.gouv.fr/reverse/?lat=X&lon=Y → nom de la ville
  3. Cache par tile (lat.toFixed(2) + lng.toFixed(2)) en localStorage
  4. Utilise ville=NomVille comme critère dans /api/rpps

→ La recherche est ciblée sur la zone visible, plus de résultats pertinents.

Limites carte

  • Limite remontée de 30 → 100 par profession
  • Console logs détaillés pour debug : [Carte RPPS] Médecin → 47 résultats

Pour debug

Ouvre la Console Chrome (F12) sur la page /carte et active un filtre RPPS. Tu verras :

[Carte RPPS] Médecin → 47 résultats
[Carte RPPS] Infirmier → 12 résultats
[Carte RPPS] résultats finaux 23 / total fetchés 59

Si tu vois 0 résultats ou API error: ... → c'est l'API ANS qui bloque.

⚠ Carte SIRENE

L'API SIRENE supporte déjà bien la recherche par proximité (depuis 0.55.41). Si rien ne s'affiche encore, possibles raisons :

  • Zone trop large (zoome plus serré, ex : sur une ville)
  • Pas de pharmacies/matmed dans la zone
  • La requête API a échoué (vérifier console F12)

Si tu vois encore 0 sur la carte SIRENE en zoomant sur Paris → c'est un autre bug à investiguer.
