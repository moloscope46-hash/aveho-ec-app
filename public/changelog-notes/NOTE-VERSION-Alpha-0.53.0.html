Chantiers livrés

BC Email aux valideurs lors de la soumission d'achat

  • Nouveau helper lib/notifyValideurs.js qui, à partir d'un structureId et d'un achat, identifie tous les users ayant la permission valider_achat via leur rôle
  • Récupère leurs emails depuis profiles et appelle l'edge function existante send-email en parallèle (Promise.allSettled — un échec n'empêche pas les autres)
  • Intégration dans app/achats/page.js dans la fonction soumettre() : après le passage du statut à "À valider", appel asynchrone (non-bloquant) à notifyValideurs(). Le résultat ({ sent, errors }) est loggé en console
  • Email contient : numéro de commande, demandeur, motif, budget estimé, fournisseur, lien direct vers /achats
  • Aucun changement schéma — utilise l'infrastructure existante (send-email + roles.droits)

BK Comparaison périodes dans /statistiques-activite

  • Nouvelle vue SQL v_stats_periode_comparee : agrège l'audit_log sur 2 fenêtres de 30 jours :
    • Période courante : 30 derniers jours
    • Période précédente : du jour J-60 à J-30
  • Compteurs par catégorie : nb_patients_crees, nb_di, nb_transferts, nb_commandes, nb_signalements, nb_users_actifs
  • Nouvelle section dans la page : "30 derniers jours vs 30 jours d'avant" avec 6 cards de comparaison
  • Composant ComparisonCard qui affiche la valeur courante en gros, la précédente en petit, et un badge avec :
    • Delta absolu (+12 ou -5)
    • Pourcentage d'évolution (+8% ou -23%)
    • Icône tendance (↗ vert / ↘ rouge / — gris)
  • Période glissante (recalculée à chaque chargement) — pas besoin de cron

BM Templates de signalements

  • Nouvelle table SQL signalement_templates :
    • Champs : nom, type, titre_modele, description_modele, icone, ordre, actif
    • RLS complètes : select pour tous les membres, insert/update/delete réservés aux admins via r.droits ilike '%manage_roles%'
  • Nouvelle page /templates-signalements (admin) avec CRUD complet :
    • Liste des templates avec colonnes : nom, type, titre, état (actif/inactif)
    • Modal d'édition avec sélection d'icône (12 icônes Tabler proposées)
    • Champ ordre d'affichage pour ranger les templates dans le picker
  • Intégration dans /signalements : la modale "Nouveau signalement" affiche maintenant des chips templates en haut. Un clic remplit automatiquement type/titre/description, prêts à compléter
  • Cas d'usage typiques : "Lit cassé", "Patient agité la nuit", "Wifi en panne", "Demande de matériel urgent", etc.

BJ Mode compact pour les tables

  • Nouveau hook useCompactMode() dans app/CompactToggle.js qui persiste l'état dans localStorage (clé aveho_compact_tables)
  • Toggle visible sur 3 pages :
    • /audit — dans la barre des filtres rapides
    • /patients — à côté du bouton "Filtres avancés"
    • /app-logs — dans la barre des filtres
  • Quand activé : ajoute la classe is-compact au document.body
  • CSS associé : réduit le padding des cells de table à 4px/8px (vs 8px/12px), font-size à 12px (vs 13.5px), et compacte les chip-row
  • Affecte TOUTES les tables wrappées dans .panel-table (les 16 tables du hotfix 0.52.5)
  • État persistant entre les sessions — un user qui préfère le mode compact le retrouve à chaque connexion

BL Mentions légales / RGPD

  • Nouvelle page /mentions-legales accessible :
    • Depuis le footer de la page de connexion (/login) — lien gris discret
    • Depuis le menu principal (section "Informations")
  • 5 sections :
    1. Éditeur : raison sociale, forme juridique, adresse, contact
    2. Protection des données (RGPD) : données traitées, base légale, droits (articles 15-22), procédure d'exercice, lien CNIL, hébergement UE (Supabase + Vercel), durée de conservation (90j logs, 20 ans patient)
    3. Cookies & stockage local : précise que localStorage = préférences personnelles, cookie session = strictement nécessaire
    4. Conditions d'utilisation : engagements de l'utilisateur (secret pro, non-partage de creds, etc.)
    5. Contact : support@, dpo@, security@
  • Contenu rédigé "Aveho Soft & Services / Groupe Fidéciel" — placeholders à compléter (siège, directeur publication)

BO Badge "NEW" dans le menu pour pages récentes

  • Constante NEW_PAGES dans app/TopBar.js avec date d'ajout de chaque page :
    • /templates-signalements (depuis 31/05)
    • /mentions-legales (depuis 31/05)
    • /changelog (depuis 30/05)
    • /digest-dashboard (depuis 30/05)
    • /statut (depuis 30/05)
    • /app-logs (depuis 30/05)
  • Durée d'affichage du badge : NEW_DURATION_DAYS = 14 jours après l'ajout
  • Tracking visite : localStorage aveho_visited_pages qui stocke les pages déjà visitées avec timestamp
  • Logique d'affichage : badge rouge "NEW" affiché si :
    1. Page dans NEW_PAGES
    2. Ajout récent (< 14 jours)
    3. Pas encore visitée par cet utilisateur
  • Mécanisme déjà câblé dans le TopBar — il suffit d'ajouter une page à NEW_PAGES à chaque release pour qu'elle reçoive le badge

SQL — Patch 0.53

2 objets DB ajoutés (idempotent, à exécuter dans Supabase > SQL Editor) :

Table signalement_templates + RLS

create table if not exists signalement_templates (
  id uuid primary key default gen_random_uuid(),
  structure_id uuid not null references structures(id) on delete cascade,
  nom text not null,
  type text not null,
  titre_modele text not null,
  description_modele text not null,
  icone text,
  ordre int default 0,
  actif boolean not null default true,
  cree_par uuid references auth.users(id) on delete set null,
  created_at timestamptz default now()
);

create index if not exists idx_signalement_templates_struct 
  on signalement_templates (structure_id, actif, ordre);

alter table signalement_templates enable row level security;
-- + 4 policies (select membres, insert/update/delete admin)

Vue v_stats_periode_comparee

create or replace view v_stats_periode_comparee as
with periode_courante as (
  select structure_id, etablissement_id, 'courante' as periode,
    count(*) filter (where entite = 'patient' and action = 'creer') as nb_patients_crees,
    count(*) filter (where entite = 'intervention') as nb_di,
    count(*) filter (where entite = 'transfert') as nb_transferts,
    count(*) filter (where entite = 'commande') as nb_commandes,
    count(*) filter (where entite = 'signalement') as nb_signalements,
    count(distinct user_id) as nb_users_actifs
  from audit_log
  where created_at >= now() - interval '30 days'
  group by structure_id, etablissement_id
),
periode_precedente as (
  -- ... mêmes compteurs, fenêtre J-60 à J-30
)
select * from periode_courante
union all
select * from periode_precedente;

grant select on v_stats_periode_comparee to authenticated;
notify pgrst, 'reload schema';

Procédure d'application — PowerShell

  1. Appliquer le patch SQL aveho-PATCH-vers-0.53.sql dans Supabase > SQL Editor (création table + vue, <5 sec)
  2. Décompresser le zip 0.53.0 par-dessus C:\aveho-ec-app\
  3. Installer + lancer : 
    cd C:\aveho-ec-app
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm install
npm run dev
  4. Tester les 6 chantiers :
    • BC — sur /achats : soumettre une commande → vérifier dans la console "📧 X valideur(s) notifié(s)" (les emails partent via Resend de l'edge function existante)
    • BK — sur /statistiques-activite : la nouvelle section "30 derniers jours vs 30 jours d'avant" apparaît avec 6 cards et badges de tendance
    • BM — sur /templates-signalements : créer 2-3 templates ("Lit cassé", "Wifi en panne"...) → aller sur /signalements → "Nouveau signalement" → cliquer un chip template → le formulaire se pré-remplit
    • BJ — sur /audit, /patients ou /app-logs : cliquer le bouton "Confort" → bascule en "Compact" → les lignes deviennent plus serrées. Persiste à la prochaine connexion.
    • BL — depuis /login, cliquer "Mentions légales & RGPD" en bas → la page s'ouvre avec les 5 sections
    • BO — ouvrir le menu drawer → un badge rouge "NEW" est visible sur les pages récemment ajoutées (templates-signalements, mentions-legales...). Cliquer une → le badge disparaît pour cette page chez ce user.
