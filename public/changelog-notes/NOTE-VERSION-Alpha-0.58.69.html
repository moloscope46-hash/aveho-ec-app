Les comptes comptables sont pré-remplis selon les conventions du plan comptable général (PCG) français : classe 7 pour les ventes, classe 6 pour les achats, 44571xx pour la TVA collectée et 44566xx pour la déductible.

Logique métier verrouillée

  • Un seul taux par défaut à la fois : cocher « est_defaut » sur un taux unset automatiquement les autres (via `UPDATE est_defaut=false WHERE id ≠ current`)
  • Impossible de supprimer le taux par défaut (toast d'erreur explicite)
  • Impossible de désactiver le taux par défaut (le bouton toggle est disabled)
  • Code unique par structure (contrainte UNIQUE en SQL + détection du 23505 côté JS)

🪄 Parse GS1-128 automatique

Si le code scanné est un GS1-128 (norme barcode de la santé pour les DM), on extrait automatiquement les Application Identifiers (AI) et on pré-remplit le formulaire :

Code scanné : ]C1010340123456789010LOT2026A1727123121SN12345

(01) GTIN-14 : 03401234567890 → EAN13 : 3401234567890
(10) Lot : LOT2026A → pré-rempli dans form.lot
(17) Péremption : 271231 → 2027-12-31 (ISO via formatGS1Date)
(21) Série : SN12345 → pré-rempli dans form.numero_serie

🔍 3 niveaux de recherche article

  1. Match exact sur code_barre (cas le plus courant)
  2. Si numérique 4-10 chiffres → fallback code_lpp (recherche par code LPP/LPPR)
  3. Sinon → code_barres_alt (array PostgreSQL, multi-codes par article)

Si rien trouvé : « Aucun article ne correspond — voulez-vous créer un nouvel article rapidement ? » → redirige vers /articles?new=1&code_barre=X avec le code pré-rempli.

📦 Création matériels physiques optionnelle

Si l'article a gere_lot ou gere_serie, une checkbox propose de générer N matériels physiques dans la table materiels (1 par unité de la quantité saisie) avec le S/N et le lot. Pratique pour les entrées de stock série/lot tracées : 1 scan = N matériels créés.

📋 Nouveau SQL — Table stock_mouvements

-- migration-0.58.69-stock-mouvements.sql
CREATE TABLE IF NOT EXISTS stock_mouvements (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  structure_id UUID NOT NULL,
  etablissement_id UUID,
  article_id UUID NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  type TEXT NOT NULL DEFAULT 'entree',     -- entree | sortie | ajustement | retour
  quantite NUMERIC(10,2) NOT NULL DEFAULT 1,
  -- Tracabilité
  lot TEXT, numero_serie TEXT, date_peremption DATE,
  -- Rattachements optionnels
  depot_id UUID, patient_id UUID, fournisseur_id UUID,
  -- Métadonnées
  prix_achat_unitaire NUMERIC(10,4),       -- snapshot prix au moment du mouvement
  notes TEXT, user_id UUID, user_email TEXT,
  source TEXT,                              -- scan_barcode | manuel | import | transfert
  reference_externe TEXT,                   -- BL fournisseur, n° facture
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 5 index optimisés
CREATE INDEX IF NOT EXISTS idx_stock_mvts_article ON stock_mouvements(article_id, created_at DESC);
-- + structure, type, lot (partial), série (partial)

-- RLS avec pattern DROP+CREATE (PG <17 compatible)
ALTER TABLE stock_mouvements ENABLE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS "stock_mvts_read_struct" ON stock_mouvements;
CREATE POLICY "stock_mvts_read_struct" ON stock_mouvements FOR SELECT
  USING (structure_id IN (SELECT structure_id FROM membres_structure WHERE user_id = auth.uid()));
