🏢 Concept "Partenaire" — distinction métier

Type d'étabDéfinitionVisible dans
🏥 Géré (collectivité) Étab dont la collectivité a la gestion active : patients, matériel, interventions, signalements y sont enregistrés. C'est l'établissement "courant" sélectionnable dans le switcher en haut. Switcher étab · Toutes les pages métier · Carte (marqueur bleu/sarcelle 🏥)
🏢 Partenaire Étab référencé pour la logistique uniquement : hôpital prescripteur, structure tiers où on livre, EHPAD avec qui on échange du matériel… Aucune gestion patient/matériel n'y est faite côté Aveho. Annuaire (onglet Partenaires) · Carte (marqueur teal/sarcelle 🏢) · Pas dans le switcher étab

SQL — Patch 0.55.3

1 patch léger (à exécuter dans Supabase > SQL Editor) :

alter table etablissements
  add column if not exists est_partenaire boolean not null default false;

create index if not exists idx_etablissements_partenaire
  on etablissements (structure_id, est_partenaire);

notify pgrst, 'reload schema';

Tous les étabs existants gardent leur statut "géré" (default false). À toi de marquer ensuite ceux qui sont des partenaires.

🐛 Fix warning Chrome géolocalisation

Symptôme

[Violation] Only request geolocation information in response to a user gesture.
  at GeolocPrompt.js:48

Cause

Quand l'user avait déjà accepté la géoloc une fois, mon useEffect appelait navigator.geolocation.getCurrentPosition() automatiquement au chargement de l'app pour refresher la position. Chrome devkit le considère comme un anti-pattern : la géoloc ne doit être demandée qu'en réponse à un user gesture explicite (clic).

Fix

Au chargement (choix "accepted" déjà en localStorage), on se contente de relire la dernière position connue depuis localStorage.aveho_geoloc_last_pos (validité 24h). Aucun appel getCurrentPosition() automatique.

Le refresh effectif de la position se fait uniquement quand l'user clique sur le bouton "Ma position" de la carte (user gesture) → fonction centerOnMe() dans app/carte/page.js qui appelle getCurrentPosition() en réponse à l'action.

Résultat : plus aucun warning Chrome, comportement plus respectueux côté UX, et la position reste fraîche tant que l'user l'utilise vraiment.

🎨 Switcher d'établissement — filtre partenaires

Le useAuth charge la liste des établissements pour le switcher en haut. Ajout d'un filtre !est_partenaire :

// Avant
etabs = (me || []).map(...).filter((e) => e.actif !== false);

// Après
etabs = (me || []).map(...).filter((e) => e.actif !== false && !e.est_partenaire);

Logique : un user travaille DANS sa collectivité, pas DANS un partenaire (qui n'a ni patients ni matériel côté Aveho). Sans ce filtre, l'user aurait pu sélectionner un hôpital prescripteur comme étab actif et créer des patients dedans par mégarde.
