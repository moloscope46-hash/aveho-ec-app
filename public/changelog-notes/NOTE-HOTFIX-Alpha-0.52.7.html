1. Erreur 503 dans la console

Cause

En mode développement (npm run dev), Next.js utilise Fast Refresh / HMR qui régénère les chunks _next/static/chunks/... à chaque sauvegarde de fichier.

Le Service Worker, configuré pour cacheFirst sur tout /_next/static/, essayait :

  1. Chercher le chunk dans le cache → absent (vient juste d'être rebuilt)
  2. Fetch réseau → parfois échoue brièvement pendant le rebuild Next
  3. Catch fetch → renvoyait new Response("Hors-ligne", { status: 503 })
  4. Le navigateur affiche l'erreur dans la console

Le SW n'est pas conçu pour le dev mode où les ressources changent en permanence. C'est uniquement utile en production où les chunks sont hashés et immutables.

Correction (public/sw.js)

Fix 1 : bypass complet du SW pour /_next/ et /api/ quand on est en dev (localhost/127.0.0.1) :

self.addEventListener("fetch", (event) => {
  // ...
  // Alpha 0.52.7 : en mode dev (localhost), bypass complet du SW
  // pour Next chunks. Évite les 503 quand HMR rebuild un chunk.
  const isDev = url.hostname === "localhost" || url.hostname === "127.0.0.1";
  if (isDev && (url.pathname.startsWith("/_next/") || url.pathname.startsWith("/api/"))) {
    return;  // Le navigateur fait son fetch normal sans interception
  }
  // ...reste du routing
});

Fix 2 : pour le cas où un chunk manque vraiment en prod, plus de 503 bruyant. On utilise Response.error() qui retourne une erreur réseau silencieuse — le navigateur la gère sans polluer la console :

async function cacheFirst(req, cacheName) {
  // ...
  try {
    const res = await fetch(req);
    if (res.ok) cache.put(req, res.clone());
    return res;
  } catch (e) {
    // Avant : return new Response("Hors-ligne", { status: 503 });
    // Après : 
    return Response.error();  // Pas de bruit en console
  }
}

Impact

  • En dev : plus aucune erreur 503 dans la console pendant les rebuilds HMR
  • En prod : si un chunk hashé manque vraiment (cas rare), le navigateur retentera naturellement sans logger d'erreur
  • Comportement offline normal (navigation, données) inchangé
