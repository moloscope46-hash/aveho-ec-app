🎯 Le concept

Quand on parcourt le changelog, on tombe régulièrement sur des versions qui nécessitent l'exécution d'un patch SQL dans Supabase pour fonctionner. Avant cette version, il fallait fouiller le dossier /supabase/ du repo pour les retrouver.

Maintenant, sur chaque carte de version qui a un SQL associé, un nouveau bouton SQL (navy + teal) apparaît à côté du bouton "HTML". Au clic, une popup s'ouvre avec :

  • Header gradient indiquant la version et le nom du fichier
  • Encart instructions Supabase (jaune)
  • Le contenu SQL complet en mode syntax-highlighted (fond navy, texte gris clair)
  • Bouton Copier dans le presse-papier (feedback vert "Copié !" 2s)
  • Bouton Télécharger le .sql direct
  • Footer avec nombre de lignes et taille du fichier
  • Fermeture par X, Escape, ou clic en dehors

📦 Couverture

36 versions équipées avec un patch SQL associé :

  • Anciennes : 0.15, 0.16, 0.16.1, 0.17.1, 0.20, 0.20.1, 0.21-0.24, 0.29-0.34, 0.37, 0.40-0.44
  • Récentes : 0.46-0.47, 0.50-0.54, 0.55.3, 0.55.6
  • Tout récentes : 0.55.12 (refonte users A), 0.55.13 (WebAuthn empreinte)

Les versions sans SQL (hotfix UI, fix de SW, refacto JS pur, etc.) n'affichent pas le bouton SQL — uniquement le bouton HTML.

🔧 Architecture

Fichiers SQL servis statiquement

Tous les SQL de supabase/aveho-PATCH-vers-*.sql sont maintenant aussi présents dans public/changelog-sql/. Vercel les sert directement avec l'URL /changelog-sql/aveho-PATCH-vers-X.Y.Z.sql.

Référence dans versions-data.js

Chaque entrée de version concernée gagne un champ sqlFile :

{
  "v": "0.55.13",
  "kind": "version",
  "titre": "...",
  "noteFile": "NOTE-VERSION-Alpha-0.55.13.html",
  "sqlFile": "aveho-PATCH-vers-0.55.13.sql"
}

État de la modale

Le state sqlModal contient { version, file, content }. Le contenu est fetché lazy au 1er ouverture, puis caché dans un sqlCacheRef pour éviter de refetch si l'user rouvre la même modale.

Comportements

  • Pendant le chargement : spinner teal "Chargement…"
  • Sur erreur : -- Erreur de chargement\n-- HTTP 404 affiché dans la zone SQL
  • Copier : navigator.clipboard.writeText() avec fallback alert si refusé
  • Télécharger : lien direct vers /changelog-sql/{file} avec attribut download
  • Échap, clic backdrop, X → ferme

Fichiers modifiés

  • public/changelog-sql/ : NOUVEAU dossier avec 36 fichiers .sql
  • app/changelog/page.js : bouton SQL + modale + helpers (~180 lignes ajoutées)
  • app/changelog/versions-data.js : champ sqlFile ajouté sur 36 entrées
  • app/changelog/versions-data.js : nouvelle entrée 0.55.15 en tête
  • package.json : 0.55.14 → 0.55.15

Procédure

Pas de SQL pour cette version. Juste :

cd C:\aveho-ec-app
# Décompresser le zip par-dessus

# ⚠ Important : le dossier public/changelog-sql/ contient maintenant

Vercel build auto (~2 min). F12 → Clear site data → reload /changelog.

Tests

  1. Ouvre /changelog
  2. Repère une version avec un encart SQL connu (par ex. 0.55.13 — WebAuthn). Tu dois voir 2 boutons : HTML + SQL
  3. Clic sur SQL → popup s'ouvre, spinner brièvement, puis contenu SQL affiché
  4. Clic sur Copier → "Copié !" vert pendant 2s · colle dans Supabase pour vérifier
  5. Clic sur Télécharger → fichier .sql téléchargé
  6. Échap → ferme la modale
  7. Une version SANS SQL (ex: 0.55.10 hotfix) → seul le bouton HTML est présent
